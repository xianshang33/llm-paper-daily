## 文章做了什么
- **背景**：企业分析旨在通过收集、分析和可视化组织数据来支持数据驱动的决策。然而，非技术用户在使用传统商业智能（BI）工具或 Text-to-SQL 系统时仍面临障碍。现代企业分析依赖于受治理的 API（Governed APIs），这些 API 封装了复杂的业务逻辑以确保一致性、可审计性和安全性。
- **已有工作的不足**：现有的基于 LLM 的 Text-to-SQL 方法主要关注直接访问原始数据库，无法适应依赖受治理 API 的企业环境。将数学或聚合逻辑委托给 LLM 会引入可靠性和合规性风险。此外，现有方法通常是单步管道，缺乏多步推理能力，无法与更广泛的分析生态系统集成，也难以强制执行数据治理策略。

## 文章的核心贡献点
- **提出了一个 Analytic Agent**：这是一个基于 LLM 的智能体系统，能够将自然语言意图转化为与企业分析 API 的安全交互。
- **挑战1：复杂意图解析与目标消歧**。在企业环境中，用户查询往往模糊且涉及特定的业务语义，直接映射到 API 端点非常困难。论文通过引入 Target Search Agent（目标搜索智能体）和 Orchestrator Agent（编排智能体），利用多步推理解析用户目标，匹配实体并验证权限，从而准确识别所需的 API 端点和指标。
- **挑战2：合规执行与安全可视化**。直接在 LLM 中生成查询结果可能导致数据泄露或违反业务规则。论文通过 Database Querying Agent（数据库查询智能体）进行端点选择和查询构建，并结合严格的验证循环确保业务规则得到遵守；同时，Visualization Agent（可视化智能体）根据策略生成合规的图表配置，确保最终输出的安全性和规范性。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：系统由编排智能体、目标搜索智能体、数据库查询智能体和可视化智能体组成，形成端到端的工作流。它在真实工业环境中部署，处理从自然语言查询到安全 API 交互的全过程。
- **评估结果**：在由领域专家构建的 90 个真实企业用例上进行评估，并由 GPT 和 Claude 进行评判。Analytic Agent 实现了 77.22% 的端到端准确率和 96.67% 的查询执行成功率。
- **对比**：相较于传统的 Text-to-SQL 方法和单步 LLM 管道，该系统在处理受治理 API 场景下表现出更高的可靠性和合规性，证明了基于 API  grounding 的分析路径的可行性。

#### 总结
本文针对企业分析中非技术用户访问受治理数据的难题，提出了 Analytic Agent。该系统克服了传统 Text-to-SQL 方法在 API 环境和数据治理方面的局限性，通过多智能体协作实现了意图解析、权限验证、安全查询执行和合规可视化。实验结果表明，该方法在真实企业场景中具有高准确性和执行成功率，为构建可信的、基于 API 的企业分析系统提供了实用路径。
