## 文章做了什么
- **背景**：LLM Agent 的故障诊断目前主要依赖人工。从业者通常仅检查少量执行轨迹（traces），形成临时假设并迭代。这种方法无法发现仅在轨迹群体层面显现的模式，且难以扩展到生产环境中包含数万 token 的大型语料库。
- **已有工作为什么解决不了**：现有的评估方法通常基于最终任务结果提供聚合信号，无法揭示中间行为或特定子集（如特定输入、任务类型）中的局部失败模式。许多“静默失败”（silent failures）和不效率行为不会触发显式错误信号，因此无法通过标准评估仪表盘检测到，必须通过群体层面的分析才能发现。

## 文章的核心贡献点
- **提出了一个 Insights Generator (IG)**：这是一个多智能体系统，旨在解决语料库级别的轨迹诊断问题。它通过在整个轨迹语料库中提出和测试假设，生成有证据支持的自然语言洞察报告。
- **挑战1：规模与复杂性**。轨迹语料库通常超出单个模型的上下文窗口限制，且单个轨迹交织着大量的推理、工具调用和环境状态，使得直接分析极其困难。IG 采用“侦察员-调查员”（scout-investigator）架构，通过分层处理和假设验证机制，在不需一次性加载所有数据的情况下，系统地探索大规模语料库以识别模式。
- **挑战2：洞察的可信度与 groundedness**。生成的洞察必须有具体的轨迹证据支持，避免幻觉或空泛结论。IG 通过将每个自然语言洞察链接到具体的支持证据（即相关的轨迹片段），确保洞察是“有根基的”（grounded），从而提高了诊断报告的可操作性和可信度。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **评估维度**：研究从定性和客观两个维度评估 IG，包括基于评分标准的报告质量评估，以及实施 IG 洞察后带来的下游性能提升。
- **性能提升**：人类专家利用 IG 生成的报告改进 scaffold 后，性能比未修改的基线提高了 30.4 个百分点（pp）。利用 IG 衍生洞察的编码 Agent 也表现出一致且稳定的增益。
- **与工作对比**：在多个基准测试中，IG 的“侦察员-调查员”架构在检测覆盖率方面与竞争方法相当。然而，领域专家评定 IG 生成的报告在深度和证据质量方面处于领先地位，优于其他方法。

#### 总结
本文形式化了语料库级别轨迹诊断的问题，并提出了 Insights Generator (IG) 系统。IG 通过多智能体协作，自动化地从大规模 LLM Agent 执行轨迹中提取有证据支持的系统性行为模式洞察。实验表明，IG 不仅能提供高质量的诊断报告，还能显著提升 Agent 的实际性能，有效解决了传统人工诊断和聚合评估无法发现的深层及静默失败问题。
