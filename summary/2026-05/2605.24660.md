## 文章做了什么
- **背景**：在 LLM Agent 使用工具前，检索系统需决定向模型展示多少候选工具（即搜索深度 K）。展示过多会导致模型选择困难且消耗大量 Token，展示过少则可能遗漏正确工具。目前大多数系统对所有查询采用固定的短列表大小，缺乏评估该大小是否合适的标准指标。
- **已有工作为什么解决不了**：现有的文档检索指标（如 nDCG@K）虽考虑深度，但工具选择领域缺乏等效的、能区分查询难度并评估深度合理性的标准方法。固定 K 的策略无法适应不同难度的查询，且难以诊断系统是未能检索到工具还是模型未能选对工具。

## 文章的核心贡献点
- **提出了一个基于 Bits-over-Random (BoR) 的机会校正评估框架及自适应深度选择机制**：将 BoR 作为评估工具检索深度的核心指标，并将其转化为强化学习奖励信号，以实现每个查询的动态深度调整。
- **挑战1：缺乏评估检索深度合理性的标准化指标**。难点在于传统指标无法剥离“随机命中”的概率，导致难以判断在特定深度下的成功是源于系统能力还是运气。论文引入 BoR 指标，通过计算观测成功率与同深度随机选择期望成功率的比值（取对数），量化了超越随机基线的信息增益，从而客观评估深度的有效性。
- **挑战2：固定深度无法平衡覆盖率与上下文效率**。难点在于简单查询只需少量工具，而复杂查询需要更深检索，固定策略要么浪费资源要么漏掉答案。论文利用 BoR 随深度增加而自然衰减的特性（因为随机命中率上升）构建 RL 奖励，无需人工设计复杂的深度惩罚项，使 Agent 能自动学习针对每个查询的最佳截断深度。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与评估设置**：在三个工具选择基准测试（BFCL, MetaTool, ToolBench）上进行评估，工具注册表规模从 20 到 3,251 不等。使用一个简单的 RL Agent 作为探针，以 BoR 为奖励信号学习每个查询的短列表深度。
- **对比结果**：
    - **BFCL (370 个工具)**：BoR 驱动的策略平均仅展示 7 个工具，却达到了与展示 50 个工具几乎相同的覆盖率（90.3% vs 90.8%）。
    - **ToolBench (3,251 个工具)**：固定展示 5 个工具的基线在总体覆盖率上略高（64.7% vs 61.9%），但在高难度查询（正确工具排名 6-20 位）上完全失效（0% 找到率）。相比之下，BoR Agent 在这些难例中通过加深搜索找到了 16.7% 的正确工具。
    - **下游任务验证**：使用 Claude Sonnet 4.6 进行验证，自适应短列表显著提升了 LLM 选择正确工具的能力。整体准确率为 93.1%（固定 5 个为 87.1%）；在中等难度查询（正确工具存在但非排名第一）中，优势更明显（76.8% vs 60.9%）。

#### 总结
本文指出了 LLM Agent 工具检索中固定深度策略的局限性，并提出使用 Bits-over-Random (BoR) 这一机会校正指标来评估和优化搜索深度。通过将 BoR 转化为强化学习奖励，实现了无需复杂工程惩罚的自适应深度选择。实验证明，该方法在大幅减少平均展示工具数量的同时，保持了高覆盖率，并显著提升了 LLM 在复杂场景下的工具选择准确率，为工具检索评估提供了新的标准和方法论。
