## 文章做了什么
- **背景**：金融领域的 LLM Agent 需要同时阻止提示词注入导致的未授权操作，并批准合法的多步业务工作流。由于金融操作往往涉及不可逆的状态变更（如转账、泄露 KYC 信息），安全性至关重要。
- **已有工作的局限性**：现有的边界过滤器（Boundary filters）通常是无状态的，无法检测到跨越多轮对话或隐藏在检索文档中的碎片化攻击载荷，容易遗漏轨迹中间的不可逆工具调用。而后置的 LLM 评判器（Post-hoc LLM judges）仅在 Agent 终止后进行审计，干预太晚且计算成本随轨迹长度线性增长，无法在运行时进行有效拦截。

## 文章的核心贡献点
- **提出了一个名为 FinHarness 的内联全生命周期安全 harness**，它端到端地包裹金融 Agent，包含查询监控、工具监控和级联模块三个核心组件。
- **挑战1：如何检测跨轮次的隐蔽意图漂移和碎片化攻击？**
  - **难点**：单轮对话看似正常，但攻击者将恶意意图分散在多轮交互中，传统单点检测无法识别累积风险。
  - **解决方法**：提出 Query Monitor，融合单轮意图与跨轮次漂移分析，持续追踪上下文中的风险累积。
- **挑战2：如何在保证低延迟和低计算成本的同时实现实时干预？**
  - **难点**：使用高级 LLM 进行每一步验证成本过高，而轻量级模型可能漏报；后置审计又无法阻止已发生的错误操作。
  - **解决方法**：提出 Cascade 模块，集成每步风险评分，自适应地在轻量级和高级 LLM 评判器之间路由验证请求。一旦触发风险因子，将其作为事前证据重新注入 Agent 输入，使 Agent 能够自主拒绝、重规划或升级处理。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **数据集与基准**：在 FinVault 基准上进行评估。
- **主要结果**：
  - **安全性提升**：FinHarness 将攻击成功率（ASR）从 38.3% 降低至 15.0%。
  - **可用性保持**：良性请求的批准率仅从 41.1% 轻微下降至 39.3%， largely preserving benign approval。
  - **效率优化**：与始终使用高级评判器的消融实验相比，FinHarness 减少了 4.7 倍的高级评判器调用次数。
- **对比优势**：相比于边界过滤器，它能捕捉中间轨迹风险；相比于后置审计，它能实现事中干预且成本更低。

#### 总结
FinHarness 通过将安全防护从“外部监督”转变为“内联生命周期管理”，解决了金融 LLM Agent 在复杂多步工作流中的安全难题。其核心创新在于结合了跨轮次意图监控和自适应的级联验证机制，既有效降低了攻击成功率，又显著控制了计算开销，为金融领域的高风险 Agent 部署提供了可行的安全框架。
