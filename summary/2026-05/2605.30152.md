## 文章做了什么
- **背景**：随着大语言模型（LLM）代理的发展， proactive agents（主动式代理）被期望能够主动提供帮助，而不仅仅是等待指令。这要求系统持续监控用户活动，并做出两个关键决策：何时介入（trigger/wake）以及基于什么上下文进行介入（anchor/grounding）。
- **已有的工作为什么解决不了**：现有的主动式代理通常将用户活动渲染为文本，并在每个事件上都调用 LLM 来决定是否行动。这种方法存在两个主要缺陷：
    1. **效率低下且昂贵**：用户活动本质上是操作系统维护的结构化事件流（如 actor, verb, object, timestamp），将其转换为文本再让 LLM 恢复结构是一种不必要的“往返”开销。LLM 的高延迟和计算成本使其难以作为实时、始终在线的触发器。
    2. **建议缺乏 grounding（落地性）**：由于触发和上下文选择往往解耦或依赖通用会话主题，生成的建议往往无法准确指向用户正在操作的具体实体（如特定文件或网页），导致建议不够精准。

## 文章的核心贡献点
- **提出了一个基于时序图学习（TGL）的轻量级触发与路由架构**：该架构直接将用户活动视为图更新，使用小型 TGL 模型作为编码器，仅在下游需要生成自然语言回复时才调用 LLM。
- **挑战1：实时性与计算成本的矛盾**。难点在于如何在毫秒级延迟内处理高频用户事件，同时保持低资源占用，而 LLM 每次前向传播都过于缓慢且昂贵。论文方法通过用小型 TGL 模型替代 LLM 作为 always-on 触发器，单次前向传播即可得出触发概率，实现了比 LLM 方案快 4-83 倍的速度，且内存 footprint 仅约 220 MiB，可部署在端侧设备。
- **挑战2：上下文选择的准确性与结构化缺失**。难点在于如何从复杂的活动流中精准识别出与当前意图相关的具体实体，避免泛泛而谈。论文方法在 TGL 中引入了 routing head（路由头），针对实体节点输出评分，从而直接选出高相关性的结构化上下文（如具体文件 ID），解决了传统方法中建议缺乏具体 grounding 的问题。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：系统采用“图优先”架构。输入为结构化事件流，构建会话图。TGL 模型包含两个头：Trigger head（决定唤醒/抑制）和 Routing head（选择实体）。只有当触发概率高时，才将选定的结构化上下文传递给下游 LLM Agent 生成自然语言回复。模型支持 BF16 精度，驻留内存约 220 MiB，可在消费级笔记本和 GPU 服务器上运行。
- **Evaluation 结果**：
    - **准确性**：在 14 种不同的 backbone 设置下，TGL 方法的 F1 分数平均提升了 16.7%，最高提升达 46.0%。在触发器架构对比中，该 TGL 检查点提供了最强的触发 AUC 和最稳定的部署阈值。
    - **效率**：在 GPU 服务器上每事件处理时间为 11.13 ms，在消费级笔记本上为 13.99 ms。
- **对比**：相比所有测试过的“LLM 作为触发器”的单次前向配置，该方法在 GPU 环境下快 4-7 倍，在笔记本环境下快 12-83 倍。传统方法需对每个事件调用 LLM，无论是否生成任务均产生全额成本，而该方法仅在必要时调用 LLM。

#### 总结
本文质疑了主动式代理中“每个事件都调用 LLM 进行决策”的必要性，指出这是一种低效的架构设计。通过引入时序图学习（TGL）模型来处理结构化的用户活动流，作者提出了一种高效、轻量的触发与路由机制。该方法不仅显著降低了延迟和计算成本，使其能够部署在隐私敏感的端侧设备上，还通过结构化的实体路由提高了建议的准确性和 grounding 能力。实验证明，该方案在速度和准确性上均优于现有的基于 LLM 的触发架构，为构建实时、高效的主动式助手提供了新的范式。
