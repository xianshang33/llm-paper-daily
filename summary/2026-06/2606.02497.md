## 文章做了什么
- **背景**：时间序列预测在基础模型的推动下取得了显著进展，特别是在数值外推的零样本性能上。然而，在实际业务场景中，统计上合理的基线预测很少直接作为最终决策依据。在用于规划或资源分配前，预测结果通常需要结合弱结构化业务上下文（如节假日效应、促销计划、外部事件、历史类比和专家反馈）进行修订。
- **已有工作为什么解决不了**：现有的研究主要集中在改进从历史观测到未来值的预测器本身，或通过多模态输入扩展预测空间。虽然最近的 LLM 系统支持检索和迭代优化，但它们通常关注如何生成或细化预测，而非如何在操作约束下对已生成的基线进行上下文感知的修订、论证和追踪。此外，传统的判断性预测调整通常被视为人工过程，缺乏可执行性和可审计性，难以满足业务对修订过程可控性及证据追溯的需求。

## 文章的核心贡献点
- **提出了一个**名为“最后一公里预测”（Last-Mile Forecasting）的问题定义，并构建了一个位于预测骨干模型之上的 LLM Agent 框架，旨在将统计基线转化为可决策的业务预测。
- **挑战1：如何将异构的非结构化业务上下文转化为具体的预测修正动作？**
  - **难点**：业务上下文（如文本新闻、日历事件）与数值预测之间存在语义鸿沟，且直接让 LLM 输出自由格式的替换预测会导致过程不可控、不可审计。
  - **解决方法**：系统维护统一的预测工作区，调用工具检索上下文证据，并将推理轨迹转化为显式的预测修订动作，同时施加结构化的安全约束，确保修订过程的可控性。
- **挑战2：如何支持长周期预测并保持修订逻辑的一致性与可追溯性？**
  - **难点**：长 horizon 预测容易累积误差，且复杂的修订逻辑难以在单次推理中保持连贯，缺乏事后反思机制导致错误难以纠正。
  - **解决方法**：采用 Map-Reduce 风格的分解策略处理长周期预测，并通过记忆库（Memory Bank）实现事后反思（Post-hoc Reflection），从而增强系统的长期推理能力和可审计性。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：该框架设计为可控制和可审计的系统，包含统一的工作区、工具调用模块、安全约束层以及记忆库。它不取代现有的预测骨干模型，而是作为上层推理框架运行。
- **评估结果**：通过真实世界的案例研究展示了该系统的能力。结果表明，LLM Agent 能够有效桥接统计预测与业务就绪预测之间的差距。
- **对比**：与主要关注提高数值准确性的传统预测模型或多模态预测方法不同，该方法强调修订过程的可解释性和可操作性。与直接生成自由格式输出的 LLM 方法相比，该方法通过显式动作和安全约束提供了更高的可控性和审计能力，满足了实际业务中对“为何调整”、“依据何种证据”以及“原始基线是否保留”等关键问题的需求。

#### 总结
本文指出了当前时间序列预测研究中忽视的“最后一公里”问题，即如何将统计基线转化为符合业务上下文的决策级预测。作者提出了一种基于 LLM Agent 的框架，通过工具调用、显式动作转化、结构化安全约束以及记忆库反思机制，解决了上下文融合难和过程不可审计的挑战。该方法在保证预测质量的同时，极大地提升了预测过程的可控性、透明度和业务适应性，为实际部署提供了新的范式。
