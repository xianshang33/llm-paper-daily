## 文章做了什么
- **背景**：临床实践并非从枚举选项中选择答案，而是医生在不确定性下逐步收集异构信息并做出连续、不可逆的决策。现有的静态基准测试无法探测这种动态过程，而现有的交互式医疗基准测试至少在其中一个方面存在妥协。
- **已有工作的不足**：数据交互基准仅衡量数据访问技能而非临床推理；诊断对话基准依赖LLM模拟患者，局限于短 vignettes 且使用 LLM 作为裁判；代码式可执行基准将临床推理简化为代码或公式生成。没有任何现有工作能评估 LLM 作为主治医生管理真实、多阶段住院过程并进行确定性验证的能力。

## 文章的核心贡献点
- **提出了一个 ClinEnv**：这是一个交互式基准测试环境，通过“纵向住院模拟”范式，评估 LLM 在真实住院记录中作为主治医生的表现。
- **挑战1：真实临床决策的复杂性与不可逆性**。难点在于临床决策是序列化的，且信息是不完整的，需要主动获取。ClinEnv 通过将原始入院记录自动构建为有序的多阶段决策序列，并要求模型在每个阶段向四个专用代理（患者、护士、实验室、病史）主动查询信息后，再提交药物、程序和诊断决策，从而模拟这一过程。
- **挑战2：缺乏对决策过程和结果的双重确定性评估**。难点在于传统方法要么只关注结果，要么使用不稳定的 LLM 裁判。ClinEnv 引入了双重评估框架：一方面通过基于本体论的确定性匹配（如 ATC 用于药物，分层 ICD F1 用于诊断和程序）评分决策内容；另一方面通过覆盖率和成本效率等过程指标评分信息收集方式，使“信息获取差距”可直接测量。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：ClinEnv 包含一个自动化管道，无需人工标注即可从 EHR 时间线和出院文档中提取结构化地面真值决策。环境包含四个专用代理来 withholding 临床信息，直到被请求。评估框架结合了确定性本体匹配和过程指标。
- **Evaluation 结果**：在七个模型中进行测试，最强的模型决策 F1 分数仅为 0.31。结果显示结果质量与过程质量严重脱钩。困难主要集中在管理决策和后期阶段，模型恢复出院诊断的可靠性远高于管理动作（F1 为 0.51 vs 0.17），并且随着病例进展继续发出冗余查询。
- **对比**：与仅关注结果的静态基准或依赖模拟患者的交互式基准不同，ClinEnv 揭示了仅靠结果评估无法发现的信息获取缺陷，证明了当前 LLM 在模拟真实主治医生行为上的巨大差距。

#### 总结
ClinEnv 填补了医疗 AI 评估中的一个关键空白，提供了一个基于真实 EHR 数据的、多阶段的、交互式的住院模拟环境。它不仅评估最终诊断的准确性，还严格量化了医生在信息收集过程中的效率和合理性。研究结果表明，当前最先进的 LLM 在模拟复杂临床决策过程方面仍面临巨大挑战，特别是在长期管理和主动信息获取策略上，这为未来医疗 Agent 的开发指明了方向。
