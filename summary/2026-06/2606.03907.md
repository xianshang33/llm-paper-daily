## 文章做了什么
- **背景**：代理式 AI 编码工具（Agentic AI Coding Tools）在自主编写代码时，会自行决定是引入外部库（Buy）还是从头实现功能（Build）。这种“构建 vs 购买”的决策直接影响软件的安全性、许可证合规性、性能及长期可维护性。
- **已有的工作为什么解决不了**：目前缺乏受控实验研究来揭示是什么因素主导了代理式 AI 工具中的“构建 vs 购买”决策。虽然配置机制是开发者影响工具行为的主要手段，但尚不清楚哪种配置机制能最有效地引导这些决策。

## 文章的核心贡献点
- **提出了一个**：针对 Claude Code 和 OpenAI Codex 两种主流代理式 AI 编码工具的预注册研究协议（Study Protocol），旨在系统评估配置机制如何改变其“构建 vs 购买”的行为。
- **挑战1：配置机制对决策影响的未知性**。难点在于代理式 AI 具有高度自主性，且配置方式多样（从无配置到显式禁止、Skills、MCP 工具等），难以量化不同配置对依赖选择的具体影响。论文通过设计包含明确“构建 vs 购买”决策点的阶段性项目基准，并操纵不同的配置输入，来隔离并测量各配置机制的效果。
- **挑战2：缺乏可复现的评估基准与纵向研究能力**。难点在于现有研究多为静态或一次性分析，无法适应快速迭代的 AI 模型和工具版本。论文设计了可复现的实验流程和九个预注册假设，并将发布基准数据集和分析管道，支持对未来工具版本的纵向比较和重复实验。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：本研究为预注册报告（Registered Report），尚未执行最终实验，但详细规划了实验设计。实验将使用两个流行的代理式 AI 工具：Claude Code 和 OpenAI Codex。任务来源于一个专门构建的基准测试，其中包含可识别的“构建 vs 购买”决策点。配置变量包括：无配置、带有软偏好和显式禁止的上下文文件、可自主发现的 Skills、启用 MCP 的库发现工具以及权限控制。
- **Evaluation 指标**：主要测量工具选择的库、是否披露新引入的库，以及披露的完整性和准确性。
- **相关工作对比**：不同于以往仅关注代码生成质量或安全漏洞的研究，本文聚焦于依赖管理决策过程及其受配置影响的机制。通过预注册假设和标准化基准，解决了现有文献中缺乏受控实验和可复现性 artifacts 的问题。

#### 总结
本文提出了一项严谨的预注册研究协议，旨在填补代理式 AI 编码工具在“构建 vs 购买”决策机制研究上的空白。通过系统性地操纵配置机制并在受控基准上测试 Claude Code 和 OpenAI Codex，该研究将为理解和管理 AI 自主引入依赖的风险提供实证依据。其产出的基准数据集和分析管道将成为社区评估未来 AI 编码工具行为的重要资源。
