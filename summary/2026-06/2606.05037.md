## 文章做了什么
- **背景**：随着大型语言模型（LLM）作为自主代理调用 API，它们在遇到验证错误时的表现与人类开发者不同。人类可以推断缺失的上下文并修正请求，而代理往往因缺乏特定领域知识而在猜测中消耗大量 Token 直至失败。
- **已有工作为什么解决不了**：现有的 API 错误报告（如 RFC 7807）通常提供通用代码和面向人类的简短文本描述。这些非结构化的自然语言诊断无法为 LLM 提供直接可执行的修复指令，特别是在涉及专有业务逻辑、特定认证要求或实时状态等 LLM 训练数据中未包含的知识时，LLM 无法仅凭通用先验知识推断出正确的修复方案。

## 文章的核心贡献点
- **提出了一个“自反思 API”（Self-Reflective API）**：在验证失败时，API 不仅返回错误原因，还返回一个机器可读的结构化 payload（`recovery_feedback.suggestions[]`），其中包含足以让代理修复请求并重试的具体建议，无需外部推理。
- **挑战1：专有领域知识的缺失导致修复困难**。当验证规则依赖于公司特定的文化规范、认证标准或复杂的技术约束时，通用 LLM 无法从训练数据中获知正确答案。论文方法通过将 API 内部持有的专有知识转化为结构化的修复建议直接传递给 LLM，消除了 LLM “猜测”的需要。
- **挑战2：非结构化错误信息的低效性**。传统的纯文本错误诊断迫使 LLM 进行额外的语义解析和推理，导致 Token 效率低下且容易出错。论文方法通过提供类型化的、机器可直接消费的建议字段，显著提高了每成功一次任务的 Token 效率，使 LLM 能够直接执行修复操作。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实验设置**：在一个经过泄漏审计的试点研究中，使用了 3 种 LLM（Claude Haiku 4.5, Claude Sonnet 4.6, GPT-4o-mini）和 10 个对抗性任务（涉及食谱转换等专有领域），每个单元格 N=30。
- **主要结果**：在 Anthropic 模型上，结构化建议相比纯英文诊断将任务完成率提高了 36.7–40.0 个百分点（Fisher 精确检验 p ≤ 0.0022），并且每次成功的 Token 效率提高了 1.8–2.2 倍。
- **对比与局限性**：在 GPT-4o-mini 上提升不显著（p=0.435），表明该机制对模型能力有一定依赖性。在计费 API 的第二领域复现确认了这一模式。研究强调，只有在审计并排除了 LLM 基准测试中未文档化的答案泄漏后，这种比较才成立。
- **基础设施贡献**：发布了 `audit_prompt_leakage.py` 作为可重用的 CI 基础设施，用于检测提示词泄漏。

#### 总结
本文证明了在 API 持有 LLM 未知的专有领域知识时，“结构化胜过冗长”。自反思 API 通过返回机器可读的修复建议，显著提升了 AI 代理在复杂验证场景下的恢复能力和效率。该方法不适用于 LLM 已知的通用验证场景，但在处理专有业务逻辑、外部状态和专用规则时具有巨大价值。
