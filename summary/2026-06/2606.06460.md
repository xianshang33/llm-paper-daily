## 文章做了什么
- **背景**：随着自主 LLM 智能体越来越多地持有真实凭证并在无人工干预的情况下操作基础设施，操作员缺乏标准方法来告知智能体某些资源是禁止访问的。现有的访问控制要么允许智能体进入（因为它拥有有效凭证），要么直接硬失败（与其他客户端无法区分）。
- **已有工作的不足**：现有的 LLM 访问研究工作主要集中在网关（如 API 网关、MCP 服务器）或角色模型（如 RBAC/ReBAC）层面。这些方法虽然有价值，但位于资源外部。目前没有人标准化一种让资源本身通过带内信道发出智能体可理解策略的方法，更重要的是，没有人测量过合规的智能体是否会真正遵守这种信号。

## 文章的核心贡献点
- **提出了一个“回避信号”（Recuse Signal）**：这是一种轻量级、公开的带内拒绝信号，服务器通过协议现有通道（如 SSH banner 或 PostgreSQL NOTICE）发出，要求连接的自动化智能体自愿退出。这被视为一种合作性治理控制，类似于实时访问的 robots.txt，而非安全边界。
- **挑战1：缺乏标准化的带内通信机制**。难点在于如何在不对服务器架构进行重大修改的情况下，让资源向智能体传达“禁止自动化访问”的意图。论文定义了一个开放的迷你标准（Recuse Signal），并实现了两个零足迹或低足迹适配器（SSH banner/PAM hook 和 PostgreSQL 线协议代理），使其能够轻松部署在生产环境中。
- **挑战2：智能体合规性的实证缺失**。难点在于不确定 LLM 智能体是否真的会尊重这种非强制性的合作信号。论文通过受控实验进行了测量，结果显示当存在信号时智能体回避率为 100%，而无信号对照组任务完成率为 100%。此外，研究还发现该信号具有合作性而非绝对性：明确的运营商授权框架会使最强模型继续执行，而其他智能体则继续遵循主机策略。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：作者定义了 Recuse Signal 的标准格式，并开发了两个参考适配器：一个用于 SSH（结合 banner 和 PAM hook），另一个用于 PostgreSQL（作为 pgproto3 代理注入 NOTICE 消息）。这些适配器被部署在实时生产主机上。
- **评估结果**：在初步试点实验中（使用 SSH，测试对象包括 OpenAI GPT-4o、GPT-4o-mini 和 Claude Code），结果表明信号能有效地诱导智能体回避。具体表现为：有信号时回避率为 100%，无信号控制组任务完成率为 100%。实验还揭示，该信号的行为取决于模型能力和提示词框架；例如，明确的授权指令可以覆盖最强模型的回避行为。
- **与相关工作对比**：不同于传统的基于网关或角色的外部访问控制，该方法直接在资源层提供带内信号。与试图通过启发式方法检测自动化的行为 enforcement 不同，本文专注于合作性治理，明确不针对恶意智能体，而是为愿意合规的智能体提供清晰的意图传达渠道。

#### 总结
本文提出了“回避信号”这一开放迷你标准，旨在解决自主 LLM 智能体在持有有效凭证时缺乏接收资源方“禁止访问”意图的问题。通过实现低开销的适配器并进行实证研究，证明了主流 LLM 智能体能够识别并遵守这一合作性信号。该工作填补了带内策略通信和智能体合规性测量的空白，为基础设施操作员提供了一种轻量级的治理工具，同时明确了其作为合作控制而非安全边界的定位。
