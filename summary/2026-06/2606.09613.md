## 文章做了什么
- **背景**：现代大语言模型（LLM）部署正从孤立的单轮对话转向多轮智能体系统。这些系统作为有状态的程序执行，将 LLM 调用与外部工具调用交错进行，导致服务重点从无状态请求处理转变为有状态程序执行。
- **已有的工作为什么解决不了**：现有的 LLM 服务模拟器（如 Vidur, APEX, LLMServingSim）主要针对无状态的请求级工作负载设计，将每个请求视为独立的预填充-解码对。它们缺乏对智能体服务核心动态的抽象，包括程序身份、工具调用引起的间隙以及跨轮次的 KV 缓存重用，因此无法准确评估针对智能体优化的调度、路由和缓存管理策略。

## 文章的核心贡献点
- **提出了一个 AGENTSERVESIM**：这是一个面向多轮 LLM 智能体服务的硬件感知模拟器，能够在普通 CPU 上运行，以程序粒度评估服务策略。
- **挑战1：如何模拟工具调用引起的中断和间隙？**
  - **难点**：工具调用持续时间差异巨大（从毫秒到分钟），导致 LLM 推理过程中出现不可预测的空闲期，传统模拟器无法建模这种时间间隙对资源调度的影响。
  - **解决方法**：引入了“工具模拟器（Tool Simulator模块）”，具体化由工具调用引起的间隙，允许模拟器在程序执行流中精确插入这些延迟，从而真实反映智能体执行的时间线。
- **挑战2：如何追踪跨轮次和有状态上下文下的 KV 缓存驻留？**
  - **难点**：智能体执行涉及跨轮次的缓存局部性和在工具间隙期间的 KV 缓存保留/驱逐策略，现有模拟器仅处理独立请求，无法追踪程序级别的缓存状态变化。
  - **解决方法**：设计了“KV 驻留模型（KV Residency Model）”和“会话感知路由器（Session-Aware Router）”，前者跟踪策略定义的 KV 放置在 HBM、主机 DRAM/CXL 及驱逐过程中的状态，后者维持程序到实例的亲和性以实现缓存感知分发。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：AGENTSERVESIM 通过可组合模块实现，包括保持程序身份和轮次顺序的程序编排器、模拟工具间隙的工具模拟器、维持缓存感知分发的会话感知路由器，以及跟踪多级内存中 KV 放置的 KV 驻留模型。整个模拟器完全在普通 CPU 上运行，无需昂贵的加速器硬件。
- **评估结果**：在真实的服务部署和多种硬件配置下，AGENTSERVESIM 在关键性能指标上重现真实系统行为的误差在 6% 以内。
- **对比**：与 Vidur、APEX 等仅支持无状态请求的模拟器相比，AGENTSERVESIM 能够捕捉多轮程序执行、跨轮缓存局部性等智能体特有的动态，填补了现有仿真工具在智能体服务策略探索方面的空白。

#### 总结
本文针对多轮 LLM 智能体服务中存在的复杂状态管理和资源调度问题，提出了 AGENTSERVESIM 模拟器。该工具通过模块化设计解决了工具调用间隙模拟和跨轮次 KV 缓存追踪两大难题，能够在低成本 CPU 环境下以高保真度（误差<6%）模拟真实硬件上的智能体服务行为。这使得研究人员能够在无需大量昂贵加速器资源的情况下，对智能体服务策略进行可控、可重复的探索和优化。
