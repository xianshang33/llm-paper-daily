## 文章做了什么
- **背景**：大型语言模型（LLM）的推理过程具有瞬时性，思维链随上下文窗口消失，被剪枝的搜索分支不留记录，且记忆缓冲区无法进行差异比较（diff）、合并或审计。相比之下，代码、基础设施和数据等复杂软件流程均受版本控制，而推理过程却缺乏这种机制。
- **已有工作的局限**：现有的代理记忆系统（如向量数据库、图数据库或简单的文本缓冲）虽然存储了信息，但缺乏不可变性、血缘追踪和合并能力。这阻碍了推理的可复现性（重放特定步骤）、审计（检测数据泄露或答案 memorization）以及跨代理的经验迁移。

## 文章的核心贡献点
- **提出了 GitOfThoughts**：一种将代理的推理树存储为 Git 仓库的框架，其中每个评分后的思考是一个 commit，分数是 notes，结果是 tags，检索即是对代理历史的 "git log" 操作。
- **挑战1：推理过程的不可审计与不可复现**。难点在于传统记忆 substrate 无法提供类似代码版本控制的细粒度历史追踪和合并功能。GitOfThoughts 通过利用成熟的 Git 协议，以近乎零的工程成本实现了推理过程的可重放、可审计和跨代理合并。
- **挑战2：记忆是否真正提升新颖问题的准确率**。难点在于区分“方法迁移”与“答案检索”，并验证不同记忆形式的实际效用。论文通过预注册的严格评估发现，对于新颖问题，没有任何记忆形式能可靠地提升准确率；记忆仅在检索案例与当前问题高度相似（相似度 >~0.8，即“可复制性阈值”）时才有效，且增益来自答案检索而非方法学习。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现**：GitOfThoughts 作为一个插件式记忆接口，允许在保持代理模型不变的情况下切换不同的记忆 substrate（无记忆、Markdown、向量、图、Git）。
- **评估设置**：在两个基准测试（GPQA-Diamond, MATH-500）、两种模型规模、五种记忆 substrate 上进行对照实验，并包含预注册的复现实验。
- **主要结果**：
    1. **H-memory 假设被拒绝**：在新颖问题上，没有任何记忆 substrate 能可靠地提高准确率。早期观察到的 Git 带来的 +15pp 增益在预注册复现中未能重现。
    2. **可复制性阈值（Copyability Threshold）**：只有当检索到的案例与测试问题余弦相似度大于 0.8 时，准确率才会显著提升（+12 至 +13.5pp）。低于此阈值，记忆无效。
    3. **答案检索 vs 方法迁移**：即使使用大 4.5 倍的更强模型，也无法从示例中提取可迁移的方法，仅能增强近重复问题的答案检索收益（增益翻倍至 +22.5~28.5pp）。
    4. **对比结论**：Git 作为 substrate 的优势不在于提升准确率（与其他方法持平），而在于提供了审计、血缘和合并能力。唯一的通用提升杠杆仍是测试时采样（test-time sampling）。

#### 总结
本文引入了 GitOfThoughts，旨在解决 LLM 推理过程缺乏版本控制的问题，实现了推理的可重放性和可审计性。更重要的是，通过严格的预注册实验，文章反驳了“通用记忆能提升新颖问题求解能力”的普遍假设，指出记忆仅在极高相似度的“可复制”场景下有效，且本质是答案检索而非方法迁移。该研究倡导以更高的评估标准（包括记录撤回的结果和被驳斥的假设）来审视代理记忆领域，强调 Git 在工程运维价值上的优势而非单纯的精度提升。
