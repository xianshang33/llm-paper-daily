## 文章做了什么
- **背景**：随着大语言模型（LLM）的发展，自动化复杂的地理空间工作流成为可能。本文旨在构建一个由 LLM 驱动的框架，通过自然语言查询从基于云的地理空间目录中检索遥感数据，将用户意图转化为结构化的 API 调用，以高效访问卫星图像和环境数据集。
- **已有工作的不足**：现有的方法在直接 interfacing 大规模卫星和航空影像库时，往往缺乏足够的安全性和策略执行机制。单纯的提示词级安全指令在面对对抗性多轮对话时，仍会出现罕见但高影响的 API 操纵失败，缺乏系统级的自适应防御来平衡安全性、可用性和成本效率。

## 文章的核心贡献点
- **提出了一个风险感知的 LLM 代理框架**：该框架集成了三个协调的代理（Guardrail、General-QA、Recommender-Analyst），用于安全地解释用户意图并生成精确的 API 调用。
- **挑战1：如何确保与外部数据服务交互的安全性与策略合规性？**
  - **难点**：LLM 容易受到提示词注入或恶意操纵，导致生成不安全或不符合政策的 API 请求，且仅靠提示词工程难以完全抵御复杂的对抗性攻击。
  - **解决方法**：引入基于 NeMo Guardrails 构建的“Guardrail”代理，作为拦截级的风险识别和预防机制，在系统层面强制执行安全策略，弥补提示词级防御的不足。
- **挑战2：如何实现跨不同地理空间平台的通用性与语义对齐？**
  - **难点**：不同的地理空间平台（如 SkyWatch, Google Earth Engine）拥有各异的 API 模式，硬编码特定平台逻辑会导致系统缺乏可移植性，且难以保证用户自然语言意图与底层 API 参数的精确映射。
  - **解决方法**：采用模块化设计，其中“Recommender-Analyst”代理专门负责 schema 感知的 API 调用生成。通过替换 API 模式和调用规范，框架可轻松移植到其他平台，同时保持用户意图与数据检索之间的语义对齐。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：系统包含三个核心代理：Guardrail（安全防护）、General-QA（意图理解与问答）、Recommender-Analyst（API 调用生成）。该架构专为 SkyWatch 平台设计，但具有模块化特性，可通过替换 API schema 适配 Google Earth Engine 等其他平台。
- **评估结果**：在对抗性多轮设置下的初步实验表明，虽然提示词级的安全指令能提高一定的鲁棒性，但在 API 操纵场景中仍存在罕见的高影响失败。这证明了引入拦截级 Guardrail 代理的必要性，该系统级防御能更有效地平衡安全性与可用性。
- **对比**：相较于仅依赖 LLM 原生能力或简单提示词工程的方法，本文提出的多代理协同架构通过显式的风险拦截模块，显著提升了在敏感地理空间数据检索任务中的可靠性和政策合规性。

#### 总结
本文提出了一种用于地理空间数据检索的风险感知 LLM 代理框架。通过集成安全防护、意图理解和 API 生成三个专用代理，该系统实现了从自然语言到结构化 API 调用的安全、可靠转换。初步评估证实了系统级防护（Guardrail）在应对对抗性攻击方面的价值，为环境监测、灾害响应等领域的自动化地球观测工作流提供了可扩展的解决方案。
