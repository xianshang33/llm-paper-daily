## 文章做了什么
- **背景**：生产环境中的 AI Agent 面临初始配置（系统提示词、工作流结构、决策规则）随环境和任务分布变化而过时的问题。传统的解决方法依赖缓慢且昂贵的人工提示工程，与生产现实脱节。
- **已有工作的局限**：现有的自改进方法（如 Self-Harness、EvolveR、EvoAgentX 等）通常只针对单一维度进行优化。例如，Self-Harness 仅通过挖掘失败集群来修补提示词 Harness，而忽略了行为原则和工作流拓扑的演变；其他方法也各自局限于单一轴线的改进，导致其他未优化的部分成为瓶颈，无法实现整体性能的最大化。

## 文章的核心贡献点
- **提出了一个 APEX (Adaptive Principle EXtraction) 框架**：这是一个三层协同进化框架，能够同时进化 Harness、行为原则和工作流拓扑。
- **挑战1：单一维度优化的局限性导致系统性失败**。完美的 Harness 若配合次优的工作流仍会失败，而良好的原则若缺乏对关键失败模式的覆盖会在分布偏移下退化。**解决方法**：APEX 采用三层协同进化机制，L1 层通过失败模式修补优化 Harness，L2 层通过成功轨迹蒸馏提取行为原则，L3 层基于结构适应度选择优化工作流拓扑，三者共享生产轨迹池并同步更新。
- **挑战2：缺乏适用于多维度进化的综合评估指标**。传统指标难以同时衡量 Harness 覆盖率、原则丰富度和工作流结构质量。**解决方法**：提出了 APEX Health Score，这是一个复合指标，能够分离并量化 Harness 覆盖、原则丰富性和结构工作流质量，从而全面评估 Agent 的多维进化进度。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：APEX 被实现在名为 Joe 的生产级超级 AI Agent 上，该 Agent 基于 NVIDIA Nemotron 构建，用于管理一个包含 15 个节点的计算集群。系统使用了在 18 天内收集的 114 个真实任务轨迹。代码开源为三个可组合的 Python 模块，可部署在任何拥有轨迹数据库和本地 Ollama 实例的 Agent 上。
- **评估结果**：在单次进化运行中，APEX 将 APEX Health Score 从基线的 0.300 提升至 0.570（提升 90%）。它提炼出了 6 个新的可重用原则，并选择了一个得分 0.900（提升 20%）的“研究优先”工作流拓扑。
- **对比与效率**：与仅优化单一轴线（如 Self-Harness）的方法相比，APEX 的多维协同进化表现出显著优势。此外，其计算成本极低，在本地 qwen2.5-coder:32b 实例上仅需 4 次 LLM 调用（约 270 秒）即可完成进化步骤。

#### 总结
APEX 证明了在生产环境中，AI Agent 的自我改进不应局限于单一的提示词或工作流优化，而应采用 Harness、行为原则和工作流拓扑的多维度协同进化。通过在真实生产轨迹上的验证，APEX 展示了以极低的计算成本实现大幅性能提升的能力，为生产级 AI Agent 的自动化持续优化提供了新的范式。
