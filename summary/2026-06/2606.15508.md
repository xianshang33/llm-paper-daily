## 文章做了什么
- **背景**：随着工具增强型大型语言模型（LLM）代理在大型工具库上运行，可见的“工具菜单”成为代理接口的核心部分。现有的评估主要关注模型是否能正确调用单个工具，而忽视了工具菜单的构建方式如何影响代理的可靠性、效率和安全性风险暴露。
- **已有工作为什么解决不了**：现有基准测试通常将可用工具集视为固定或给定的，未能隔离“工具菜单设计”这一关键问题。它们无法有效评估在每一步决策中应向代理展示哪些工具、菜单大小如何影响可靠性、干扰项的影响，以及过滤策略如何在任务成功率、Token成本和安全风险之间进行权衡。仅靠语义相关性检索往往不够，因为语义相关的工具在当前任务状态下未必是因果上合适的下一步行动。

## 文章的核心贡献点
- **提出了一个 ToolMenuBench**：这是一个用于评估多步 LLM 代理中工具菜单构建的基准测试框架。它通过变化工具菜单大小、干扰项类型、状态依赖的任务结构和风险暴露程度，报告过滤层级和下游代理指标（如可见工具数量、风险工具暴露、任务成功率、错误工具调用、过早行动和 Token 使用量）。
- **挑战1：如何在减少可见工具数量的同时保持高任务成功率？**
    - **难点**：暴露所有工具会增加错误调用和 Token 消耗，但过度过滤可能导致遗漏必要工具。语义过滤可能包含无关但语义相似的干扰项。
    - **解决方法**：论文引入并评估了因果最小工具过滤（CMTF），该方法基于前置条件、效果和任务状态进度来塑造工具菜单，而非仅依赖语义相关性，从而在大幅减少可见工具的同时显著提升成功率。
- **挑战2：如何量化和降低代理的安全风险暴露？**
    - **难点**：传统评估缺乏对“风险工具暴露”的细粒度衡量，难以区分安全与危险的工具选择场景。
    - **解决方法**：ToolMenuBench 专门设计了包含风险暴露变量的评估设置，通过对比不同过滤方法（如无过滤、词汇过滤、状态感知过滤等），证明 CMTF 能有效减少 risky-tool exposure（风险工具暴露）和 premature actions（过早行动）。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实验设置**：在7种模型后端、3种工具菜单大小、6种过滤方法和7种评估设置下进行了受控评估。
- **主要结果**：
    - **CMTF 性能**：因果最小工具过滤（CMTF）将任务成功率从全工具暴露下的 32.1% 提升至 85.7%。
    - **效率提升**：平均 Token 使用量减少了约 98%。
    - **综合权衡**：相较于无过滤、词汇过滤、状态感知过滤和更广泛的因果路径基线，CMTF 在减少可见工具、错误工具调用、过早行动和风险工具暴露方面实现了最强的整体权衡。
- **对比结论**：现有方法（如仅基于语义检索）在处理复杂状态依赖任务和干扰项时表现不佳，而基于因果关系的过滤策略被证明能更有效地解决代理接口问题。

#### 总结
本文提出了 ToolMenuBench，填补了 LLM 代理评估中关于工具菜单构建研究的空白。研究指出，可靠的代理不仅需要正确的工具调用语法，更需要系统的界面评估来决定在何种成本和风险约束下、何时向模型展示哪些工具。实验表明，基于因果逻辑的最小化工具过滤（CMTF）是提升代理可靠性、效率和安全性的有效途径，为未来的代理接口设计提供了可重用的评估框架和指导原则。
