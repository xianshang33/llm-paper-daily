## 文章做了什么
- **背景**：随着大语言模型（LLM）智能体在长周期会话中的部署，上下文积累导致推理成本急剧上升。现有的方法通常采用文本剪枝或动态记忆驱逐来最小化 Token 占用。
- **已有工作的局限**：现有方法通过无约束的序列突变（如截断、压缩）来减少 Token，但这改变了输入布局，导致前缀不匹配和 KV Cache 失效。这揭示了文本稀疏性与提示词缓存连续性之间的关键权衡：激进的压缩虽然减少了 Token 数量，但破坏了硬件层面的缓存命中机制，导致严重的预填充惩罚。

## 文章的核心贡献点
- **提出了一个双粒度上下文管理框架 TokenPilot**：旨在平衡文本压缩效率与硬件缓存命中率。
- **挑战1：全局层面的前缀稳定性与环境噪声干扰**。难点在于开放世界的环境噪声会污染上下文，而传统的压缩方式会破坏 Prompt 前缀结构，导致 Cache Miss。TokenPilot 通过“摄入感知压缩”（Ingestion-Aware Compaction）作为框架枢纽，在摄入网关处稳定提示词前缀并消除环境噪声，从而保持缓存布局的连续性。
- **挑战2：局部层面的上下文生命周期管理与精准驱逐**。难点在于难以判断上下文片段的剩余效用，过早驱逐影响性能，过晚驱逐增加成本。TokenPilot 采用“生命周期感知驱逐”（Lifecycle-Aware Eviction），监控上下文片段的持续剩余效用，执行保守的批量轮次调度，仅在任务相关性过期时才卸载内容片段，确保缓存的高效利用。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：TokenPilot 已集成到 LightMem2 系统中，代码开源。
- **评估结果**：在 PinchBench 和 Claw-Eval 基准测试中，分别在隔离模式和连续模式下进行了评估。
- **对比优势**：
    - 在隔离模式下，TokenPilot 相比先前系统分别降低了 61% 和 56% 的成本。
    - 在连续模式下，成本降低幅度更为显著，分别达到 61% 和 87%。
    - 在大幅降低成本的同时，TokenPilot 保持了与先前系统相当的竞争性能，证明了其在解决缓存失效问题上的有效性。

#### 总结
TokenPilot 针对 LLM 智能体长会话中的上下文管理难题，提出了一种兼顾文本稀疏性与缓存连续性的双粒度解决方案。通过全局的摄入感知压缩稳定前缀，以及局部的生命周期感知驱逐优化资源释放，该方法有效解决了传统剪枝方法导致的 KV Cache 失效问题。实验表明，TokenPilot 能在保持性能的前提下显著降低推理成本，特别是在连续交互场景中表现优异，为 LLM 智能体的可持续部署提供了高效的基础设施支持。
