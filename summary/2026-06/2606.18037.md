## 文章做了什么
- **背景**：随着大语言模型（LLM）智能体越来越多地使用模型上下文协议（MCP）从异构证据源（如搜索、API、数据库、临床记录等）中获取信息来回答问题，事实性验证变得至关重要。
- **已有工作的不足**：现有的事实性和忠实度指标通常仅评估答案是否被“池化”后的整体证据所支持。这种抽象忽略了一个对来源敏感的关键故障模式：一个声明可能在某处得到证据支持，但被错误地归因于另一个来源。作者将这种失败称为“跨源混淆”（cross-source conflation），而传统方法无法检测此类归因错误。

## 文章的核心贡献点
- **提出了一个 ProvenanceGuard**：这是一个针对 MCP 落地答案的“来源感知”验证器，能够识别并纠正跨源混淆问题。
- **挑战1：如何精确追踪声明与特定来源的对应关系？**
  - **难点**：在多个语义相近的来源中，确定某个具体声明究竟由哪个特定来源支持是非常困难的，因为不同来源可能包含相似但不完全相同的信息。
  - **解决方法**：ProvenanceGuard 消费捕获的 MCP 轨迹（包含稳定的工具 ID、来源 ID 和原始输出），将答案分解为原子声明，并将每个声明路由到特定的来源证据。通过自然语言推理（NLI）和基于注意力机制的 token 对齐代理来检查支持情况，并将声明的 stated attribution（陈述归因）与路由到的实际来源进行比对。
- **挑战2：如何处理验证失败的错误归因？**
  - **难点**：仅仅检测出错误是不够的，系统需要具备自我修正能力，否则会导致大量答案被直接丢弃，影响可用性。
  - **解决方法**：系统不仅返回每个声明的来源 verdict（裁决）和答案级别的允许/阻止决策，还能调用检索增强答案修订（RARR）风格的修复机制。对于被阻止的答案，系统会进行修订并重新验证，从而在保持事实准确性的同时提高答案的采纳率。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **数据集**：在 281 个医疗领域 MCP 智能体轨迹上进行评估。其中 266 个轨迹的子集产生了 2,325 个由 LLM 辅助标注的声明标签，其中 361 个保留标签经过人类专家验证。
- **主要结果**：
  - 在 40 个轨迹的保留测试集上，ProvenanceGuard 在 260 个符合来源条件的声明上达到了 **0.802 的 Block F1** 分数和 **0.858 的来源准确率**。
  - **对比基线**：相比之下，不考虑来源的基线模型（如 MiniCheck, RAGAS Faithfulness, AlignScore, SummaC-ZS）虽然能判断整体支持度，但无法输出声明到来源的 ID 映射。MiniCheck 的 Block F1 为 0.783，其他基线更低，且均不具备来源感知能力。
  - **困难场景**：在一个更难的多来源基准测试中，Block F1 达到 0.846，但“来源+关系”准确率降至 0.229，表明在语义接近的候选来源中确定确切的所有权仍然具有挑战性。
  - **修复效果**：在整个轨迹集中，修复并重新验证循环解决了所有 173 个被阻止的答案（尽管大部分是通过保守的回退策略）。在 50 个受控的临床混淆探测中，ProvenanceGuard 检测到了所有注入的属性交换，没有保留任何错误的归因。

#### 总结
ProvenanceGuard 证明了来源归因是 MCP 基础智能体事实性验证的一个独立且至关重要的维度。通过引入来源感知的验证机制和修复循环，该方法有效解决了“跨源混淆”这一传统指标忽略的故障模式，显著提高了医疗等高风险领域 LLM 智能体输出的可靠性和可解释性。尽管在语义极度相似的来源间进行精确归属仍具挑战，但其整体性能优于现有的无来源感知基线。
