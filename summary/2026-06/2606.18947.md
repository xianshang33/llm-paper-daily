## 文章做了什么
- **背景**：生产环境中的 LLM Agent 日益依赖实时搜索来确保事实准确性。目前主流做法是使用“原生搜索接地”（Native Search Grounding），即由模型提供商在 API 内部捆绑检索策略、证据注入和生成行为。
- **已有工作的局限**：这种紧耦合架构使得检索过程难以检查、调优、复用或迁移。更严重的是，它会导致“搜索诱导的冗余”（Search-Induced Verbosity），即模型违背严格的输出契约（如只返回实体），转而生成解释性文本，破坏了下游系统的解析和处理流程。

## 文章的核心贡献点
- **提出了一个供应商无关的解耦搜索接地架构（Decoupled Search Grounding, DSG）**：通过 MCP 兼容网关将接地逻辑从推理模型中剥离，使提供商路由、缓存和上下文渲染成为独立可控的一等公民。
- **挑战1：缺乏对检索成本和延迟的细粒度控制**。原生方案黑盒化导致成本高昂且无法优化。DSG 通过暴露精确加语义缓存、检索深度控制和配置化回退机制，实现了资源的显式管理。
- **挑战2：搜索诱导的冗余破坏输出契约**。原生搜索常导致模型输出冗长，违反严格格式要求。DSG 通过将检索与生成分离，确保模型仅接收清洗后的源感知上下文，从而在保持高准确率的同时严格遵守简洁的输出合同。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实验设置**：在 SimpleQA、FreshQA 和 HotpotQA 数据集上评估了五种前沿模型，并在 DoorDash 的大规模电商查询理解（QIU）生产工作负载中进行了部署测试。
- **对比结果**：
    - **准确率与成本**：在 SimpleQA 上，DSG 的准确率（86.1%）几乎媲美原生搜索（87.7%），但搜索成本降低了 91%。
    - **延迟与缓存**：DSG 实现了 99.4% 的热缓存命中率，延迟降低了 68%。
    - **生产环境表现**：在电商 QIU 工作负载中，DSG 的准确率匹配或略高于原生搜索，同时搜索成本降低了超过 98%。
    - **特定场景**：在对时效性极度敏感的 FreshQA 上，原生搜索仍具优势，但在大多数需要控制力和成本效益的场景中，DSG 展现了更强的综合性能。

#### 总结
本文论证了实时接地应被视为一个可优化的接口边界，而非固定的模型特性。DSG 架构成功解耦了搜索与推理，在几乎不牺牲准确率的前提下，显著降低了成本和延迟，并解决了原生搜索导致的输出格式不可控问题，为构建高效、可移植的生产级 LLM Agent 提供了新的架构范式。
