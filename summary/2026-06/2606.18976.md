## 文章做了什么
- **背景**：软件工程教育高度依赖项目式学习，学生需提交需求规格说明书、UML图和架构设计等文档。随着班级规模扩大，教师审查这些技术密集型文档并提供个性化反馈成为瓶颈，导致反馈频率和质量下降。
- **已有的工作为什么解决不了**：现有的自动化工具在代码评分（通过静态分析和单元测试）方面已成熟，但在开放式软件架构文档的形成性反馈方面仍面临挑战。直接应用大语言模型（LLM）处理复杂的多模态架构文档时，缺乏鲁棒的架构来确保反馈的准确性和可靠性，容易产生幻觉或冗余批评，从而误导学生。

## 文章的核心贡献点
- **提出了一个 CAPRA (Configurable Architecture Proficiency Report Assessment)**：这是一个多智能体 LLM 系统，旨在分析软件架构交付物并生成符合模板的个性化 LaTeX 反馈。
- **挑战1：多模态文档解析与提取的准确性**。难点在于架构文档包含文本和复杂的 UML 图表，单一模型难以同时精准处理两种模态且保持上下文关联。CAPRA 采用基于 Python 的微服务进行多模态提取，利用 PyMuPDF 处理文本，并结合视觉增强型 LLM（如 gpt-4o）专门解析 UML 图，确保结构信息的完整提取。
- **挑战2：LLM 幻觉与反馈的教育可靠性**。难点在于 LLM 可能生成无依据的技术批评或重复建议，降低教育价值。CAPRA 引入了确定性的“证据锚定”步骤，通过归一化莱文斯坦距离进行模糊匹配以验证引用证据，并部署 ConsistencyManager 智能体对发现进行交叉验证、去重和合并，从而 mitigating 幻觉并确保反馈的一致性。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：CAPRA 协调多个专用智能体，后端使用 Python 微服务处理文档提取。系统输出为符合特定模板的 LaTeX 格式反馈。
- **评估结果**：在 10 份学生报告上的初步实证评估显示，在严格的双评分者聚合规则下，CAPRA 满足了 88.8% 的评估标准。系统与人类评估者之间达到了中等程度的一致性（Kappa = 0.582），每份报告的处理时间略超过 4 分钟。
- **对比**：相较于传统仅针对代码的自动评分工具，CAPRA 填补了架构文档自动化反馈的空白；相较于直接调用 LLM，其多智能体协作和证据锚定机制显著提高了反馈的可信度和结构化程度，尽管在主观评估维度上仍需人工监督。

#### 总结
CAPRA 证明了多智能体 LLM 系统在软件架构教育反馈中的可行性。通过结合多模态提取、确定性证据验证和一致性管理，它能够有效扩展形成性反馈的规模，减轻教师负担。然而，目前系统在处理高度主观的评估维度时仍需人类专家的介入，未来可进一步优化以提升完全自动化的可靠性。
