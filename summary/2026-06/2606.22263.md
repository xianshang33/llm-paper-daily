## 文章做了什么
- **背景**：内存安全漏洞即使在经过广泛模糊测试和人工审计的项目中仍然构成重大威胁。大型语言模型（LLM）在检测此类漏洞方面展现出巨大潜力，但存在不可靠、易产生幻觉以及难以扩展到仓库级代码库的问题。
- **已有工作为什么解决不了**：现有的基于 LLM 的方法要么假阳性率高（由于幻觉或分析错误），要么假阴性率高（模型能力不足或覆盖范围有限），要么成本过高（在完整仓库上运行先进模型极其昂贵）。传统方法如模糊测试和静态分析虽然有效，但难以发现需要复杂语义推理的深层漏洞。

## 文章的核心贡献点
- **提出了一个**名为 Revelio 的成本效益高、端到端的代理式内存安全漏洞检测框架。
- **挑战1：LLM 的幻觉问题导致高假阳性率。**
  - **难点**：LLM 可能生成看似合理但实际不存在的漏洞报告，难以信任。
  - **解决方法**Revelio 通过生成可执行的“漏洞证明”（Proof-of-Vulnerability），并使用确定性 sanitizer 进行验证，仅在漏洞可复现且被确认时才报告，从而消除幻觉。
- **挑战2：仓库级代码分析的高昂成本与扩展性问题。**
  - **难点**：直接在大规模代码库上使用前沿大模型进行全量分析成本极高，难以普及。
  - **解决方法**：Revelio 结合廉价 LLM 和轻量级静态分析来生成并排序漏洞假设，仅对高置信度的假设进行深入验证，显著降低了 token 消耗和计算成本。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **评估设置**：在7个持续模糊测试5至8年的生产级项目，以及 CyberGym 基准测试中随机选择的100个 Arvo 项目上进行评估。
- **主要结果**：Revelio 以每个项目约1小时、总成本300美元的代价，发现了19个此前未知的内存安全漏洞。
- **对比结果**：在基准测试中，Revelio 在相当的 token 成本下，跨越多种骨干模型，性能优于前沿的代码代理（frontier coding agents）。结果表明其实现了可扩展且可信的端到端基于 LLM 的内存安全漏洞检测。

#### 总结
Revelio 通过引入可执行的漏洞证明机制和分层成本控制策略，有效解决了 LLM 在漏洞检测中的幻觉和高成本问题。它在成熟软件项目中成功发现了新的内存安全漏洞，证明了其在实际部署中的高效性和可靠性，为大规模代码库的安全审计提供了新的解决方案。
