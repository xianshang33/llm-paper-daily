## 文章做了什么
- **背景**：当前的生成式音乐系统（如 Suno、MusicGen）能够根据文本提示生成高质量的音频，但这些音频输出难以作为音乐结构进行检查、编辑和诊断。波形虽然可听，但无法直接暴露音符时序、声部分配、乐句结构或和声进行。
- **已有工作为什么解决不了**：现有的符号音乐生成方法（如基于 ABC 记谱法或 MIDI 的模型）通常将音乐视为原始 token 序列。紧凑格式（如 ABC）的时序往往是隐式的，使得语言模型代理（LLM Agents）难以进行时序推理和局部编辑。此外，现有评估多依赖人类偏好或全局质量评分，缺乏可解释的结构属性反馈，导致代理无法知道具体哪里出错以及如何修正。

## 文章的核心贡献点
- **提出了一个 Libretto框架**：这是一个面向代理的符号音乐生成与修订框架，它将符号音乐从原始 token 序列转化为可测量、可编辑的对象。
- **挑战1：LLM 难以理解和管理音乐的结构化时序与声部关系。**
  - **难点**：传统符号表示中时序隐含，LLM 难以精确控制 onset（起音）位置和声部交织，导致生成结果结构混乱。
  - **解决方法**：Libretto 使用一种 LLM 原生的语法，具有显式的 onset 槽位、声部定义和小节级组织结构，使时序和结构对 LLM 直接可读且支持局部编辑。
- **挑战2：缺乏可解释的评估机制来指导代理进行自我修订。**
  - **难点**：传统评估仅给出整体分数，无法指出节奏、和声或形式上的具体缺陷，代理无法据此进行针对性修改。
  - **解决方法**：Libretto 在节奏、和声、旋律、织体、曲式和变奏等维度上构建了一个语料库校准的统计空间（statistical cloud）。通过将这些结构轴作为测量标准，代理可以诊断生成作品在统计空间中的位置，从而支持检索、风险评估和迭代自我修订。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与任务**：Libretto 被应用于多个任务，包括缺口填充（gap filling）、参考引导的全曲生成、渐进变形（gradual morphing）以及教育音乐生成。
- **评估结果**：通过将音乐映射到可解释的结构轴上，Libretto 使得生成过程可诊断。相比于仅依赖似然性或黑盒美学预测器的现有系统，Libretto 允许代理根据相对于现有音乐语料库的统计偏差进行自我修正。
- **对比优势**：与传统的序列模型相比，Libretto 不需要专门的部署环境，而是利用 LLM 的原生能力处理结构化语法；与纯音频生成模型相比，它提供了可编辑的符号表示和细粒度的结构控制能力。

#### 总结
Libretto 解决了 LLM 代理在音乐生成中面临的“结构盲区”问题。通过引入显式结构的 LLM 原生语法和基于多维结构轴的统计评估空间，它将符号音乐转化为可测量和可编辑的对象。这不仅提升了生成音乐的结构合理性，还赋予了代理诊断错误和迭代修订的能力，为可控的音乐创作提供了新的范式。
