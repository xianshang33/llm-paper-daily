## 文章做了什么
- **背景**：长程 LLM Agent 在交互过程中会积累大量结构化工具结果、文件、计划和用户约束。随着交互轮次增加，上下文成为影响成本、延迟和任务质量的关键运行时资源。
- **已有工作为什么解决不了**：现有系统主要依赖运行时的启发式方法（如按时间顺序剪枝、工具输出掩码）或在接近上下文限制时进行最终自我总结。启发式方法成本低但无法感知未来的依赖关系，容易误删关键信息；而总结方法虽然保留了叙事状态，但往往将精确的证据、定位器和可编辑工件压缩为不可寻址的文本，导致后续步骤无法准确引用或恢复。

## 文章的核心贡献点
- **提出了一个 Self-GC (Self-Governing Context) 框架**：将上下文管理从简单的令牌回收转变为对代理上下文对象生命周期的治理。
- **挑战1：如何识别并保留对未来任务至关重要的结构化证据？**
  - **难点**：传统的基于位置或时间的剪枝无法判断旧的工具输出是否包含后续步骤唯一的 URL、表格值或文件路径。
  - **解决方法**：Self-GC 将用户轮次、工具跨度和服务状态转化为索引化的对象，并通过侧信道规划器（side-channel planner）分析对象间的依赖关系，提出折叠、掩码和剪枝动作，确保关键证据不被盲目丢弃。
- **挑战2：如何在大幅压缩上下文的同时保证信息的可恢复性和安全性？**
  - **难点**：激进的压缩可能导致信息丢失且不可逆，影响 Agent 的审计能力和后续操作的正确性。
  - **解决方法**：引入可恢复的侧车（recoverable sidecars）、安全的提交边界和缓存感知的提交机制。即使对象被掩码或剪枝，系统仍能通过侧车机制在需要时恢复原始内容，实现了类似垃圾回收中“标记-清除”但更具可控性的生命周期管理。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实验设置**：在包含 33 个会话的 Hard Set 和包含 332 个会话的生产衍生套件上进行评估。
- **对比结果**：
  - 在 Hard Set 上，Self-GC 剪枝了 43.95% 的前缀令牌，同时保持 84.85% 的未来续写不受影响；相比之下，启发式基线方法的无影响率仅为 54.55% 至 69.70%。
  - 在生产衍生套件上，使用三种不同规划器后端的 Self-GC 无影响率达到 91.27% 至 94.58%，而基线方法仅为 77.71% 至 87.46%。
- **生产环境部署**：在线账户级别的拆分测试显示，白天平均输入令牌减少了 10% 至 15%，峰值减少接近 20%。

#### 总结
Self-GC 证明了长程 Agent 的上下文管理应被视为对索引化、可恢复对象的运行时生命周期控制，而非事后的文本清理。通过将上下文视为具有不同生命周期需求的对象集合，并利用侧信道规划器进行智能治理，Self-GC 在显著降低令牌消耗的同时，有效保留了对未来任务至关重要的结构化信息，优于传统的启发式剪枝和摘要方法。
