## 文章做了什么
- **背景**：随着大语言模型（LLM）向代理（Agent）风格发展，具备代码执行和工具使用能力，需要评估其在具体任务上的端到端问题解决能力。线性规划（LP）从文本到求解是一个严格的测试场景，要求模型同时正确完成自然语言理解、数学建模、代码生成和数值计算。
- **已有工作为什么解决不了**：现有的 LP-from-text 基准测试（如 NL4OPT, MAMO）多为静态数据集，由人工编写和标注。这些数据集规模固定、难度固定，且容易泄露到未来 LLM 的训练数据中。此外，人工标注成本高、扩展性差，难以提供无限的新鲜问题来抵抗数据污染。

## 文章的核心贡献点
- **提出了一个 A$^{2}$utoLPBench**：这是一个自动生成的、对 Agent 友好的线性规划基准测试，包含一个按需生成新鲜问题的生成器和一个开箱即用的评估环境。
- **挑战1：如何确保地面真值（Ground Truth）绝对正确且无需昂贵的外部求解器验证？**
  - **难点**：传统方法先生成问题再求解验证，依赖外部求解器且可能因数值误差或求解失败导致标签错误。
  - **解决方法**：采用“逆 KKT 条件”构造法。先随机选择一个可行点和其对偶变量，然后反向构建一个以该点为最优解的线性规划问题。因此，答案在构造时即已知且绝对正确，无需调用求解器或人工标注。
- **挑战2：如何防止训练数据泄露并实现难度的可控调节？**
  - **难点**：静态数据集一旦发布，问题即被固定，容易被模型记忆；且难以动态调整问题复杂度以测试不同能力水平的模型。
  - **解决方法**：将基准测试设计为生成器而非固定数据集。通过调整变量数 $n$ 和约束数 $m$ 作为“难度旋钮”来控制复杂度；使用截断日期后的新种子范围生成问题，确保问题新鲜且抵抗数据泄露。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：评估环境打包了一个参考的“求解器-批评家”（solver-critic）基线和一个 Docker 镜像。Docker 镜像中的使用说明专门写给 LLM-driven Agent 阅读，任何 Agent 只需一条命令即可接入并运行基准测试，获得校准后的分数。
- **Evaluation 结果**：
  - **平滑的难度响应**：实证显示，随着问题规模（$n, m$）的增加，求解率平滑变化，证明难度控制有效。
  - **可重复性**：独立批次生成的问题产生的评分高度一致，证明了基准测试的稳定性。
  - **基线有效性**：捆绑的 solver-critic 基线不仅在 A$^{2}$utoLPBench 上有效，在现有的其他 LP 基准测试上也表现出帮助作用。
- **对比优势**：相比 NL4OPT 和 MAMO 等人工数据集，A$^{2}$utoLPBench 提供了无限的新鲜问题、构造即正确的真值、更低的大模型侧成本（相对于人工创作）、以及抗数据泄露能力。

#### 总结
A$^{2}$utoLPBench 通过逆 KKT 构造方法解决了传统 LP 基准测试中数据静态、标注成本高和数据泄露的问题。它提供了一个动态生成、难度可控、真值绝对正确且易于 Agent 接入的评估框架，为评估 LLM 代理在数学规划和代码执行方面的端到端能力提供了可靠工具。
