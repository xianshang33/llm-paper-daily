## 文章做了什么
- **背景**：编码智能体（Coding Agents）依赖“智能体脚手架”（Agentic Scaffolding）作为中间件，负责编排系统提示、工具执行、上下文管理和迭代推理。这些脚手架的更新速度极快（每天超过两次发布），但业界常将智能体质量的回归归咎于底层大语言模型（LLM），而非脚手架本身。
- **已有工作局限**：现有研究通常固定脚手架而改变模型，缺乏对脚手架演化如何独立影响智能体质量（有效性和效率）的纵向研究，导致无法隔离脚手架变更对性能的具体贡献。

## 文章的核心贡献点
- **提出了一个**：首个控制变量的纵向实证研究框架，旨在隔离并量化智能体脚手架演化对编码智能体质量的影响。
- **挑战1：难以区分模型能力与脚手架设计对最终性能的影响。**
  - **难点**：模型和脚手架同时快速迭代，混淆变量使得归因困难。
  - **解决方法**：通过固定底层LLM，仅变化脚手架版本，对Qwen Code CLI的35个连续发布版本进行受控评估，从而精确分离出脚手架演化的独立影响。
- **挑战2：缺乏对高频发布下质量波动根源的细粒度解释。**
  - **难点**：面对数千个Issue和极高的发布频率，难以定位导致质量回归或停滞的具体代码变更或架构组件。
  - **解决方法**：结合定量基准测试（SWE-bench Verified）与定性分析，将质量波动追踪到具体的开发模式（如功能添加、修复密集型发布）和高风险架构组件，并通过Pull Request级别的证据建立因果联系。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实验设置**：首先实证分析了五个主要开源脚手架（Codex, Qwen Code, Gemini, OpenCode, OpenHands）的演化特征。随后深入评估了Qwen Code CLI的35个连续版本，每个版本在固定的LLM下针对50个分层的SWE-bench Verified任务进行测试。
- **主要结果**：
  1. **有效性停滞**：尽管开发活动持续且代码库复杂度增加，但在固定LLM版本下，SWE-bench的解决率（Resolve Rates） across releases 没有统计学意义上的显著提升。
  2. **效率下降**：后期的脚手架版本消耗的計算令牌（tokens）和工具调用次数几乎翻倍，但未带来相应的质量增益。
  3. **归因分析**：识别出与质量波动相关的开发模式，并将回归定位到特定的高风险架构组件。
- **对比**：与以往关注模型升级带来性能提升的研究不同，本文揭示了在模型不变的情况下，盲目快速的脚手架迭代可能导致资源浪费而无实质性能改进，甚至出现质量回归。

#### 总结
本文通过严格的控制变量实验证明，编码智能体的质量瓶颈往往不在于底层LLM，而在于快速演化的脚手架层。研究发现当前的脚手架开发存在“高投入低回报”的现象，即计算成本大幅增加但任务解决率未显著提升。文章呼吁在智能体脚手架的开发中引入新的“智能体质量保证”（Agentic QA）实践，强调对架构组件和开发模式的精细化监控，以避免无效迭代和资源浪费。
