## 文章做了什么
- **背景**：随着深度学习模型的快速扩展，对特定硬件内核优化的需求日益增加。虽然 NVIDIA GPU 拥有成熟的 CUDA 生态，但新兴的 AI 加速器（如 AWS Trainium 和 Inferentia）缺乏自动化的内核生成和优化方案。
- **已有的工作为什么解决不了**：现有的基于 LLM 的代理方法（如 CUDA-Agent）主要针对 CUDA 架构，无法直接应用于 Neuron 硬件。Neuron Kernel Interface (NKI) 编程具有独特的挑战性，包括多引擎架构、基于 tile 的编程模型以及跨多级存储层次的手动数据移动。此外，该领域缺乏公开的训练数据、基准测试或工具增强型代理。

## 文章的核心贡献点
- **提出了一个 NKI-Agent**：这是第一个将领域特定的监督微调（SFT）与编译-验证-修复代理循环相结合的系统，用于 NKI 内核生成。
- **挑战1：NKI 编程复杂性高，缺乏高质量训练数据**。NKI 需要处理四种专用计算引擎和显式内存管理，且无现成数据集。论文通过整理 6,000 个 NKI 内核生成任务（NKI-Agent-Ops-6K）进行 SFT，并构建了包含 250 个任务的三级难度基准测试 NKIBench，为模型提供了必要的领域知识和评估标准。
- **挑战2：单纯依靠大模型单次生成成功率极低，且高昂的推理成本限制了应用**。实验显示 Claude Opus 4.8 在无工具辅助的单次模式下通过率仅为 6%。论文设计了带有编译和验证工具的多轮代理循环，并结合等级感知系统提示词，使 Opus 4.8 的通过率提升至 77.3%；同时证明了经过 SFT 的 Qwen3-Coder-30B-A3B 能以百分之一的成本达到 25.0% 的通过率，优于 Claude Sonnet 4。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：NKI-Agent 适配了现有的 CUDA-Agent 框架以支持 Neuron 硬件，集成了编译和验证工具。模型方面，支持使用 SFT 和组相对策略优化（GRPO）训练的 Qwen3-Coder-30B-A3B，同时也兼容 Claude Opus 4.8 等闭源模型。
- **评估结果**：在真实的 Trn1 硬件上评估，NKI-Agent 配合 Claude Opus 4.8 在 150 任务的 NKIBench 子集上取得了 77.3% 的通过率。相比之下，不使用代理工具的单次模式通过率仅为 6%，突显了工具使用的关键性。
- **相关工作对比**：在 60 个任务的子集上，SFT 训练的 Qwen3-Coder-30B-A3B 实现了 25.0% 的通过率，显著高于 Claude Sonnet 4 的 15.0%，且成本仅为后者的 1/100。此外，研究发现使用二进制编译奖励的 GRPO 相比 SFT 并未带来性能提升，这为基于 RL 的内核生成中的奖励设计提供了重要参考。

#### 总结
本文针对 AWS Neuron 硬件内核生成的空白，提出了 NKI-Agent 系统。通过构建专用的训练数据集和基准测试，并结合领域特定的 SFT 与代理工具循环，有效解决了 NKI 编程中多引擎架构和复杂内存管理的难题。实验表明，该方法在真实硬件上取得了显著的通过率提升，并证明了开源小模型在经过适当微调后能在低成本下超越部分闭源大模型的表现，同时指出了当前 RL 奖励设计在该领域的局限性。
