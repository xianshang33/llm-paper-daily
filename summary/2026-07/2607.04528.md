## 文章做了什么
- **背景**：大型语言模型（LLM）智能体在软件任务中的评估通常仅关注最终结果（是否解决任务），而忽略了执行过程中“Harness”（测试 harness/执行框架）的中介作用。Harness 控制着智能体看到的观测、可采取的动作、失败的修复方式以及日志记录。
- **已有工作为什么解决不了**：现有研究将执行系统视为中性基础设施，假设只要任务和基础 LLM 固定，智能体的行为逻辑就是一致的。然而，这种观点忽视了 Harness 对信息流的操控会改变智能体的多步信念（Beliefs），进而影响其后续决策路径，即使最终任务成功率保持不变，这种隐性的信念偏差也未被量化或纠正。

## 文章的核心贡献点
- **提出了一个信念展开诊断方法（Belief-Rollout Diagnostic）和跨 Harness 信念发散度量**：该方法通过 eliciting 结构化的 K 步轨迹（涵盖进度、风险、可恢复性等维度）来量化不同 Harness 设置下智能体信念的差异，并将其分解为“到达项”（即时接口变化）和“增长项”（依赖 horizon 的信念变化）。
    - **挑战1：如何量化 Harness 对智能体内部状态的非显性影响？**
        - **难点**：传统的评估只看最终输出，无法捕捉中间推理过程中的信念偏移；且信念是隐式的，难以直接测量。
        - **解决方法**：论文设计了信念展开诊断，强制智能体在不同 Harness 视图下生成结构化的多步信念轨迹，从而直接观测并量化由 Harness 干预（如阻塞动作、压缩修复）引起的信念发散。
    - **挑战2：如何在无需重新训练的情况下消除 Harness 引起的信念偏差？**
        - **难点**：不同的 Harness 导致观测空间不一致，直接对齐困难；且重新训练成本高，缺乏通用的去偏协议。
        - **解决方法**：提出了 BIWM（Belief-Invariant World-Modeling），一种无需训练的协议。它通过规范化观测、记录被审查的分支、扩展修复痕迹、记录验证掩码以及在影子模式下执行高风险分支，来对齐不同 Harness 视图下的信念轨迹。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实验设置**：在受控的编码任务和公共基准压力测试上进行评估。
- **主要发现**：研究表明，阻塞动作、压缩修复、选择性验证和成本感知的证据剪枝等操作，虽然往往能保持终端任务的成功率，但会显著改变驱动后续决策的信念。这证明 Harness 设计是智能体评估中的一个关键实验变量，而非单纯的实现细节。
- **对比与效果**：与传统仅关注结果的评估方法相比，本文提出的诊断方法揭示了隐藏的信念分歧。引入 BIWM 协议后，能够有效对齐不同 Harness 下的信念轨迹，减少了因界面差异导致的决策偏差，证明了其在保持性能一致性的同时提升了评估的公平性和可解释性。

#### 总结
本文揭示了 LLM 智能体评估中被忽视的关键问题：Harness 的设计会诱导智能体产生信念分歧，进而影响其决策过程，即使最终任务结果相同。通过提出信念展开诊断和 BIWM 协议，作者不仅量化了这种偏差，还提供了一种无需训练的解决方案来规范观测和对齐信念。这项工作强调了在智能体评估中将 Harness 设计视为核心实验变量的重要性，为构建更鲁棒、更公平的智能体评估体系提供了新的视角和方法。
