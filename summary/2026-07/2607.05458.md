## 文章做了什么
- **背景**：大型语言模型（LLM）智能体通常通过修改提示词、模型参数或手工设计的工作流来提升性能，而围绕模型执行的“控制层”（Harness，如决定何时观察、检索、调用工具、检查、修订等）通常被视为固定的基础设施。
- **已有工作的局限**：现有的控制层多由手写规则、固定模板或静态执行图构成。这种静态设计无法根据任务难度、轨迹状态或中间尝试的成功与否动态调整控制逻辑。例如，“总是检查”会在解决方案已完整时浪费预算，而“起草后即提交”则在草稿未经验证时导致失败。主要问题在于控制序列的僵化，而非模型知识的缺失。

## 文章的核心贡献点
- **提出了一个基于离线强化学习的可学习 Harness 控制框架**：将 Harness 的操作形式化为有限 horizon 的 Harness MDP，使用轻量级控制器选择结构化的执行动作，同时保持 LLM 执行器冻结。
- **挑战1：在线探索成本高且易产生低质量轨迹**。在智能体环境中进行在线强化学习探索昂贵且容易生成无效轨迹。**解决方法**：采用离线强化学习方法，利用有限的离线 rollout 缓冲区，通过优势加权回归（Advantage-Weighted Regression, AW）仅使用终端任务评分奖励来训练控制器，避免了在线探索的风险。
- **挑战2：难以区分最终任务质量与控制过程的可靠性**。传统评估仅关注最终答案是否正确，无法衡量控制策略本身的成熟度。**解决方法**：引入了事后“Harness 成熟度分数”（Harness Maturity Score），将最终任务质量与控制过程是否遵循可靠的执行模式分离开来。这种分离提供了有限缓冲区的视图：最终质量的提升需要离线缓冲区中的高回报支持，而过程行为的改变只要与优势权重对齐即可发生。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实验设置**：在六个受控领域和两个公共基准适配器上进行了评估。
- **主要结果**：学习到的控制器一致地改进了验证行为，并有选择地提高了最终任务质量。在适配的 tau-bench retail、适配的 AgentBench DB-Bench 以及带有校准结构验证器的编码任务中取得了最大增益。
- **对比分析**：
    - 与**行为克隆（Behavior Cloning）**对比：消融实验表明，性能提升不能仅由模仿学习解释，证明了 RL 优势加权的有效性。
    - 与**强制检查（Forced CHECK）**对比：增益并非仅仅来自于增加检查步骤，而是来自于智能地决定何时检查。
    - 结果证实，Harness 控制是冻结 LLM 智能体的一个可学习层，但离线支持限制了过程控制转化为最终答案提升的上限。

#### 总结
本文论证了 LLM 智能体的执行 Harness 不应被视为固定基础设施，而是一个可学习的控制层。通过将其建模为 MDP 并使用离线强化学习训练轻量级控制器，该方法在不更新 LLM 参数的情况下，显著优化了智能体的执行流程（如验证、检索、提交决策）。提出的 Harness 成熟度分数进一步解耦了过程质量与结果质量，揭示了离线数据分布对最终性能提升的限制。这项工作为提升冻结 LLM 智能体的效率和质量提供了新的视角和方法。
