## 文章做了什么
- **背景**：在使用工具的 LLM Agent 中，存在一种“静默错误状态”（silent wrong-state）故障模式。在策略宽松（policy-permissive）的环境中，只要工具调用格式正确，即使该操作违反了领域策略（如取消不可退款的预订），工具也会执行并返回成功，而不会抛出错误。这导致 Agent 看似成功完成任务，但底层系统状态已违规且未被察觉。
- **已有工作为什么解决不了**：现有的基准测试（如 $\tau^2$-bench）和模型主要依赖 LLM 自身的推理能力来遵守自然语言形式的策略。然而，研究发现 78% 的失败是静默的策略违规，且这种失败率在不同随机种子下是可复现的，并非采样噪声。单纯依靠更强的模型或多次采样无法可靠地解决这一问题，因为根本原因在于缺乏在执行前对策略合规性的确定性检查机制。

## 文章的核心贡献点
- **提出了一个**：轻量级的确定性、只读预执行门控机制（deterministic, read-only pre-execution gates）。该机制在允许写入操作之前，检查提议的工具调用和当前数据库状态。
- **挑战1：静默策略违规难以通过 Agent 自我报告发现**。由于工具不报错，Agent 无法从轨迹中感知错误。论文方法通过引入外部确定性门控，在动作边界直接拦截违规写入，不依赖模型的自我反思能力。
- **挑战2：通用推理增强成本高且效果不稳定**。试图通过提升模型推理能力来避免所有策略违规既昂贵又不可靠。论文方法将策略执行从概率性的模型推理剥离为确定性的代码检查，仅在必要时触发，显著提升了特定场景下的成功率。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：研究在 $\tau^2$-bench 航空领域进行评估，实施了一套包含四个门控的规则套件。这些门控是只读的，在执行写操作前验证状态转换是否符合领域策略。
- **Evaluation 结果**：
    - 在 gpt-4o-mini 上，全基准成功率从 29.6% 提升至 42.0%（+12.4pp，P=0.0012）。
    - 在独立的 15 种子复制集上复现了该提升（+12.3pp，P=0.0008）。
    - 效果集中在门控触发的任务上：在 26/50 个触发任务中，成功率提升了 19.2pp；而在未触发任务中变化不显著。
- **相关工作对比**：
    - **负面对照组**：在自强制（self-enforcing）的零售领域和 BFCL 基准中，门控机制帮助甚微，证明该方法专门针对策略宽松的工具环境有效。
    - **前沿模型对比**：即使在 gpt-5.2（默认推理设置）上，静默违规依然存在，应用相同的门控套件后成功率从 61.2% 提升至 71.6%（+10.4pp），表明该问题在前沿模型中仍未完全解决，且该方法具有通用性。

#### 总结
本文揭示并量化了工具使用型 LLM Agent 中一种严重但常被忽视的“静默策略违规”故障模式。作者证明，依赖模型推理来执行策略是不可靠的，尤其是在工具本身不强制执行策略约束的情况下。通过引入确定性的预执行门控，可以在不改变模型本身的情况下，以低成本显著恢复系统的可靠性。这一贡献强调了在 Agent 系统中，“少推理，多验证”（Reason Less, Verify More）的重要性，即在动作边界通过确定性代码而非概率性生成来保障策略合规性。
