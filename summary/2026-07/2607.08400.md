## 文章做了什么
- **背景**：LLM Agent 通过分销商触达用户，分销商可能重新品牌化或替换模型。当出现归属权争议时，归因依赖于轨迹日志（工具调用、观察和执行动作的记录），而该日志由分销商存储和处理。水印必须能够抵御拥有完全读写权限的 adversaries。
- **已有工作的不足**：现有的 Agent 水印直接从日志中读取归因信息，无法抵抗对日志进行删除或重写攻击的 adversaries，因为删除会导致基于位置的关键字不同步，而重写会改变内容，单一关键字无法同时解决这两个问题。

## 文章的核心贡献点
- **提出了一个 TRACE**：一种双通道鲁棒归因水印，通过互补嵌入实现无失真、删除自同步和重写不变性。
- **挑战1：删除攻击导致同步丢失**。删除步骤会使基于位置的水印密钥失效，难以检测。**解决方法**：TRACE 引入了“选择通道”（Selection Channel），基于局部内容生成密钥并使用无失真采样器决定动作选择，使得代理分布保持不变，且在删除后检测能自动重新同步。
- **挑战2：重写攻击改变内容语义**。LLM 重写会改变日志的具体文本内容，破坏基于内容的水印。**解决方法**：TRACE 引入了“计数通道”（Tally Channel），仅基于日志的骨架（结构/位置）设置每个决策组的记录数量，这种结构信息不受任何强度的 LLM 重写影响，从而保持绝对不变。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实验设置**：在 ToolBench 和 ALFWorld 数据集上进行评估。
- **性能表现**：TRACE 在水印嵌入后，Agent 的成功率与未加水印的 Agent 持平，证明了其无失真特性。
- **鲁棒性结果**：
    - **选择通道**：在长视野轨迹上检测得分接近 z = 100，且在 70% 的步骤被删除的情况下仍可检测。
    - **计数通道**：在任何强度的 LLM 重写下保持完全不变。
- **对比优势**：相比现有直接读取日志的水印方法，TRACE 是首个同时实现动作选择无失真、删除自同步和重写无条件不变性的 Agent 水印方案。

#### 总结
TRACE 通过创新的双通道设计解决了 LLM Agent 轨迹水印中的核心难题。它利用基于内容的选择通道抵抗删除攻击，利用基于结构的计数通道抵抗重写攻击，理论上证明了水印信号以决策熵为代价，且迫使攻击者若要消除水印必须破坏轨迹本身。该方法在保证 Agent 性能的同时，提供了极强的归因鲁棒性。
