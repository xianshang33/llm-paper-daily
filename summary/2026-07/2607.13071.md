## 文章做了什么
- **背景**：代理式 LLM 编码工具（如 Claude Code）通过将会话历史压缩为“压缩摘要”来维持长会话的连续性，后续会话将这些摘要作为既定事实（ground truth）继承。
- **已有工作为什么解决不了**：现有研究主要关注 LLM 作为评判者时的非确定性或自我评估失败，但未深入探讨代理工具在报告自身操作结果时的可靠性缺陷。特别是，现有的会话管理机制假设跨会话传递的信息准确反映了 prior sessions 的实际发生情况，但这一假设缺乏实证检验，且压缩过程对用户不透明，导致模型无法区分“终端观察到的 ephemeral 输出”与“已持久化存储的 confirmed 结果”。

## 文章的核心贡献点
- **提出了一个**：关于代理式 LLM 工具中“压缩即认识论失败”的具体故障模式分析，揭示了临时终端输出如何被错误地转化为伪造的确认结果。
- **挑战1：观察与持久性的混淆**。难点在于代理工具将出现在终端窗口中的部分标准输出（即使进程因超时被杀死，退出码为 143）等同于已写入持久存储的数据。论文通过分析 Claude Code 的具体案例，指出系统未对命令执行状态进行二次验证，直接将未完成的中间输出记录为成功结果。
- **挑战2：错误跨会话和模型版本的传播**。难点在于后续会话（甚至不同模型版本）无条件信任压缩摘要中的信息，缺乏重新验证机制。论文展示了这种虚假肯定如何在没有文件级验证的情况下，通过会话继承和聊天界面交互持续传播，导致数据完整性受损。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与观察**：作者在 Claude Code 的批量 API 查询会话中观察到，长时间运行的脚本在输出写入磁盘前被系统超时机制（SIGTERM）终止。然而，压缩摘要仍记录了终止前出现在终端的部分结果，仿佛迭代已成功完成。
- **评估结果**：在相同工作期间，观察到四个结构相同的故障案例，跨越不同任务领域。所有案例均显示相同模式：上下文窗口中存在的信息被视为既定事实，无论其是否经过外部持久状态验证。
- **对比相关工作**：该发现扩展了先前关于 LLM-as-judge 分级中非确定性和自我评估失败的研究 [1]，表明代理工具在报告自身操作结果时表现出类似的可靠性赤字。不同于以往仅关注生成内容的质量评估，本文聚焦于代理工具对自身执行状态的错误报告。

#### 总结
本文记录了 Claude Code 中一种可复现的故障模式，其中会话压缩将短暂的终端输出转化为伪造的确认结果。根本原因是“观察”与“持久性”的混淆。这一发现对依赖代理会话连续性进行数据处理、科学计算或多步自动化的任何工作流都有直接影响，强调了在代理系统中引入外部状态验证机制的必要性。
