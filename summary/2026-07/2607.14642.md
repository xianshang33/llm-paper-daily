## 文章做了什么
- **背景**：随着模型上下文协议（MCP）服务器成为连接大语言模型（LLM）与外部工具的核心基础设施，评估 LLM Agent 的工具使用能力变得至关重要。然而，现有的基准测试主要利用静态的或实时的 MCP 服务器进行评估。
- **已有工作的不足**：现有基准测试忽视了 MCP 服务器中工具接口和功能的持续演变。这种静态评估无法捕捉 Agent 在动态变化的工具环境中的适应能力，导致评估结果存在缺陷，不能真实反映 Agent 在面对工具变更时的鲁棒性。

## 文章的核心贡献点
- **提出了一个 MCPEvol-Bench**：这是一个用于评估 LLM Agent 在动态工具集演变下任务解决能力的新型基准测试框架。
- **挑战1：如何真实模拟工具演变？**
  - **难点**：工具演变具有多样性和复杂性，简单的随机修改无法反映真实开发场景中的接口变更模式。
  - **解决方法**：通过对大量 MCP 服务器进行实证研究，识别出主要的演变模式，并据此设计了 11 种变异算子。利用 LLM 驱动的方式自适应地选择这些算子对源代码进行修改，从而在 123 个 MCP 服务器中生成逼真的工具演变版本。
- **挑战2：如何量化 Agent 对演变的适应性？**
  - **难点**：需要在一个受控环境中，精确衡量同一 Agent 在不同版本工具集上的性能差异，并区分错误类型（如规划错误 vs 推理错误）。
  - **解决方法**：构建了跨版本的评估流水线，在多个演变阶段的 MCP 服务器上基准测试 12 个最先进的 LLM。通过对比 Agent 在原始版本和演变版本上的任务成功率及错误分布，揭示了模型在适应动态工具时的具体弱点。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与数据**：研究团队分析了远程托管服务器和公共代码仓库的版本历史， curated 了包含 1,272 个工具的 123 个 MCP 服务器，涵盖软件开发、数据分析等多个领域。通过基于 LLM 的管道自动生成跨服务器任务。
- **评估结果**：实验表明，即使是前沿模型也难以适应不断演变的工具。例如，GPT-5.4 和 Claude-Sonnet-4-6 在演变后的 MCP 服务器上性能分别下降了 13.7% 和 14.4%。此外，随着工具的演变，Agent 的规划和推理错误显著增加。
- **对比**：与忽略工具演变的现有静态基准测试相比，MCPEvol-Bench 揭示了 LLM 驱动工作流在动态环境中的脆弱性，提供了更贴近真实世界部署场景的评估标准。

#### 总结
本文指出了当前 LLM Agent 基准测试在评估工具适应性方面的空白，提出了 MCPEvol-Bench。通过实证研究指导的变异算子和 LLM 驱动的演变模拟，该基准测试有效评估了 Agent 在动态工具环境下的表现。研究发现主流 LLM 在应对工具接口和功能变化时存在显著的性能下降和错误率上升，强调了提升 Agent 适应动态工具环境能力的重要性，并将 MCPEvol-Bench 确立为评估此类适应性的新标准。
