## 文章做了什么
- **背景**：大型语言模型（LLM）智能体日益依赖工具调用（Tool Calling）来操作外部系统，模型上下文协议（MCP）已成为事实上的标准接口。然而，在云规模下运行 MCP 面临巨大困难。
- **已有工作为什么解决不了**：
    1. **工具提供方**：大量遗留服务（Legacy Services）无法直接通过 MCP 调用；MCP 协议快速迭代导致持续的兼容性成本。
    2. **智能体方**：受限于 LLM 的上下文窗口和推理开销，可挂载的工具数量有限。挂载大量工具会增加 Token 消耗、推理延迟，并降低任务成功率。
    3. **架构限制**：对于具有多个副本的有状态 MCP 后端，保持会话亲和性（Session Affinity）增加了客户端的复杂性。现有的 Web 导向负载均衡器因 MCP 路由信息位于 HTTP Body 而非 Header 中，无法直接复用。

## 文章的核心贡献点
- **提出了一个**：面向云规模的 MCP 服务网关系统。该系统打破了数据平面上的直连模型，将遗留服务集成、不兼容 MCP 变体的整合、访问控制、工具推荐以及会话感知路由等功能卸载到网关层。
- **挑战1：遗留系统集成与协议兼容性难题**。由于现有海量 API 基于 OpenAPI 且 MCP 协议演进迅速，直接适配成本高且难以维护。**解决方法**：网关内置协议适配模块，将 MCP 工具调用转换为对现有 API 服务器的调用，并桥接不同版本的 MCP 变体，从而屏蔽底层差异，降低开发者的适配成本。
- **挑战2：大规模工具集下的选择效率与上下文限制**。LLM 上下文窗口有限，直接输入数千个工具描述会导致 Token 爆炸和选择准确率下降。**解决方法**：在网关层实现混合检索（Hybrid Retrieval）机制，仅向 LLM 返回最相关的少量工具候选集。该方法在维持高召回率的同时，显著减少了 Token 使用和选择时间，支持扩展至 3000+ 工具。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：系统在阿里云生产环境中部署，处理大规模流量。网关承担了协议转换、访问控制和路由分发等核心功能，解决了传统 L7 负载均衡器无法解析 MCP 内部路由信息的问题。
- **Evaluation 结果**：
    - **工具选择准确性**：混合检索机制保持了 98% 的 Top-15 召回率。
    - **扩展性**：支持智能体访问 3000+ 个工具，且在横向扩展时保持稳定。
    - **性能提升**：与传统全量输入或基线方法相比，工具选择时间减少了 8.9 倍，Token 使用量减少了 23.8 倍。
    - **开销**：每次调用的额外开销极低。
- **对比**：相较于直接在客户端管理所有工具连接和处理兼容性的传统直连模式，该网关方案显著降低了客户端复杂度，并在大规模场景下提供了更优的资源效率和稳定性。

#### 总结
本文针对 LLM 智能体在云规模下使用 MCP 协议面临的遗留系统集成难、上下文窗口限制、协议兼容性差及会话路由复杂等问题，提出了一种云规模的 MCP 网关系统。通过将协议适配、工具检索和路由逻辑卸载至网关，并结合混合检索技术，该系统成功实现了从直连模型到中心化网关模型的转变。实验表明，该系统在支持数千种工具访问的同时，大幅降低了 Token 消耗和延迟，提升了工具选择的准确性和系统的可扩展性，为生产环境中的大规模 LLM 智能体部署提供了可行的基础设施解决方案。
