## 文章做了什么
- **背景**：大型语言模型（LLM）正被广泛用于自动化数据处理工作流（如合成数据生成、评估等）。然而，现有的代码代理通常生成的是自由形式的脚本，这些脚本无法自动转化为持久化、可编辑的平台原生构件。
- **已有工作的不足**：这种自然语言到平台流水线的脱节被称为“NL2Pipeline gap”。现有方法生成的脚本缺乏与底层数据平台的深度集成，导致难以维护、编辑和可视化，且往往需要高昂的计算成本和延迟来反复生成和调试代码。

## 文章的核心贡献点
- **提出了一个 DataFlow-Harness 平台**：这是一个基于 grounding 的代码代理平台，旨在通过类型化的增量突变而非自由形式脚本来构建平台原生的有向无环图（DAG）。
- **挑战1：如何将自然语言意图准确转化为平台原生的持久化 DAG 结构？**
  - **难点**：直接生成脚本容易出错且不可编辑，而直接生成复杂 DAG 需要理解平台特定的算子注册表和状态。
  - **解决方案**：引入 Model Context Protocol (MCP) 层，暴露实时算子注册表和当前流水线状态，结合 DataFlow-Skills 提供过程性指导，引导 LLM 进行类型化的增量修改，确保生成的 DAG 既符合平台规范又可编辑。
- **挑战2：如何降低构建过程的计算成本并提高可靠性？**
  - **难点**：传统的代码生成基线（如 Vanilla Claude Code）往往需要多次尝试才能生成正确代码，导致高延迟和高货币成本。
  - **解决方案**：通过 DataFlow-WebUI 实现对话式创作与可视化 DAG 编辑器的同步，利用平台 grounding 减少幻觉和无效尝试。实验表明，该方法在保持与上下文感知基线相当的通过率的同时，显著降低了成本和延迟。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：系统包含数据管道后端、DataFlow-WebUI（前端可视化编辑器）、MCP 工具层（连接 LLM 与平台状态）以及 DataFlow-Skills（程序性知识库）。代码已开源。
- **Evaluation 结果**：
  - 在包含 12 个任务的数据工程基准测试中，DataFlow-Harness 实现了 93.3% 的端到端观察通过率。
  - **与 Vanilla Claude Code 对比**：货币成本降低 72.5%，生成延迟降低 49.9%。
  - **与 Context-Aware Claude Code 基线对比**：观察通过率仅差 0.9 个百分点，但成本低 42.8%。
- **分析**：每任务分析显示，当构建依赖于隐式过程知识时，Skills 模块最为有用。结果表明，实时平台 grounding 能够以接近脚本生成基线的可靠性产生持久、可编辑的工作流构件，同时具有更低的构建成本和延迟。

#### 总结
DataFlow-Harness 有效解决了 LLM 代码代理在数据工程领域的“NL2Pipeline gap”问题。通过结合 MCP 协议、技能引导和可视化同步编辑，该平台不仅提高了工作流生成的可靠性和可编辑性，还大幅降低了经济成本和时间延迟，为生产环境中的 LLM 驱动数据管道构建提供了高效解决方案。
