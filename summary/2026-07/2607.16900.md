## 文章做了什么
- **背景**：训练能够调用 API 的大型语言模型（LLM）智能体需要海量的高质量轨迹数据，这些数据需包含多步交互、状态跟踪及错误恢复过程。
- **已有工作的局限**：现有的合成数据生成方法通常依赖于完全实现的可执行环境，包括可运行的 API 和预填充真实状态的后台数据库。这种对环境基础设施的强耦合导致为新 API 集合生成数据时面临巨大的工程瓶颈，严重限制了可扩展性。

## 文章的核心贡献点
- **提出了一个无环境合成数据生成框架（ESAT）**：该方法仅依赖 API 规范，利用 LLM 作为即时数字世界模型来模拟有状态的环境交互，从而生成高质量的智能体轨迹。
- **挑战1：如何在没有真实后端数据库的情况下模拟一致且有状态的 API 响应？**
  - **难点**：API 调用往往涉及状态改变（如转账、修改文档），后续调用的结果依赖于之前的操作历史。在没有真实数据库的情况下，保持跨多步交互的状态一致性极具挑战性。
  - **解决方案**：引入“模拟器 LLM”（Simulator LLM），它根据任务上下文和模拟历史，动态生成连贯的合成 API 响应，充当虚拟的状态管理器，确保交互逻辑的自洽性。
- **挑战2：如何确保生成的合成轨迹在逻辑正确性和任务可行性上的高质量？**
  - **难点**：纯 LLM 生成的任务和轨迹可能包含幻觉、逻辑错误或不可执行的步骤，直接用于训练会损害模型性能。
  - **解决方案**：采用“教师智能体”迭代求解任务，并引入“裁判 LLM”（Judge LLM）对生成的轨迹进行严格过滤，剔除无效或低质量的样本，仅保留高置信度的轨迹用于最终数据集。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现细节**：流程分为任务合成、轨迹合成和轨迹过滤三个阶段。首先由任务生成 LLM 基于 API 规范创建多样化任务；接着教师智能体与模拟器 LLM 交互生成轨迹；最后由裁判 LLM 筛选数据。
- **评估基准**：在具有挑战性的 AppWorld 和 OfficeBench 基准上进行评估，涵盖信息检索和状态变更两类任务。
- **结果对比**：在该合成数据上微调模型后，取得了显著的性能提升。结果表明，无需任何可执行环境，仅凭 API 规范生成的监督数据即可有效训练 API 调用智能体，证明了该方法在多样 API 生态系统中的实用性和可扩展性，克服了传统方法依赖复杂环境搭建的限制。

#### 总结
本文提出了一种创新的无环境合成数据生成方法，通过利用 LLM 作为数字世界模型，解决了 API 智能体训练中数据收集对环境基础设施的依赖问题。通过任务生成、状态模拟和质量过滤的闭环流程，该方法能够仅从 API 规范中生成高质量、状态一致的交互轨迹。实验证实，基于此数据训练的模型在多个基准测试中表现优异，为大规模训练 API 智能体提供了一条高效、可扩展的新路径。
