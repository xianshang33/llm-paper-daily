## 文章做了什么
- **背景**：随着大型语言模型（LLM）融入供应链工作流，货主开始将承运商选择任务委托给自主 LLM 代理。数字货运匹配（DFM）平台正从算法推荐转向由代理直接做出选择。
- **已有工作的不足**：现有研究多关注传统算法匹配或静态供应商筛选，缺乏对基于真实 LLM 代理的动态市场行为、内生容量限制及信息设计对市场集中度影响的深入模拟与分析。传统方法无法解释当数千名货主通过少数基础模型进行选择时，模型共享偏好导致的“算法单一文化”风险。

## 文章的核心贡献点
- **提出了一个**：基于真实商业 LLM（GPT, Claude, Gemini）构建的货主代理系统进行为期30天的数字货运匹配市场仿真框架，揭示了 LLM 中介市场中的集中度风险及有效的平台信息设计对策。
- **挑战1：LLM 代理的选择趋同导致市场高度集中。**
  - **难点**：不同 LLM 模型在初始阶段表现出强烈的偏好一致性，导致特定承运商在第一天即占据高达76%的请求量，形成垄断风险。
  - **解决方法**：研究发现这种集中度的急剧上升与候选列表长度有关（超过10个承运商时显著），且不同模型 onset 不同。通过控制平台向货主展示的候选列表长度和结构，可以干预这一过程。
- **挑战2：传统信任信号（如评级、质量展示）无法有效缓解市场波动和集中。**
  - **难点**：显示真实质量而非估算评级并不能降低集中度或其变异性，因为质量仅影响代理所见信息而不改变交付结果；供应商多样化、列表随机化和热度显示也无明显效果。
  - **解决方法**：提出并验证了“披露承运商剩余日容量”这一信息设计策略。该策略通过提供实时供需状态信息，使需求分散，成功将集中度降低了三分之一，并使货主盈余翻倍。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：构建了包含50个货主代理的基于代理的仿真环境，代理分别基于 OpenAI (GPT)、Anthropic (Claude) 和 Google (Gemini) 的商业 LLM。市场模拟了数字货运匹配规则，包括瀑布式招标、承运商日容量限制、拥堵响应现货价格以及累积交易评级。
- **Evaluation 结果**：
  1. **快速收敛风险**：所有模型在第一天就收敛到同一个主要承运商。
  2. **列表长度效应**：当候选列表超过约10个承运商时，集中度急剧上升。
  3. **无效干预**：供应商多样化、列表顺序随机化、显示流行度或真实质量均未能显著降低集中度或变异性。
  4. **有效干预**：披露剩余容量是唯一有效的杠杆，显著降低集中度并提高货主盈余。
- **对比**：与传统算法推荐或静态评分系统相比，本研究强调了在 LLM 代理主导的市场中，信息透明度（特别是实时容量信息）比传统的声誉机制更能有效调节市场健康度。

#### 总结
本文首次模拟了由真实 LLM 代理群体进行的货运采购过程，揭示了 LLM 中介市场中存在的算法单一文化和市场集中风险。研究指出，平台的信息设计（特别是披露剩余容量）是比模型选择或监管更有效的调控杠杆。这一发现为设计更健康、更具竞争性的 LLM 驱动市场提供了重要的理论依据和实践指导。
