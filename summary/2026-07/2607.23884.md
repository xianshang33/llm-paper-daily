## 文章做了什么
- **背景**：随着大语言模型（LLM）的进步，由异构、工具增强且基于 LLM 的智能体组件构成的智能体系统迅速兴起。这引发了关于智能体间协调和协议设计的实际问题。
- **已有工作为什么解决不了**：现有的多智能体系统（MAS）文献主要关注经典代理定义，而当代基于 LLM 的智能体系统在架构上有所不同，缺乏针对这种新型异构智能体间通信协议（如 MCP 和 A2A）在实际工程实现中的对比研究，特别是在可发现性、状态管理、生命周期处理等具体工程需求方面的权衡尚不明确。

## 文章的核心贡献点
- **提出了一个**：基于实现的 Model Context Protocol (MCP) 与 Agent2Agent (A2A) 协议的实证对比研究，通过相同的软件工程任务场景评估两种协议在智能体协调中的表现。
- **挑战1：如何在保持低复杂度的同时实现基本的智能体协调？**
  - **难点**：复杂的协议会增加实现负担，阻碍快速部署。
  - **解决方法**：论文指出 MCP 提供了一种相对轻量级的实现模型，降低了协调复杂度，适合受限的 LLM 系统，但需应用层显式处理状态和生命周期。
- **挑战2：如何原生支持有状态的多轮对话和任务生命周期管理？**
  - **难点**：简单的协议难以处理复杂的交互状态和长期运行的任务流程。
  - **解决方法**：论文发现 A2A 通过协议级的任务和生命周期管理抽象，提供了更丰富的原生支持，但以显著增加实现和协调复杂性为代价。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与评估**：研究者实现了基于 MCP 和基于 A2A 的两个多智能体系统，执行相同的软件工程任务。评估指标包括智能体可发现性、多部分消息传递、多轮对话、异步通信、可观察性、互操作性和访问控制。
- **结果对比**：
  - **MCP**：优势在于实现轻量、协调复杂度低；劣势是会话状态管理和任务生命周期处理必须在应用层显式实现，缺乏原生支持。
  - **A2A**：优势在于通过协议级抽象原生支持有状态的多轮协调和任务生命周期；劣势是实现和协调的复杂性显著更高。
- **结论性质**：由于评估范围局限于特定的协调模式，结果被视为实证经验报告中的设计观察，强调了协议抽象如何塑造当代智能体系统中协调责任的分布，而非宣称某一方在所有 MAS 类别中普遍优越。

#### 总结
本文通过实证研究对比了 MCP 和 A2A 两种协议在基于 LLM 的智能体系统中的应用。研究表明，MCP 适合追求轻量级和低复杂度的场景，但需开发者自行处理状态管理；而 A2A 适合需要复杂状态和多轮交互的场景，提供了强大的原生支持，但增加了系统复杂性。该研究为工程师在选择智能体协调协议时提供了重要的权衡参考，突出了协议设计对系统架构责任分配的影响。
