## 文章做了什么
- **背景**：自主 LLM Agent 在处理混合机密性数据时，面临提示注入攻击和推理错误带来的严重安全风险。传统的动态信息流控制（IFC）虽然能提供结构性安全保障，但存在“标签蠕变”问题，即一旦读取未审查数据，整个上下文会被永久污染，导致后续工具调用受限，严重损害 Agent 的可用性。
- **已有工作的不足**：现有的防御手段主要分为两类：一是命令式护栏（如硬编码逻辑、分类器），它们难以组合且易被绕过，无法应对非对抗性错误；二是静态结构限制（如白名单、人工审批），过于严格且僵化，阻碍了合法工作流。现有的 Agent IFC 框架虽能追踪标签，但因永久性污点传播导致实用性瓶颈，无法在安全与效用之间取得平衡。

## 文章的核心贡献点
- **提出了一个 APPA (Agentic Permissions Policy Algebra)**：一种基于引擎管理的上下文分支和前瞻性获取执行的 IFC 框架，旨在解决传统污点跟踪导致的可用性问题。
- **挑战1：如何在检查未审查数据时不污染主上下文？**
  - **难点**：传统方法中，读取低信任度数据会立即提升主上下文的保密级别，导致后续高权限操作被禁止。
  - **解决方案**：APPA 通过生成带有标签种子的子轨迹（child trajectory）来局部吸收标签降级，允许受信任的清理程序将有限的衍生数据返回给保持不变的主上下文，从而实现污点隔离。
- **挑战2：如何在数据获取前确保策略合规并恢复效用？**
  - **难点**：事后检测往往为时已晚，而事前预测缺乏形式化保证，难以动态调整权限而不破坏安全性。
  - **解决方案**：APPA 在数据获取前前瞻性地评估标签降级和缺失前提条件，生成可操作的补救计划（授权或接受）。基于安全标签和共享事件日志的双幺半群模型，形式化证明了父标签保留和合并 confinement，从而在三个模型上恢复了因单纯污点跟踪而损失的大部分效用。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与评估**：作者在包含四个不同模型的多轮工具链基准测试中评估了 APPA。
- **安全性结果**：APPA 显著抑制了数据泄露，将攻击成功率从基线的 31%-50% 降低至 0%-7%。
- **效用对比**：与传统的污点跟踪方法相比，APPA 的分支机制在四个模型中的三个上恢复了大量因安全限制而 forfeit 的效用，证明了其在保持高安全标准的同时显著提升了 Agent 的任务完成能力。

#### 总结
APPA 通过引入上下文分支和前瞻性策略执行，有效解决了 LLM Agent 中信息流控制的可用性瓶颈。它在形式化保证安全性的前提下，成功隔离了污点传播，既大幅降低了提示注入和数据泄露的风险，又保留了 Agent 处理复杂任务的能力，为构建安全且实用的自主 Agent 提供了新的范式。
