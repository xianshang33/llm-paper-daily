## 文章做了什么
- **背景**：随着推理工作负载多样化，华为 Ascend NPU 成为 NVIDIA GPU 的重要替代方案。Ascend C 编程模型基于 CANN 工具包，与 CUDA 有根本不同（强调向量计算管道和统一缓冲区 UB tiling，需显式管理数据流而非并行执行）。优化 Ascend C 算子对提升 NPU 推理性能至关重要，但需要深厚的硬件专业知识。
- **已有工作为什么解决不了**：现有的 LLM 自动代码生成方法（如针对 CUDA 的 KernelBench, EvoEngineer）严重依赖预训练语料库中丰富的目标平台代码。Ascend C 属于极低语料领域，公共代码极少，导致现有框架出现分布外泛化失败。在没有外部知识注入的情况下，标准 LLM 甚至无法为除简单元素级模式外的任何算子生成可编译的代码。主要挑战从性能调优转变为在极端数据稀缺下实现代码合成的可行性。

## 文章的核心贡献点
- **提出了一个** AgenticCANN，这是一个专为低语料 NPU 环境设计的、知识增强的代理进化框架，用于自动化 Ascend C 算子合成。
- **挑战1：严重缺乏平台知识导致的上游可行性瓶颈**。由于 Ascend C 语料稀缺，LLM 缺乏必要的硬件领域知识，难以生成符合语法和语义约束的基础代码，导致编译失败率高。**解决方法**：引入知识编排生成系统，在整个开发生命周期中提供结构化、多层次的领域洞察，通过知识注入弥补平台知识赤字，从而解决可行性问题。
- **挑战2：平衡探索与收敛的效率难题**。在代码生成过程中，既需要广泛探索候选方案以发现潜在最优解，又需要精细调优以提升性能，单一的交互模式难以兼顾。**解决方法**：采用阶段自适应的代理进化策略，动态调整 LLM 的交互模式以匹配特定的生成和进化阶段，在高探索性的候选发现和高收敛性的性能调优之间取得平衡。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实验设置**：在华为 Ascend 910B NPU上进行实验，涵盖五种模式类别的六个算子。
- **主要结果**：
    - **可行性**：在元素级（elementwise）和归一化（normalization）算子上达到 90% 到 100% 的可行性；在融合（fusion）算子上达到 56% 的可行性。
    - **性能加速**：在 1B Pangu 模型推理内核上实现了高达 6.65 倍的加速比。
    - **知识注入效果分析**：进一步分析显示，知识注入使元素级算子的可行性从 57% 单调提升至 86%，证明了其具有普遍性益处，而非仅针对特定算子有效。
- **对比**：相比于直接迁移现有的 CUDA 自动化生成方法（如 EvoEngineer），AgenticCANN 解决了在低语料环境下无法生成可编译代码的根本问题，并在可行性和最终推理速度上取得了显著优势。

#### 总结
AgenticCANN 成功解决了在低资源、陌生硬件平台（Ascend C）上利用 LLM 进行自动算子生成的难题。通过结合知识增强以解决可行性瓶颈，以及阶段自适应的代理进化策略以优化性能，该框架不仅在代码生成的可行性上取得了突破（特别是在元素级和归一化算子上），还实现了显著的推理加速。这项工作证明了在极端数据稀缺场景下，通过结构化的知识注入和动态代理策略，可以有效克服 LLM 的分布外泛化限制，为 NPU 算子自动化开发提供了新范式。
