## 文章做了什么
- **背景**：多智能体系统（MAS）在解决复杂任务时日益普及，但当输出错误或不可接受时，用户需手动检查智能体轨迹以定位错误（故障归因）并提供反馈进行修复。尽管已有研究致力于自动化故障归因，但自动化的 MAS 修复机制仍 largely unexplored。
- **已有工作局限**：现有的唯一自动化修复工作 DoVer 采用顺序探索策略，在高 Token 成本下搜索空间受限；且其仅在编排器（orchestrator）层面进行修复，限制了其在无中心化编排器的智能体系统中的适用性。

## 文章的核心贡献点
- **提出了一个 MARS 框架**：一种基于搜索的框架，将 MAS 修复形式化为蒙特卡洛树搜索（MCTS）过程，通过诊断引导的扩展和分类增强的评估来导航巨大的潜在修复空间。
- **挑战1：如何在巨大的修复空间中高效搜索并降低 Token 消耗？**
  - **难点**：标准 MCTS 需要完整 rollout 来评估模拟，导致极高的计算和 Token 成本，难以在大规模 MAS 中应用。
  - **解决方法**：MARS 采用“部分 rollout”（partial rollout），即仅重新执行智能体系统的前 k 步，而非运行至完成。结合诊断引导的扩展（包括回滚、引导修复和继续动作），在显著降低 Token 消耗的同时实现了对轨迹探索的细粒度控制。
- **挑战2：如何在没有完整轨迹的情况下评估部分修复的质量？**
  - **难点**：由于部分 rollout 不产生完整轨迹，无法使用最终任务结果作为评估信号，导致传统评估方法失效。
  - **解决方法**：引入“分类增强评估”（taxonomy-augmented evaluation）机制，该机制刻画常见的失败模式并为 MCTS 生成动态奖励信号，使得即使在没有完整轨迹的情况下也能做出明智的搜索决策。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **基准数据集**：引入了 StateMAS，这是一个大规模的 MAS 修复基准，包含 1,310 个可重放的多智能体失败轨迹，涵盖四种智能体架构和四种 LLM 后端。
- **实验结果**：在 StateMAS 上的实验表明，MARS 在所有设置下均一致优于最先进的方法（SOTA），绝对改进幅度从 3.0% 到 12.1% 不等。
- **效率对比**：在取得性能提升的同时，MARS 保持了与现有方法相当的 Token 消耗成本。
- **消融实验**：证实了分类增强评估和诊断引导扩展是实现性能增益的关键组件。

#### 总结
本文针对多智能体系统自动化修复这一空白领域，提出了 MARS 框架。通过将修复过程建模为 MCTS，并利用部分 rollout 和分类增强评估解决了搜索效率和中间状态评估两大难题。同时，作者构建了 StateMAS 基准以推动该领域研究。实验证明 MARS 在修复成功率和成本效率上均显著优于现有方法，为 MAS 的自主修复提供了新的解决方案。
