## 文章做了什么
- **背景**：稀疏矩阵核（如 SpMV、SpMM、SpGEMM）是科学计算、图分析和机器学习的核心。其 GPU 性能高度依赖于输入的稀疏模式和执行策略。同一矩阵在不同格式下（如 CSR 与 Blocked-ELL）性能差异可达 350 倍。
- **已有工作为什么解决不了**：现有的专用系统或稀疏编译器（如 CB-SpMV, SparseTIR）通常基于对输入结构、算子或目标架构的特定假设进行优化。这些假设在匹配时能带来高性能，但在不匹配时会导致严重的性能下降。研究表明，没有任何一种单一实现在所有稀疏模式和算子上都能保持一致的主导地位，固定实现无法适应多样化的工作负载和硬件环境。

## 文章的核心贡献点
- **提出了一个名为 SparseDitto 的基于 LLM 的智能体系统**，能够为每个矩阵、算子和目标 GPU 动态构建定制化的 GPU 内核，支持 SpMV、SpMM 和 SpGEMM。
- **挑战1：稀疏优化空间巨大且高度不对称，难以通过静态规则选择最优策略。**
  - **难点**：存储格式与执行调度的组合空间极大，且错误的配对会导致数量级的性能损失，而正确的配对仅带来有限增益，传统启发式方法难以覆盖所有情况。
  - **解决方法**：引入轻量级加法模型，利用输入矩阵的结构特征对既定策略进行初步排名，缩小搜索空间；随后由架构感知规划器提出候选设计方案，避免盲目搜索。
- **挑战2：生成的内核需要针对特定硬件进行精细调整以确保正确性和高性能。**
  - **难点**：不同 GPU 架构（如 RTX PRO 6000 与 H200）的资源限制和内存层级不同，静态代码生成难以自动适配硬件细微差别，且需保证代码正确性。
  - **解决方法**：采用编码和验证智能体（Coding and Verification Agents），利用来自目标 GPU 的实际测量数据迭代实施和优化内核，通过闭环反馈机制确保生成的代码既高效又正确。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：SparseDitto 是一个统一的框架，集成了轻量级模型排序、架构感知规划以及基于 LLM 的代码生成与验证智能体。它能够在运行时针对特定工作负载生成定制化内核。
- **评估结果**：
  - 在 NVIDIA RTX PRO 6000 GPU 上，SparseDitto 在三种稀疏算子和多样化矩阵测试中，相比 cuSPARSE 实现了 **2.68 倍的几何平均加速比**，最高加速比达 **146.61 倍**。
  - 在 NVIDIA H200 GPU 上，实现了 **2.79 倍的几何平均加速比**，最高加速比达 **78.5 倍**。
  - 在全批量 GCN 训练任务中，其生成的 SpMM 内核带来了高达 **3.39 倍**的加速。
- **对比**：优于现有的专用系统（如 CB-SpMV, DTC-SpMM 等）和通用库 cuSPARSE，特别是在处理非典型稀疏模式时，避免了因格式不匹配导致的性能悬崖。

#### 总结
SparseDitto 通过结合轻量级统计模型与 LLM 驱动的智能体系统，解决了稀疏矩阵计算中因稀疏模式多样性和硬件差异性导致的性能优化难题。它不再依赖单一的固定实现，而是为每个工作负载动态生成最优 GPU 内核，显著提升了稀疏算子在多种 GPU 架构上的执行效率，展示了 LLM 在系统底层优化中的巨大潜力。
