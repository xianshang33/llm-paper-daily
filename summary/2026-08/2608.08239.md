## 文章做了什么
- **背景**：LLM 路由器（Routers）通过为每个请求匹配最便宜且足够的模型来承诺提高效率，并越来越多地应用于多步 Agent 的每一步中。然而，目前的评估方法沿用了单轮路由器的逻辑，即通过重放日志轨迹并替换另一个模型的记录输出来进行评估。
- **已有工作的问题**：这种“重放评估”假设如果在一个步骤中替换了模型，轨迹的其余部分不会受到影响（即假设环境是开环的）。但实际上，Agent 的行动决定了下一步的观察结果，轨迹是一个与环境交互的闭环。现有的静态评估方法忽略了这种依赖性，导致评估结果无法反映真实世界的表现。

## 文章的核心贡献点
- **提出了一个分支 rollout 协议（Branching-Rollout Protocol）**：用于对每步模型切换进行反事实评估的开源框架，能够准确量化重放差距。
- **挑战1：量化重放假设的错误程度及其结构**。难点在于需要区分由模型切换引起的真实分歧与由采样或环境重放噪声引起的基线分歧，且实时分支 rollout 成本高昂。论文通过在受控点分叉 live SWE-bench Agent 轨迹，重建环境，并与同模型控制分叉（control forks）进行配对比较，隔离了噪声，从而精确测量了分歧的大小和结构。
- **挑战2：验证重放评估在结果预测上的有效性**。难点在于证明静态重放不仅轨迹不同，而且会导致最终结果（如代码补丁是否正确）的误判。论文通过对比交换臂（swap arms）和控制臂的结果翻转情况，发现重放评估器错误预测了所有与成功相关的结果调用，且生成的补丁与现实相似度极低，证明了重放基准测试的是“错误的世界”。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：作者开发了一个开源 harness，支持在 SWE-bench 环境中进行分支 rollout。实验包括约 900 次 rollout，分为六组配对运行。每次在特定步骤分叉轨迹，重新执行前缀动作，并在新鲜容器中用不同模型继续，同时设有同模型控制组以隔离噪声。
- **Evaluation 结果**：
    - **轨迹分歧**：模型交换导致的归一化编辑距离比匹配的控制基线高出 +0.25 到 +0.66。交换后 61-94% 的动作被重写。74-77% 的早期交换在分叉后的第一个动作就发生分歧，而控制组仅为 6-35%。只有 3% 的重放状态是有效的。
    - **结果翻转**：观察到的所有 5 次结果翻转（如升级模型解决了未解决的实例，降级模型丢失了唯一解）都发生在交换臂中，而 359 个控制分叉中零次发生。
    - **重放评估失效**：使用日志拼接重放评估器评分时，它错误预测了每一个与成功相关的结果调用，预测的补丁与现实的相似度仅为 0.00-0.11。
    - **噪声审计**：Temperature-0 的“确定性”依赖于配置。FP8 服务的控制组在超过 90% 的分叉中出现分歧，而 AWQ 服务的则保持几乎一致。此外，在预算紧张时，更强的模型更常因耗尽步骤而未提交结果。
- **对比**：与传统静态重放评估相比，本文方法揭示了重放评估完全无法捕捉 Agent 交互中的动态变化，其预测结果与现实严重脱节。

#### 总结
本文指出当前 LLM Agent 路由评估中存在的根本性缺陷：静态重放评估错误地假设轨迹是开环的，忽略了模型切换对环境状态的连锁反应。通过引入分支 rollout 方法，作者证明了模型切换会导致轨迹迅速且大幅度的分歧，且重放评估在预测最终结果上完全失效。研究还揭示了推理服务配置（如 FP8 vs AWQ）对确定性的显著影响。作者发布了相关 harness 和轨迹数据，呼吁社区采用更真实的动态评估方法来指导 Agent 路由的研究与部署。
