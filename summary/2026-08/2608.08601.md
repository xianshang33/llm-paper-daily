## 文章做了什么
- **背景**：随着 AI Agent 在职场中的广泛部署，组织需要分类法来识别和分类其带来的社会技术风险。然而，现有的 AI 风险分类法通常过于宽泛或侧重于技术故障，无法捕捉由 Agent 引入的特定于工作岗位的风险。
- **已有工作的不足**：现有分类法未能涵盖 Agent 与其社会环境（包括人类、组织和机构）之间动态交互产生的社会技术风险，导致许多职场特定的风险未被命名或追踪。

## 文章的核心贡献点
- **提出了一个多层框架与职场 AI Agent 风险分类法**：基于文献综述开发了包含 Agent、目标和环境三个核心组件及其交互的多层框架，并据此构建了包含 15 个类别的职场 AI Agent 风险分类法。
- **挑战1：如何系统化地生成特定于具体工作任务的真实风险场景？**
  - **难点**：通用风险模型难以映射到千差万别的具体职业任务中，且人工枚举所有潜在风险场景成本极高且不全面。
  - **解决方法**：将多层框架嵌入结构化提示词中，应用于 O*NET 数据库中的 2,078 个工作任务描述，自动生成了 8,356 个按严重程度和部署模式（自动化或增强）标记的风险场景，并通过工人验证和 LLM 裁判确认了其合理性。
- **挑战2：如何准确区分不同部署模式（自动化 vs 增强）下的风险差异及用户偏好？**
  - **难点**：传统观点可能认为“增强”模式比“自动化”更安全，且缺乏针对职场 Agent 的易用性分类工具对比。
  - **解决方法**：通过实证分析发现增强模式并非固有安全（可能导致技能侵蚀），并让用户在实际分类任务中对比新分类法与其他两种分类法，结果显示用户认为新分类法更易用且在 64% 的非平局比较中更受青睐。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与数据**：利用 O*NET 职业数据库中的 2,078 个任务描述，结合结构化 Prompt 生成 8,356 个风险场景。邀请来自 10 种不同职业角色的 45 名工人进行验证，并使用独立的 LLM 作为裁判进行评估。
- **评估结果**：
  1. **风险分布**：“错误 Agent 行为”占据了最大比例的风险场景，且集中了最严重的风险，许多风险发生在人机边界。
  2. **部署模式差异**：自动化主要关联组织风险（如运营失败、财务损失），而增强主要关联对工人的风险（如能力侵蚀、心理和社会风险）。
  3. **技能侵蚀**：增强模式并非固有安全，过度依赖 Agent 会逐渐削弱工人的技能和监督能力。
- **对比相关工作**：在与另外两种风险分类法（包括最近的生成式 AI 风险分类法）的对比中，工人发现本文提出的分类法在风险分类任务中更易于使用，并在 64% 的非平局比较中优先选择该分类法。

#### 总结
本文指出职场 AI Agent 的风险不仅源于 Agent 本身，还取决于人与 Agent 的协作方式及部署模式。通过构建专门的多层框架和风险分类法，研究揭示了自动化与增强模式下的不同风险特征，强调了设计良好的人机协作机制对于构建更安全职场的重要性，为组织提供了更精准的风险识别和管理工具。
