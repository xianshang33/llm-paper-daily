## 文章做了什么
- **背景**：LLM Agent 服务在模型推理和工具调用之间执行大量小型确定性状态转换（如路由结果、更新状态）。现有研究表明，这种控制路径频繁跨越 CPU-GPU 边界，导致主机编排成为关键路径，并产生突发性 CPU 负载。
- **已有工作的局限**：现有的固定时间窗口批处理机制无法充分利用 GPU 的并发能力，因为相似性不足以构成有效的 GPU 任务；必须满足硬件阈值、可执行语义一致性以及严格的启动截止时间。此外，每一步都将决策返回主机再重新分发，带来了复制、同步和分支开销，现有工作未充分量化避免这些往返的潜力。

## 文章的核心贡献点
- **提出了一个“就绪队列”（Ready Cohorts）理论框架**：形式化了固定分区份额 (F)、精确离线份额 (P*)、局部上界 (U) 和在线实现份额 (A)，用于界定 GPU 执行的控制路径边界。
- **挑战1：如何量化因固定窗口边界而丢失的 GPU 调度机会？**
  - **难点**：在零服务时间、无限容量和相等相对启动截止时间的理想条件下，精确计算可打包的最大同组工作量是一个复杂的组合优化问题。
  - **解决方法**：论文设计了一种专用的动态规划算法来精确计算 P*。实验显示，在特定配置下（10万活跃会话，K=256，50ms 截止期），精确打包恢复了固定窗口边界损失的 81.83% 的机会，将有效份额从 30.19% 提升至 43.00%。
- **挑战2：如何消除控制决策中的主机往返开销？**
  - **难点**：传统的架构需要将 GPU 计算的少量数据（如4字节的路由决策）传回主机，由主机决定下一步操作并重新分发，这引入了显著的延迟。
  - **解决方法**：提出了一种机制，使 GPU 计算的二元决策保留在设备端（Device-resident），避免返回主机。实验表明，在四种 GPU 放置方案的所有 36 种配置中，设备端路径均更快，速度提升倍数在 1.19x 到 2.39x 之间，且所有测试用例均与主机预言机结果一致。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与评估设置**：
  - **轨迹回放实验**：使用一个包含 851 个会话的公开 Agent 轨迹面板，进行静态泊松回放。设定目标活跃会话数为 100,000，批次大小 K=256，启动截止时间为 50ms。
  - **机制研究实验**：在 CUDA 环境中保持状态转换和路由主体固定，改变观察 GPU 计算决策的位置。对比了四种不同的 GPU 放置策略以及一种作为负对照的早期设备启动设计。
- **主要结果**：
  - **机会边界**：固定分区份额 F=30.19%，精确离线份额 P*=43.00%，局部上界 U=45.85%。精确打包显著优于固定窗口方法。
  - **性能加速**：设备驻留路径在所有 36 种配置中均优于主机往返路径，行中位数加速比为 1.19x 至 2.39x。
  - **正确性验证**：在所有 14,557,440 次批量调用测试中，两种允许机制的结果均与单独实现的主机预言机完全匹配。
  - **负面对照**：一种不消除任何主机决策的固定嵌套设备图在所有 60 种配置中均表现更慢，证明了减少主机交互的必要性。
- **对比结论**：研究确立了 GPU Agent 控制的两个可测量门槛：截止期可行的队列供应和观察位置。相比固定窗口，动态精确打包能捕捉更多可调度工作；相比传统主机回调，设备端决策能显著降低延迟。

#### 总结
本文通过理论分析和实验验证，解决了 LLM Agent 控制路径中的 GPU 利用率低和主机往返开销大问题。首先，通过“就绪队列”框架量化了 GPU 并发执行的潜在机会，证明精确打包能大幅恢复因固定窗口损失的性能。其次，通过保持路由决策在 GPU 设备端，避免了不必要的主机通信，实现了 1.19x-2.39x 的加速。这项工作为构建高效的 LLM Agent 系统提供了具体的系统设计指导，强调了截止期管理和数据放置的重要性。
