## 文章做了什么
- **背景**：社交机器人（如 Misty）在辅助、教育和社交互动中日益普及，但让非专业用户通过自然语言控制机器人仍极具挑战。现有的机器人平台虽然提供了开放 API，但要求开发者手动将 API 组合成技能、配置参数、绑定传感器事件并管理运行时状态。
- **已有工作为什么解决不了**：现有接口缺乏对多样化、开放式用户指令的实时解释能力。它们无法同时有效处理“反应式物理交互”（如传感器触发动作）和“有状态的社交交互”（如依赖对话历史的复杂任务），导致非专家用户难以在运行时动态创建或修改交互模式，且随着技能库扩大，手动集成新技能的复杂度急剧增加。

## 文章的核心贡献点
- **提出了一个 MistyPilot**：一种基于多智能体 LLM 的框架，用于解释高级自然语言指令并在 Misty 社交机器人上编排相应技能。
- **挑战1：如何区分并处理反应式物理交互与有状态社交交互？**
  - **难点**：物理交互需要低延迟的传感器-技能绑定和直接调用，而社交交互需要维护对话上下文和任务状态，单一模型难以兼顾两者的不同需求。
  - **解决方法**：引入任务路由器（Task Router），将指令分发给两个专用智能体：物理交互智能体负责传感器触发控制和直接技能调用；社交交互智能体负责面向对话的任务状态管理和上下文相关的多模态响应生成。
- **挑战2：如何在保证响应质量的同时提高系统效率？**
  - **难点**：社交交互中频繁生成完整的多模态响应会导致高延迟和高计算成本，尤其是在处理重复或相似请求时。
  - **解决方法**：社交交互智能体采用了结果复用机制，在适用时重用之前生成的结果，仅在必要时才调用完整生成过程，从而显著提升了效率。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：MistyPilot 在物理 Misty 机器人上进行了部署和测试。评估包括五个组件级套件（涵盖路由、传感器-技能绑定、任务状态解析、结果复用和技能扩展），以及一项包含 12 名参与者的初步用户研究。
- **评估结果**：
  - **准确性**：在路由、传感器-技能绑定、任务状态解析、结果复用方面均取得高准确率。
  - **可扩展性**：支持高达 100 种技能的扩展。
  - **稳定性**：与结构相同的单智能体基线相比，MistyPilot 表现出更低的方差，说明多智能体架构更稳定。
  - **用户体验**：参与者对可用性和交互质量给予了积极评价。
- **对比**：相较于需要手动编码和预定义交互模式的传统方法，以及性能波动较大的单智能体 LLM 基线，MistyPilot 在自动化程度、稳定性和用户友好性上均有显著提升。

#### 总结
MistyPilot 通过多智能体 LLM 架构成功解决了社交机器人自然语言编程中的关键难题，实现了反应式物理行为与有状态社交行为的无缝协同。其特有的任务路由和结果复用机制不仅提高了指令执行的准确性和效率，还降低了非专家用户的使用门槛。实验证明，该框架在真实机器人部署中具有高准确性和良好的用户体验，为社交机器人的普及应用提供了新的技术路径。
