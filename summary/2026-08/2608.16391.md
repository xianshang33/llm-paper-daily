## 文章做了什么

**背景**
随着大语言模型（LLM）的普及，第三方提供商部署开源权重模型并通过 API 提供服务已成为生态系统的重要组成部分。然而，用户无法直接验证这些托管 API 是否真正运行了声称的模型版本、量化配置或解码策略，这导致了“验证缺口”。

**已有的工作为什么解决不了**
现有的审计方法通常依赖于目标 API 返回的对数概率（logprobs）信息，但许多商业或第三方 API 并不提供此数据，或者提供的数据不可信。此外，传统的黑盒测试难以区分由于随机性引起的输出差异与由于模型路由替换（如使用更便宜的模型或旧版本检查点）引起的系统性偏差，缺乏一种无需内部概率信息即可量化行为偏差的有效手段。

## 文章的核心贡献点

**提出了一个 Ventor-QTest**
这是一种复合黑盒审计框架，将托管模型路由形式化为随机过程，无需目标 API 提供概率信息即可验证其行为一致性。

**挑战1：如何在没有 logprobs 的情况下量化分布偏差？**
*   **难点**：传统 KL 散度计算需要完整的概率分布，而黑盒 API 仅返回文本，且存在采样随机性，难以准确重构分布。
*   **解决方法**：提出“重复请求组件”，向目标发送多次冻结的约束上下文，从返回的文本计数中重构分类输出分布，并报告“平均保真度损失”（AFL），这是一种经过零偏差校正的窗口内均值粗粒度 KL 统计量。

**挑战2：如何检测长序列任务中的极端异常行为？**
*   **难点**：长程代理任务对极端的保真度损失敏感，但平均指标可能掩盖尾部风险，且长序列生成的参考基准难以确定。
*   **解决方法**：提出“长序列组件”，通过独立运行报告“极端保真度损失”（EFL），利用运行级参考中心惊喜度（surprisal）统计量的经验上尾来捕捉极端偏差，从而揭示特定路由下的性能下降。

## 实现与部署，evaluation 结果，要有和相关工作对比

**实现与部署**
Ventor-QTest 已开源，作为腾讯 AI Infra Guard 的一部分提供。该工具完全基于黑盒查询，不依赖模型内部状态。

**Evaluation 结果**
1.  **AFL 有效性验证**：在三种支持 logprob 的路由条件下，AFL 与基于 logprob 衍生的粗粒度 KL 比较器显示出强烈的线性描述一致性，证明了其在无 logprob 场景下的代理有效性。
2.  **EFL 变异性检测**：在七个路由快照中，20 次运行的序列探针揭示了特定于路由的 EFL 变化，表明不同部署配置下极端偏差存在显著差异。
3.  **与下游任务性能的相关性**：
    *   AFL 和 EFL 与 GPQA-Diamond 准确率几乎没有检测到路由级别的关联。
    *   相比之下，随着任务暴露度的增加，显著的 EFL 与 Terminal-Bench 通过率的下降相吻合。这表明长程任务的正确性对极端保真度损失更为敏感。

**对比**
与传统仅关注平均准确率或使用 logprob 的方法相比，Ventor-QTest 能够联合报告 AFL 和 EFL，特别适用于审计长程代理任务，揭示了平均指标无法捕捉的尾部风险对复杂任务的影响。

#### 总结

本文针对第三方托管 LLM API 的验证难题，提出了 Ventor-QTest 黑盒审计框架。通过引入平均保真度损失（AFL）和极端保真度损失（EFL）两个指标，该方法在不依赖目标 API 概率信息的情况下，有效量化了部署行为与可信参考之间的偏差。实验表明，EFL 与长程代理任务的性能下降密切相关，强调了在审计复杂应用场景时联合监控平均偏差和极端偏差的重要性。
