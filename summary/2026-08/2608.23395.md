## 文章做了什么
- **背景**：当前的 LLM Agent 系统在设计上存在分歧：是将工作分解给多个窄领域 Agent，还是使用一个强大的工具型单 Agent。Anthropic 等机构推崇多 Agent 协作，而 Cognition 等则认为多 Agent 设计脆弱且分散上下文。
- **已有工作的不足**：现有的对比研究往往同时改变编排框架、基础模型、提示词预算、工具面和任务类型，导致无法单独控制并评估“Agent 作用域粒度”这一变量对性能的具体影响。

## 文章的核心贡献点
- **提出了一个**：针对增值税（VAT）判定任务的预注册受控试点研究框架，用于探索 Agent 分解的“合适规模”（Right-Sizing），并发布了包含 Oracle、数据集、测试 harness、原始轨迹和分析管道的完整资源。
- **挑战1：如何隔离 Agent 数量与提示词预算的影响？**
  - **难点**：多 Agent 系统通常消耗更多 Token，难以区分性能提升是源于分工协作还是单纯的计算/提示词预算增加。
  - **解决**：通过设置“匹配 Token”的实验臂，在保持总 Token 预算一致的情况下对比单 Agent 与多 Agent 配置，从而分离出纯架构效应。
- **挑战2：如何在复杂依赖关系中确定最佳分解粒度？**
  - **难点**：任务包含并行查找和串行依赖（如反向充电逻辑），过度分解可能导致上下文丢失，不分解决策又可能超出单 Agent 能力。
  - **解决**：固定活动表面（子任务、工具、I/O 模式等），仅变化子任务分配给 Worker 的方式（从 1 个宽范围 Worker 到 5 个窄范围 Worker），并提出启发式建议：在依赖层的中点放置一个分区边界。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实验设置**：基于跨境增值税（含反向充电）判定任务，拥有确定性规则引擎作为 Oracle。共进行 4,400 次运行，包括 40 个案例的主扫描、匹配 Token 臂和故障注入臂。
- **主要结果**：
  - **准确率**：两种中间配置（中等粒度分解）准确率最高（0.830），优于极端配置（单 Agent 0.720，五 Agent 0.770）。但未达到预先设定的显著优于细粒度端点的标准，因此“中间最优”假设在试点规模下未获完全支持，仅为方向性结果。
  - **Pareto 优势**：单 Agent 并未在 Pareto 意义上主导编排集合。
  - **预算影响**：在匹配 Token 条件下，单 Agent 比领先配置低 6.5 个百分点，但置信区间包含零，表明任何优势都可能由提示词预算解释。
- **鲁棒性对比**：
  - **可用性故障**：所有粒度均能吸收超时和工具中断故障，宽范围重启甚至超额恢复基线 (+0.160)。
  - **幻觉注入**：单个符合模式的幻觉记录会 degrade 所有配置并逆转排序，对碎片化（多 Agent）配置打击最大。

#### 总结
本文通过严格控制变量的试点研究，揭示了 LLM Agent 分解粒度对性能的非单调影响。虽然中间粒度的分解在准确率上表现最佳，但其优势受限于提示词预算的解释空间。研究指出，简单的多 Agent 分解并不总是优于单 Agent，且在面对结构化幻觉时更为脆弱。最终贡献在于提供了一套可复现的基准测试方法和“在依赖层中点进行分区”的启发式策略，为未来 Agent 系统设计提供了实证依据。
