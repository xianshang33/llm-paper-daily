## 文章做了什么
- **背景**：多智能体大语言模型（LLM）工作流通过协调专用代理进行协作推理，已成为解决复杂开放式任务的强大范式。然而，由于需要多次调用 LLM 并维护长程上下文，导致令牌消耗、计算资源、能源需求和延迟极高，运营成本昂贵。
- **已有工作的局限性**：现有的级联路由方法通常做出一次性、查询级别的决策，将简单查询分配给轻量级模型，复杂查询分配给强力模型。这种方法无法适应多步工作流的动态性和状态依赖性，即每一步的最佳 LLM 选择取决于不断演变的任务进度、剩余任务难度和成本效率要求，因此难以在长期运行中平衡质量与成本。

## 文章的核心贡献点
- **提出了一个 ProgRouter**：一种在线进度引导的路由框架，能够在工作流步骤中自适应地选择 LLM 代理，以在遵守时间和成本预算的同时保持任务解决质量。
- **挑战1：如何准确量化动态变化中的任务进度？**
  - **难点**：多智能体工作流是开放且有状态的，传统的静态基准或离线偏好数据无法反映在线上下文中的实时状态，难以评估当前步骤对最终结果的贡献。
  - **解决方案**：引入了多视图任务进度评分器（Multi-view Task Progress Scorer），结合粗粒度的工作流结果机制与细粒度的子任务完成度、进度趋势和工作流状态质量信号，全面评估当前进展。
- **挑战2：如何在保证进度的同时优化长期成本效益？**
  - **难点**：需要在每一步权衡即时进度增益、剩余时间预算和长期运营成本，简单的贪婪策略可能导致后期资源不足或前期浪费。
  - **解决方案**：设计了双路径任务进度预测器和自适应元门控机制，估计每个候选 LLM 的进度增益，并据此做出在线逐步路由决策，平衡进度增益与成本效率。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实验设置**：在 HumanEval Plus、MBPP（代码生成）、MATH-500（数学推理）和 ASQA（检索增强长形式问答）等多个基准上进行评估。
- **对比基线**：与关键的现有基线方法（如静态路由、一次性级联路由等）进行对比。
- **结果**：实验表明，ProgRouter 在保持强劲的任务解决性能（与最强基线相当或更优）的同时，显著降低了相对于关键基线的运营成本。它证明了在复杂的代理工作流中，通过细粒度的进度感知路由可以实现更好的质量-成本权衡。

#### 总结
本文针对多智能体 LLM 工作流高昂的运营成本问题，提出了 ProgRouter 框架。通过引入多视图任务进度评分器和自适应路由机制，ProgRouter 能够根据实时任务状态动态选择最合适的 LLM 代理。该方法有效解决了传统一次性路由无法适应动态工作流的缺陷，在多个复杂任务基准上实现了成本大幅降低且性能不降反升的效果，为可持续的 LLM 服务提供了新的思路。
