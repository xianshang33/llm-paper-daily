## 文章做了什么
- **背景**：随着检索、工具调用和多轮交互的积累，Agent LLM 的上下文长度不断增加，导致推理成本急剧上升。为了控制延迟，部署中通常会对输入进行压缩，但这会牺牲任务准确性。
- **已有工作为什么解决不了**：现有的投机解码（Speculative Decoding, SD）虽然能无损加速生成，但假设草稿模型（Drafter）和验证模型（Verifier）共享完全相同的上下文。这意味着如果验证模型使用压缩上下文以节省成本，SD 无法恢复被压缩丢弃的信息；如果两者都使用完整上下文，则无法降低计算开销。SD 无法打破这种对称性来解决准确性与开销之间的权衡。

## 文章的核心贡献点
- **提出了一个 AsymSpec**：一种上下文非对称的投机解码框架，打破了草稿模型和验证模型必须共享相同上下文的限制。
- **挑战1：如何在验证模型仅见压缩上下文的情况下，利用完整上下文信息来指导生成？**
  - **难点**：传统 SD 要求输入一致，直接融合不同上下文的 logits 会导致分布不匹配和不稳定。
  - **解决方法**：让轻量级草稿模型读取完整输入，而大型验证模型仅操作压缩视图。草稿模型通过对比完整上下文和压缩上下文的输出，计算出对比性 $\\delta$-fusion logits，从而隔离出未压缩输入提供的信息增益，并将其融合到验证模型的 logits 中。
- **挑战2：如何保证在引入额外信息增益时的验证稳定性和高接受率？**
  - **难点**：直接注入差异信号可能导致验证模型偏离其原始分布，降低草稿令牌被接受的概率，从而抵消加速效果。
  - **解决方法**：引入一个感知发散度的接受门控机制（divergence-aware acceptance gate），动态调制融合后的 logits，确保在保留关键推理信号的同时，维持验证过程的稳定性和较高的草稿接受率。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **评估设置**：在四种 Agent 能力和两个端到端 Agent 基准测试上进行评估。
- **主要结果**：
  - **准确性**：AsymSpec 平均达到了完整上下文准确率的约 90%。
  - **效率提升**：在隔离文本能力上，实现了 1.3–1.7 倍的吞吐量加速，计算成本仅为原来的 0.2–0.3 倍。
- **对比优势**：相比传统 SD 只能加速固定目标分布（要么全慢且准，要么快但不准），AsymSpec 在压缩丢弃关键推理信号的场景下，通过非对称上下文访问获得了显著的性能增益，有效缓解了准确性与开销的权衡困境。

#### 总结
AsymSpec 通过解耦草稿模型和验证模型的上下文访问权限，创新性地解决了 Agent LLM 中上下文累积带来的推理瓶颈。它允许轻量级草稿模型利用完整上下文来弥补验证模型因压缩而丢失的信息，并通过对比 logits 融合和发散感知门控机制确保生成的稳定性和效率。实验表明，该方法在大幅降低计算成本的同时，保留了绝大部分的任务准确性，为高效部署长上下文 Agent 提供了新的思路。
