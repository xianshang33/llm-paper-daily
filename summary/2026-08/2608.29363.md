## 文章做了什么
- **背景**：企业级数据代理（Data Agents）通过多步推理串联大量工具调用来回答业务查询，导致会话上下文迅速累积至数十万 token。这不仅超出模型窗口限制，还导致成本高昂和注意力分散。
- **已有工作为什么解决不了**：现有的上下文压缩策略（如 token 级剪枝、摘要或步骤丢弃）通常采用统一策略，未考虑移除特定工具输出对下游任务的后果。激进压缩虽减少了当前 token 数，但可能因关键信息丢失导致代理重新调用工具（Re-invocation），产生的额外 token 消耗抵消了压缩收益。这种现象被称为“压缩-后果差距”（Compression-Consequence Gap）。

## 文章的核心贡献点
- **提出了一个 TRACER 框架**：一种基于后果归因强化学习的每工具上下文保留机制，将压缩建模为序列化的每工具决策问题。
- **挑战1：如何量化压缩的 downstream 后果？**
  - **难点**：传统方法孤立评估压缩效果，忽略了被删减信息在后续步骤中是否会被再次需要，导致无法准确评估净收益。
  - **解决方法**：TRACER 引入后果感知目标函数，联合考量任务成功率、总 token 消耗及压缩后的工具重调用次数；并通过学习到的结果模型（Outcome Model）对比选定保留比例与完全保留的后果，以改进信用分配。
- **挑战2：如何在异构工具输出中动态分配保留预算？**
  - **难点**：不同工具输出对后续推理的重要性差异巨大（如 Schema 查找 vs 权限检查），静态或均匀策略无法适配这种查询条件依赖性。
  - **解决方法**：使用轻量级 REINFORCE 策略，仅利用每次压缩事件时的可用信息，为每个工具输出分配查询条件的连续保留比例，使 token 预算流向那些移除后会触发昂贵恢复操作的关键输出。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实验设置**：在三个压缩器后端上的保留生产查询数据进行测试，并在五个 LOCA-bench 环境中进行泛化测试。
- **主要结果**：
  - 相比保留所有上下文，TRACER 将总 token 消耗降低了 29–46%，同时保持相当或更高的任务成功率。
  - 相比基于工具类型的静态策略，TRACER 额外提供了 15–18% 的 token 节省。
  - 在五个 LOCA-bench 环境中，token 消耗减少了 18–25%。
- **对比分析**：干预性 rollout 显示，学习到的每工具信用评分与测量的单工具后果高度相关。该策略在不同代理骨干网和压缩器架构间迁移时仍能产生正向节省，证明了其鲁棒性和通用性，优于现有的孤立压缩方法。

#### 总结
TRACER 有效解决了长 horizon 语言代理中的“压缩-后果差距”问题。通过引入后果感知的强化学习框架，它实现了细粒度的、每工具级别的动态上下文保留。实验表明，该方法在显著降低 token 成本的同时，避免了因信息丢失导致的昂贵工具重调用，提升了企业级数据代理的整体效率和实用性。
