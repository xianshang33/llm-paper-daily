## 文章做了什么
- **背景**：现代 AI Agent 框架（Harnesses）暴露了生命周期钩子（Lifecycle Hooks），将 Shell 命令绑定到运行时事件（如会话开始、工具调用、文件编辑）。这些命令以主机权限运行，但作为配置分发，且可能在 LLM 无法观察到的时刻触发。
- **已有工作为什么解决不了**：现有研究主要关注恶意插件代码、工具描述投毒或技能操纵，但未将框架管理的生命周期钩子作为独立的攻击目标。由于钩子执行发生在 LLM 推理循环之外，形成了防御盲区，传统的提示词对抗或模型对齐防御无法检测此类执行。

## 文章的核心贡献点
- **提出了一个 HookPry**：一个开源且完全自动化的攻击框架，用于系统地利用异构 AI Agent 框架中的生命周期钩子更新路径漏洞。
- **挑战1：隐蔽的命令绑定与执行脱离 LLM 监控**。难点在于钩子配置被视为元数据而非代码，且执行过程不经过 LLM 决策路径，导致传统基于内容审查的防御失效。HookPry 通过控制插件元数据和钩子配置，在 benign 插件更新中静默绑定攻击者选择的命令，利用事件驱动机制在主机侧触发恶意行为。
- **挑战2：跨框架的通用性与供应链威胁模型的实现**。难点在于不同 Agent 框架架构差异大，需验证该攻击面的普遍性。HookPry 利用了生命周期钩子的双层插件架构特征（市场元数据控制发现，钩子控制运行），实现了跨 7 种主流框架的攻击，证明了仅控制元数据和配置即可实现特洛伊木马化。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：HookPry 实现了 10 种攻击目标。在 25 种框架与后端组合的 1000 次端到端运行中进行了评估。
- **评估结果**：HookPry 成功攻破了所有 7 个被评估的 Harness，单个 Harness 的成功率高达 92.5%。
- **相关工作对比**：现有防御措施严重不足。Microsoft Defender 的召回率为 0%；三种静态防御方法的联合使用仍漏掉了 47.5% 的恶意工件。这表明当前的静态分析和终端防护无法有效识别这种基于配置更新的供应链攻击。

#### 总结
本文揭示了 AI Agent 框架中生命周期钩子更新路径这一新的攻击面。攻击者仅需控制插件元数据和钩子配置，即可通过供应链将良性插件特洛伊木马化，导致权限提升等恶意主机行为。提出的 HookPry 框架证明了该漏洞在多种主流框架中的普遍存在性和高成功率，且现有防御手段几乎无效，亟需针对生命周期钩子的专门安全机制。
