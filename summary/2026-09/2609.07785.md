## 文章做了什么
- **背景**：LLM Agent 排行榜通常被用户直接解读为排名靠前的 Agent 性能更优。然而，Agent 系统不仅包含基础模型，还涉及脚手架（提示词、工具、控制逻辑）、标签来源（测试、专家标注、LLM 裁判）以及资源预算等复杂配置。
- **已有工作为什么解决不了**：现有的公共评估日志和排行榜分数往往忽略了这些配置差异。当系统在任务混合、标签来源、发布细节或成本规则上存在差异时，简单的排名比较无法支持“ pairwise superiority”（成对优越性）的结论。例如，不同标签来源（专家 vs LLM 裁判）可能导致完全不同的排名结果，且现有方法缺乏对统计不确定性和估计量（estimand）的明确界定，导致许多看似显著的排名差异在统计上并不稳健。

## 文章的核心贡献点
- **提出了一个估计量感知的成对决策程序（estimand-aware pairwise procedure）**：该程序旨在明确排行榜分数所估计的具体目标，并判断在何种条件下可以得出一个 Agent 优于另一个 Agent 的结论。
- **挑战1：排行榜分数背后的估计量（Estimand）不明确，导致比较基准不一致。**
  - **难点**：不同的评估设计（如任务权重、标签来源、通过规则 pass@k）对应不同的估计量，直接比较原始分数会混淆这些差异。
  - **解决方法**：该程序强制声明比较目标和测量来源，检查共同支持（common support），并使用明确的 uncertainty rule（不确定性规则）和实际边际来评估受支持的差异，从而确保比较是在同一估计量下进行的。
- **挑战2：有限样本下的统计不确定性常被忽略，导致虚假的优越性结论。**
  - **难点**：在有限样本条件下，微小的分数差异可能源于随机噪声而非真实性能差距，且对目标重加权敏感。
  - **解决方法**：通过受控检查评估决策标签，引入置信区间和最大偏差同时区间（simultaneous interval），仅在证据充分时报告统计上支持的胜者，否则指出限制条件（如支持不足或标签分歧）。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与评估数据集**：研究在 SWE-bench、AgentRewardBench 和 tau2-bench 上进行了实证分析，并利用 DataAgentBench 和 Open Agent 展示了从较粗糙的公共记录中可估计的内容。
- **主要结果**：
  - 在 SWE-bench Verified 的前10名形成的45个配对比较中，描述性点对点95%区间和2点决策规则仅确定了5个稳定胜者，1个对目标敏感，39个功效不足（underpowered）；最大偏差同时区间未能解决任何配对。
  - 在 AgentRewardBench 上，专家标签选择 Claude 3.7 Sonnet 为最佳，而 GPT-4o-mini 裁判则选择 GPT-4o，显示标签来源对排名的决定性影响。
  - 在 tau2-bench 上，pass@4 相比 pass@1 将分数提高了17.7至20.4分，且成本效用规则会改变最终选择的系统。
- **对比结论**：与传统直接读取排行榜排名的做法相比，该方法揭示了大多数紧密的排名差异在统计上是“未决”的（unresolved）。它证明了代理标签（proxy labels）和效用规则（utility rules）的选择会根本性地改变系统选择结果，强调了必须结合估计量和不确定性规则来解释分数差异。

#### 总结
本文指出 LLM Agent 排行榜分数仅是对已发布评估的总结，而不能直接等同于通用的 Agent 优劣排序。作者提出的估计量感知成对决策程序强调，要得出细粒度的优越性主张，必须明确比较的估计量、测量来源以及不确定性规则。研究表明，在当前的公共基准中，许多排名接近的系统之间并无统计学上的显著差异，盲目依赖排行榜排名可能导致错误的模型选择决策。
