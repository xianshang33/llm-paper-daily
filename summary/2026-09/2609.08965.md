## 文章做了什么
- **背景**：自动驾驶系统（ADS）的安全性验证至关重要，基于场景的测试是验证 ADS 的系统化流程。然而，当前的测试流程高度碎片化，场景生成、检索、修改、ADS 执行和结果分析由独立的工具完成，缺乏交互且依赖大量人工脚本。
- **已有工作的局限**：现有的大型语言模型（LLM）应用主要局限于 ADS 的子模块（如感知、规划）或仅专注于场景生成阶段。没有任何 prior work 能够使用统一的 LLM Agent 框架覆盖从场景生成到 ADS 评估的完整测试流水线，导致流程僵化、难以根据用户意图灵活调整且效率低下。

## 文章的核心贡献点
- **提出了一个 PlannerForge**：这是一个基于 LLM Agent 的框架，扩展了基于场景的测试的所有阶段（从场景生成到 ADS 评估），并新增了两个 LLM 增强阶段：ADS 增强和 ADS 基准测试。
- **挑战1：全流程自动化与模块间协同难**。传统的测试管线各阶段孤立，难以实现端到端的意图传递。**解决方法**：PlannerForge 通过 chaining modules end-to-end，利用 LLM Agent 统一协调生成、选择、修改、路由、测试和增强环节，在商业和开源模型上分别保留了 83% 和 78% 的初始查询意图，实现了全链路的自动化闭环。
- **挑战2：场景生成的物理有效性与属性遵循难**。现有方法生成的场景往往缺乏物理合理性或无法准确遵循复杂的自然语言指令。**解决方法**：该方法在自然语言生成可执行率上超越 Scenario Factory 2.0（200 个中 193 个可执行 vs 144 个），并在物理有效编辑方面显著优于 From-Words-to-Collisions（>=94% vs 31%），同时实现了 92-96% 的城市、道路和车辆属性遵循率。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实验设置**：使用 10 种现成的 LLM（包括商业 API 和开源模型如 Qwen3.6:35B），在 5 种提示条件下对所有任务进行评估。
- **主要结果**：
    - **性能表现**：最佳单任务得分在 0.88 到 1.00 之间。开源的 20-35B 后端模型在大多数任务上与商业 API 表现相当，其中 Qwen3.6:35B 在五项任务中的三项上匹配商业 API。
    - **对比优势**：
        - **生成**：优于 Scenario Factory 2.0，可执行场景数量更多（193 vs 144）。
        - **选择**：在 Rank 1 选择上优于 BM25（92.0% vs 67.5%）。
        - **修改**：在物理有效编辑上优于 From-Words-to-Collisions（>=94% vs 31%）。
    - **ADS 增强效果**：在 N=400 的测试中，通过成本调优（cost-tuning），无需领域特定微调即可将规划器成功率从 50.4% 提升至 70.2%，并将碰撞率从 19.0% 降低至 8.4%。

#### 总结
PlannerForge 填补了自动驾驶基于场景测试中缺乏统一 LLM Agent 框架的空白。它成功地将碎片化的测试流程整合为一个自动化的端到端系统，不仅在场景生成、检索和修改的关键指标上超越了现有的 SOTA 方法（如 Scenario Factory 2.0 和 BM25），还证明了开源中等规模模型（20-35B）在该任务上具有媲美商业模型的潜力。此外，该框架展示了通过 LLM 进行无需微调的规划器参数优化能力，显著提升了自动驾驶系统的安全性和测试效率。
