## 文章做了什么
- **背景**：现代手术室集成了大量精密医疗设备（如手术灯、内窥镜、电刀等）。传统控制方式依赖物理按钮、触摸屏或脚踏开关，存在破坏无菌环境、交叉感染风险高、医护人员认知负荷大以及多设备协同困难等问题。
- **已有工作为什么解决不了**：现有的语音助手或通用大模型方案难以满足手术室对低延迟、高可靠性及严格无菌交互的实时要求。通用模型缺乏针对特定手术阶段和设备状态的上下文优化，且推理延迟较高，无法实现流畅的多设备并行控制和自然的人机协作。

## 文章的核心贡献点
- **提出了一个名为 SurgicalRoomAgent 的基于大语言模型的语音交互式多智能体系统**，包含语音交互流水线（唤醒、ASR、轮次检测、代理推理、TTS）和代理核心（技能注册、任务规划、设备管理）。
- **挑战1：大模型推理延迟高，无法满足手术室实时控制需求。**
  - **难点**：设备状态频繁变化导致 KV Cache 失效，重新计算开销大（约 500ms），影响响应速度。
  - **解决方法**：提出 KV Cache 前缀预热技术，通过字节级最长公共前缀（LCP）复用，将重计算开销从约 500ms 降低至几十毫秒。
- **挑战2：端到端交互延迟长，且上下文窗口有限导致信息密度低。**
  - **难点**：传统串行处理等待完整输出再执行任务效率低；全量系统提示词占用大量 Context Window，限制有效信息输入。
  - **解决方法**：采用流式部分 JSON 解析与早期并行任务执行，在检测到完整任务数组时立即启动并行执行，降低端到端延迟约 30%；同时引入渐进式技能提示披露机制，根据用户角色、连接设备和手术阶段动态过滤提示词，最大化上下文窗口的信息密度。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：系统基于 Qwen3-27B 模型构建，使用 llama.cpp/sglang 作为推理引擎，支持流式输出和实时设备控制。架构分为语音交互层和代理核心层。
- **评估结果**：实验表明，系统在 16,384 token 的上下文限制下能有效运行。KV Cache 预热显著降低了推理延迟，流式解析使端到端延迟降低约 30%。多设备并行控制的响应时间满足手术室的实时性要求。
- **对比**：相较于传统物理控制和未优化的通用 LLM 方案，该系统在保持无菌环境、降低认知负荷和提升多设备协同效率方面具有显著优势，特别是在低延迟推理和上下文高效利用方面解决了现有技术的瓶颈。

#### 总结
本文提出的 SurgicalRoomAgent 通过创新的架构设计和三项关键技术（KV Cache 前缀预热、流式部分 JSON 解析与并行执行、渐进式技能提示披露），成功构建了一个低延迟、高效率的手术室语音交互多智能体系统。该系统有效解决了传统手术室控制中的无菌破坏、交叉感染和认知过载问题，为智能手术室的落地应用提供了可行的技术方案。
