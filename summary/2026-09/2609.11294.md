## 文章做了什么
- **背景**：现代 AI Agent 在执行任务（如代码修复、数据分析）时，通常采用高扇出（High-Fanout）模式，即单个任务会衍生出多个并发的沙箱会话（例如 RL 训练中的多条轨迹或推理时的并行候选）。由于每个沙箱都需要隔离环境，导致内存成为主要的资源瓶颈。
- **已有工作为什么解决不了**：传统的内存压缩技术在此场景下表现不佳，主要存在三个维度的不匹配：
    1. **如何压缩**：传统方法未能利用非相同沙箱页面之间的相似性（模板相对和跨沙箱冗余）。
    2. **压缩什么**：为了控制页面错误开销，传统方法采用保守的页面选择策略，限制了压缩范围。
    3. **何时压缩**：传统压缩通常由内存压力触发，且未感知 Agent 的执行阶段，容易干扰前台工具的执行。

## 文章的核心贡献点
- **提出了一个 AgentZip**：这是首个专为 AI Agent 沙箱设计的内存压缩系统。
- **挑战1：如何高效利用沙箱间的高度冗余进行压缩？**
    - **难点**：沙箱虽源自同一模板且执行相关轨迹，但页面并非完全相同，传统通用压缩算法难以捕捉这种细粒度的模板相对和跨沙箱相似性。
    - **解决方法**：AgentZip 引入了专门利用模板相对和跨沙箱冗余的压缩机制，将压缩范围扩大到任何具有有利表示的页面，从而显著提高了压缩率。
- **挑战2：如何在大幅压缩的同时避免性能下降？**
    - **难点**：激进的压缩会导致解压时的页面错误开销巨大，造成严重的性能 slowdown；同时若在 Agent 忙碌时压缩会干扰前台执行。
    - **解决方法**：AgentZip 将开销控制从“压缩时的页面选择”转移到“恢复时的预取（Restore-time Prefetching）”，并将昂贵的压缩操作与 LLM 的等待周期对齐，从而在不牺牲太多内存节省收益的情况下，将性能损耗降至最低。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实验设置**：在 LLM 训练和推理工作负载上进行评估。
- **内存节省效果**：AgentZip 将沙箱占用的内存减少了高达 **8.7倍**，相比之下，标准 Linux 配置仅能减少 **2.1倍**。
- **性能开销对比**：通过恢复预取和感知 Agent 执行的调度，AgentZip 将激进压缩带来的性能减速从高达 **3.1倍** 降低至 **1.40倍**，同时保留了几乎所有的内存节省优势。

#### 总结
AgentZip 针对高扇出 Agent 工作负载的特性，重新设计了内存压缩的策略。通过利用沙箱间的结构相似性、优化压缩时机以匹配 LLM 等待期、以及采用恢复时预取技术，AgentZip 在显著降低内存占用（最高 8.7 倍）的同时，有效控制了性能开销，为大规模 Agent 部署提供了高效的系统支持。
