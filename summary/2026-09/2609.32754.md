## 文章做了什么

### 背景
大型语言模型（LLM）代理在短任务上能做出合理的局部决策，但在需要长序列依赖动作和工具调用的长视野任务中，性能显著下降。在执行过程中，任务需求、历史证据和当前执行状态逐渐脱节，导致后续决策偏离原始目标。

### 已有的工作为什么解决不了
现有的记忆架构（如检索增强、生成式代理记忆）虽然扩展了对早期上下文的访问，但往往难以在有限的上下文窗口内有效组织和呈现与当前决策最相关的历史信息。即使信息在上下文窗口内，LLM 也难以从杂乱的历史轨迹中提取关键关联，导致“迷失在中间”或上下文漂移问题，且现有方法多侧重于替换规划器或工具执行器，而非优化上下文构建本身。

## 文章的核心贡献点

### 提出了一个自适应一致性图（Adaptive Consistency Graph, ACG）
ACG 是一种用于长视野执行的框架，它不替换基础代理的规划器或工具执行器，而是通过增量组织执行证据及其来源，为每个决策提供结构化且可追溯的上下文视图。

### 挑战1：长序列执行中的上下文漂移与信息脱节
**描述与难点**：随着执行步骤增加，历史证据、当前状态与初始任务需求之间的关联逐渐减弱，导致代理遗忘核心目标或误用历史信息。难点在于如何在有限的上下文预算下，动态地从海量历史轨迹中筛选出与当前决策最相关的信息。
**解决方法**：ACG 将执行证据及其来源增量地组织在一个持久化图中，并在每次决策时构建一个临时的、以需求为中心的视图。这种方法确保了上下文始终围绕当前子任务和原始需求进行结构化重组，从而保持决策的一致性。

### 挑战2：在不改变底层代理架构的前提下提升长视野能力
**描述与难点**：许多现有方法需要修改代理的核心规划逻辑或训练专门的记忆模块，部署成本高且兼容性差。难点在于如何设计一个即插即用的中间层，既能增强上下文质量，又能兼容各种现有的 ReAct 或其他代理框架。
**解决方法**：ACG 作为独立的上下文管理层，仅负责构建和提供结构化的上下文视图，不干预基础代理的推理或执行逻辑。这种解耦设计使得 ACG 可以无缝集成到现有的 LLM 代理系统中，无需重新训练或大幅修改代码。

## 实现与部署，evaluation 结果，要有和相关工作对比

### 实现与部署
ACG 通过维护一个持久化图来存储执行过程中的证据和来源关系。在每一步决策前，系统根据当前需求和上下文预算，从图中提取相关节点构建临时视图，并将其注入到 LLM 的提示词中。代码已开源。

### Evaluation 结果
在匹配评估中，ACG 显著提升了 GPT-5.6-luna 的性能：
- **平均成功率**：从使用 ReAct 基线的 44.5% 提升至 50.2%。
- **最大增益**：在 BrowseComp-Plus 基准测试中，成功率从 62.4% 提升至 73.5%。

### 对比分析
文章进一步分析了轨迹结构和推理成本，表明 ACG 在保持合理推理开销的同时，通过更精准的上下文检索减少了无效尝试。相比于传统的检索增强生成（RAG）或全量上下文输入，ACG 提供的结构化视图更能帮助代理理解长期依赖关系。

#### 总结

本文针对 LLM 代理在长视野任务中的上下文漂移问题，提出了自适应一致性图（ACG）。ACG 通过构建持久化证据图和动态生成以需求为中心的上下文视图，有效解决了历史信息与当前决策脱节的难题。实验表明，ACG 能在不修改底层代理架构的情况下，显著提升复杂任务的成功率，特别是在需要长序列依赖的场景中表现优异。该方法为提升 LLM 代理的长期一致性和可追溯性提供了新的思路。
