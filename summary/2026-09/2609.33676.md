## 文章做了什么
- **背景**：大型语言模型（LLM）代理在网页导航、客户服务等领域日益普及，并执行具有后果性的操作。为了确保可靠性，不仅需要在失败时进行归因，还需要在成功执行时审计具体动作的历史依据（如策略合规性、参数来源等）。
- **已有工作的不足**：现有的归因方法无法针对多样化的审计目标提供特定于问题的追踪轨迹。此外，在仅能通过 API 访问模型且生成长轨迹的场景下，现有方法通常依赖昂贵的输入扰动或外部 LLM 对完整轨迹的分析，效率低下且成本高昂。

## 文章的核心贡献点
- **提出了一个查询条件化的代理动作归因（Query-Conditioned Agent Action Attribution）新任务及基准 $A^3Bench$**：该任务接收自然语言审计查询作为输入，恢复动作中特定方面的来源及有序的中间证据。$A^3Bench$ 包含 1,396 个涵盖策略基础、参数来源、故障传播和不安全行为追踪的审计查询。
- **挑战1：如何实现高效且针对特定查询的归因？**
  - **难点**：传统方法难以根据细粒度的审计查询动态调整归因重点，且计算成本高。
  - **解决方案**：使用小型开源模型作为“归因提议者”（Attribution Proposer），结合查询条件的梯度显著性（gradient saliency）与查询语义相关性对历史单元进行排序，仅需两次前向传播和一次反向传播即可实现高效排序。
- **挑战2：如何在有限的模型访问权限（如 API-only）下实现高精度归因？**
  - **难点**：无法直接获取内部状态，且调用前沿大模型 API 延迟高、成本高。
  - **解决方案**：基于提议者集成构建端到端系统，通过适应审计查询的细粒度变化提高归因特异性，在保持低推理成本的同时超越最强前沿模型基线。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现细节**：采用小型开源权重模型作为核心组件，利用梯度信息和语义相似度对交互历史中的单元进行排名。
- **性能对比**：
  - **与开源基线相比**：提议者在源排序（Source MRR）上提升高达 40.9%，证据排序（Evidence MAP）提升高达 42.1%，且计算开销极低（仅 2 次前向 + 1 次反向传播）。
  - **与前沿模型基线相比**：端到端系统在源准确率上达到 64.5%，优于最强前沿模型基线的 60.4%。
  - **延迟优势**：相较于最快的前沿 API 基线，实证部署延迟降低了 29.9%。
- **有效性验证**：控制实验证实，该方法能根据审计查询的细微变化自适应调整排名，提高了归因的特异性。

#### 总结
本文针对 LLM 代理审计中缺乏针对性追踪和低效的问题，提出了查询条件化的动作归因任务。通过引入 $A^3Bench$ 基准和基于小型模型的归因提议者机制，该方法在无需访问模型内部权重或依赖昂贵 API 调用的情况下，实现了比现有最先进方法更高精度和更低延迟的动作归因，为代理系统的透明度和安全性审计提供了高效解决方案。
