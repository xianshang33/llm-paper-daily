## 文章做了什么
- **背景**：当前的 LLM-as-a-Judge 评估主要针对固定任务定义下的固定输出进行评分。然而，生产环境中的多轮业务 Agent 需要的是一个持续维护的测量系统，因为其正确性依赖于特定业务的事实和流程，结果在多轮交互中涌现，且必须将失败归因于 Agent 能力不足还是业务知识缺失，以便采取实际行动。
- **已有工作的局限性**：现有的多轮基准测试主要衡量对话能力，但缺乏对多轮轨迹持续运行的测量系统的构建和维护方法。标准 Judge 无法处理实例特定的正确性（如特定商家的目录、价格、流程），也无法有效区分模型失败与数据缺失，且直接的用户反馈稀疏且不可靠，单纯的人工审查则缺乏可扩展性和自动可靠性。

## 文章的核心贡献点
- **提出了一个集成方法论**：涵盖评估规范、模块化 LLM Judge、意图保持的用户模拟以及人机协同治理框架，旨在使多轮 Agent 的测量可靠、可操作且可维护。
- **挑战1：多轮交互中的状态一致性与失败归因难**。在多轮对话中，任务完成度和状态一致性是动态涌现的，且难以区分是模型能力问题还是业务知识库缺失。**解决方法**：通过定义对话级别的终态和可操作的失败所有权，使用原子化 Judge 共享版本化证据并输入显式的聚合图，从而精确追踪和归因失败来源。
- **挑战2：评估系统的持续校准与维护难**。随着业务指南、产品和流量的变化，评估标准需要不断演进，且人工参考标准本身也需要修正。**解决方法**：引入独立的人工审计来估算测量保真度，更新分层参考集，并将分歧路由至标签修正、指南修订或 Judge 改进，形成共享反馈闭环，确保系统随演化而保持校准。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：该系统包含评估规范模块、模块化 LLM Judge、经过任务保持和稳定性检查后发布的用户模拟器，以及人机协同治理流程。模拟器仅在通过严格检查后发布，以确保意图保持。
- **评估结果**：生产环境研究表明，经过多次审计，系统级保真度得到提升；在共享反馈循环下，人工审查员和自动化 Judge 共同改进；两者的结合工作流程在报告的任务完成设置中表现出最强的描述性性能。
- **对比与结论**：由于研究是观察性的且人工参考本身需要修订，这些发现证明的是操作实用性而非因果性或普遍优越性。与传统固定输出的 LLM-as-a-Judge 相比，该框架在处理动态、实例特定的业务场景时更具可靠性和可操作性。

#### 总结
本文针对生产环境中多轮业务 Agent 的评估难题，提出了一套完整的 LLM-as-a-Judge 测量系统设计方法论。通过整合评估规范、模块化 Judge、用户模拟和人机协同治理，解决了多轮交互中的状态追踪、失败归因及系统持续校准等核心挑战。实证结果表明，该框架能有效提升测量保真度，实现人工与自动化评估的共同进化，为构建可靠、可维护的业务 Agent 评估系统提供了实用指南。
