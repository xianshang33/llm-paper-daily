## 文章做了什么
- **背景**：企业级 AI Agent 的技能并非静态，而是随着工具 API 变更、LLM 版本升级以及业务规范调整而持续演进。每次变更都可能引入行为回归（即偏离预期执行过程）。
- **已有工作为什么解决不了**：现有的评估实践主要关注最终输出结果（如报告、数值）的准确性。然而，Agent 可能通过错误的步骤（如调用错误范围的 API、跳过必要的数据库读取、写入错误的中间表）得出看似正确的最终结果。这种“过程层面的行为漂移”对仅检查结果的评估是不可见的，但会破坏数据完整性或在输入微变时导致失败，且在持续适应环境中错误会累积。

## 文章的核心贡献点
- **提出了一个**：结合结果层和过程层检查的持续评估框架，用于企业级 Agent 技能。
- **挑战1：过程偏差难以通过最终结果捕捉**。即使最终数值正确，执行路径可能存在严重错误（如工具选择错误、参数错误、执行顺序混乱），这些错误具有隐蔽性且危害下游任务。**解决方法**：框架独立计算每次运行的地面真值，实例化可重用的模板测试，并通过程序化检查结合窄范围 LLM 裁判，专门评估工具选择、参数正确性、执行顺序和数据库完整性。
- **挑战2：评估噪声与根因定位困难**。复杂的 Agent 执行轨迹会产生大量检查失败点，难以区分根本原因与连带错误。**解决方法**：引入依赖归因机制，将每次运行平均 6.34 个失败检查压缩为 2.65 个根本原因，提高了调试效率；同时利用运行时解析的模板提供跨配置的可重用回归覆盖。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：在企业的价值感知弹性（VAR）系统中，针对“业务价值确定”（BVD）技能的两种变体（收入分配和生产率分配）进行评估。测试涵盖 240 次试验，涉及 2 种技能、2 种规范变体（SKILL.md 和 Skill.txt）、2 种 Agent  harness（Claude Code 和 Codex）以及 3 种模型（GPT-5.6-Sol, Claude Opus 4.8, Claude Sonnet 4.6）。
- **Evaluation 结果**：
    - 在 175 次通过所有最终数值检查的试验中，有 162 次（92.6%）被评估器检测到存在其他过程偏差。
    - 即使在更宽松的七项最终状态定义下，164 次通过运行的中有 151 次（92.1%）仍然违反了轨迹检查。
    - 依赖归因有效减少了需要人工审查的错误数量。
    - 不同模型和 harness 对规范变体的敏感性不同，统计显著性分析显示收入比较均显著，生产率比较中部分显著。
- **对比**：与传统仅关注最终输出的评估方法相比，该框架揭示了高达 92% 的“假阳性”通过案例，证明了过程级评估在捕捉行为漂移方面的必要性，而传统方法完全无法检测此类问题。

#### 总结
本文强调了在企业级 AI Agent 持续演进过程中，仅靠结果评估不足以保障系统可靠性。作者提出的持续过程级评估框架通过程序化检查和受限 LLM 裁判，有效捕捉了隐藏在正确结果背后的过程错误。实验表明，绝大多数看似成功的运行实际上存在过程偏差，证明了该框架作为负责任部署循环中质量网关的重要价值。未来工作将包括在实际 API 演进下的纵向验证。
