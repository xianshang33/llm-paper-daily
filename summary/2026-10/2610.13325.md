## 文章做了什么
- **背景**：随着 LLM 代理（Agentic）应用的兴起，工作负载呈现出长上下文重复调用的特点。虽然前缀缓存（Prefix Caching）技术已经能够跳过大部分预填充（Prefill）计算，但在查询缓存之前，每个请求仍然必须完整地进行分词（Tokenization）。
- **已有工作的局限**：传统服务栈中，分词被视为可忽略的 CPU 阶段。然而，在前缀缓存命中后，分词成为了首字延迟（TTFT）中最大的组成部分。此外，由单个 CPU 前端为整个 GPU 集群进行分词限制了系统能够服务的 GPU 数量，成为扩展瓶颈。

## 文章的核心贡献点
- **提出了 GraphTok**：一种基于 GPU 的分词器，将包括预分词、字节对编码（BPE）合并到 Token ID 组装在内的整个编码管道，作为一个可重放的 CUDA 图运行。
- **挑战1：GPU 分词的精度与兼容性难题**。在 GPU 上复现复杂的 BPE 算法并保证与参考实现比特级一致极具挑战性，且需适配多种模型架构。GraphTok 通过在 GPT-2、Llama 3、Qwen 2.5 等模型上实现比特级精确复现，并针对短输入智能回退至 CPU 引擎，解决了精度和效率平衡问题。
- **挑战2：系统集成与端到端性能瓶颈**。将分词从 CPU 移至 GPU 需无缝集成到现有服务框架中而不破坏原有优化。GraphTok 无需修改即可插件式接入 vLLM 和 NVIDIA Dynamo，通过消除 CPU-GPU 间的同步等待和数据传输瓶颈，显著降低了 TTFT 并提升了吞吐量。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：GraphTok 作为一个独立的 GPU 分词模块，支持无缝集成到未修改的 vLLM 和 NVIDIA Dynamo 中。它采用混合策略，长文本使用 GPU CUDA 图加速，短文本交由 CPU 处理。
- **速度对比**：在 Llama 3 上，GraphTok 比最强的 CPU 分词器 gigatoken 快 4.7-6.0 倍；在 TokTier 基准测试中，比 gigatoken 快 2.6-3.9 倍，比 TokTier 快高达 18.1 倍。编码一百万个 GPT-2 Token 仅需 1.7-3.2 毫秒（含数据传输）。
- **TTFT 优化**：在启用前缀缓存的 vLLM 中，GraphTok 将平均 TTFT 降低了 2.1-2.4 倍。
- **吞吐量与容量**：在 P99 延迟低于 2 秒的目标下，单个 Dynamo 前端配合 GraphTok 可维持 518 请求/秒（121k Token 流量），足以支撑 56 个 GPU 的繁忙小时负载；相比之下，gigatoken 仅支持 296 请求/秒，默认分词器仅支持 18.5 请求/秒。GraphTok 的负载承受能力是 gigatoken 的 1.75-2.5 倍，且在 gigatoken 尾延迟崩溃的场景下，P99 延迟低至其 1/64。

#### 总结
GraphTok 通过将分词任务卸载到 GPU 并利用 CUDA 图技术，有效解决了 Agentic 工作负载中因前缀缓存普及而凸显的分词瓶颈。它不仅大幅降低了首字延迟，更显著提升了单前端能支持的 GPU 集群规模和整体系统吞吐量，为大规模 LLM 代理服务提供了高效的基础设施支持。
