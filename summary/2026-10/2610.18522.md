## 文章做了什么
- **背景**：随着 LLM Agent 技能库（Skill Libraries）的迅速扩张，可复用的技能模块允许 Agent 按需加载特定任务的指令。当前的主流设计（如 Anthropic Agent Skills）采用“渐进式披露”机制，即 Agent 在执行任务的同时，通过隐式路由（Implicit Routing）基于元数据判断并加载相关技能。
- **已有工作为什么解决不了**：现有设计假设 Agent 能够在解决复杂任务的同时，从大量技能描述中准确筛选出少数相关技能。然而，随着无关技能数量的增加，这种隐式路由机制面临严重的扩展性问题，导致 Agent 无法有效加载所需技能，且此前缺乏对这一规模化失效现象的系统性分析。

## 文章的核心贡献点
- **提出了一个关于“隐式路由崩溃”（Skill Routing Collapse）的系统性分析与缓解方案**：揭示了在大规模技能库中，隐式路由机制因语义干扰和指令竞争而失效的现象，并评估了显式预选择（Explicit Preselection）作为缓解策略的有效性。
- **挑战1：语义干扰导致的相关性判断失效**。随着无关技能数量增加，其描述产生的语义噪声干扰了 Agent 对目标技能的识别，导致加载率急剧下降。论文通过实验发现，仅屏蔽无关技能的描述即可大幅恢复技能加载能力，证明了描述信息的语义干扰是主要原因之一。
- **挑战2：执行与选择竞争的指令干扰**。在隐式路由中，Agent 需同时处理任务规划和技能选择，这种多任务竞争导致注意力分散。论文指出，即使保留元数据，让 Agent 显式规划技能使用仍不如独立的预选择步骤有效，因为预选择将“检索”与“执行”解耦，减少了上下文中的指令冲突。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实验设置**：基于 SkillsBench 基准，固定任务和黄金技能（Golden Skills），逐步增加无关技能的数量（从 0 到 1,000+）。
- **主要结果**：
    - **隐式路由崩溃**：当引入 1,000 个无关技能时，隐式路由的技能加载召回率从 73.6% 暴跌至 27.4%，零加载率（Zero-load rate）从 9.3% 飙升至 51.6%。
    - **显式预选择优势**：相比之下，采用显式预选择（Explicit Selection）的方法在相同条件下保持了 73.9% 的召回率，显示出极强的鲁棒性。
    - **消融实验**：屏蔽无关技能的描述能显著恢复性能；但即便要求 Agent 进行显式规划，其效果仍低于独立的预选择模块。
- **对比方案**：评估了三种预选择器：LLM 直接选择、RAG 基于嵌入相似度检索、以及混合模式（RAG 检索候选 + LLM 最终选择）。结果显示显式预选择在覆盖率和延迟之间提供了更好的权衡，优于单纯的隐式执行。

#### 总结
本文揭示了 LLM Agent 在大规模技能库中面临的“隐式路由崩溃”问题，证明了随着无关技能增加，语义干扰和指令竞争会导致 Agent 无法加载必要技能。研究建议采用显式的技能预选择机制（如 RAG 或 LLM 过滤器）将技能检索与任务执行解耦，从而在保持高召回率的同时提升 Agent 的可扩展性和成功率。这一发现为未来 Agent 技能协议的设计和评估提供了重要指导。
