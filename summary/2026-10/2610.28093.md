## 文章做了什么
- **背景**：现代 AI Agent（如 Claude Code、Codex）具备长期记忆能力，能够从网页和工具结果中获取并存储信息。Agent Harness（运行模型的软件）负责管理这些内存，但在当前架构中，系统并不记录内存数据的来源或权限归属。
- **已有工作为什么解决不了**：现有的内存管理系统（如 MemGPT、ClawVM）虽然优化了内存的分层或分页管理，但缺乏对数据来源的信任追踪。当前的防御机制主要依赖模型自身识别恶意指令或使用检测器扫描内容，但这无法提供安全保证，因为合法文档也包含指令，且攻击者可以通过对抗性输入绕过检测。此外，持久化存储使得被投毒的数据经过多次摘要和转换后，看起来像 Agent 自己的笔记，从而在后续执行中触发恶意行为。

## 文章的核心贡献点
- **提出了一个 ClawMMU**：一种针对有状态 LLM Agent 的保护一致性虚拟内存系统，通过为每一块内存标记所有者、范围、来源和权限标签，并在数据进入上下文、写入/读取存储或驱动工具调用时进行检查，实现基于来源而非内容的访问控制。
- **挑战1：间接提示注入与 sleeper memory poisoning（休眠记忆投毒）**
    - **描述与难点**：攻击者将恶意指令隐藏在 fetched page 或工具返回结果中，这些数据被存入长期记忆。由于现有系统不区分数据来源，Agent 会将这些非用户控制的文本视为高权限指令。难点在于攻击载荷可能经过多次摘要和变换，难以通过内容检测发现。
    - **解决方法**：ClawMMU 引入“保护描述符”标签，强制执行核心规则：“信息可以提升权限，但权限不能自我提升”。无论内容如何变换，其原始来源的低权限标签始终跟随，系统在数据进入上下文或触发工具时检查标签，直接阻断未授权的高权限操作，即使模型被欺骗也能生效。
- **挑战2：缺乏基于来源的细粒度访问控制**
    - **描述与难点**：传统 OS 通过 MMU 硬件检查内存页权限，而 Agent Harness 缺乏类似的机制，导致无法区分用户指令与外部不可信数据。现有的用户确认机制不知道参数来源，无法防止被篡改的工具调用。
    - **解决方法**：ClawMMU 模拟操作系统 MMU 的功能，为每个内存页及其衍生表示（如摘要）附加权限标签。在每次内存访问（读/写/执行工具）时，Harness 依据标签而非内容进行决策，将内存攻击转化为经典的保护错误（protection faults），由系统层面直接拦截。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：ClawMMU 作为 Agent Harness 的一个保护层实现，集成到虚拟内存管理系统中。它为每个页面分配保护描述符，并在关键路径（上下文加载、存储读写、工具调用）插入检查逻辑。
- **Evaluation 结果**：论文展示了 ClawMMU 能够有效阻止间接提示注入和休眠记忆投毒攻击。与依赖模型判断或内容扫描的基线方法相比，ClawMMU 提供了确定性的安全保障，不受对抗性输入的影响。
- **相关工作对比**：
    - **vs. MemGPT/ClawVM**：MemGPT 关注内存分层，ClawVM 关注内存分页，但两者均缺乏权限保护。ClawMMU 填补了这一空白，提供了类似 OS MMU 的保护机制。
    - **vs. 内容检测/训练防御**：现有防御试图让模型区分好坏文本，但存在漏报和误报，且易被绕过。ClawMMU 基于来源标签进行强制访问控制，不依赖模型对内容的语义理解，因此更加鲁棒。

#### 总结
ClawMMU 通过将操作系统中的内存管理单元（MMU）保护理念引入 LLM Agent 架构，解决了因缺乏数据来源追踪而导致的安全漏洞。它通过为内存数据附加不可篡改的权限标签，并在系统层面强制执行访问控制策略，成功将复杂的语义攻击转化为可拦截的系统级保护错误。这种方法不依赖模型的内容识别能力，为有状态 Agent 的长期记忆安全提供了强有力的保障。
