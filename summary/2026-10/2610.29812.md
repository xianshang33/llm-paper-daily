## 文章做了什么
- **背景**：文献搜索语言代理正成为生命科学领域科学助手的标准组件，但缺乏受控证据表明其架构（harness）中哪些部分真正有效。
- **已有的工作为什么解决不了**：现有研究多关注模型本身或固定语料库上的检索，缺乏在开放世界（如实时 PubMed API）环境下对不同代理架构（如闭卷、单次检索、多步代理）的系统性消融实验，且往往忽视引用真实性的深层审计，导致无法区分是检索失败还是推理失败。

## 文章的核心贡献点
- **提出了一个**：针对生物医学声明验证的可复现架构消融协议，并在 SciFact 基准上使用实时 PubMed API 对比了四种架构（闭卷、单次检索、ReAct 风格代理、Oracle）。
- **挑战1：检索质量低下导致验证失败**。 naive 的单次检索仅能召回 6% 的金标论文，且容易将过度自信的错误转化为弃权而非提高准确率。论文通过让模型自主构建和细化查询（ReAct 风格），使金标召回率提高了三倍，从而显著提升了验证准确率。
- **挑战2：虚假引用与存在性检查的局限性**。 闭卷模型倾向于引用真实存在但无关的 PMID，传统的“存在性检查”无法识别这种幻觉。论文通过跨家族 LLM 法官进行引用审计，揭示了闭卷模型引用的相关性极低（3/327），而搜索代理的引用相关性高达 67%，证明了仅检查 PMID 是否存在不足以作为科学代理的安全保障。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：研究使用 SciFact 数据集，集成实时 PubMed E-utilities API 作为唯一工具。固定主干模型和输出格式，对比两种高效前沿 backbone 在四种 harness 下的表现。代码、提示词及缓存的工具调用已开源。
- **Evaluation 结果**：
    - **检索瓶颈**：拥有金标摘要时，模型准确率达到 79-86%，比最佳现实架构（62%）高出 17-24 个百分点，证明检索而非推理是主要瓶颈。
    - **架构对比**：ReAct 风格代理取得最佳现实 verdicts（62% 准确率），优于闭卷和单次检索（49-59%），尽管在小样本下差异不显著，且代理未用满搜索预算。
    - **引用审计**：闭卷模型引用的 PMID 几乎都存在（327/335），但仅 3 个被判定为相关；相比之下，搜索代理生成的引用有 67% 被判定为相关。
- **对比**：相较于 MultiVerS 等固定语料库系统，本研究在开放世界中验证了动态检索代理的优势；相较于 MedRAG 等基准，本研究更侧重于架构组件的消融和引用忠实度审计。

#### 总结
本文通过严格的控制实验指出，在生物医学文献验证任务中，提升代理自主构建查询的能力比单纯增加模型参数知识更有效。研究揭示了当前科学助手面临的主要瓶颈在于检索环节，并警告仅依靠 PMID 存在性检查无法防止引用无关文献的幻觉问题，为未来科学代理的设计提供了实证依据和安全警示。
