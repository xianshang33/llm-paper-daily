## 文章做了什么
- **背景**：LLM Agent 由基础模型（Model）和执行层（Harness，即连接模型与环境的执行框架）共同组成。Agent 在基准测试中的表现反映的是“模型-执行层”系统的联合行为，而非单纯的模型能力。
- **已有工作为什么解决不了**：现有的评估方法大多是任务中心的，仅关注最终的任务成功率或聚合奖励，将执行层视为固定的设置部分。这种评估方式掩盖了执行过程中的诊断信息，无法区分失败是源于模型能力不足还是执行层设计缺陷，也缺乏对不同模型与执行层配对交互效果的细粒度分析。

## 文章的核心贡献点
- **提出了一个**针对 LLM Agent “模型-执行层”交互的综合评估框架，包含五个互补的度量指标：有效完成率（VCR）、模型-执行层适配度（Model-Harness Fit）、跨模型适配度（Cross-Model Fit）、交互残差（Interaction Residuals）以及 Token 负载（Token Load）。
- **挑战1：如何解耦并量化模型与执行层的协同效率？**
  - **难点**：传统指标无法区分是因为模型没生成正确指令，还是执行层没能正确解析或执行指令，导致归因困难。
  - **解决方法**：引入“有效完成率（VCR）”和“模型-执行层适配度”，独立于任务正确性来衡量 Agent 是否正常结束并交付可评估结果，从而量化特定执行层对特定模型任务达成的支持程度。
- **挑战2：如何评估执行层的通用性及隐藏的执行特征？**
  - **难点**：单一模型上的表现不能代表执行层的整体优劣，且组件级的总结往往掩盖了特定配对下的执行强弱项及资源消耗差异。
  - **解决方法**：提出“跨模型适配度”以评估执行层在不同模型间的整体适用性；利用“交互残差”揭示特定配对的执行强弱项，并通过“Token 负载”分析包括失败尝试在内的资源消耗，发现高 Token 消耗并不必然对应更好的结果。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实验设置**：评估了4个通用执行层（OpenCode, Codex CLI, Pi CLI, DeepAgents）与4个核心模型，加上2个固定的原生模型-执行层系统。在涵盖上下文管理、工具使用、长上下文规划、多模态交互和工件交接的6个基准测试上进行评估。共包含111个评估设置，产生52,168条轨迹。
- **主要结果**：
  - **排名差异**：执行层的排名随模型和基准测试的变化而变化。任务性能（Task Performance）和有效完成率（VCR）可能倾向于不同的配对组合。
  - **最佳表现**：OpenCode 在跨模型性能（Cross-Model Fit）中排名第一，显示出良好的通用性。DeepSeek V4 Flash Preview 在共享的四个基准测试面板中， across 不同执行层保持了 consistently 高的平均 VCR。
  - **资源效率**：更高的 Token 使用量并不一定对应更好的结果，不同的执行配置文件可能伴随相似的任务分数。
- **对比结论**：与传统仅看最终成功率的方法相比，该框架揭示了相同任务分数下截然不同的执行剖面，证明了评估模型-执行层交互的重要性。

#### 总结
本文强调了将 LLM Agent 视为模型与执行层的联合系统进行评估的重要性。通过提出的五维评估框架，研究揭示了执行层排名的高度依赖性，以及任务成功与执行可靠性之间的复杂关系。结果表明，未来的方向应包括训练模型具备可迁移的执行层使用能力，以及设计适应特定模型和任务的执行层，而非仅仅优化模型本身或孤立地优化执行框架。
