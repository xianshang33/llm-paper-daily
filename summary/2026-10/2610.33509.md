## 文章做了什么
- **背景**：大型语言模型（LLM）智能体正被越来越多地用于安全代码审查，以在代码合并前发现漏洞。然而，现有的基准测试大多基于漏洞修复后的代码变更构建，而非真实的引入漏洞的提交记录。
- **已有工作的不足**：现有的检测数据集通常对单个函数进行二分类评分，模型可能因错误的原因得出正确结果；复现和利用基准从已知漏洞出发，侧重于生成概念验证（PoC）；现有的安全PR审查基准（如MalPR-Bench）大多使用后来修复的逆向或部分应用补丁，导致diff集中在修复代码上，无法真实反映审查者在面对原始漏洞引入代码时的诊断能力。

## 文章的核心贡献点
- **提出了 SecPRBench**：这是第一个针对代理式安全审查的综合基准测试，旨在评估智能体在经验证的真实世界代码变更上的表现。
- **挑战1：缺乏真实的漏洞引入场景评估**。难点在于现有基准多基于修复后的代码，无法衡量智能体在未知漏洞情况下的根本原因诊断能力。解决方法：构建自动化智能体管道，自主收集、构建并验证来自Firefox、V8、OpenSSL等关键系统的真实漏洞引入提交，确保每个任务都基于历史真实的bug-introducing commit。
- **挑战2：评估标准的精确性与诊断深度**。难点在于简单的二元标签或匹配文件不足以证明智能体真正理解了漏洞机制。解决方法：采用“LLM-as-a-judge”机制，仅当智能体的发现能够解释目标漏洞的根本原因时才给予积分，从而精确评估其诊断质量而非仅仅是定位能力。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与数据**：SecPRBench 包含来自9个关键系统（包括Firefox, V8, OpenSSL等，数百万行代码）的265个任务。每个任务提供真实的历史变更diff、提交信息和仓库上下文，但不提供漏洞描述。
- **评估结果**：在8个前沿模型上进行测试，召回率范围从32.5%到78.1%。Grok 4.6 和 GPT-6 sol 排名靠前。
- **深入分析**：研究发现，大多数漏报并非简单的疏忽：在68%的漏报案例中，智能体报告了包含缺陷的文件，但论证了错误的机制。此外，安全专用 harness 表现各异：OpenAI 的 Codex Security 主要因弃权导致召回率降低8.3个百分点，而 Anthropic 的 Defending Code harness 则以更高成本将召回率提高了7.7个百分点。
- **对比**：相较于 MalPR-Bench 等基于修复补丁的基准，SecPRBench 提供了更贴近现实预合并审查场景的评估，揭示了当前模型在根本原因诊断上的局限性。

#### 总结
本文介绍了 SecPRBench，填补了代理式安全代码审查在真实漏洞引入场景评估上的空白。通过自动化管道收集真实世界的漏洞提交并利用 LLM 作为裁判进行细粒度诊断评估，研究揭示了当前顶尖模型在安全审查中仍存在显著的诊断偏差，且不同的安全优化策略对召回率有截然不同的影响。该基准为未来提升 LLM 安全审查能力提供了重要的评估基础和方向。
