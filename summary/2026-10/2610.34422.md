## 文章做了什么
- **背景**：随着计算成本上升、加速器容量受限以及对单一硬件供应商（如 NVIDIA）的依赖，组织正寻求将机器学习工作负载从 GPU 迁移到 TPU 等替代加速器。编码智能体（Coding Agents）被寄予厚望，旨在自动化这一迁移过程以降低工程努力。
- **已有工作的不足**：现有的研究工具大多针对单一内核、算子或框架翻译，缺乏对完整项目迁移后是否可信、数值行为是否保持以及运营成本是否合理的全面评估。仅仅减少代码适配的工作量并不能证明代理生成的迁移是可靠的，也无法确定其操作收益是否合理。

## 文章的核心贡献点
- **提出了一个实证研究框架与数据集**：构建了包含 148 个 PyTorch ML 研究项目的数据集，并使用 Claude Code 将其中的 10 个项目从 NVIDIA GPU 迁移到 Google Cloud TPU，独立评估迁移的运行情况、数值行为保持、硬件执行正确性、目标达成情况及性能。
- **挑战1：静默失败与数值行为漂移**。难点在于迁移后的代码可能无报错运行，但因底层库交互或并行策略改变（如梯度裁剪逻辑变化）导致模型精度下降，智能体却报告成功。论文通过独立验证数值行为和设定严格的项目目标标准，揭示了这种“成功但错误”的风险（如某案例中精度从 86.53% 降至 84.89%）。
- **挑战2：高失败率与隐性成本**。难点在于自动化迁移的实际成功率低且调试困难。论文发现 70 次执行尝试中有 53 次失败（76%），其中近半数无报错；平均每次迁移需 2.4 次人工干预。通过分析失败原因（如重复编译、第三方库兼容性问题），量化了人力成本和计算成本，指出需结合两者制定验收标准。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：使用 Claude Code 作为编码智能体，针对 10 个选定的 PyTorch 项目进行 GPU 到 TPU 的迁移。评估指标包括代码是否运行、是否在预期硬件上执行、数值行为是否一致、是否达到项目目标以及性能成本。
- **Evaluation 结果**：
    - **成功率**：10 个项目中有 8 个满足项目目标标准。
    - **失败分析**：70 次执行尝试中 53 次失败（76%），其中 26 次（49%）未抛出任何错误。主要失败原因是重复编译和执行效率低下，以及第三方库交互导致的静默计算变更。
    - **人力成本**：平均每次迁移需要 2.4 次人工干预。
    - **性能与成本**：差异显著。在一个工作负载中，使用 TorchTPU 后端在 TPU 上的训练速度比 GPU 快 1.86 倍，每次运行成本低 25%。
- **对比**：相较于 Google 此前报道的多智能体系统在生产环境 TensorFlow 到 JAX 迁移中实现的 6.4–8 倍加速，本研究聚焦于更广泛的 PyTorch 研究项目，揭示了在实际科研代码迁移中存在的更高复杂性和静默错误风险，强调了独立参考运行和特定工作负载验收标准的必要性。

#### 总结
本文通过实证研究指出，虽然编码智能体能辅助 GPU 到 TPU 的迁移，但存在较高的静默失败风险和显著的人工干预需求。迁移不仅涉及代码转换，更关乎数值行为的保持和成本效益的平衡。建议实践者采用独立的参考运行、在目标硬件配置下进行验证，并制定涵盖计算和人力成本的特定工作负载验收及停止标准，以确保迁移的可信度和经济性。
