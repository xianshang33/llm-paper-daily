## 文章做了什么
- **背景**：在长会话的 LLM Agent 应用中，主要成本在于每次请求重新发送的前缀 tokens，主要风险在于上下文窗口溢出或关键信息被无关 tokens 淹没。现有的生产级 Agent 框架（如 Claude Code, Codex）通常采用基于固定 token 阈值的硬性压缩策略，由操作员统一配置窗口大小，模型本身不参与决策。
- **已有工作为什么解决不了**：早期研究表明，开源模型在没有额外脚手架（如固定间隔的检查规则、准入网关和强制回退机制）的情况下，无法有效管理自身上下文，因为它们无法识别上下文何时退化。然而，这些研究未验证当前最强的前沿闭源模型是否具备这种元认知能力，也未对比模型自主管理与传统阈值管理在成本和性能上的差异。

## 文章的核心贡献点
- **提出了一个 CTXAgent**：一种让模型自主决定何时压缩上下文、保留什么内容以及如何编写交接摘要的 Agent 框架，仅通过两个工具和一段指导原则实现。
- **挑战1：模型能否在无复杂脚手架下自主管理上下文？**
  - **难点**：模型需要准确判断任务状态和上下文相关性，避免过早遗忘或过晚压缩。
  - **解决方法**：论文测试了七种前沿模型，发现大多数最强模型能够定期压缩和整理上下文，将混合会话的活动上下文保持在 100k tokens 以下，且基准测试分数无显著下降，证明了前沿模型具备足够的元认知能力来自主管理上下文。
- **挑战2：自主管理相比传统阈值管理有何优势？**
  - **难点**：需要在降低 token 成本的同时，确保任务成功率不降低，并适应不同任务的动态需求。
  - **解决方法**：通过构建包含编码练习、多步 SciCode 问题等复杂任务的基准测试，对比发现对于表现良好的模型，自主管理能大幅降低成本。例如，Claude Opus 5.5 在任务成功率匹配 Claude Code 的情况下，成本比其显式 200k 窗口配置低 34%，比默认配置低 49%。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与基准**：构建了由现有基准（编码练习、SciCode、SWE-bench Pro、Terminal-Bench 4.0）组成的混合基准，穿插植入事实、短暂观察和常驻指令，会话长度为 35-212 轮，模拟真实用户多任务场景。所有检查均为确定性。
- **评估结果**：
  - **模型能力**：大多数最强模型能有效管理上下文，活动上下文通常低于 100k tokens，性能无明显下降。
  - **成本效益**：成本降低幅度因模型而异，部分模型因过度压缩导致其他成本增加。Claude Opus 5.5 表现最佳，无需选择上下文窗口即可实现显著成本节约。
- **对比相关工作**：将 CTXAgent 与三种广泛使用的 Agent 框架在两个模型上进行对比，结果显示自管理框架在保持性能的同时显著降低了成本，优于基于固定阈值的传统方法。

#### 总结
CTXAgent 证明了前沿 LLM 具备在无复杂脚手架情况下自主管理上下文的能力。通过让模型决定压缩时机和内容，该方法在保持任务成功率的同时显著降低了 token 成本，特别是对于 Claude Opus 5.5 等高级模型，成本降低可达 34%-49%。该研究发布了 Agent、基准测试及所有结果数据，为未来高效 Agent 系统设计提供了新方向。
