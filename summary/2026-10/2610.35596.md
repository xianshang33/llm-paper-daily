## 文章做了什么
- **背景**：统计理论论文通常包含冗长的证明，读者和审稿人很难逐行检查，导致常规步骤中的错误容易被忽视，直到期刊发布更正。专家使用 Lean 4 等证明助手进行形式化验证虽然可靠，但需要数周的专业工作；而直接使用大语言模型（LLM）生成的非正式论证缺乏可靠性且难以自动验证。
- **已有工作的局限**：单纯依靠人类专家形式化成本过高且效率低下；单纯依赖 LLM 则存在幻觉风险，且其输出无法被机器内核严格验证，容易导致“看似正确但实际有误”或“证明了比原文更窄的命题”等问题。

## 文章的核心贡献点
- **提出了 KAPPA (Kit of Agents for Proof-checking Papers with a proof Assistant)**：一个开源软件套件，组织由 Claude Code 运行的 LLM 智能体，将 LaTeX 论文中的证明逐步翻译成 Lean 4 代码并利用 Mathlib 库进行形式化验证。
- **挑战1：确保形式化证明与原始论文陈述的一致性**。难点在于 LLM 可能会无意中修改命题条件，导致 Lean 中证明的是一个与原文不同（通常更窄）的定理。解决方法：在证明前将每个陈述与论文原文进行比对并生成指纹，确保证明对象未发生漂移，且所有裁决均基于可重跑的 Lean 证据。
- **挑战2：处理长证明中的复杂依赖与错误定位**。难点在于统计证明结合了引用结果和大量常规步骤，错误可能隐藏在细微处。解决方法：采用多智能体协作（编写与审查分离），遵循论文原有的证明步骤而非寻找新证明；对每个编号结果给出四种裁决（无条件验证、条件验证、记录问题、未完成），并能精确定位出错步骤及责任方。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：KAPPA 能够无人值守运行数小时，自动处理 API 限制，仅重新检查修订部分，并按角色、模型和结果报告成本。系统包含独立的编写和审查智能体，每个裁决都有可复现的证据。
- **评估结果**：
    - 在四个带有答案键的示例论文和三篇已发表的统计论文（盲测其公开更正前的版本）上进行了测试。
    - 在所有三篇已发表论文中，KAPPA 均在更正指出的步骤处发现了已发布的错误，并额外发现了经人工确认的其他问题。
- **与相关工作对比**：
    - 相比于直接将相同论文交给同一 LLM 配合 Lean 使用（无 KAPPA 架构），KAPPA 在最长的论文上正确分类的结果更多。
    - 基线方法（直接 LLM+Lean）报告了一些比原文陈述更窄的命题为“已证明”，存在过度声称的风险；而 KAPPA 的任何裁决都没有超出其 Lean 证据所支持的范围，保证了严谨性。

#### 总结
KAPPA 通过结合 LLM 的翻译能力与 Lean 4 的形式化验证能力，提供了一种高效、自动化的统计论文证明检查方案。它解决了传统形式化耗时过长和纯 LLM 验证不可靠的问题，能够准确发现证明中的错误并精确定位，同时确保了验证过程的透明性和可复现性，显著提升了统计理论研究的可靠性和可重复性。
