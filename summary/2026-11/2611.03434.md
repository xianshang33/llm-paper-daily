## 文章做了什么
- **背景**：政府情报团队需要利用 LLM Agent 分析大量杂乱且异构的证据集合（如邮件、报告、通话记录等）。然而，出于数据敏感性和成本考虑，通常无法使用托管的前沿大模型，且安全审查要求对暴露的工具表面进行严格控制。
- **已有工作为什么解决不了**：现有的 Harness 设计往往过于庞大或依赖不可审计的广泛工具集，难以满足高安全性环境下的严格审查要求。同时，传统的优化方法往往侧重于模型本身或预定义的工具集，缺乏在固定、可自托管的小型模型上，通过最小化 Agent 架构来平衡准确性、通用性和可审计性的有效方法。

## 文章的核心贡献点
- **提出了一个 CLEO (Constrained Loop for Environment Optimization)**：一种将最小化 Agent Harness 适配到固定、可自托管 LLM 的方法。
- **挑战1：如何在严格的安全和审计约束下保持高准确性？**
  - **难点**：减少工具和代码会限制模型能力，而增加复杂性又违背安全最小化原则，难以平衡。
  - **解决方法**：引入“显式理由门控”（explicit justification gate），仅当提议的 Harness 变更（工具、护栏、记忆策略等）能提高准确性，且具备通用性、可审计性并值得增加能力表面时，才予以采纳。
- **挑战2：如何避免过度工程化并确保 Harness 的最小化？**
  - **难点**：传统方法往往先构建复杂系统再剪枝，导致残留冗余代码，难以通过安全审查。
  - **解决方法**：采用“自底向上”的构建策略，Harness 初始几乎为空，仅当评估证明必要时才添加工具或组件，从而通过构造过程本身实现最小化优化。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：CLEO 被用于构建一个围绕固定自托管模型的调查 Agent。该方法强调评估驱动的开发（evaluation-driven development），确保每个组件都经过专家验证数据集的测试。
- **Evaluation 结果**：在保留测试集上，CLEO Harness 达到了 83.8% 的通过率。
- **对比**：该成绩仅比最强的开箱即用 Claude Code SDK 基线低 1.2 个百分点，但其规模小了两个数量级（two orders of magnitude smaller），显著降低了审计负担和部署成本。

#### 总结
本文针对高安全需求下的情报分析场景，提出了 CLEO 方法，通过自底向上的最小化构建和严格的理由门控机制，成功在可自托管的小型 LLM 上实现了接近前沿闭源模型性能的 Agent Harness。该方法在保证高准确性的同时，极大提升了系统的可审计性和安全性，为受限环境下的 LLM 应用提供了新的范式。
