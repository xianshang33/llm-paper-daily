## 文章做了什么
- **背景**：生成式人工智能，特别是基于大语言模型（LLM）的智能体（Agents），有望重塑化学工程领域。智能体不仅能回答问题，还能使用工具、编辑文件并迭代结果。软件工程已证明这种模式能加速开发，因为代码存在于可版本控制和自动测试的文本文件中。
- **已有工作为什么解决不了**：化学工程比软件工程更复杂，因为工厂由许多耦合文档描述（如流程模拟、P&ID、设备数据、布局、安全研究等）。这些文档相互依赖，但依赖关系很少被记录，导致一处变更（如设计产能增加）会静默地使其他地方的数据失效。现有的集成信息模型和数字线程虽能交换数据，但无法在整个项目周期中记录哪些结果仍保持一致、哪些已过时。此外，早期的流程图和P&ID生成器（无论是基于规则还是学习模型）通常只生成部分设计，缺乏决策过程且脱离工程工作流，难以应对智能体快速产生的大量需验证的输出。

## 文章的核心贡献点
- **提出了一个 ChemE-as-Code 开源平台**：这是一个开放源码环境，允许基于 LLM 的 AI 智能体执行化学工程任务，并让工程师进行检查。它将工程文件链接、机器可读并通过 Git 进行版本控制，计算在 LLM 外部运行，每个值记录其来源，并通过自动化检查报告不一致和过时的结果。
- **挑战1：多文档耦合与一致性维护难**。化学工程设计涉及多种异构文档，变更会导致静默错误，传统方法难以追踪依赖。**解决方法**：通过将工程知识封装为“技能”（Skills，指导智能体如何操作的指令文件）和“工具”（Tools，执行计算或检查的程序），并将所有工程文件置于 Git 版本控制下。计算在 LLM 外部执行并记录数据来源，自动化检查工具按文件和行号报告不一致性，从而确保数据溯源和一致性。
- **挑战2：智能体输出的验证与可信度**。智能体生成的输出可能看似合理但实际无效，且数量庞大，人工审查压力大。**解决方法**：采用通用智能体加载所需技能和工具的模式，而非多学科专用智能体团队。通过自动化检查规则发现覆盖范围内的错误，明确告知人类审查者哪些部分通过了规则检查，哪些未覆盖，从而引导而非替代人工审查，提高审查效率。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与案例**：在一个 illustrative ammonia（氨合成）案例中，智能体将书面任务转化为初步的基础工程包，包括模拟文件、P&ID、布局、HAZOP 分析、数据表和泄压设计。整个设计会话的 API 成本仅为 224 美元。
- **评估结果**：通过植入故障和工程变更进行测试，结果显示自动化检查能够发现规则覆盖范围内的错误，但会遗漏规则未覆盖的部分。这证明了该系统能有效辅助人类审查，但不能完全取代独立工程师的审核（目前尚无独立工程师审查该设计）。
- **对比**：与传统的基于规则或学习的流程图/P&ID 生成器相比，ChemE-as-Code 不仅生成设计产物，还保留了决策过程，并将其整合到可版本控制的工程工作流中，解决了以往工具脱离工程上下文且缺乏一致性追踪的问题。

#### 总结
ChemE-as-Code 通过将化学工程工作转化为类似软件的“代码即基础设施”模式，利用 LLM 智能体、Git 版本控制和自动化检查工具，解决了化学工程设计中多文档耦合、一致性维护难以及智能体输出验证的问题。它提供了一个开源框架，使智能体能够以较低成本完成初步工程设计，并通过透明的溯源和自动化检查辅助工程师进行高效审查，推动了化学工程向智能化、自动化工作流的转型。
