## 文章做了什么
- **背景**：在基于 ReAct 范式的 LLM Agent 中，外部工具调用是主要的运行成本来源。由于每次调用的观察结果都会保留在上下文中并在后续步骤中被重新处理，低效或冗余的工具调用会显著增加延迟和计算成本。
- **已有工作为什么解决不了**：现有的训练目标几乎完全专注于任务完成，忽略了调用成本。虽然部分方法引入了效率奖励以减少调用次数，但存在三个主要缺陷：1) 效率锚点（如组内最短正确轨迹）随策略动态变化，导致不稳定；2) 训练容易漂移至“策略崩溃”，即 Agent 完全不发起任何工具调用；3) 一次训练只能产生单一的操作点，用户无法在效率和能力之间进行权衡。

## 文章的核心贡献点
- **提出了一个 CARE-PO (Controllable Anchored Relative Efficiency Policy Optimization)**：一种可控的、基于锚点的相对效率策略优化方法，旨在解决工具调用效率与任务成功率之间的平衡问题。
- **挑战1：动态锚点导致的训练不稳定与策略崩溃**。难点在于如果参考标准随策略自身 rollout 变化，模型可能倾向于不调用工具以最小化惩罚。CARE-PO 通过将效率奖励的定价锚定在基于任务难度且训练前固定的参考预算上，并在每个在线 GRPO rollout 组中注入来自训练数据的成功轨迹，同时对未收集证据的行为进行收费，从而缓解了向零调用崩溃的漂移。
- **挑战2：单一操作点缺乏灵活性**。难点在于传统方法一次训练仅输出一种行为模式，无法适应不同场景对效率或精度的偏好。CARE-PO 通过在提示词中引入“努力标签”（effort tag）来塑造成本曲线，使得从单次训练运行中即可衍生出多个操作点（如高效模式和高质量模式），允许用户在推理时动态权衡效率与能力。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实验设置**：在 GAIA 基准测试及四个持有多跳基准上，对 Qwen3.5 系列模型（4B, 9B, 27B）进行评估。
- **对比结果**：
    - **GAIA 基准**：在三种模型尺寸的六个操作点中，有五个在成功率和调用次数上同时优于基础模型。例如，在 9B 模型上，CARE-PO 的不同操作点在保持或提高成功率的同时显著降低了平均工具调用数。
    - **持有多跳基准**：结果呈现尺寸依赖性。在 27B 和 4B 模型上，CARE-PO 在降低调用次数的同时保持或提高了成功率；而在 9B 模型上，两个操作点均以轻微的成功率下降换取了更少的调用次数。
    - **稳定性**：在所有三种尺寸的模型训练过程中，工具调用次数始终保持在远高于零的水平，避免了策略崩溃问题，而基线方法（如 OTC-PO）在某些情况下表现出退化。

#### 总结
CARE-PO 通过引入固定难度的参考预算和提示词中的努力标签，有效解决了现有 RL 方法在优化工具调用效率时的策略崩溃和操作点单一问题。该方法不仅在多个模型尺寸上实现了成功率与效率的双重提升，还提供了灵活的可控性，使开发者能够根据实际需求在单次训练权重的基础上调整 Agent 的行为模式，显著降低了 LLM Agent 的运行成本。
