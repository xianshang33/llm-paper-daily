## 文章做了什么
- **背景**：随着大语言模型（LLM）驱动的代理（Agent）被用于网络攻击，归因分析不仅涉及攻击者身份，还涉及识别执行攻击的软件配置（即具体的 LLM 版本和 Agent 框架/Harness）。传统的归因方法通常依赖于访问攻击者的内部日志或配置文件，但在实际防御场景中，防御者往往只能被动观察目标系统接收到的请求和执行效果，处于“盲视”和“被动”的状态。
- **已有工作为什么解决不了**：现有的模型指纹识别技术（如 LLMmap）通常需要主动向 LLM 应用提交特定查询并检查响应，这要求防御者拥有与模型的直接交互接口。然而，在面对攻击性 Agent 时，防御者无法直接查询其背后的模型，只能观察到 Agent 为获取资源而采取的行动序列和工具调用结果，因此现有方法无法直接应用于这种被动遥测场景。

## 文章的核心贡献点
- **提出了一个名为“Shibboleth Traps”（示巴陷阱）的技术**：这是一种模块化的蜜罐服务，旨在通过设计特定的交互条件，诱导攻击性 Agent 暴露其底层 LLM 和 Harness 的特征行为。
- **挑战1：如何在无需成功注入提示词的情况下识别 LLM 模型？**
  - **难点**：传统的模型识别依赖直接的问答交互，而攻击 Agent 可能不会直接回答身份问题，或者防御者无法控制对话上下文。
  - **解决方法**：论文设计了“声明式门控”（Declarative Gates），将获取关键资源（如部署密钥）的条件设置为要求 Agent 声明其模型名称或生成特定风格的文本。这种设计迫使 Agent 为了完成任务而主动提供区分性信息，从而在不依赖提示词注入成功的前提下 eliciting 模型声明和特征写作风格。
- **挑战2：如何从外部间接识别封装 LLM 的 Harness（框架/执行环境）？**
  - **难点**：Harness 负责管理工具调用、秘密掩码、超时控制和并发调度，这些内部机制对防御者是不可见的，且不同 Harness 的行为差异细微。
  - **解决方法**：论文引入了“行为探针”（Behavioral Probes），通过观察 Harness 在处理特定工具调用时的副作用来间接推断其行为。例如，通过故意挂起某个工具调用来测试 Harness 的超时处理机制，或观察工具输出中秘密信息的掩码方式。这些探针仅利用后续请求中可见的效果，即可揭示 Harness 的独特执行逻辑。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：研究者构建了基于 MCP（Model Context Protocol）服务器的 Shibboleth 陷阱，包含声明式门控和行为式门控。实验模拟了攻击者 Agent 尝试从蜜罐中窃取资源的过程。
- **评估结果**：
  - **LLM 识别**：结合声明性和行为性推理，该方法在 15 个候选模型中实现了平均 90% 的 Top-1 识别准确率。即使在保留的 Harness 或任务家族上测试，行为分类器依然有效。
  - **Harness 识别**：在针对 4 种不同 Harness 的独立实验中，使用固定的探针规则以 92% 的准确率识别出了正确的 Harness。
  - **抗隐蔽性**：当指示 Agent 隐藏其身份时，虽然其声明变得无信息量，但 Agent 仍留下了有用的行为证据，证明该方法对对抗性隐藏具有鲁棒性。
- **对比**：相较于需要直接查询接口的 LLMmap 等方法，本文方法在完全被动、仅观察目标系统遥测数据的设定下，依然能高精度地还原攻击者配置，填补了被动防御场景下 Agent 指纹识别的空白。

#### 总结
本文针对 LLM 驱动的网络攻击，提出了一种被动式的指纹识别框架“Shibboleth Traps”。通过巧妙设计蜜罐服务的交互逻辑，迫使攻击 Agent 在追求目标资源的过程中暴露其底层 LLM 的声明特征和 Harness 的行为特征。实验表明，该方法能在不依赖内部日志或直接查询接口的情况下，高精度地识别出攻击者使用的具体模型版本和执行框架，即使面对试图隐藏身份的 Agent 也依然有效，为网络安全防御中的攻击归因提供了新的技术手段。
