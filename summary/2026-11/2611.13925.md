## 文章做了什么
- **背景**：基于大语言模型（LLM）的多智能体需求工程（RE）框架日益普及，这些框架通过角色专用的智能体来 elicitation、建模、协商和验证需求。
- **已有的工作为什么解决不了**：现有的框架（如 MARE、iReDev、QUARE）使用不同的智能体角色、协商策略和输出格式，且通常在各自的运行时、指标和小规模 curated 系统描述集上进行评估。这导致难以在相同条件下进行公平、可复现的比较，且现有评估输入缺乏来自真实软件仓库的出处记录，限制了外部有效性。

## 文章的核心贡献点
- **提出了一个 OpenRE-Bench**：这是一个用于 LLM 基于多智能体 RE 框架的开源基准测试基础设施。
- **挑战1：异构框架难以公平比较**。不同框架的输入、输出和评估指标不统一，导致直接对比困难。OpenRE-Bench 通过提供一个共享的运行 harness 和契约（contract），统一了输入、阶段产物和指标合同，使得异构框架能在完全相同的条件下运行和评分。
- **挑战2：评估数据缺乏真实性和可扩展性**。传统评估依赖少量手工构建的案例，无法反映真实项目中的需求演变。OpenRE-Bench 引入了一个可复现的 GitHub Issue 挖掘管道，从真实的功能请求中提取案例，并通过适配器机制允许新框架仅通过实现单个适配器即可加入基准测试，无需修改核心案例或指标。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：OpenRE-Bench 包含四个可重用组件：共享运行 harness、适配器机制、GitHub Issue 挖掘管道和版本化案例套件。它提供了固定的环境、Docker 镜像、冻结的 API 快照以及包含 651 个测试用例的套件。
- **Evaluation 结果**：作为演示，作者从五个项目（三种语言，五个领域）中挖掘了 3,000 个 Issue，构建了 5 个挖掘案例，并与 5 个手工构建案例组成 v1.0 套件。在该协议下运行了三个异构框架：MARE 和 iReDev（作为论文忠实复现）以及 QUARE。
- **对比**：通过在统一协议下运行这些框架，OpenRE-Bench 解决了以往各框架各自为政、指标不一的问题，提供了直接的横向对比能力。该基准已作为 QUARE 研究的评估后端，并被团队内的其他两项研究复用，证明了其通用性和实用性。

#### 总结
OpenRE-Bench 通过标准化运行环境、引入适配器机制和构建基于真实 GitHub Issue 的可扩展数据集，解决了多智能体需求工程框架评估中缺乏公平性和可复现性的关键问题。它不仅提供了一个紧凑的版本化案例套件，还建立了一个可持续增长的基准测试生态系统，促进了该领域的标准化比较和研究进展。
