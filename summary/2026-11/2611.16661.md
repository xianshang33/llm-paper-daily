## 文章做了什么
- **背景**：LLM Agent 的训练与开发工作流（如基准评估、合成数据生成、RL rollout）严重依赖批量任务执行。这些任务在 LLM 推理和环境交互之间交替进行，整个批次的完成时间（Batch Makespan）直接决定了开发迭代效率。
- **已有工作的不足**：传统的 LLM 服务优化主要关注请求级延迟指标（如首 token 时间 TTFT 和每 token 输出时间 TPOT），而非批次整体完成时间。此外，现有系统通常未针对 Agent 任务中推理与环境交互交替的特性进行协同优化，导致在混合架构下的资源分配不均、缓存复用率低以及长尾任务拖慢整体进度。

## 文章的核心贡献点
- **提出了一个推理-环境协同优化框架**：旨在通过协调 GPU 资源分配、路由调度及环境执行策略，最小化 Agent 工作流的批次完成时间。
- **挑战1：混合模型下的资源竞争与并行效率平衡**。难点在于如何在 KV Cache 和循环状态（Recurrent State）之间合理分配有限的 GPU 显存，同时确定最佳并发数以利用并行性并限制重计算。解决方法是提出基于工作负载的资源模型，指导显存分配并提供参考样本并发度。
- **挑战2：环境容量受限下的长尾效应与负载不平衡**。难点在于环境交互能力有限，且长链条任务容易成为批次完成的瓶颈，同时需兼顾缓存复用。解决方法是引入轨迹感知路由以促进缓存复用，并解耦样本准入与环境执行，提出链推进动作调度（CAAS），根据观察到的进度优先处理长链条任务以缩短批次尾部时间。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：该方法已应用于 Ling-3.x 系列模型的训练和评估工作流中。通过受控回放（Controlled Replay）技术，结合真实推理与记录的环境响应及耗时，对各优化模块进行了消融实验。
- **评估结果**：在 BFCL、SWE-bench Multilingual、WideSearch 和 MCP-Atlas 等基准上，使用 Ling-3.0-Flash 和 Ling-3.1-Flash 进行实时评估。结果显示，批次完成时间减少了 10.4% 至 65.0%，且评估得分保持一致。
- **对比优势**：相较于传统仅优化单请求延迟的服务系统，该方案显著加速了模型开发周期，特别是在处理需要多轮环境交互的复杂 Agent 任务时，通过协同优化解决了传统方法忽视的批次整体效率问题。

#### 总结
本文针对 LLM Agent 工作流中批量执行效率低下的问题，提出了一套推理与环境协同优化的解决方案。通过工作负载感知的资源建模、轨迹感知路由以及链推进动作调度（CAAS），有效解决了混合模型资源分配和环境受限下的调度难题。实验证明该方法能大幅降低批次完成时间，已成功应用于实际模型开发流程，显著提升了研发效率。
