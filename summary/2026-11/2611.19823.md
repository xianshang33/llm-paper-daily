## 文章做了什么
- **背景**：随着多轮 LLM 代理（Agent）在编码和工具使用任务中的普及，基于反思的技能优化器通过从失败和成功的执行轨迹中修订指令来提升性能。然而，现有的方法主要专注于最大化任务准确率。
- **已有工作的局限性**：单纯追求准确率导致两个严重问题：一是边缘案例规则的累积使得提示词（Prompt）膨胀，增加了 Token 消耗并导致代理陷入冗长且易错的循环；二是现有的效率优化方法要么在搜索初期就惩罚 Token 使用，从而抑制了必要的探索并导致优化停滞，要么仅压缩静态指令而未减少运行时生成的推理和行动 Token，无法解决多轮交互中历史上下文二次增长带来的高昂成本。

## 文章的核心贡献点
- **提出了 EfficientSkill**：一个两阶段框架，旨在发现可靠的技能并进行 Token 高效的修剪，从而在保证准确率的同时显著降低输出 Token 数量和代理交互轮数。
- **挑战1：早期探索与 Token 效率的矛盾**。难点在于如果在优化初期就严格限制 Token，代理在面对陌生环境时无法进行必要的探索和诊断，导致优化在低准确率附近停滞。EfficientSkill 通过第一阶段在不施加长度惩罚的情况下修复失败轨迹，先确立一个高准确率的“锚点技能”（Anchor Skill），解决了探索受阻的问题。
- **挑战2：提示词过拟合与多轮漂移导致的冗余**。难点在于反复修补指令会导致代理犹豫不决、陷入重新检查的循环，且静态压缩无法减少运行时生成的冗长推理。EfficientSkill 在第二阶段以锚点技能为热启动，在保持准确率不低于阈值（如 90%）的前提下，对 episodic 输出 Token 进行精度保护的剪枝，并将可重用代码卸载到工作区实用程序中，实现了零实现提示成本的紧凑工作流。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实验设置**：在 MATH-500、ALFWorld 和 SpreadsheetBench 三个基准测试上，评估了四种前沿、中端和开源权重的模型。
- **对比基线**：主要与无约束的技能进化方法 EvoSkill 以及后处理压缩方法 SkillReducer 进行对比。
- **主要结果**：
  - **Token 效率**：在 12 种配置中的 11 种里，EfficientSkill 相比 EvoSkill 减少了输出 Token，降幅高达 80%。
  - **准确率提升**：在所有基准测试中平均准确率均有提升。特别是在 SpreadsheetBench 上，Gemini 3.8 Flash 和 Grok 4.1 Fast 的准确率分别提升了 14.3 和 17.5 个百分点，这得益于用紧凑的工作流替换了停滞的循环。
  - **成本降低**：通过减少生成的 Token 和重放的历史记录，EfficientSkill 在所有评估配置中（无论是否使用前缀 KV 缓存）都降低了总 Token 使用量和服务成本。
  - **对比优势**：相比 SkillReducer 仅减少 27% 的输入 Token 且不缩短运行时推理，EfficientSkill 同时优化了输入和输出效率，并显著缩短了代理的执行路径。

#### 总结
EfficientSkill 通过解耦“准确率发现”和“效率优化”两个阶段，有效解决了多轮 Agent 中提示词膨胀和推理冗余的问题。该方法不仅大幅降低了 Token 消耗和服务成本，还通过消除无效循环提升了复杂任务（如电子表格操作）的执行准确率，为构建高效、低成本的多轮 LLM 代理提供了新的范式。
