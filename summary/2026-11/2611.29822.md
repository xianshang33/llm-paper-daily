## 文章做了什么
- **背景**：随着大型语言模型（LLM）编码代理的兴起，“Vibe Coding”（即仅通过自然语言指令生成代码，几乎不检查源代码）成为一种新兴的开发范式。这种模式降低了软件创建的门槛，使非专业人士也能构建网站。
- **已有工作的不足**：现有的研究多关注代码的功能正确性或安全性，但缺乏对 LLM 生成的端到端网站在无障碍性（Accessibility）方面的系统性评估。目前尚不清楚在缺乏人工审查的情况下，Vibe Coding 是否会产生符合无障碍标准（如 WCAG）的网站，以及现有的代理级干预措施是否有效。

## 文章的核心贡献点
- **提出了一个针对 LLM 编码代理生成网站无障碍性的实证研究框架**：系统评估了不同代理、模型和推理努力水平下生成网站的无障碍缺陷分布，并测试了特定“技能”（Skills）干预的效果。
- **挑战1：量化 Vibe Coding 产生的无障碍缺陷规模与类型**。难点在于需要模拟完整的用户交互路径并综合多种检测工具的结果，以反映真实用户体验。论文通过结合 axe-core、IBM Equal Access 和 QualWeb 三种工具，对 90 个生成的网站进行全旅程评估，发现所有基线网站均存在缺陷，平均每个网站有 80.43 个违规元素，其中颜色对比度问题最为普遍。
- **挑战2：评估代理级无障碍干预的有效性及副作用**。难点在于平衡无障碍改进与功能正确性之间的关系，因为优化非功能性需求可能损害核心功能。论文引入了通用无障碍技能和特定对比度技能进行重测，结果显示虽然无障碍评分显著提升，但并未消除所有违规，且功能正确性有所下降，揭示了干预措施的双刃剑效应。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实验设置**：使用 3 种编码代理、4 种语言模型和多种推理努力级别，为 3 个项目生成了 90 个网站。随后选取 24 个匹配配置，分别应用通用无障碍技能和对比度专用技能进行重新生成。
- **评估结果**：
    - **基线表现**：90 个基线网站中没有一个完全符合无障碍标准。共观察到 13 种 WCAG 成功准则被违反。主要问题依次为：颜色对比度、标签缺失、语义结构错误、键盘导航失败和可视化问题。
    - **干预效果**：引入无障碍技能后，无障碍评分显著提高，但仍有残留违规。盲人用户的实际测试证实了这些缺陷对用户体验的负面影响。
    - **副作用**：随着技能的加入，网站的功能正确性出现下降。
- **对比分析**：与以往仅关注代码片段或单一属性的研究不同，本研究强调了端到端生成过程中的系统性无障碍缺失，并指出了当前代理干预在提升无障碍性的同时可能牺牲功能稳定性的权衡关系。

#### 总结
本文通过大规模实证研究揭示，当前的“Vibe Coding”工作流无法可靠地产生符合无障碍标准的网站。尽管引入专门的无障碍技能可以显著改善部分指标，但无法彻底消除缺陷，且可能导致功能回归。研究表明，自动化代理在提升可访问性方面具有潜力，但也引入了新的风险，未来需要在工具设计中更好地平衡无障碍性与功能正确性。
