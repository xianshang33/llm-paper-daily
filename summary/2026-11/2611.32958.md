## 文章做了什么
- **背景**：随着大型语言模型（LLM）与高性能计算（HPC）的融合，AI Agent 开始自动化数据分析、编排和模拟 steering。然而，这引入了一种现有集群防御无法解决的安全问题：“被劫持的授权 Agent”。攻击者可以通过提示注入、投毒共享数据、受损工具或多 Agent 协调来颠覆 Agent，并通过合法的加密 LLM API 流量泄露敏感数据。
- **已有工作为什么解决不了**：现有的 HPC 安全机制主要依赖身份认证（如 Kerberos）和授权（如 POSIX 权限）。由于被劫持的 Agent 拥有合法用户的完整凭证和权限，认证和授权检查均会通过。此外，传统监控系统不 inspect 加密的 HTTPS LLM 后端流量，且无法应对通过共享并行文件系统（如 Lustre）或共置节点临时存储进行的隐蔽注入攻击。

## 文章的核心贡献点
- **提出了一个名为 AEGIS 的系统**：这是一种基于行为证明（Behavioral Attestation）的运行时防御架构，旨在为 HPC AI Agent 构建零信任安全环境。
- **挑战1：如何在不解密流量的情况下检测恶意行为？**
  - **难点**：Agent 与 LLM 后端的通信是加密的，且攻击载荷隐藏在合法的系统调用和数据访问中，传统网络监控失效。
  - **解决方法**：AEGIS 编译任务衍生的行为约束配置文件，利用 eBPF 技术拦截系统调用以监控 Agent 的实际操作（如文件访问、进程执行），并将证据与约束 profile 进行验证，从而在运行时识别偏离预期行为的异常。
- **挑战2：如何应对多 Agent 协同攻击及降低误报率？**
  - **难点**：单个 Agent 的行为可能看似正常，但多个 Agent 协同可能导致分布式数据泄露；同时，严格的监控容易干扰正常的科学工作流。
  - **解决方法**：AEGIS 跨 Agent 关联行为证据，并在检测到违规时触发 Slurm 级别的 containment（隔离/终止）。实验表明，该方法在覆盖全部四类攻击的同时，在评估的良性工作流中未观察到误报，且验证器开销极低。

## 实现与部署，evaluation 结果，要有和相关工作对比
- **实现与部署**：AEGIS 集成在 HPC 环境中，使用 eBPF 进行底层 syscall 拦截，并与 Slurm 作业调度系统联动以实现快速响应。它以 1 秒为间隔进行监控。
- **Evaluation 结果**：
  - **检测能力**：在真实证明路径上，AEGIS 检测到了所有四种实现的攻击类别（提示注入、数据投毒、工具受损、多 Agent 协调）。
  - **性能**：中位检测延迟低于 1 秒，验证器开销低。
  - **准确性**：在评估的良性工作流中没有观察到误报（False Positives）。
- **对比**：受控实验显示，AEGIS 实现了完整的攻击套件覆盖，其检测能力强于代表性的基线方法（existing baselines），解决了传统基于身份和网络的防御盲区。

#### 总结
本文针对 HPC 环境中 AI Agent 面临的“被劫持授权 Agent”威胁，提出了 AEGIS 系统。通过引入行为证明机制，利用 eBPF 监控和 Slurm 集成，AEGIS 能够在不依赖解密流量的情况下，以低延迟和低开销实时检测并遏制多种复杂的注入和协同攻击，填补了 HPC 零信任架构在 AI Agent 安全领域的空白。
