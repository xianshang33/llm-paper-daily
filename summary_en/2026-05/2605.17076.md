## 1. What the Paper Does
- **Background**: Concurrent LLM agents sharing mutable natural-language state produce Structural Race Conditions (SRCs), including write-write and cross-shard stale-read conflicts, which silently corrupt agent output.
- **Limitations of Existing Work**: Current multi-agent frameworks (e.g., LangGraph, CrewAI, AutoGen) lack write-ownership semantics for shared state and typically detect conflicts post-hoc, if at all, failing to prevent SRCs mechanistically.

## Core Contributions
- **Proposed S-Bus**: An HTTP middleware featuring a server-side DeliveryLog that automatically reconstructs each agent's read set and provides Observable-Read Isolation (ORI) consistency.
- **Challenge 1: How to accurately capture an agent's read set for concurrency control under HTTP/1.1 without modifying the agent SDK?**
  - **Difficulty**: Traditional methods require invasive code changes or specific protocol support, making precise read-set tracking difficult without altering existing agent architectures.
  - **Solution**: S-Bus introduces the DeliveryLog mechanism, which records server-side HTTP GET operations per agent to automatically reconstruct the read set at commit time. This transforms ordinary HTTP traffic into a verifiable read set, enabling zero-intrusion optimistic concurrency control.
- **Challenge 2: How to formally verify the safety of this mechanism and prove it effectively prevents structural conflicts?**
  - **Difficulty**: The state space of concurrent systems is vast, making it hard to cover all edge cases via testing, and rigorous mathematical proof is needed to guarantee the correctness of the consistency property (ORI).
  - **Solution**: The paper provides three tiers of mechanized evidence: machine-checked ReadSetSoundness and ORICommitSafety using TLAPS; exhaustive model checking with TLC (exploring over 20 million states for N=3 with zero violations); and verification of 9 inductive soundness lemmas using Dafny, ensuring theoretical correctness.

## Implementation and Evaluation
- **Implementation & Deployment**: S-Bus is implemented as an HTTP middleware in Rust. It is optimized for the "dedicated-shard" topology, where each agent owns a distinct write key but reads from shared reference shards.
- **Evaluation & Comparison**:
  - **Conflict Prevention**: In shared-shard contention sweeps involving 427,308 active HTTP-409 conflicts, S-Bus achieved zero Type-I corruptions, demonstrating parity with PostgreSQL 17 SERIALIZABLE and Redis 7 WATCH/MULTI in preventing structural race conditions.
  - **Effectiveness**: In a non-code workload experiment (data pipeline architecture planning), enabling ORI resulted in 0/638 divergent commits, whereas disabling ORI resulted in 590/639 divergent commits, showing statistically significant improvement.
  - **Operational Envelope**: Experiments show ORI is semantically neutral and effective in dedicated-shard workloads but harmful in single-shard collaborative writing scenarios, as preservation propagates concurrent contradictions.

## 4. Conclusion
S-Bus addresses structural race conditions in multi-agent LLM systems by introducing the DeliveryLog mechanism based on HTTP traffic analysis. It provides formally verified Observable-Read Isolation (ORI) consistency guarantees without requiring modifications to agent code. Empirical results demonstrate that S-Bus achieves conflict prevention efficacy comparable to strict database isolation levels, making it a crucial infrastructure component for building reliable multi-agent systems, particularly in dedicated-shard topologies.
