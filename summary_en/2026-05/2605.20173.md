## 1. What the Paper Did
- **Background**: Production LLM agents combine stochastic model outputs with deterministic systems, yet the boundary between them is rarely treated as a first-class architectural object. As per-call model variance decreases, the architecture surrounding the model becomes the primary driver of long-term reliability.
- **Why Existing Work Falls Short**: Current open-source frameworks implicitly implement verification and commit logic but lack a unified theoretical abstraction for architectural selection. Most production failures (71%) stem from weaknesses at this boundary, yet existing literature focuses on model capabilities rather than the deterministic architecture around them, failing to systematically address coordination, state, and control issues.

## Core Contributions
- **Proposed the "Stochastic-Deterministic Boundary" (SDB)**: Defined as a four-part contract among a proposer (LLM), verifier (deterministic check), commit step (durable write), and reject signal. Organized agent runtime design into three concerns (Coordination, State, Control) and a catalog of six patterns around this primitive.
- **Challenge 1: How to select appropriate architecture patterns for diverse scenarios?**
  - **Difficulty**: Agent scenarios vary (conversational, autonomous, long-horizon), and distributed system concepts mutate when workers are stochastic, making direct application of traditional patterns error-prone.
  - **Solution**: Presented a five-step selection methodology that maps different SDB compositions to specific patterns (e.g., Hierarchical Delegation, Scatter-Gather + Saga) using decision predicates and validation artifacts.
- **Challenge 2: How to diagnose and prevent long-term reliability issues caused by architectural flaws?**
  - **Difficulty**: It is difficult to distinguish errors caused by model variance from systemic failures caused by architectural momentum, especially with new failure modes like "replay divergence."
  - **Solution**: Developed a reliability decomposition model $y(t) = \\mu t + \\sigma\\xi(t)$ to separate model variance ($\\sigma$) from architectural momentum ($\\mu$). Provided a diagnostic procedure mapping production failures to pattern weaknesses and identified replay divergence.

## Implementation and Evaluation
- **Implementation**: Provided a runnable reference implementation for a 90-day contract-renewal agent using the IBM Telco Customer Churn dataset, available in a companion GitHub repository.
- **Evaluation Results**: Applied the methodology to five workloads spanning conversational, autonomous, and long-horizon runtimes. Analyzed 21 published agent failure post-mortems, finding that 81% of documented fixes strengthened one of the four parts of the SDB, validating its centrality.
- **Comparison**: Audited five widely-used open-source frameworks, finding that 19 out of 21 LLM-to-action call sites explicitly instantiated verifier-and-commit logic, proving SDB is a ubiquitous but unnamed engineering surface. Unlike approaches focusing solely on model optimization, this work argues that as model variance compresses, architectural pattern choice becomes the dominant lever for reliability.

## 4. Conclusion
This paper establishes the Stochastic-Deterministic Boundary (SDB) as the load-bearing primitive of production LLM agent runtimes. By defining the SDB's four-part contract, the authors curated six runtime architecture patterns and proposed a selection methodology and failure diagnostic process. The study highlights that as model capabilities improve, architectural momentum (determined by pattern choice and SDB strength) becomes the dominant factor in long-term reliability, providing a systematic engineering methodology for building robust production agents.
