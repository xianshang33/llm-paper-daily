## 1. What the Paper Did
- **Background**: Before an LLM agent can use a tool, a retrieval system must decide how many candidate tools to present (search depth K). Showing too many tools causes selection difficulty and high token costs, while showing too few may miss the correct tool. Most systems use a fixed shortlist size for all queries, lacking a standard metric to evaluate if this size is appropriate.
- **Why Existing Work Fails**: Current document retrieval metrics (e.g., nDCG@K) consider depth but lack an equivalent in tool selection that distinguishes query difficulty and evaluates depth appropriateness. Fixed-K strategies cannot adapt to varying query complexities and make it difficult to diagnose whether failures stem from retrieval misses or model selection errors.

## Core Contributions
- **Proposed a Chance-Corrected Evaluation Framework and Adaptive Depth Selection Mechanism based on Bits-over-Random (BoR)**: The paper introduces BoR as a core metric for evaluating tool retrieval depth and converts it into a reinforcement learning reward signal for dynamic depth adjustment per query.
- **Challenge 1: Lack of standardized metrics for evaluating retrieval depth合理性**. The difficulty lies in traditional metrics failing to isolate "random hit" probability, making it hard to determine if success at a given depth is due to system capability or luck. The paper introduces BoR, which quantifies information gain over random baselines by comparing observed success rates with expected random success rates at the same depth, objectively evaluating depth effectiveness.
- **Challenge 2: Fixed depth fails to balance coverage and context efficiency**. The challenge is that simple queries need few tools while complex ones require deeper search; fixed strategies either waste resources or miss answers. By leveraging the natural decay of BoR with increasing depth (as random hit probability rises), the paper constructs an RL reward that requires no engineered depth penalties, allowing the Agent to automatically learn the optimal truncation depth for each query.

## Implementation and Evaluation
- **Implementation & Setup**: Evaluated across three tool-selection benchmarks (BFCL, MetaTool, ToolBench) with registries ranging from 20 to 3,251 tools. A simple RL Agent was used as a probe, learning shortlist depth per query using BoR as the reward signal.
- **Comparison Results**:
    - **BFCL (370 tools)**: The BoR-driven policy presented an average of only 7 tools while achieving coverage nearly matching that of showing 50 tools (90.3% vs 90.8%).
    - **ToolBench (3,251 tools)**: A fixed shortlist of 5 tools had slightly higher aggregate coverage (64.7% vs 61.9%) but failed completely on hard queries (0% find rate for tools ranked 6th-20th). In contrast, the BoR Agent found 16.7% of these hard cases by searching deeper.
    - **Downstream Validation**: Using Claude Sonnet 4.6, adaptive shortlists significantly improved the LLM's ability to select the correct tool. Overall accuracy was 93.1% (vs 87.1% for fixed 5); the advantage widened on medium-difficulty queries where the correct tool was present but not ranked first (76.8% vs 60.9%).

#### Summary
This paper addresses the limitations of fixed-depth strategies in LLM agent tool retrieval by proposing Bits-over-Random (BoR), a chance-corrected metric, to evaluate and optimize search depth. By converting BoR into a reinforcement learning reward, the method achieves adaptive depth selection without complex engineering penalties. Experiments demonstrate that this approach maintains high coverage while significantly reducing the average number of tools presented, and notably improves LLM tool selection accuracy in complex scenarios, providing a new standard and methodology for tool retrieval evaluation.
