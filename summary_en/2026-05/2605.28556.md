## 1. What the paper did
- **Background**: As agent capabilities advance, existing benchmarks like $\tau^2$-Bench are becoming increasingly saturated. Constructing new benchmark tasks remains complex, costly, and labor-intensive.
- **Limitations of existing work**: The standard approach of writing natural language scenarios first and then mapping them to tool sequences captures only a narrow subset of tool-use patterns. This leads to saturation where high scores reflect benchmark limitations rather than robust task-solving abilities.

## Core Contributions
- **Proposed TASTE (Task Synthesis from Tool Sequence Evolution)**: An automatic method that reverses the task construction process to generate challenging tasks with broader tool-use coverage.
- **Challenge 1: How to generate valid and diverse tool sequences?**
  - **Difficulty**: Randomly generated sequences are often invalid or illogical, and it is hard to cover a wide range of tool combinations.
  - **Solution**: TASTE uses an Adaptive Contrastive n-gram model trained on LLM-judged validity signals to sample valid tool sequences covering a vast range of combinations.
- **Challenge 2: How to ensure task difficulty and representativeness?**
  - **Difficulty**: Simple sequences may be too easy, and representative tasks need to be selected to avoid redundancy.
  - **Solution**: Representative sequences are selected via clustering, instantiated into complete benchmark tasks, and refined through iterative difficulty evolution (e.g., adding decoys, making users less cooperative) to ensure challenge.

## Implementation and Evaluation
- **Implementation**: The authors constructed $\tau^c$-Bench, a challenging extension of the three domains of $\tau^2$-Bench, using TASTE. Code and data are available in an anonymous Git repo.
- **Evaluation Results**:
  - Evaluated on 11 agent/user LLM pairs.
  - Models that nearly saturated $\tau^2$-Bench suffered severe performance drops on $\tau^c$-Bench. For example, Gemini-3-Flash dropped from $0.82-0.94$ to $0.28-0.61$.
  - The generated tasks more than doubled the number of unique tool combinations agents must execute (quantified by Type-Token Ratio, TTR).
- **Comparison**: Compared to the existing $\tau^2$-Bench, $\tau^c$-Bench is not only more difficult but also has broader coverage, revealing the saturation issue in current benchmarks and demonstrating that high scores do not equate to strong task-solving capabilities.

#### Summary
This paper addresses the saturation and high cost of constructing agent benchmarks by proposing TASTE. By reversing the task construction flow, it uses an adaptive contrastive n-gram model to generate valid and diverse tool sequences, and builds high-quality tasks through clustering and iterative difficulty evolution. Experiments show that $\tau^c$-Bench, built with TASTE, effectively distinguishes agent capabilities, exposes the shortcomings of existing benchmarks, and provides a new pathway for continuous, scalable evaluation of future agents.
