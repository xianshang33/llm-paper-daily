## 1. What the Paper Does
- **Background**: Tool-augmented Large Language Model (LLM) agents rely on orchestration layers to coordinate planning, retrieval, tool invocation, validation, and recovery. Failures in these systems stem not only from model errors but also from orchestration-level issues such as tool timeouts, malformed arguments, stale context, contradictory evidence, retry loops, and unverified intermediate outputs.
- **Limitations of Existing Work**: Current recovery mechanisms are often "failure-agnostic." Static workflows terminate or follow fixed branches; retry mechanisms blindly repeat failed calls; prompt-level self-correction lacks specificity; and full replanning restarts execution inefficiently. These methods fail to explicitly connect observable failure signals to likely causes, targeted recovery actions, recovery budgets, and post-recovery verification, leading to ineffective handling of specific orchestration errors.

## Core Contributions
- **Proposed a Self-Healing Agentic Orchestrator**: This orchestrator treats reliability as a bounded runtime control problem, implementing a "monitor-detect-diagnose-recover-verify" loop.
- **Challenge 1: How to achieve precise and efficient recovery for diverse orchestration failures?**
  - **Difficulty**: Different failure signals (e.g., timeout vs. argument error vs. stale context) require distinct recovery strategies. Blind retries or full replanning are either ineffective or excessively costly.
  - **Solution**: The orchestrator maps observable failure signals to inferred failure classes and selects targeted recovery actions conditioned on execution state and remaining recovery budget (e.g., backoff retry for timeouts, evidence refresh for stale context). This preserves useful execution state while enabling efficient repair.
- **Challenge 2: How to prevent "semantic silent failures," where models return plausible but incorrect answers?**
  - **Difficulty**: Traditional non-verifying baselines often generate wrong-but-plausible outputs that the system fails to detect as logical or factual errors.
  - **Solution**: Introduces a verifier-guided self-healing mechanism that strictly verifies recovered trajectories. Experiments show this reduces semantic silent failures to **0.0%**, significantly outperforming non-verifying baselines that frequently return incorrect plausible outputs.

## Implementation and Evaluation
- **Evaluation Setup**: Evaluated on a controlled fault-injection benchmark with 100 tasks, comparing against static workflow, retry-only, ReAct-style, and full-replanning baselines.
- **Key Results**:
  - **Task Success Rate**: The self-healing orchestrator achieved **98.8%**, significantly higher than retry-only (94.5%) and full replanning (93.8%).
  - **Budget Efficiency**: In a matched recovery-budget sweep, self-healing outperformed baselines at every tested budget. Under a single recovery attempt constraint, it achieved **94.0%** success, compared to 85.3% for retry-only and 88.2% for full replanning, showing the largest gap.
  - **Silent Failures**: In a controlled semantic silent-failure setting, verifier-guided self-healing reduced silent failures to **0.0%**, whereas non-verifying baselines returned wrong-but-plausible outputs more often.
- **Model-in-the-Loop Validation**: Compact validation demonstrated that the same recovery mechanism operates effectively when a live tool-calling model performs tool selection, argument generation, and answer synthesis over local fault-injected tools.

## 4. Conclusion
This paper provides controlled evidence that failure-aware, budgeted, and verification-guided orchestration significantly improves reliability and diagnosability in tool-augmented LLM systems. By applying bounded runtime control to agent orchestration, the self-healing mechanism precisely identifies failure roots and executes targeted recovery, avoiding the blindness and inefficiency of traditional methods. This offers a new paradigm for building highly reliable LLM agent systems.
