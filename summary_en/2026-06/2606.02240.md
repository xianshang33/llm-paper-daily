## 1. What the Paper Did
- **Background**: LLM agents interact with third-party SaaS integrations (e.g., Gmail, Salesforce) via tool calls. Indirect prompt injection exploits the "read-write gap," where adversarial content in one integration triggers unauthorized actions in another, posing a concrete production threat.
- **Why Existing Work Fails**: Current benchmarks underestimate the threat due to limited integration coverage, static template-based payloads that lack dynamic attacker behavior, and a lack of evaluation for cross-integration chained attacks. Furthermore, existing guardrails (e.g., Llama Guard) are trained on chat-style data, not tool-response content, creating a blind spot for this specific attack vector.

## Core Contributions
- **Proposed AgentRedBench (a dynamic redteaming benchmark) and AgentRedGuard (an integration-aware defense model).**
- **Challenge 1: Existing benchmarks lack dynamism and diverse real-world integration coverage, leading to inaccurate assessments and overfitting.**
  - **Difficulty**: Static payloads do not reflect adaptive attacker behaviors, and limited integrations fail to represent complex enterprise environments.
  - **Solution**: Created 215 scenarios across 24 enterprise integrations, 9 functional families, and 5 attack types. Used an LLM-driven dynamic redteaming approach where an attacker agent generates injection content. Scenarios are evaluated via a maintainer-mediated channel with immutable versioning to prevent data leakage into training corpora.
- **Challenge 2: Existing guardrails have weak detection capabilities for adversarial content within tool responses, suffering from high false positives or negatives.**
  - **Difficulty**: Traditional models are not optimized for the structure and semantics of integration tool responses, making it hard to distinguish legitimate logic from malicious injections.
  - **Solution**: Released AgentRedGuard, a guardrail model trained on a diverse corpus of adversarial tool-response content from various integrations, specifically optimized for integration-aware defense.

## Implementation and Evaluation
- **Implementation**: The codebase, integration schemas, and AgentRedGuard model are open-sourced. The pipeline involves an attacker agent generating content, an orchestrator placing it in mock integration states, and a target agent executing tool calls, scored by an LLM judge.
- **Results**: 
  - Across an 8-model panel (Anthropic, OpenAI, Google), the no-guard Attack Success Rate (ASR) ranged from 32% (Claude Sonnet 4.6) to 81% (Gemini 3 Flash).
  - **AgentRedGuard Performance**: Reduced the panel ASR from 69.9% to 2.4% with a false-positive rate of only 0.37%.
- **Comparison**: AgentRedGuard outperformed all open-source baselines with non-trivial detection capabilities (Llama Guard, PromptGuard 2, ProtectAI) on both detection accuracy and false-positive rates. Holdout tests across integrations and attack types confirmed strong generalization.

## 4. Conclusion
This paper highlights the severe threat of indirect prompt injection in LLM agents operating within SaaS ecosystems and exposes the inadequacy of current benchmarks and defenses. By introducing the dynamic AgentRedBench and the specialized AgentRedGuard, the authors provide a more realistic security evaluation standard and demonstrate that defense models optimized for tool-response content can significantly mitigate attack success rates, offering crucial insights for secure enterprise deployment of LLM agents.
