## 1. What the Paper Did
- **Background**: As autonomous LLM agents increasingly operate infrastructure with real credentials and without human-in-the-loop, operators lack a standard way to inform agents that certain resources are off-limits. Existing access controls either grant access (due to valid credentials) or hard-fail (indistinguishable from other clients).
- **Limitations of Existing Work**: Current LLM-access research focuses on gateways (API gateways, MCP servers) or role-based models (RBAC/ReBAC). These are external to the resource. There is no standardized method for the resource itself to emit an agent-legible policy in-band, and crucially, no empirical measurement of whether compliant agents would honor such signals.

## Core Contributions
- **Proposed the "Recuse Signal"**: A lightweight, published in-band deny signal emitted by servers over existing protocol channels (e.g., SSH banner, PostgreSQL NOTICE) asking automated agents to voluntarily withdraw. It is designed as a cooperative governance control, analogous to robots.txt for live access, explicitly not a security boundary.
- **Challenge 1: Lack of standardized in-band communication**. The difficulty lies in conveying "no automation" intent from the resource to the agent without significant server-side changes. The paper defines an open mini-standard (Recuse Signal) and implements two zero/low-footprint adapters (SSH banner/PAM hook and PostgreSQL wire-protocol proxy) for easy deployment.
- **Challenge 2: Empirical gap in agent compliance**. It was unknown if LLM agents would respect this non-mandatory cooperative signal. Through controlled experiments, the paper demonstrates that agents do comply: 100% recusal when the signal is present versus 100% task completion in the no-signal control. It also reveals the signal is cooperative, not absolute; explicit operator authorization can override the most capable models.

## Implementation and Evaluation
- **Implementation & Deployment**: The authors defined the Recuse Signal standard and built two reference adapters: one for SSH (using banner and PAM hook) and one for PostgreSQL (injecting NOTICE messages via a pgproto3 proxy). These were deployed on live production hosts.
- **Evaluation Results**: In a pilot study (SSH, testing GPT-4o, GPT-4o-mini, and Claude Code), the signal effectively induced recusal. Results showed 100% recusal with the signal vs. 100% completion without it. The study also found that compliance is model-dependent and context-sensitive; for instance, explicit authorization framing caused the most capable model to proceed despite the signal.
- **Comparison with Related Work**: Unlike traditional gateway or role-based external controls, this approach provides in-band signaling directly from the resource. Contrasted with behavioral enforcement that uses heuristics to detect automation, this work focuses on cooperative governance for willing agents, explicitly excluding defense against malicious actors.

## 4. Conclusion
This paper introduces the "Recuse Signal," an open mini-standard addressing the lack of in-band communication for resource access intent towards autonomous LLM agents. By implementing low-overhead adapters and conducting empirical studies, it proves that mainstream LLM agents can recognize and adhere to this cooperative signal. The work fills a gap in in-band policy communication and agent compliance measurement, offering a lightweight governance tool for infrastructure operators while clearly defining its scope as a cooperative control rather than a security boundary.
