## 1. What the Paper Does
- **Background**: Modern LLM deployments are shifting from isolated single-turn queries to multi-turn agentic systems. These systems execute as stateful programs, interleaving LLM calls with external tool invocations, shifting serving from stateless request processing to stateful program execution.
- **Why Existing Work Fails**: Existing LLM serving simulators (e.g., Vidur, APEX, LLMServingSim) target stateless, request-level workloads, treating each request as an independent prefill-decode pair. They lack abstractions for core agent dynamics such as program identity, tool-induced gaps, and cross-turn KV cache reuse, making them unsuitable for evaluating agent-specific scheduling and caching policies.

## Core Contributions
- **Proposed AGENTSERVESIM**: A hardware-aware simulator for multi-turn LLM agent serving that evaluates policies at program granularity and runs entirely on commodity CPUs.
- **Challenge 1: How to simulate interruptions and gaps caused by tool invocations?**
  - **Difficulty**: Tool calls vary widely in duration (milliseconds to minutes), creating unpredictable idle periods during LLM inference that traditional simulators cannot model.
  - **Solution**: Introduces a "Tool Simulator" module that materializes tool-induced gaps, allowing precise insertion of these delays into the program execution flow to realistically reflect agent timelines.
- **Challenge 2: How to track KV cache residency across turns and stateful contexts?**
  - **Difficulty**: Agent execution involves cross-turn cache locality and KV retention/eviction policies during tool gaps; existing simulators handle only independent requests and cannot track program-level cache state changes.
  - **Solution**: Designs a "KV Residency Model" and a "Session-Aware Router." The former tracks policy-defined KV placement across HBM, host DRAM/CXL, and eviction, while the latter maintains program-to-instance affinity for cache-aware dispatch.

## Implementation and Evaluation
- **Implementation**: AGENTSERVESIM is implemented via composable modules: a Program Orchestrator (preserves identity/order), a Tool Simulator (models gaps), a Session-Aware Router (cache-aware dispatch), and a KV Residency Model (tracks multi-level memory placement). It runs entirely on commodity CPUs without needing expensive accelerators.
- **Evaluation Results**: Across real serving deployments and various hardware configurations, AGENTSERVESIM reproduces real-system behavior within a 6% error margin on key performance metrics.
- **Comparison**: Unlike Vidur and APEX which support only stateless requests, AGENTSERVESIM captures agent-specific dynamics like multi-turn program execution and cross-turn cache locality, filling the gap in simulation tools for agent serving policy exploration.

## 4. Conclusion
This paper addresses the complex state management and resource scheduling issues in multi-turn LLM agent serving by proposing AGENTSERVESIM. By solving the challenges of simulating tool invocation gaps and tracking cross-turn KV caches through modular design, the tool achieves high fidelity (<6% error) in simulating real hardware behavior on low-cost CPUs. This enables controlled, repeatable exploration of agent serving policies without requiring extensive expensive accelerator resources.
