## 1. What the Paper Did
- **Background**: Software engineering tools increasingly rely on LLM-based agents to localize files for issue resolution. Most existing AI agents employ a linear exploration pattern, visiting one directory or file per step.
- **Limitations of Existing Work**: Current linear sequential exploration methods (e.g., Agentless, SWE-agent, RLMs) suffer from a structural mismatch when handling multi-file changes spanning multiple subsystems. A single-threaded agent may exhaust its step or token budget in the first subsystem it explores, missing critical files in others. Additionally, exposing raw file-system access can introduce navigation errors and over-prediction, degrading accuracy.

## Core Contributions
- **Proposed a non-linear, domain-scoped parallel agentic exploration framework**
- **Challenge 1: Structural limitations of linear exploration in multi-file changes**. The difficulty lies in single-threaded agents missing subsystems due to budget constraints. The paper addresses this by introducing domain-scoped parallel agent spawning, allowing small models (e.g., Haiku-class) to explore different domains simultaneously, significantly improving micro-F1 scores.
- **Challenge 2: Navigation noise and over-prediction from raw file-system access**. Unconstrained directory traversal can lead agents into irrelevant test hierarchies, inflating false positives. The paper mitigates this by using structured parallel exploration instead of naive file-system access, reducing localization degradation caused by test-file over-prediction without substantially increasing token costs.

## Implementation and Evaluation
- **Setup**: Using Ansible as an exemplar and SWE-Bench Pro as the initial benchmark, the authors constructed a persistent-session evaluation approach anchored at a single base commit. An expanded benchmark included recent PRs from 2025 and 2026.
- **Baselines**:
    1. Base LLM without direct repository access.
    2. Single-agent Recursive Language Model (RLM) with a persistent Python REPL.
    3. External CLI baseline using Codex 5.5 High.
    4. Larger Sonnet plain LLM baseline.
- **Results**:
    - Domain-scoped parallel agent spawning achieved the highest micro-F1 among Haiku-class models by a large margin.
    - On the expanded benchmark, it ranked second, behind only the much larger Codex 5.5 High.
    - On the original 2020 SWE-Bench Pro, the larger Sonnet plain LLM baseline achieved higher micro-F1 via higher precision (predicting fewer files) but suffered from significantly lower all-gold recall.
    - **Additional Findings**: Documentation co-evolution remains an unresolved latent dependency; forced multi-agent consultation provided no measurable benefit and substantially increased token costs.

## 4. Conclusion
This paper highlights the structural defects of linear exploration patterns in current LLM agents for multi-file change localization. By proposing a non-linear, domain-scoped parallel exploration method, it demonstrates that even smaller models can outperform traditional linear baselines in coverage and accuracy. The study also reveals the risks of raw file-system access and the poor cost-benefit ratio of forced multi-agent consultation, offering key insights for building more efficient software engineering agents.
