## 1. What the Paper Did
- **Background**: LLM-based coding agents are increasingly used in practical software development. Existing multi-agent systems (e.g., ChatDev, MetaGPT, AutoGen) have proposed role-based or conversation-based collaboration models.
- **Limitations of Existing Work**: Most frameworks assume agents operate within the same vendor model family, common runtime, central conversation server, or identical API family. This prevents LLM agents from different vendors from easily exchanging messages directly in their own execution environments while sharing a codebase. Additionally, homogeneous models tend to share error biases, making consensus-based strategies ineffective at filtering shared errors.

## Core Contributions
- **Proposed tap**: A file-based collaboration protocol that enables heterogeneous LLM agents (e.g., Anthropic's Claude and OpenAI's Codex) to collaborate on a single codebase without shared memory or identical runtimes.
- **Challenge 1: Direct communication and state synchronization in heterogeneous environments**. Isolated execution environments and lack of shared memory render traditional central-server or unified-API communication ineffective. **Solution**: tap employs a "file-first" design, using Markdown files with metadata as original message stores. It combines a file inspection path (Tier 1) with environment-specific real-time notification paths (Tier 2), ensuring message persistence and re-inspectability even if notifications fail or receivers restart.
- **Challenge 2: Isolation and inheritance of development and review tasks**. Long-term iterations require context management and work isolation while ensuring continuity. **Solution**: Work is isolated via separate git worktrees. Operations are divided into "generations," where new agent teams inherit records from previous ones upon context limits or mission completion, enabling a 27-day, 37-generation self-evolution process.

## Implementation and Evaluation
- **Implementation & Deployment**: tap is released as an open-source npm package (`@hua-labs/tap` v0.5.2). It uses the file system as the primary message store combined with real-time notifications.
- **Evaluation Process**: A 27-day self-applied operation across 37 generations was conducted, using tap to develop and review itself. This resulted in 209 pull requests and 717 operational artifacts.
- **Evaluation Results**: Analysis of 375 review artifacts showed that 69.8% of reviews by heterogeneous model pairs recorded at least one defect or change request, compared to 53.1% for homogeneous model pairs.
- **Comparison & Conclusion**: The results demonstrate that tap operates effectively in a real production repository. Heterogeneous collaboration broadens review perspectives and detects more defects than homogeneous setups. Unlike Google A2A which relies on HTTP/SSE, tap focuses on local, repository-centric file-based collaboration.

#### Summary
This paper presents tap, a lightweight file-based protocol addressing direct communication between heterogeneous LLM agents without shared runtimes. By combining file-first storage with real-time notifications, tap facilitates efficient collaboration between agents like Claude and Codex. Empirical evidence shows that heterogeneous agent collaboration significantly increases defect detection rates in code reviews, proving the protocol's effectiveness and value in practical production environments.
