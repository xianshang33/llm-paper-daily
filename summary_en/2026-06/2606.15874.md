## 1. What the Paper Does
- **Background**: Most mainstream LLM agent frameworks (e.g., AutoGen, OpenHands) position the LLM as the central "orchestrator," responsible for deciding next steps, tool calls, and termination. While effective for short tasks, this design fails in long-horizon tasks like multi-file refactoring.
- **Why Existing Work Fails**: Current approaches treat symptoms like token explosion, control-flow hallucinations, and unreliable completion as implementation bugs, attempting fixes via better prompts, larger context windows, or retry logic. However, these fail to address the root architectural flaw: assigning deterministic control flow (looping, branching) to a probabilistic system. No matter how strong the model, errors compound over long sequences without architectural guarantees.

## Core Contributions
- **Proposed Agentic Programming**: A new paradigm where the program governs all control flow, and the LLM serves as an adaptive component within it, termed "LLM-as-Code," invoked only for reasoning or generation.
- **Challenge 1: Control-flow Hallucinations and Unstable Execution Paths**. The difficulty lies in probabilistic models deviating from logic or prematurely reporting completion in long sequences. The paper solves this by retaining control flow in the code; the LLM retains flexibility within calls but cannot alter the program's execution path, architecturally eliminating control-flow hallucinations.
- **Challenge 2: Token Explosion and Context Redundancy**. The difficulty is that traditional ReAct patterns accumulate context linearly, causing loss of early information or window overflow. The paper constructs a Directed Acyclic Graph (DAG) from the execution history's call tree, ensuring context length is determined by call depth rather than step accumulation, effectively managing context size.

## Implementation and Evaluation
- **Implementation & Case Study**: The design is validated through a case study on computer-use agents. The LLM is encapsulated as an adaptive component in code, with the program handling the logic of visual operation sequences.
- **Evaluation Results**: Experiments show that Agentic Programming substantially improves the stability of long visual operation sequences. Compared to frameworks where the LLM autonomously decides every step, the new method demonstrates greater robustness in long-horizon, multi-step tasks, avoiding failures caused by context truncation or logical jumps.
- **Comparison**: Unlike mainstream frameworks like AutoGen that rely on full LLM orchestration, this approach demonstrates architectural superiority in long-horizon tasks, proving that a hybrid mode (deterministic logic in code, probabilistic reasoning in LLM) outperforms pure LLM-driven modes.

## 4. Conclusion
This paper critiques the architectural flaw of using probabilistic models for deterministic control flow in current LLM agent frameworks. It proposes Agentic Programming and the LLM-as-Code concept, where control flow is managed entirely by the program, and the LLM is embedded as a node in a DAG structure. This approach fundamentally resolves token explosion and control-flow hallucinations, offering a new architectural perspective for building reliable, scalable long-horizon agent systems.
