## 1. What the Paper Did
- **Background**: Agent memory systems consist of a "recall plane" for retrieving facts and a "control plane" for mutating them (supersede, release, purge). In production, the primary failure mode is "forgetting failure" (e.g., rotated credentials still being recommended, GDPR-deleted records resurfacing), not retrieval failure.
- **Why Existing Work Fails**: Current memory frameworks and benchmarks (e.g., LongMemEval, MTEB, BEIR) are saturated with optimizing recall metrics (R@k) and completely neglect testing the "controlled forgetting" capability. High recall accuracy does not guarantee the system can correctly execute forget commands, leading to poor performance when data deletion or update is required.

## Core Contributions
- **Proposed ForgetEval benchmark and an architectural study on control-plane LLM placement**: Includes a 1000-case templated suite, a 385-case adversarial layer, and an adapter protocol for heterogeneous memory stores.
- **Challenge 1: Forgetting failures due to canonicalization issues (cross-lingual/identifier obfuscation)**. The difficulty lies in deterministic primitives failing to handle semantic equivalence. The paper shows that introducing an LLM at "inscribe-time" for canonicalization recovers success rates from ≤5% to 100% in these scenarios.
- **Challenge 2: Intent-aware deletion failures (e.g., prefix collisions, compound facts)**. The difficulty is that inscribe-time processing cannot grasp complex deletion intents or context dependencies. The paper proposes hooking an LLM at "mutation-time," which recovers intent-aware deletion capabilities (78-85% success) and boosts overall performance across nearly all categories to 91.7-93.2%.

## Implementation and Evaluation
- **Implementation**: ForgetEval comprises 132 hand-crafted and 253 LLM-drafted/oracle-validated cases, scored via deterministic substring matching. A six-method Adapter Protocol allows integration of diverse memory backends in ~130 lines of code. All assets are released under MIT license.
- **Evaluation Results**:
    - **Deterministic Primitives**: Suffice for lexical/temporal tasks but fail significantly in identifier obfuscation and cross-lingual settings (0-5% success).
    - **Inscribe-time LLM**: Solves canonicalization (100% success) but fails completely in intent-aware deletion (0%).
    - **Mutation-time LLM Hook**: Achieves 91.7-93.2% overall success rate with unchanged recall paths. Cost is ~$0.17 per 385-case run, with mutation latency of ~2.3s/case (vs. 64-191ms for deterministic).
- **Comparison with Related Work**: For instance, MemPalace scores 60/150 on the Memora recall benchmark but scores 0/385 on the adversarial forgetting tests, demonstrating the disconnect between recall optimization and control-plane efficacy. External blind validation replicated the findings, showing a +27.8 point lift from joint placement.

## 4. Conclusion
The paper reveals that the placement of the LLM within the agent memory pipeline (inscribe-time vs. mutation-time) dictates which forgetting failure modes the system can recover from. Using the ForgetEval benchmark, the authors demonstrate that existing recall-centric optimizations are insufficient for production privacy and consistency needs. The optimal approach involves a "mutation-time LLM hook" or a hybrid architecture combining inscribe-time canonicalization, achieving efficient controlled forgetting with manageable cost and latency.
