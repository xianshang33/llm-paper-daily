## 1. What the Paper Did
- **Background**: LLM agents increasingly use the Model Context Protocol (MCP) to answer questions by drawing from heterogeneous evidence sources such as search engines, APIs, databases, and clinical records.
- **Limitations of Existing Work**: Standard factuality and faithfulness metrics typically evaluate whether an answer is supported by pooled evidence, ignoring a provenance-sensitive failure mode: a claim may be supported by some evidence but attributed to the wrong source. The authors term this "cross-source conflation," which existing source-blind methods fail to detect.

## Core Contributions
- **Proposed ProvenanceGuard**: A source-aware verifier designed specifically for MCP-grounded answers to detect and correct cross-source conflation.
- **Challenge 1: How to precisely map claims to their specific supporting sources?**
  - **Difficulty**: Determining exactly which source supports a specific claim is difficult, especially when multiple sources contain semantically similar but distinct information.
  - **Solution**: ProvenanceGuard consumes captured MCP traces (with stable tool/source IDs and raw outputs), decomposes answers into atomic claims, and routes each claim to source-specific evidence. It verifies support using Natural Language Inference (NLI) and a token-alignment proxy, then compares the claim's stated attribution against the routed source.
- **Challenge 2: How to handle verification failures and incorrect attributions?**
  - **Difficulty**: Merely detecting errors is insufficient; the system needs self-correction capabilities to avoid discarding too many answers, which would hinder usability.
  - **Solution**: The system returns per-claim verdicts and an answer-level allow/block decision. For blocked answers, it invokes a Retrieval-Augmented Answer Revision (RARR)-style repair mechanism to revise the answer and re-verify it, balancing factual accuracy with answer availability.

## Implementation and Evaluation
- **Dataset**: Evaluated on 281 captured medical-domain MCP-agent traces. A subset of 266 traces yielded 2,325 LLM-assisted claim labels, with 361 held-out labels verified by human experts.
- **Key Results**:
  - On a 40-trace held-out split, ProvenanceGuard achieved a **Block F1 of 0.802** and **Source Accuracy of 0.858** over 260 source-eligible claims.
  - **Comparison with Baselines**: Source-blind baselines (MiniCheck, RAGAS Faithfulness, AlignScore, SummaC-ZS) cannot emit claim-to-source IDs. MiniCheck achieved a Block F1 of 0.783, while others performed worse, highlighting the advantage of source-awareness.
  - **Harder Scenario**: On a multi-source benchmark, Block F1 reached 0.846, but source-plus-relation accuracy dropped to 0.229, indicating that exact source ownership remains challenging among semantically close sources.
  - **Repair Efficacy**: The repair-and-reverify loop resolved all 173 blocked answers in the full trace set (mostly via conservative fallback). In 50 controlled clinical conflation probes, ProvenanceGuard detected all injected attribution swaps with zero retained wrong attributions.

## 4. Conclusion
ProvenanceGuard demonstrates that source attribution is an independent and critical axis for factuality verification in MCP-based agents. By introducing a source-aware verification mechanism and a repair loop, the method effectively addresses "cross-source conflation," a failure mode overlooked by traditional metrics. This significantly enhances the reliability and interpretability of LLM agent outputs in high-stakes domains like healthcare, outperforming existing source-blind baselines despite remaining challenges in distinguishing between semantically similar sources.
