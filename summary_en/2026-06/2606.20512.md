## 1. What the Paper Did
- **Background**: LLM-based coding agents require high-level operational knowledge about a repository (e.g., subsystem file locations, test execution methods, historical debugging workflows) that is not explicitly present in the code. Engineers often maintain `AGENTS.md` files to provide this context, but recent studies disagree on whether LLM-generated guidance improves or harms agent performance.
- **Why Existing Work Falls Short**: Previous approaches typically rely on single-pass LLM generation, which yields generic advice that may lack specificity or even be counterproductive. Existing literature fails to distinguish between the concept of guidance and the method of its production, leaving practitioners without a principled basis for investing in such context files.

## Core Contributions
- **Proposed**: "Probe-and-Refine Tuning," a procedure that uses synthetic bug-fix probes to iteratively diagnose and patch a repository's guidance file via single-shot LLM calls, without requiring an agent loop or tool use during tuning.
- **Challenge 1: How to automatically generate high-quality, repository-specific operational guidance?**
    - **Difficulty**: Static or one-time generated guidance is often too generic to capture implicit repository knowledge (e.g., specific debugging workflows), causing agents to waste steps in wrong files or propose breaking changes.
    - **Solution**: The paper introduces synthetic bug-fix probes as diagnostic tools to iteratively identify gaps or errors in the guidance file. It then uses LLMs to directly patch the guidance, transforming generic advice into refined instructions targeted at specific failure modes.
- **Challenge 2: How to verify that improvements stem from increased coverage rather than chance or code quality?**
    - **Difficulty**: It is difficult to distinguish whether performance gains come from the agent finding the correct file (coverage/navigation) or generating higher-quality code patches (precision).
    - **Solution**: Through detailed ablation studies and statistical analysis, the paper demonstrates that performance gains are primarily driven by increased coverage (14.5 percentage points more evaluable patch instances), while per-patch precision remains statistically constant. This indicates that refined guidance helps agents navigate to the correct files rather than improving the quality of the code changes themselves.

## Implementation and Evaluation
- **Implementation & Deployment**: Evaluated on the SWE-bench Verified benchmark using the Qwen3.5-35B-A3B model with a 200-step limit, across four independent trials. The tuning process involves only single-shot LLM calls, avoiding complex agent loops.
- **Evaluation Results**:
    - **Probe-and-Refine**: Achieved a mean resolve rate of 33.0%.
    - **Static Knowledge Base Baseline** (initial guidance): 28.3%.
    - **Unguided Baseline**: 25.5%.
    - Statistical Significance: Both contrasts against Probe-and-Refine were significant (p < 0.001).
- **Comparison with Related Work**:
    - Contrasting with Lulla et al. (2026) and Gloaguen et al. (2026), this paper shows that the efficacy of guidance depends on its generation method. The proposed iterative refinement addresses issues where LLM-generated context was previously found to be harmful.
    - **Step-Budget Experiment**: Demonstrated that good guidance allows agents to productively utilize larger step budgets.
    - **Cross-Model Experiment**: Using NVIDIA-Nemotron-3-Nano-30B-A3B, the study found that the tuning loop degrades if the model cannot generate sufficient diagnostic output, yet per-patch precision remains constant, further confirming that guidance primarily impacts navigation.

#### Summary
This paper highlights the critical role of repository guidance files (like `AGENTS.md`) for coding agents and argues that their effectiveness hinges on the generation method. By introducing "Probe-and-Refine Tuning," the authors demonstrate that iterative, failure-diagnosed guidance significantly improves resolve rates on SWE-bench. The key finding is that optimized guidance enhances performance primarily by improving the agent's ability to locate the correct files (coverage), not by increasing the precision of the code patches. This provides a principled methodology to resolve current controversies regarding the utility of context guidance in AI-assisted programming.
