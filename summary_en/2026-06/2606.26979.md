## 1. What the Paper Did
- **Background**: LLM-based code agents typically employ a "grep-first" retrieval strategy, navigating repositories via keyword searches. While fast and infrastructure-light, this approach ignores structural relationships (e.g., call graphs, inheritance hierarchies, configuration dependencies) that define how software actually works.
- **Why Existing Work Falls Short**: Current grep-first agents suffer from a fundamental representation mismatch. Grep returns lines based on lexical criteria without exposing structural topology (who calls whom, data flow). This forces agents to rediscover structural links through ad-hoc multi-hop queries, leading to fragmented context. Furthermore, the inherent stochasticity of LLM controllers makes agent navigation random and difficult to reproduce across runs.

## Core Contributions
- **Proposed Deterministic Anchoring**: The study investigates whether lightweight static analysis can provide "deterministic anchors" by injecting stable structural facts as plain-text comments, thereby constraining probabilistic exploration and making navigation more predictable.
- **Challenge 1: How to improve navigation discipline and reproducibility without excessive context overhead?**
  - **Difficulty**: Injecting full static analysis graphs creates context bloat, while pure keyword search lacks structural constraints, leading to random behavior.
  - **Solution**: The paper proposes injecting lightweight call/inheritance topology as plain-text comments. This does not necessarily make agents "smarter" but disciplines their navigation by providing stable structural facts, reducing randomness.
- **Challenge 2: How to determine the optimal granularity of static structure injection for different repository scales?**
  - **Difficulty**: Dense semantic information yields diminishing returns, and fully connected links in hub-heavy projects can cause information overload.
  - **Solution**: The study finds anchoring is scale-sensitive. For medium projects, use lightweight topology; for large, hub-heavy repositories, prune forward edges and use inverse-only links ("who-calls-me"); reserve dense tags for implicit dependencies.

## Implementation and Evaluation
- **Implementation & Baseline**: Built upon OpenAI's Codex as a strong baseline. The study systematically injects structural annotations of varying granularities and measures effects on localization, trajectory, and stability.
- **Key Results**:
  1. **Anchoring Works**: Lightweight topology improves function-level localization (Func@5 +2.2pp) and shortens trajectories (-1.6 interaction rounds).
  2. **Stability**: Tags increase link-following rates (0.15-0.18 to 0.21-0.24), roughly halve run-to-run variance, and improve single-run reliability (Pass@1 +3.4pp) on medium-scale repos, with ~10% more input tokens.
  3. **Scale Sensitivity**: Diminishing returns for dense semantics; inverse-only links benefit hub-heavy projects.
- **Comparison**: Unlike complex graph-based approaches, this method retains the lightweight nature of grep-first agents while mitigating their stochasticity and structural blindness, offering better stability and reproducibility in end-to-end repair benchmarks.

## 4. Conclusion
The paper identifies the "deterministic anchoring effect": static structure helps less by making agents "smarter" and more by making their navigation disciplined and reproducible. It provides practical guidelines: default to lightweight topology for medium projects, prune forward edges in large repositories, and use dense tags sparingly. This work offers a new perspective on balancing the determinism of static analysis with the probabilistic exploration of LLMs.
