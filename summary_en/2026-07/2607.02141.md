## 1. What the Paper Did
- **Background**: As Large Language Models (LLMs) evolve towards agent-style capabilities involving code execution and tool use, there is a need to evaluate their end-to-end problem-solving skills on concrete tasks. Linear Programming (LP) from text is a strict test requiring simultaneous correctness in natural language understanding, mathematical formulation, code generation, and numerical computation.
- **Why Existing Work Falls Short**: Current LP-from-text benchmarks (e.g., NL4OPT, MAMO) are static datasets with human-authored and labeled problems. They have fixed sizes and difficulties, are prone to data leakage into future LLM training sets, and are costly and difficult to scale due to manual annotation.

## Core Contributions
- **Proposed A$^{2}$utoLPBench**: An auto-generated, agent-friendly benchmark for linear programming, consisting of a generator for on-demand fresh problems and a ready-to-run evaluation environment.
- **Challenge 1: How to ensure absolute ground truth correctness without expensive external solver verification?**
  - **Difficulty**: Traditional methods generate problems first and then verify with solvers, which relies on external tools and risks errors from numerical issues or solver failures.
  - **Solution**: Uses "Inverse-KKT Construction." It first selects a feasible point and its dual variables, then reverse-engineers an LP problem for which this point is the optimal solution. Thus, the answer is known by construction, requiring no solver calls or human annotators.
- **Challenge 2: How to prevent training data leakage and enable controllable difficulty adjustment?**
  - **Difficulty**: Static datasets are fixed upon release, making them susceptible to memorization by models, and lack dynamic complexity adjustment.
  - **Solution**: Designed as a generator rather than a fixed dataset. Difficulty is controlled via a "knob" using variable count $n$ and constraint count $m$. Using new seed ranges post-cutoff ensures fresh problems and resistance to data leakage.

## Implementation and Evaluation
- **Implementation & Deployment**: The evaluation environment bundles a reference "solver-critic" baseline and a Docker image. Instructions within the Docker image are tailored for LLM-driven agents, allowing any agent to run the benchmark and get a calibrated score with a single command.
- **Evaluation Results**:
  - **Smooth Difficulty Response**: Empirical results show that solve rates change smoothly with problem size ($n, m$), validating effective difficulty control.
  - **Repeatability**: Independent batches yield matching scores, demonstrating the stability of the benchmark.
  - **Baseline Effectiveness**: The bundled solver-critic baseline aids performance not only on A$^{2}$utoLPBench but also on existing LP benchmarks.
- **Comparison**: Compared to manual datasets like NL4OPT and MAMO, A$^{2}$utoLPBench offers unlimited fresh problems, construction-guaranteed ground truth, lower LLM-side costs, and robustness against data leakage.

## 4. Conclusion
A$^{2}$utoLPBench addresses the limitations of static, high-cost, and leak-prone LP benchmarks by employing inverse-KKT construction. It provides a dynamic, difficulty-controllable, and agent-accessible evaluation framework, offering a reliable tool for assessing the end-to-end capabilities of LLM agents in mathematical programming and code execution.
