## What the Paper Did
- **Background**: Modern coding agents expose multiple tool surfaces, including IDE primitives (e.g., Read/Edit), Bash, and Model Context Protocol (MCP) code-execution tools. The field has produced three contradictory claims regarding which surface is critical: some argue specialized IDE primitives are essential, others claim Bash alone is sufficient, and industry reports suggest replacing all native tools with code execution can reduce token usage by ~98–99%.
- **Why Existing Work Falls Short**: Previous studies have never performed a crossed comparison on a single harness, using the same models and prompts, stratified by task regime and agent design. Consequently, it remains unclear under which conditions each claim applies or whether they genuinely contradict each other.

## Core Contributions
- **Proposed**: An integrity-clean three-arm ablation framework (baseline / bash_only / code_only) evaluated on synthetic computation tasks and SWE-bench Mini modification tasks. The study holds the model, harness, and prompts fixed while crossing two agents (Claude Code, OpenAI Codex CLI) with two task regimes.
- **Challenge 1: How to decouple the impact of task regime and agent design on tool selection?**
  - **Difficulty**: Differences in agent architectures and task types (e.g., pure computation vs. code modification) can lead to different optimal tool surfaces, making single-dimension comparisons biased.
  - **Solution**: By constructing a (Regime × Agent-Design) matrix and strictly controlling variables, the study reveals that the cheapest tool surface is jointly determined by both task regime and agent design, not by either axis alone.
- **Challenge 2: How to accurately assess the cost impact of tool restrictions, distinguishing between successful and failed runs?**
  - **Difficulty**: Simple average costs may mask high expenses on specific failure trajectories, leading to misjudgments of tool efficiency.
  - **Solution**: Introduced conditional-cost analysis to localize cost gaps to failure costs on "doomed-run" trajectories rather than a per-edit tax on successful runs. This revealed that the headline cost signal resides in cache-adjusted costs, while pass rates remain invariant across surfaces.

## Implementation, Deployment, and Evaluation Results
- **Implementation & Deployment**: The study utilized two benchmark suites: a synthetic Artifact benchmark for computation tasks and SWE-bench Mini for code modification tasks. Three tool arms were implemented: Baseline (default tools), bash_only (native bash + read/glob/grep, removing Edit/Write), and code_only (single MCP execute_code tool, disabling all native built-ins). The benchmark harness and code are open-sourced.
- **Evaluation Results**:
  - In three out of four (regime, agent) cells, restricting the agent to the execute_code tool was cheaper than or statistically tied with its cheapest tool-rich rival (significant on Artifact/Claude and SWE-bench/Codex; directional on Artifact/Codex).
  - The lone exception was SWE-bench/Claude, where code_only was directionally costlier (+14.4%, not significant), attributed to failure costs on doomed trajectories.
  - Pass rates were statistically tied across all cells, indicating that changing the tool surface does not affect success rates at the evaluated model sizes, but primarily impacts cache-adjusted costs.
- **Comparison**: Contrasting with SWE-agent's emphasis on ACI primitives, mini-SWE-agent's sufficiency of Bash, and industry claims of massive token reduction via MCP, this paper demonstrates that these conclusions are contingent on specific task and agent combinations, disproving the existence of a universally "best" tool surface.

## Summary
This paper resolves the controversy over coding agent tool interface selection through rigorous crossed ablation experiments. It finds that restricting agents to a single execute_code MCP tool is generally cost-effective or comparable, without compromising pass rates. The optimal tool surface depends on the joint effect of task regime and agent design. Cost optimization hinges on cache-adjusted costs, particularly by avoiding high expenses on doomed trajectories. These findings provide empirical evidence for future coding agent tool design, emphasizing the importance of contextualized design.
