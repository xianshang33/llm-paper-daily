## 1. What the Paper Did
- **Background**: Infrastructure-as-Code (IaC) scanners detect cloud misconfigurations in Terraform before deployment, but repairing these issues remains largely manual. While recent Large Language Model (LLM)-based approaches can repair some findings, they often hallucinate unsupported constructs or suppress warnings without actually fixing the issue.
- **Limitations of Existing Work**: Current LLM-based repair methods lack tool grounding, leading to hallucinations of invalid Terraform structures. They also fail to effectively determine when to escalate issues due to missing deployment-specific context, resulting in a significant gap between claimed and verified repair rates.

## Core Contributions
- **Proposed TerraRepair**: A prototype of a tool-grounded LLM agent for Terraform repair with structured escalation.
- **Challenge 1: LLMs tend to hallucinate invalid or unsupported configuration structures in IaC repair.**
  - **Difficulty**: Terraform relies on specific Provider Schemas and versions; LLMs trained on general data cannot guarantee that generated HCL code adheres to current environmental syntactic and semantic constraints.
  - **Solution**: TerraRepair grounds the generation process by querying the installed Provider Schema and retrieving dependency context from Terraform references. It re-runs the scanner to verify candidate repairs before returning them.
- **Challenge 2: When deployment-specific context (e.g., KMS keys, CIDR ranges) is missing, LLMs tend to fabricate plausible but unusable fixes.**
  - **Difficulty**: Many security repairs require specific environmental parameters not available in static code analysis, which LLMs cannot infer, leading to erroneous forced repairs.
  - **Solution**: TerraRepair introduces a structured escalation mechanism. When required deployment-specific context is absent, the agent escalates the issue instead of fabricating a fix, thereby preventing invalid repairs.

## Implementation and Evaluation
- **Experimental Setup**: Evaluated on two vulnerable-by-design Terraform repositories using two IaC security scanners (Checkov and Trivy) across AWS, Azure, and GCP.
- **Baseline**: Compared against a controlled one-shot LLM baseline.
- **Key Results**:
  - On the combined AWS benchmark, TerraRepair significantly improved scanner-verified fix rates: from 26.6% to 78.4% for Checkov, and from 44.8% to 72.4% for Trivy.
  - It drastically reduced the gap between "claimed" and "verified" repairs: from 44.8–73.6 percentage points in the baseline to under 5 percentage points for TerraRepair.
  - In a sampled semantic audit, 78.9% of TerraRepair's scanner-verified AWS repairs were labeled as correct under a majority-vote protocol.

## 4. Conclusion
TerraRepair demonstrates that tool grounding can substantially improve scanner-verified LLM-based IaC repair success rates. By combining Provider Schema queries, dependency context retrieval, and structured escalation, it effectively addresses LLM hallucinations and context missingness. However, the study highlights that missing deployment-specific context remains the primary knowledge boundary for achieving full autonomy in IaC repair.
