## 1. What the Paper Does
- **Background**: LLM agents increasingly rely on tool calling to interact with external systems, with the Model Context Protocol (MCP) becoming the de facto interface. However, operating MCP at cloud scale presents significant challenges.
- **Why Existing Solutions Fail**:
    1. **Tool Providers**: Legacy services are not directly callable via MCP, and rapid protocol evolution creates ongoing compatibility costs.
    2. **Agent Side**: The number of accessible tools is constrained by the LLM context window and inference overhead. Mounting large tool sets increases token usage, latency, and reduces task success rates.
    3. **Architectural Limits**: Maintaining session affinity for stateful MCP backends with multiple replicas increases client-side complexity. Existing web-oriented load balancers cannot be directly reused because MCP routing information resides in the HTTP body rather than headers.

## Core Contributions
- **Proposed**: A cloud-scale gateway system for MCP services. This system breaks the direct-connect model on the data plane, offloading legacy service integration, consolidation of incompatible MCP variants, access control, tool recommendation, and session-aware routing to the gateway.
- **Challenge 1: Legacy Integration and Protocol Compatibility**. Integrating massive existing OpenAPI services and handling frequent MCP updates is costly and complex for developers. **Solution**: The gateway includes a protocol adaptation module that translates MCP calls into existing API calls and bridges incompatible MCP variants, abstracting away underlying differences and reducing adaptation costs.
- **Challenge 2: Efficiency and Context Limits in Large-Scale Tool Selection**. Limited LLM context windows make it inefficient to input thousands of tool descriptions, leading to token explosion and reduced accuracy. **Solution**: The gateway implements a hybrid retrieval mechanism that returns only the most relevant candidate tools to the LLM. This maintains high recall while significantly reducing token usage and selection time, supporting scalability to over 3,000 tools.

## Implementation and Evaluation
- **Implementation & Deployment**: The system is deployed in production on Alibaba Cloud, handling large-scale traffic. The gateway manages protocol translation, access control, and routing, addressing the inability of traditional L7 load balancers to parse MCP internal routing info.
- **Evaluation Results**:
    - **Accuracy**: The hybrid retrieval mechanism sustains 98% Top-15 recall.
    - **Scalability**: Supports agent access to 3,000+ tools with stability during scale-out.
    - **Performance**: Reduces tool selection time by 8.9x and token usage by 23.8x compared to baselines.
    - **Overhead**: Incurs low per-call overhead.
- **Comparison**: Compared to the traditional direct-connect model where clients manage all connections and compatibility, this gateway approach significantly reduces client complexity and offers superior resource efficiency and stability at scale.

## 4. Conclusion
This paper addresses the challenges of legacy integration, context window limits, protocol compatibility, and complex session routing for LLM agents using MCP at cloud scale. It proposes a cloud-scale MCP gateway that shifts protocol adaptation, tool retrieval, and routing logic from the client to the gateway. By employing hybrid retrieval, the system successfully transitions from a direct-connect model to a centralized gateway model. Experiments demonstrate that the system supports access to thousands of tools while drastically reducing token consumption and latency, improving tool selection accuracy and scalability, thus providing a viable infrastructure solution for large-scale LLM agent deployment in production.
