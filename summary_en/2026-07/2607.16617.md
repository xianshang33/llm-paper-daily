## 1. What the Paper Did
- **Background**: Large Language Models (LLMs) are increasingly used to automate data-processing workflows (e.g., synthetic data generation, evaluation). However, existing coding agents typically produce free-form scripts that do not automatically materialize as persistent, editable platform-native artifacts.
- **Limitations of Existing Work**: This disconnect is termed the "NL2Pipeline gap". Current methods lack deep integration with underlying data platforms, making the resulting scripts difficult to maintain, edit, or visualize, and often incurring high computational costs and latency due to repeated generation and debugging cycles.

## Core Contributions
- **Proposed DataFlow-Harness**: A grounded code-agent platform that guides an LLM agent to construct platform-native Directed Acyclic Graphs (DAGs) through typed, incremental mutations rather than generating free-form scripts.
- **Challenge 1: How to accurately translate natural language intents into persistent, platform-native DAG structures?**
  - **Difficulty**: Direct script generation is error-prone and non-editable, while generating complex DAGs requires understanding platform-specific operator registries and states.
  - **Solution**: Introduced a Model Context Protocol (MCP) layer to expose live operator registries and pipeline states, combined with DataFlow-Skills for procedural guidance. This guides the LLM to perform typed, incremental modifications, ensuring the generated DAGs are both platform-compliant and editable.
- **Challenge 2: How to reduce construction costs and improve reliability?**
  - **Difficulty**: Traditional code generation baselines (e.g., Vanilla Claude Code) often require multiple attempts to generate correct code, leading to high latency and monetary costs.
  - **Solution**: Synchronized conversational authoring with a visual DAG editor via DataFlow-WebUI, leveraging platform grounding to reduce hallucinations and invalid attempts. Experiments show this approach maintains pass rates comparable to context-aware baselines while significantly reducing cost and latency.

## Implementation and Evaluation
- **Implementation & Deployment**: The system comprises a data pipeline backend, DataFlow-WebUI (frontend visual editor), an MCP tool layer (connecting LLM to platform state), and DataFlow-Skills (procedural knowledge base). The code is open-sourced.
- **Evaluation Results**:
  - Achieved a 93.3% observed end-to-end pass rate on a 12-task data-engineering benchmark.
  - **Vs. Vanilla Claude Code**: Reduced monetary cost by 72.5% and generation latency by 49.9%.
  - **Vs. Context-Aware Claude Code Baseline**: Observed pass rate was within 0.9 percentage points, but with 42.8% lower cost.
- **Analysis**: Per-task analysis indicated that Skills are most useful when construction depends on implicit procedural knowledge. Results demonstrate that live platform grounding produces persistent, editable workflow artifacts with reliability close to script-generation baselines but at lower construction cost and latency.

## 4. Conclusion
DataFlow-Harness effectively addresses the "NL2Pipeline gap" for LLM code agents in data engineering. By combining the MCP protocol, skill-based guidance, and synchronized visual editing, the platform enhances the reliability and editability of workflow generation while significantly reducing economic costs and time latency, offering an efficient solution for constructing LLM-driven data pipelines in production environments.
