## What the Paper Does
- **Background**: LLM agents are increasingly used to create reusable scripts, wrappers, or skills. However, building tools incurs a fixed cost (time and tokens), requiring agents to trade off between "writing a script for the current task immediately" and "waiting for more evidence of recurrence for reuse." An ideal agent should prefer creating a few highly reusable tools over many one-offs.
- **Why Existing Work Falls Short**: Current evaluations focus on whether models can write correct tools, select available ones, or retrieve from libraries, ignoring the fundamental decision of *when* to create a tool. While prior studies suggest models lack budget awareness but can be easily post-trained, this paper identifies an unaddressed capability gap between abstract allocation reasoning and concrete tool creation, showing that existing budget-aware methods fail to induce selective tool creation in scripts.

## Core Contributions
- **Proposed AlloBench**: A paired benchmark designed to test whether LLM agents exhibit conscious resource allocation behavior under a fixed budget in two contexts: an abstract text-based formulation and a concrete code-construction task.
- **Challenge 1: Failure to Transfer Abstract Reasoning to Concrete Execution**. The difficulty lies in the fact that models may understand optimal allocation strategies abstractly but fail to apply them to code generation decisions. Through comparative experiments, the paper finds that all tested frontier models (Claude Haiku/Opus, GPT-5.4-mini, GPT-5.6 Sol) perform near-optimally in abstract framing but completely fail to transfer this ability to script-writing, revealing a significant capability boundary.
- **Challenge 2: Distinct Failure Modes Across Models**. The challenge is identifying at which stage models abandon selective strategies. Refined experiments show that the first three models fail even when scripts are not evaluated, while GPT-5.6 Sol remains selective under weaker manipulations and only collapses during full construction. Additionally, an open-source Qwen model policy-trained for abstract allocation generalizes across lexical variations but shows no improvement in script allocation, highlighting the limitation of this transfer.

## Implementation, Evaluation, and Comparison
- **Implementation**: AlloBench consists of abstract text tasks and code construction tasks, run under a fixed action budget. Code, environments, and raw logs are open-sourced.
- **Evaluation Results**:
    - **Frontier Model Performance**: Claude Haiku, Claude Opus, GPT-5.4-mini, and GPT-5.6 Sol all demonstrate near-optimal strategies in abstract allocation tasks, indicating they understand basic resource trade-off concepts.
    - **Transfer Failure**: All aforementioned models fail to transfer these strategies to script-writing tasks. They do not effectively choose when to build tools based on budget constraints, often exhibiting over-building or under-building.
    - **Failure Mode Analysis**: Models like Claude and GPT-5.4-mini lose selectivity even when script execution is not required; GPT-5.6 Sol performs slightly better, maintaining selectivity in simple conditions but collapsing under the pressure of full code construction.
    - **Fine-tuned Model Performance**: An open-source Qwen model policy-trained for abstract allocation generalizes its ability across held-out lexical variations but shows no improvement in script allocation tasks, further confirming the barrier between abstract reasoning and concrete code generation.
- **Comparison with Related Work**: Contrary to prior views that models merely lack natural budget awareness which is easily fixable via post-training, this paper proves there is a fundamental capability wall where abstract allocation skills do not automatically translate into budget-aware behavior in tool creation, a gap existing work has not sufficiently addressed.

## Summary
This paper introduces AlloBench, revealing significant deficiencies in the online tool allocation capabilities of modern LLM agents. While frontier models can understand and execute near-optimal resource allocation strategies at an abstract level, they fail to transfer this ability to actual code construction tasks. Both closed-source frontier models and specifically policy-trained open-source models exhibit systematic failures in budget-aware selection for script writing. This finding establishes online tool allocation as a critical capability boundary for current LLMs, suggesting that future research must focus on bridging the gap between abstract reasoning and concrete tool generation.
