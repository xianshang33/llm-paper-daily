## 1. What the Paper Did
- **Background**: In agentic software development, third-party API routers (e.g., LiteLLM, OpenRouter) have become a common middleware layer to unify access to diverse LLM providers. Coding agents often operate with high autonomy to reduce interaction overhead, placing the router on the trusted path between the agent and the upstream provider.
- **Why Existing Work Falls Short**: Existing client-side permission mechanisms assume LLM outputs are trustworthy. However, routers can inspect and modify every request and response, and there is no mechanism to verify alignment between the provider's output and the repository-level actions executed by the agent. This control gap renders client-side safeguards potentially ineffective, and its real-world impact had not been empirically measured prior to this work.

## Core Contributions
- **Proposed SIDEL Framework**: A framework for trace recording, replay, injection, and defense evaluation, accompanied by a curated dataset of 400 samples.
- **Challenge 1: Subtlety and Diversity of Router-Side Injection**. The difficulty lies in attackers replacing or appending malicious commands without altering contextual explanations, or using LLMs to polish injections to align with normal output distributions, thereby bypassing rule-based detection. The paper addresses this by defining four levels of increasing subtlety (L1 Response Substitution, L2 Response Append, L3 LLM-Polished Injection, L4 Distribution Alignment Injection) to systematically simulate and evaluate these attacks.
- **Challenge 2: Insufficiency of Existing Client-Side Defenses**. The challenge is that high-autonomy agents struggle to semantically validate every operation in real-time, and traditional whitelists or post-hoc reviews fail against carefully disguised injections. The paper quantifies this defense gap by evaluating four representative coding agents and two mitigation strategies (whitelist-based execution control, LLM review), demonstrating that client-side measures alone cannot fully restore end-to-end control.

## Implementation and Evaluation
- **Implementation**: The SIDEL framework was developed to record and replay agent interaction trajectories and implement the four levels of injection attacks. Four mainstream coding agents were evaluated.
- **Evaluation Results**:
    - Without additional mitigations, all evaluated agents achieved a 0% defense success rate across all injection levels.
    - Router-side interventions substantially altered repository-level actions and remained difficult for existing client-side safeguards to detect.
    - Client-side mitigations (e.g., whitelists) and reactive reviews improved resistance but did not fully restore end-to-end control.
- **Comparison**: Unlike previous works focusing on prompt injection or model-intrinsic security, this study focuses on the "man-in-the-middle" risk in the supply chain, empirically revealing the specific security costs of API routers as untrusted intermediaries and filling a gap in empirical research.

## 4. Conclusion
This paper empirically reveals the severe security risks posed by third-party API routers in agentic software development. It demonstrates that router-side injection attacks can easily bypass existing client-side defenses, leading to malicious modifications of code repositories. While client-side mitigations offer some protection, they are insufficient to address the root cause. The paper calls for provider-side output integrity guarantees to repair this trust chain gap.
