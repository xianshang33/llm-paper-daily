## 1. What the Paper Did
- **Background**: The rapid emergence of agentic systems composed of heterogeneous, tool-enhanced, and LLM-mediated components has raised practical questions about inter-agent coordination and protocol design.
- **Why Existing Work Falls Short**: Classical Multi-Agent Systems (MAS) literature does not fully address the architectural differences of contemporary LLM-based agents. There is a lack of implementation-grounded comparisons between emerging protocols like Model Context Protocol (MCP) and Agent2Agent (A2A), particularly regarding engineering trade-offs in discoverability, state management, and lifecycle handling.

## Core Contributions
- **Proposed**: An empirical, implementation-grounded comparative study of MCP and A2A protocols for inter-agent coordination in LLM-based systems, evaluated through a common software engineering task.
- **Challenge 1: How to achieve basic agent coordination with low complexity?**
  - **Difficulty**: Complex protocols can hinder rapid deployment and increase implementation burden.
  - **Solution**: The paper demonstrates that MCP offers a comparatively lightweight implementation model with lower coordination complexity, suitable for constrained systems, though it requires explicit application-layer handling for state and lifecycle.
- **Challenge 2: How to natively support stateful multi-turn conversations and task lifecycle management?**
  - **Difficulty**: Simple protocols struggle with complex interaction states and long-running task flows.
  - **Solution**: The paper finds that A2A provides richer native support for stateful coordination through protocol-level abstractions for tasks and lifecycle management, albeit at the cost of substantially greater implementation and coordination complexity.

## Implementation and Evaluation
- **Implementation & Evaluation**: The authors implemented two multi-agent systems (one MCP-based, one A2A-based) to perform the same software engineering task. They evaluated them against requirements such as agent discoverability, multi-part messaging, multi-turn conversations, asynchronous communication, observability, interoperability, and access control.
- **Results Comparison**:
  - **MCP**: Advantages include a lightweight implementation and lower coordination complexity. Disadvantages include the lack of native support for conversational state management and task lifecycle, which must be handled explicitly at the application layer.
  - **A2A**: Advantages include rich native support for stateful, multi-turn coordination via protocol-level abstractions. Disadvantages include significantly higher implementation and coordination complexity.
- **Nature of Findings**: Given the narrow scope, findings are presented as design observations from an empirical experience report, highlighting trade-offs and how protocol abstractions shape the distribution of coordination responsibilities, rather than making general claims of superiority.

## 4. Conclusion
This paper provides an empirical comparison of MCP and A2A protocols in LLM-based agentic systems. It reveals that MCP is suitable for scenarios prioritizing lightweight implementation and low complexity, requiring developers to manage state manually. In contrast, A2A is better suited for complex, stateful interactions, offering robust native support but introducing higher complexity. The study offers critical trade-off insights for engineers selecting coordination protocols, emphasizing the impact of protocol design on architectural responsibility distribution.
