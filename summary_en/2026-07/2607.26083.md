## 1. What the Paper Did
- **Background**: AI coding agents are ubiquitous in software engineering, with extensive existing research on their serial code accuracy and speed. However, initial findings suggest their parallel programming capabilities significantly lag behind serial ones.
- **Limitations of Existing Work**: Current benchmarks (e.g., ParEval, PCEBench) often focus on single languages (mostly C++ or Python) or code translation rather than native generation. They primarily evaluate functional correctness, lacking a systematic cross-language and cross-model comparison of runtime performance efficiency (speedup), which fails to capture real-world HPC efficacy.

## Core Contributions
- **Proposed a cross-model, cross-language evaluation framework for AI coding agents generating parallel code**: Systematically evaluated Cursor Composer 2.0, GPT 5.4, and Claude Sonnet 4.6 across three algorithm categories (sorting, graph traversal, search) in C++, Python, and Julia.
- **Challenge 1: Functional Correctness in Parallel Implementation**. Parallel programming involves complex synchronization and race conditions, making correctness difficult to achieve. The paper tracks prompting effort from serial baselines, finding that agents can produce functionally correct parallel code with modest effort, demonstrating basic syntactic and logical competence.
- **Challenge 2: Achieving Meaningful Runtime Speedup**. Generating correct parallel code does not guarantee performance gains, and parallelization potential varies widely across languages and algorithms. By comparing against custom serial baselines and third-party libraries, the study reveals that speedup is highly algorithm- and language-dependent; for instance, Sonnet 4.6 delivered strong performance gains, while GPT 5.4 showed no measurable speedup despite correct code, highlighting the gap between accuracy and efficiency.

## Implementation and Evaluation
- **Experimental Setup**: Evaluated three AI agents (Cursor Composer 2.0, GPT 5.4, Claude Sonnet 4.6) implementing parallel versions of three CLRS algorithm types in three languages (C++, Python, Julia).
- **Metrics**: Functional correctness, prompting effort, and speedup relative to both custom serial baselines and third-party library implementations.
- **Key Results**:
    - **Model Comparison**: Claude Sonnet 4.6 achieved the strongest overall performance gains. GPT 5.4 consistently produced correct code but yielded no measurable speedups. Cursor Composer 2.0 performed intermediately.
    - **Language and Algorithm Dependency**: No single language dominated all categories. C++ was most consistently parallelizable for graph algorithms. Python and Julia achieved the largest speedups on search algorithms but regressed on some graph algorithms.
- **Comparison with Related Work**: Unlike studies like ParEval that focus on single languages or correctness alone, this work emphasizes "runtime performance efficiency" as a critical LLM metric. It reveals the complexity of cross-language environments, showing that correctness alone is insufficient for evaluating parallel programming assistants.

## 4. Conclusion
This paper fills the gap in cross-language, cross-model performance evaluation of AI coding agents for parallel code generation. Results indicate that while current agents can generate correct parallel code with low prompting overhead, achieving true performance acceleration remains challenging and is heavily dependent on algorithm type and language specifics. Notably, Claude Sonnet 4.6 excelled in performance optimization, whereas GPT 5.4 showed significant shortcomings in efficiency improvement. The study calls for the inclusion of runtime efficiency as a core metric in LLM evaluation, particularly for high-performance computing and parallel processing scenarios.
