## 1. What the Paper Does
- **Background**: While Large Language Models (LLMs) excel at writing, patching, and searching code, on-call Root Cause Analysis (RCA) demands distinct capabilities: reasoning over noisy metrics, logs, traces, and source code starting from ambiguous user reports, often hours after an incident.
- **Why Existing Work Falls Short**: Current software engineering benchmarks rely on static repositories and clear failing tests, lacking the dynamics of production environments. Existing RCA benchmarks (e.g., AIOpsLab, ITBench) lack comprehensive support for real telemetry interfaces, source code access, and human-verified scoring, failing to fully evaluate Agent performance in complex microservice architectures.

## Core Contributions
- **Proposed ORCA-bench**: A high-fidelity production benchmark featuring a live OpenTelemetry-instrumented microservice system (exposing 6 days of metrics, logs, and traces via Prometheus, Jaeger, and OpenSearch) and 1,079 RCA tasks.
- **Challenge 1: Handling Ambiguous Inputs and Multi-source Heterogeneous Data**. The difficulty lies in pinpointing issues from unstructured user reports and massive noisy telemetry. The paper addresses this by creating a realistic microservice environment with diverse task settings (varying report specificity, time-to-detection, and concurrent faults), forcing Agents to cross-validate code with runtime data like real SREs.
- **Challenge 2: Objective and Accurate Evaluation**. The challenge is that RCA outcomes lack a single "correct" code patch but require diagnostic plausibility. The paper uses ground-truth symptoms curated and signed off by expert SREs, employing an LLM-as-judge initially validated by independent human re-scoring (Cohen's $\\kappa_w=0.90$) to ensure reliability.

## Implementation and Evaluation
- **Implementation & Deployment**: ORCA-bench provides a 50GB testbed with six days of system data, supporting real telemetry access via Grafana and full source code availability. Tasks systematically vary report specificity, Time-to-Detection (TTD), and concurrent fault scenarios.
- **Evaluation Results**: Among five frontier agents, the best RCA accuracy was only 25.3% on Medium-difficulty tasks (realistic input) and 10.0% on Hard tasks. Even advanced models like Claude Fable 5 showed significant gaps. The weakest model hallucinated implausible root causes in 40% of reports. Removing source code access degraded all metrics.
- **Comparison**: Unlike AIOpsLab, ITBench, OpenRCA, and SREGym, ORCA-bench is the only benchmark supporting real environments, complete telemetry interfaces, source code access, distinction between symptoms and root causes, and human-verified scoring. Existing benchmarks lack most of these features.

## 4. Conclusion
ORCA-bench reveals a significant capability gap in current frontier coding agents for production-level reliability tasks. Since real production systems are orders of magnitude larger, more dynamic, and idiosyncratic than the testbed, the reported gap represents a lower bound on the engineering investment required. The study emphasizes that substantial technical progress and engineering effort are needed before Agents can be safely entrusted with production reliability. The dataset is publicly released.
