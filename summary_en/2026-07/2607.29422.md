## 1. What the Paper Does
- **Background**: Automated vulnerability repair aims to reduce the time and effort required to patch security flaws. While agentic AI approaches show promise in general program repair, vulnerability repair demands richer program context than typical bug fixes.
- **Limitations of Existing Work**: Current agentic approaches fail to engineer the critical context that security engineers routinely assemble. Specifically, they lack: (1) code-structure context for cross-file data flows and memory patterns, (2) runtime-execution context for crash semantics, and (3) commit-history context for understanding how fragile code patterns were introduced.

## Core Contributions
- **Proposed AgenticRepair**: An agentic vulnerability repair framework that addresses these gaps through multi-faceted program context engineering.
- **Challenge 1: Capturing complex, dispersed code context**. Vulnerabilities often involve cross-file data flows and low-level memory interactions that are hard for single models to grasp. **Solution**: AgenticRepair orchestrates specialized LLM subagents to engineer "code-structure context," capturing cross-file dependencies and memory patterns, which are then embedded into the repair agent's memory.
- **Challenge 2: Linking dynamic behavior and historical origins**. Static code alone cannot fully reflect runtime crash semantics or trace the introduction of fragile patterns. **Solution**: Two additional subagents construct "runtime-execution context" (revealing crash semantics) and "commit-history context" (recovering code evolution). These three complementary contexts guide a dedicated repair subagent for context-conditioned patch synthesis.

## Implementation and Evaluation
- **Evaluation Setup**: Evaluated on SEC-Bench, comprising 300 real-world instances, using sanitizer-based patch verification.
- **Key Results**: AgenticRepair achieved a 73% success rate.
- **Comparison**: It substantially outperformed the strongest baseline by 29%.
- **Ablation Study**: Confirmed that the three context facets are mutually complementary and that both multi-agent scaffolding and base-model capacity play essential roles.

## 4. Conclusion
AgenticRepair innovatively introduces multi-faceted program context engineering by simulating the workflow of security engineers. By coordinating multiple specialized LLM subagents to build code-structure, runtime-execution, and commit-history contexts, it effectively addresses the limitations of existing methods in handling complex vulnerability contexts. Experimental results demonstrate that the method significantly outperforms state-of-the-art techniques in real-world vulnerability repair tasks, establishing multi-faceted context engineering as a promising direction for agentic vulnerability repair.
