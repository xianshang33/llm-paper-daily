## 1. What the Paper Does
- **Background**: AI agents built on the Model Context Protocol (MCP) often perform cryptographic operations (e.g., signing Git commits, API authentication) by storing private keys in software-accessible locations such as plaintext files, environment variables, or container memory. Any process with sufficient read privileges can extract raw key material.
- **Why Existing Work Fails**: Current key management tiers (plaintext storage, software vaults, runtime-isolated containers) share an irremovable flaw: the raw key exists in software-accessible memory at some point. Prompt injection can convert tool invocations into read-and-exfiltrate primitives, leading to key leakage within minutes. Purely software-based architectures cannot eliminate this structural exposure.

## Core Contributions
- **Proposed a** Zero-Trust MCP Enforcement Architecture using Hardware Keystores (HSM, TPM, smart cards). Private keys are confined within hardware boundaries and accessed via a vendor-neutral PKCS#11 interface, ensuring the host OS only receives cryptographic results via opaque handles.
- **Challenge 1: How to prevent key exfiltration via prompt injection?**
  - **Difficulty**: Traditional methods keep keys in memory, allowing attackers to use injected instructions to induce the agent to read memory or execute malicious tools to export keys.
  - **Solution**: Implement hardware confinement so keys never enter RAM. This is enabled by a five-layer Zero-Trust stack (Session Identity SAGA, Scope Bounds Smax, Semantic Validation RAV, Taint Tracking, and Hardware Execution Boundary), ensuring that even if the agent is compromised, raw keys remain inaccessible.
- **Challenge 2: How to enforce content-aware authorization without exposing keys?**
  - **Difficulty**: Simple hardware isolation might be too rigid; it needs to distinguish between legitimate signing requests and malicious abuse without revealing the key.
  - **Solution**: Introduce Semantic Validation (RAV) and taint tracking to analyze request context and integrity before hardware execution, ensuring only policy-compliant operations trigger cryptographic signing within the hardware.

## Implementation and Evaluation
- **Implementation & Deployment**: Evaluated using SoftHSMv2 (software PKCS#11 emulator) for reproducibility and confirmed drop-in behavior on an embedded TPM 2.0 (Infineon SLB9670). The architecture integrates five zero-trust components: SAGA, Smax, RAV, taint tracking, and the hardware boundary.
- **Evaluation Results**: Tested against 12 injection scenarios derived from AgentDojo's ImportantInstructionsAttack template across four LLM models (gpt-oss-120b, Qwen2.5-72B, DeepSeek-V4-Flash, etc.).
  - **Baseline Attack Success Rate (ASR)**: 19.3% [95% CI: 14.3%, 25.4%], indicating high vulnerability in existing setups.
  - **Protected ASR**: 0% [95% CI upper bound 2.0%], demonstrating complete mitigation.
  - **False Positives**: Zero false positives across four benign task scenarios.
- **Comparison**: Compared to plaintext storage, software vaults, and container isolation, this architecture fundamentally eliminates key exposure in memory, shifting the attack surface from feasible "key extraction" to infeasible "hardware breakthrough," significantly enhancing security.

#### Summary
This paper highlights the structural weakness in current AI agent key management, where keys inevitably reside in software memory, making them vulnerable to prompt injection. The authors propose a hardware keystore-based Zero-Trust architecture that confines key operations entirely within hardware boundaries via PKCS#11, supported by a five-layer enforcement mechanism. Experiments show the solution reduces prompt injection success rates from 19.3% to 0% with zero false positives, providing robust security for AI agent cryptographic workflows.
