## 1. What the Paper Does
- **Background**: LLM Agent services repeatedly execute small deterministic state transitions (routing outcomes, updating state) between model inference and tool calls. Recent studies show this control path frequently crosses the CPU-GPU boundary, making host orchestration a critical path and causing bursty CPU demand.
- **Limitations of Existing Work**: Current fixed-window batching mechanisms fail to fully exploit GPU concurrency because similarity alone is insufficient; tasks must meet hardware thresholds, share executable semantics, and adhere to strict launch deadlines. Furthermore, returning every decision to the host for redispatch incurs significant copy, synchronization, and branching overheads, which prior work has not sufficiently quantified or optimized.

## Core Contributions
- **Proposed a "Ready Cohorts" Theoretical Framework**: Formalized the boundaries for GPU-executable control paths using Fixed-partition share (F), Exact offline share (P*), Local upper bound (U), and Online achieved share (A).
- **Challenge 1: How to quantify GPU scheduling opportunities lost due to fixed window boundaries?**
  - **Difficulty**: Precisely calculating the maximum packable same-group workload under ideal conditions (zero service time, unlimited capacity, equal relative launch deadlines) is a complex combinatorial optimization problem.
  - **Solution**: The paper designs a specialized dynamic programming algorithm to compute P* exactly. Experiments show that exact packing recovers 81.83% of the opportunity lost at fixed window boundaries, increasing the effective share from 30.19% (F) to 43.00% (P*) under specific configurations (100k active sessions, K=256, 50ms deadline).
- **Challenge 2: How to eliminate host round-trip overhead in control decisions?**
  - **Difficulty**: Traditional architectures require transferring small amounts of data (e.g., 4-byte routing decisions) from GPU to host for the next-step decision and redispatch, introducing significant latency.
  - **Solution**: A mechanism is proposed to keep GPU-computed binary decisions on-device (Device-resident). Experiments demonstrate that this path is faster in all 36 configurations across four GPU placements, with speedups ranging from 1.19x to 2.39x, while maintaining correctness against a host oracle.

## Implementation and Evaluation
- **Implementation & Setup**:
  - **Trace Replay**: Used a public Agent trace panel with 851 sessions for stationary Poisson replay. Configured with 100,000 target active sessions, batch size K=256, and a 50ms launch deadline.
  - **Mechanism Study**: Conducted in a CUDA environment, keeping state transition and routing bodies fixed while varying the observation point of the GPU-computed decision. Compared four GPU placement strategies against a negative control (early device-launch design).
- **Key Results**:
  - **Opportunity Bounds**: F=30.19%, P*=43.00%, U=45.85%. Exact packing significantly outperforms fixed-window methods.
  - **Performance Speedup**: The device-resident path outperformed the host round-trip path in all 36 configurations, with row-median speedups of 1.19x to 2.39x.
  - **Correctness**: All 14,557,440 batched invocations matched the results of a separately implemented host oracle.
  - **Negative Control**: A fixed nested device graph that did not eliminate host decisions was slower in all 60 configurations, proving the necessity of reducing host interaction.
- **Comparison Conclusion**: The study establishes two measurable gates for GPU Agent control: deadline-feasible cohort supply and observation placement. Compared to fixed windows, dynamic exact packing captures more schedulable work; compared to traditional host callbacks, on-device decisions significantly reduce latency.

#### Summary
This paper addresses low GPU utilization and host round-trip overhead in LLM Agent control paths through theoretical analysis and experimental validation. First, it quantifies the potential for GPU concurrency via the "Ready Cohorts" framework, demonstrating that exact packing substantially recovers performance lost to fixed windows. Second, by keeping routing decisions on the GPU device, it avoids unnecessary host communication, achieving 1.19x-2.39x speedups. This work provides concrete system design guidance for building efficient LLM Agent systems, emphasizing the importance of deadline management and data placement.
