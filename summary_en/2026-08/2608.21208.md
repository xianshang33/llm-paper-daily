## 1. What the Paper Did
- **Background**: Large Language Models (LLMs) are shifting software engineering from prompt-based assistance to agentic development. In Specification-Driven Development (SDD), specifications serve as operational inputs that directly guide code generation, acting as intermediate representations between intent and implementation, particularly in complex tasks like database migration (Oracle to PostgreSQL).
- **Why Existing Work Falls Short**: Prior research largely focuses on single-agent code generation or direct source-to-target translation, often assuming specifications are "agent-neutral" artifacts. There is a lack of systematic evaluation regarding specification portability across different agents, ignoring the semantic drift and quality degradation that occur when specifications created by one agent are consumed by another.

## Core Contributions
- **Proposed an empirical framework for cross-agent specification portability**: Using Oracle-to-PostgreSQL migration as a controlled task, the study systematically evaluates compatibility and performance when specifications are transferred between various LLM agents (e.g., Amazon Kiro, Google Gemini, GitHub Copilot).
- **Challenge 1: Severe performance degradation during cross-agent transfer**. The difficulty lies in the divergent training data and reasoning mechanisms of different agents, leading to biased interpretations of the same specification. The paper demonstrates this with experiments showing that when Gemini directly consumes a Kiro-origin specification, Token F1 drops to 0.035 and SQL syntax validity to 2.33%, proving specifications are not agent-neutral.
- **Challenge 2: Lack of effective specification adaptation strategies**. The challenge is improving the usability of foreign specifications in target agents without regenerating them from scratch. The paper evaluates rewriting, compression, and retrieval-augmented ingestion. It finds that rewriting significantly improves Gemini's performance, while retrieval-augmented ingestion is the only strategy consistently appearing on the Pareto frontiers for both Gemini and Copilot, offering a viable path for compatibility.

## Implementation and Evaluation
- **Experimental Setup**: The study involved two stages. Stage 1 evaluated a single-agent specification-first pipeline on 1,006 PL/SQL files (623 successfully regenerated, 380 executed successfully in PostgreSQL 16). Stage 2 conducted cross-agent experiments on a dataset of 1,802 Oracle scripts with corresponding PostgreSQL implementations, involving Amazon Kiro, Google Gemini, GitHub Copilot, Claude Code, and Cursor.
- **Metrics**: Token F1, exact match, SQL syntax validity, AST exact match, AST mean similarity, and immediate runnability.
- **Key Results**:
    - Specification size alone does not predict implementation quality.
    - Cross-agent transfer causes substantial agent-dependent degradation. The worst case (Gemini consuming Kiro specs) showed extremely low metrics.
    - **Strategy Comparison**: Rewriting substantially improved Gemini's performance; compression provided no universal benefit; retrieval-augmented ingestion was the only common strategy on the Pareto frontiers for both Gemini and Copilot, highlighting its effectiveness as a general adaptation method.
- **Comparison Significance**: Contrasting with the traditional view of universal specifications, this study quantifies the existence of "specification dialects" and proves the necessity of optimizing specification ingestion strategies for specific agents.

## 4. Conclusion
The paper reveals that specifications in heterogeneous SDD workflows should not be treated as agent-neutral artifacts. Cross-agent specification transfer carries significant risks of quality degradation due to agent-specific interpretations. The study suggests that multi-agent software engineering must explicitly consider specification portability and agent-specific interpretation. Retrieval-augmented ingestion is identified as an effective method for enhancing cross-agent compatibility, providing crucial insights for building more interoperable LLM developer agent ecosystems.
