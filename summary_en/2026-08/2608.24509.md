## 1. What the Paper Did
- **Background**: LLM agents are evolving into autonomous task-solvers that invoke external tools. Parallel execution is essential for low latency in complex workflows.
- **Limitations of Existing Work**: Current benchmarks primarily evaluate tool selection and argument generation under serial execution assumptions, overlooking valid parallelization and resource-constrained scheduling. This leads to a trade-off where serial execution is safe but slow, while resource-agnostic parallel execution is fast but prone to avoidable resource overflows.

## Core Contributions
- **Proposed PeakBench**: A benchmark of executable multi-tool workflows featuring execution-grounded dependency annotations and measured resource profiles.
- **Challenge 1: Attribution Difficulty**. Failures and inefficiencies can stem from incorrect dependency planning, poor scheduling, or both, making it hard to identify the root cause. PeakBench addresses this with a two-part evaluation framework that disentangles logical planning from physical scheduling, providing dedicated metrics for each dimension.
- **Challenge 2: Lack of Resource Awareness**. Existing frameworks often assume infinite infrastructure capacity, conflating logical independence with execution readiness, which causes resource overflows. PeakBench incorporates measured resource profiles, demonstrating that exposing resource information reduces avoidable overflows and improves utilization, enabling better diagnosis of resource-aware agent behavior.

## Implementation and Evaluation
- **Implementation & Evaluation**: PeakBench provides executable workflows with dependency and resource data. The study employs a decoupled evaluation framework to assess logical planning and physical scheduling separately.
- **Results & Comparison**: Experiments show that strong logical planning does not guarantee safe or efficient execution under resource constraints. Compared to sequential execution (safe but slow) and blind parallelism (fast but unsafe), resource-aware scheduling preserves speedup without causing overflows. Exposure to resource information significantly reduced avoidable errors and improved resource efficiency.

## 4. Conclusion
PeakBench fills the gap in resource-aware scheduling for LLM agent benchmarks. By decoupling logical planning from physical scheduling, it reveals systemic vulnerabilities in current agents operating under resource constraints. The study concludes that logical reasoning alone is insufficient; resource-aware scheduling is critical for efficient execution. PeakBench serves as a valuable testbed for diagnosing and optimizing resource-aware agent behaviors.
