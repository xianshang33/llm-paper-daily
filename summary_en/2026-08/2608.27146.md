## What the Paper Does
- **Background**: Tool-augmented LLM agents must rely on untrusted runtime Observations to complete open-ended tasks. When tool outputs specify concrete actions rather than just providing data, they effectively become "commands" that can drive real-world side effects beyond user intent.
- **Why Existing Work Fails**: Current defenses face a structural tension: restricting untrusted external content improves security but weakens the runtime adaptability required for open-ended tasks. Conversely, allowing observations to freely influence subsequent decisions lets attack semantics propagate through normal tool steps. Existing methods struggle to distinguish legitimate runtime adaptation from attack-induced behavior, leading to a difficult trade-off between security and utility.

## Core Contributions
- **Proposed SARA Framework**: A framework that treats action induction and execution authorization as distinct runtime roles, separating action provenance from execution authority.
- **Challenge 1: How to identify and isolate action-inducing semantics from untrusted observations without blocking legitimate dynamic instantiation?**
  - **Difficulty**: Open-ended tasks inherently require using untrusted observations to dynamically instantiate subsequent actions and arguments; simple filtering breaks task usability.
  - **Solution**: SARA introduces a context-isolated "Action Probe" on the observation side to expose action-inducing semantics and persistently record action-origin provenance across steps as a review signal, tracking potential risks without blocking information flow.
- **Challenge 2: How to prevent malicious sources in historical executions from being "laundered" into legitimate execution authority through multi-step interactions?**
  - **Difficulty**: In multi-step execution, attackers may exploit the recurrence of historical records to disguise originally untrusted action sources as authorized legitimate behaviors.
  - **Solution**: SARA applies a "No-History-Promotion" strategy to prevent historical recurrence from laundering action origins into execution authority. On the execution side, actual tool calls are authorized only against the user objective and audited evidence from authorized successful executions, ensuring goal, execution-chain, and argument-level support.

## Implementation, Deployment, and Evaluation Results
- **Implementation & Evaluation**: Evaluated on AgentDojo and AgentDyn benchmarks.
- **Results**: SARA limits the Attack Success Rate (ASR) to no more than 0.63% across four primary evaluation settings while maintaining competitive task utility.
- **Comparison**: Compared to existing methods, SARA consistently reduces ASR across additional Agent backbones, demonstrating its ability to significantly enhance security while preserving utility, effectively addressing the security-utility trade-off prevalent in traditional approaches.

## Summary
This paper identifies security risks in tool-augmented LLM agents arising from conflating action induction with execution authorization. It proposes the SARA framework, which separates action provenance from execution authority. By using action probes to track provenance and implementing strict execution authorization with no-history-promotion, SARA achieves a very low attack success rate while maintaining high task utility, offering a new solution for agent security in open-ended environments.
