## 1. What the Paper Does
- **Background**: Enterprise data agents answer business queries by chaining multiple tool calls over many reasoning steps, routinely accumulating hundreds of thousands of context tokens per session. This leads to exceeded model windows, high costs, and degraded reasoning due to diluted attention.
- **Why Existing Work Fails**: Existing compression strategies (e.g., token-level pruning, summarization) typically apply uniform strategies without accounting for the downstream consequences of removing specific tool outputs. Aggressive compression can trigger costly tool re-invocations to recover lost information, offsetting initial savings. This mismatch is termed the "compression–consequence gap."

## Core Contributions
- **Proposed TRACER**: A framework for Per-Tool Context Retention via Consequence-Attributed Reinforcement Learning, formulating compression as a sequential per-tool decision problem.
- **Challenge 1: Quantifying downstream consequences of compression.**
  - **Difficulty**: Traditional methods evaluate compression in isolation, ignoring whether removed information is needed later, leading to inaccurate net benefit assessment.
  - **Solution**: TRACER uses a consequence-aware objective that jointly accounts for task success, total token consumption, and post-compression tool re-invocations. It employs a learned outcome model to compare predicted consequences of selected retention ratios against full retention, improving credit assignment.
- **Challenge 2: Dynamically allocating retention budgets across heterogeneous tool outputs.**
  - **Difficulty**: Tool outputs vary widely in downstream importance (e.g., schema lookup vs. permission check), making static or uniform strategies inefficient.
  - **Solution**: A lightweight REINFORCE policy assigns query-conditioned continuous retention ratios for each tool output using only information available at each compression event, directing token budget to outputs whose removal would trigger expensive recovery.

## Implementation and Evaluation
- **Setup**: Evaluated on held-out production queries across three compressor backends and five LOCA-bench environments.
- **Results**:
  - TRACER reduces total token consumption by 29–46% compared to keeping all context, while maintaining comparable or higher task success.
  - Compared to a tool-type-conditional static policy, TRACER provides an additional 15–18% token savings.
  - On five LOCA-bench environments, it reduces token consumption by 18–25%.
- **Comparison**: Interventional rollouts confirm that learned per-tool credit scores correlate with measured single-tool consequences. The policy demonstrates positive savings when transferred across different agent backbones and compressor architectures, outperforming existing isolated compression methods in robustness and efficiency.

## 4. Conclusion
TRACER effectively addresses the "compression–consequence gap" in long-horizon language agents. By introducing a consequence-aware reinforcement learning framework, it enables fine-grained, per-tool dynamic context retention. Experiments demonstrate that the method significantly reduces token costs while avoiding expensive tool re-invocations caused by information loss, thereby enhancing the overall efficiency and practicality of enterprise data agents.
