## 1. What the Paper Does
- **Background**: With advances in Large Language Models (LLMs), evaluation has shifted from function-level code generation to repository-level agents (e.g., SWE-Bench). Existing benchmarks primarily measure whether generated patches pass functional tests.
- **Why Existing Work Falls Short**: Current repository-level benchmarks rely solely on functional test success, ignoring "Review Constraints"—additional requirements derived from code reviews (e.g., backward compatibility, coding conventions). In practice, a functionally correct patch may still be rejected if it violates these constraints. Thus, functional-only evaluation overestimates an agent's ability to meet full real-world requirements.

## Core Contributions
- **Proposed SWE-Gate**: A repository-level benchmark for software engineering agents that explicitly evaluates both functional correctness and review constraint compliance.
- **Challenge 1: How to quantify and separate "issue resolution capability" from "review constraint compliance"?**
  - **Difficulty**: Traditional benchmarks conflate these aspects, making it impossible to distinguish whether an agent failed to fix the bug or simply violated style/convention rules.
  - **Solution**: SWE-Gate extracts review constraints from real Pull Request comments and synthesizes repair instances. Each instance provides separate functional and constraint tests, along with non-compliant and gold patches, enabling explicit separation of the two capabilities.
- **Challenge 2: How to construct a high-quality, representative dataset of review constraints?**
  - **Difficulty**: Review constraints are often implicit in unstructured natural language comments and require executable tests for verification.
  - **Solution**: The authors constructed a dataset of 303 repository-level repair instances across 75 diverse open-source Python repositories. They transformed review comments into executable constraint tests through analysis and synthesis, ensuring objective and realistic evaluation.

## Implementation and Evaluation
- **Implementation**: SWE-Gate comprises 303 repair instances from 75 Python repositories. A full replication package (code, data, results) is provided.
- **Evaluation Results**: Experiments with four LLM backends under a common agent scaffold revealed a significant gap: among 644 repairs that passed functional tests, 221 failed to satisfy the provided review constraints.
- **Comparison & Findings**: Compared to existing works like SWE-Bench that focus only on functional tests, SWE-Gate demonstrates that functional-only evaluation significantly overestimates agents' ability to satisfy the complete specification of repository-level repair tasks.

## 4. Conclusion
SWE-Gate addresses a critical gap in software engineering agent evaluation by highlighting that "passing functional tests" is not equivalent to "acceptance." By introducing constraint tests based on real review comments, it better reflects industrial code merge standards. The results indicate that current LLM agents struggle significantly with implicit non-functional constraints, suggesting future research must optimize for both functional correctness and code convention compliance.
