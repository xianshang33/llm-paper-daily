## 1. What the Paper Does
- **Background**: Modern AI Agents often operate in high-fanout modes, where a single task spawns multiple concurrent sandbox sessions (e.g., multiple trajectories in RL training or parallel candidates in inference). This creates a significant memory bottleneck as each sandbox requires an isolated environment.
- **Why Existing Work Fails**: Conventional memory compression is ill-suited for this setting due to three mismatches:
    1. **How to compress**: It fails to exploit similarity across non-identical sandbox pages (template-relative and cross-sandbox redundancy).
    2. **What to compress**: It uses conservative page selection to control page-fault overhead, limiting compression scope.
    3. **When to compress**: It is triggered by memory pressure without awareness of agent execution phases, potentially interfering with foreground tasks.

## Core Contributions
- **Proposed AgentZip**: The first memory compression system specifically designed for AI-agent sandboxes.
- **Challenge 1: How to efficiently leverage high redundancy across sandboxes?**
    - **Difficulty**: Sandboxes share a template and related trajectories but are not identical, making it hard for general-purpose compression to capture fine-grained similarities.
    - **Solution**: AgentZip introduces mechanisms to exploit both template-relative and cross-sandbox redundancy, broadening the compression scope to any page with a profitable representation.
- **Challenge 2: How to minimize performance degradation while achieving high compression?**
    - **Difficulty**: Aggressive compression leads to high decompression overhead (page faults), causing significant slowdowns. Compressing during active execution interferes with tool usage.
    - **Solution**: AgentZip shifts overhead control from compression-time page selection to restore-time prefetching and aligns expensive compression operations with LLM waiting periods, reducing slowdown significantly.

## Implementation and Evaluation
- **Evaluation Setup**: Tested on LLM training and inference workloads.
- **Memory Savings**: AgentZip reduces sandbox-owned memory by up to **8.7x**, compared to only **2.1x** for standard Linux configurations.
- **Performance Overhead**: By using restore prefetching and agent-execution-aware scheduling, AgentZip reduces the slowdown from aggressive compression from as high as **3.1x** down to **1.40x**, while retaining nearly all memory-saving benefits.

## 4. Conclusion
AgentZip rethinks memory compression for high-fanout agent workloads by leveraging structural similarities between sandboxes, optimizing compression timing to match LLM idle periods, and employing restore-time prefetching. It achieves substantial memory reduction (up to 8.7x) with controlled performance overhead, offering an efficient system solution for large-scale Agent deployment.
