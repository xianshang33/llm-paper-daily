## 1. What the Paper Did
- **Background**: Security benchmarks for LLM-based agents typically use Attack Success Rate (ASR) as the primary metric to measure model robustness and compare defense mechanisms, assuming these scores accurately reflect agent security.
- **Why Existing Work Falls Short**: While prior work acknowledges that tool metadata influences agent behavior, it fails to quantify how the benchmark's "representation" (e.g., tool names, descriptive wording) impacts measurement outcomes. If ASR fluctuates significantly with representation changes, a single score cannot generalize to represent the agent's true security level against the same underlying threat, rendering current robustness claims unreliable.

## Core Contributions
- **Proposed Concept**: Threat-Preserving Representation Sensitivity (TPRS), a metric measuring the change in ASR when only the agent-visible representation is altered, while keeping the underlying task, harmful action, security policy, ground truth, environment, and evaluation criteria fixed.
- **Challenge 1: Quantifying the impact of representation bias on security evaluation**. The difficulty lies in isolating the independent effects of "representation form" versus "underlying threat" on model behavior. The paper addresses this by conducting controlled experiments across three independent benchmarks (ASB, MCPTox, AgentDojo), fixing all variables except tool names or descriptions. Results showed significant and non-uniform ASR shifts (e.g., replacing threat-related tool names with neutral ones in ASB increased GPT-5-mini's ASR by 11.67%).
- **Challenge 2: Ruling out superficial features to verify the root cause of sensitivity**. The difficulty is determining whether ASR changes are driven by "threat vocabulary" itself or by surface features like token length and casing. The paper conducted a control experiment on MCPTox, finding that a threat-neutral name matched for token count, length, and casing reproduced most of the ASR shift caused by the explicit threat name (8.54 out of 11.00 points on GPT-5-mini), proving that sensitivity is not solely due to threat vocabulary but is a deeper representation sensitivity issue.

## Implementation and Evaluation
- **Experimental Setup**: Conducted a total of 28,904 agent runs across three mainstream agent security benchmarks: Agent Security Bench (ASB), MCPTox, and AgentDojo.
- **Key Results**:
    - **ASB Benchmark**: Replacing threat-related tool names with neutral ones increased ASR by 11.67% for GPT-5-mini and 13.21% for Claude Haiku 4.5.
    - **MCPTox Benchmark**: Replacing original neutral tool names with explicit threat-related names decreased ASR by 11.00% for GPT-5-mini and 4.11% for Claude Haiku 4.5.
    - **AgentDojo Benchmark**: Adding threat-related wording had a minimal effect on ASR (0.50% change for GPT-4o-mini) but reduced benign utility by 5.36% for tasks requiring that tool.
- **Comparison & Conclusion**: The results demonstrate that security scores measured under one representation may fail to generalize across other threat-preserving representations of the same security problem. Unlike previous works relying on a single ASR score, this paper argues that robustness claims must be supported by performance across a controlled set of threat-preserving representations rather than a single, representation-dependent score.

#### Summary
This paper reveals a critical issue of "Threat-Preserving Representation Sensitivity" in LLM agent security benchmarks. By introducing the TPRS metric and conducting large-scale empirical studies across multiple benchmarks, the authors demonstrate that minor changes in surface representations, such as tool names and descriptions, lead to significant fluctuations in Attack Success Rates. This finding challenges the current practice of evaluating model security based on a single ASR score and calls for the community to adopt multi-representation testing to ensure the generalizability and authenticity of security evaluations.
