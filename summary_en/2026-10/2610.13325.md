## 1. What the Paper Does
- **Background**: With the rise of LLM agents, workloads involve repeated calls with long, largely unchanged contexts. While prefix caching skips most prefill computation, every request must still be fully tokenized before the cache can be queried.
- **Limitations of Existing Work**: Tokenization, historically a negligible CPU stage, has become the dominant component of Time-to-First-Token (TTFT) when prefix caching is used. Furthermore, a single CPU frontend tokenizing for an entire GPU fleet creates a scalability bottleneck, limiting the number of GPUs it can feed.

## Core Contributions
- **Proposed GraphTok**: A GPU-based tokenizer that executes the entire encoding pipeline—from pre-tokenization and Byte-Pair Encoding (BPE) merging to token-ID assembly—as a single replayable CUDA graph.
- **Challenge 1: Precision and Compatibility on GPU**. Replicating complex BPE logic on GPU with bit-for-bit accuracy across diverse models is difficult. GraphTok solves this by achieving exact reference reproduction on models like Llama 3 and Qwen 2.5, while intelligently offloading short inputs to CPU where GPU offers no advantage.
- **Challenge 2: System Integration and End-to-End Latency**. Moving tokenization to GPU requires seamless integration without disrupting existing optimizations. GraphTok plugs into unmodified vLLM and NVIDIA Dynamo, eliminating CPU-GPU synchronization bottlenecks and significantly reducing TTFT.

## Implementation and Evaluation
- **Implementation**: GraphTok integrates as a plugin into standard serving stacks (vLLM, NVIDIA Dynamo) without code modifications, using a hybrid approach for input lengths.
- **Speed Comparison**: On Llama 3, GraphTok is 4.7-6.0x faster than gigatoken (the strongest CPU tokenizer). It encodes one million GPT-2 tokens in 1.7-3.2 ms including data transfers.
- **TTFT Reduction**: In vLLM with prefix caching, GraphTok reduces mean TTFT by 2.1-2.4x.
- **Throughput and Capacity**: Under a 2s P99 latency target, a single Dynamo frontend with GraphTok sustains 518 requests/s (121k-token traffic), supporting the load of 56 GPUs. In contrast, gigatoken supports only 296 requests/s, and the default tokenizer only 18.5 requests/s. GraphTok sustains 1.75-2.5x the load of gigatoken with up to 64x lower P99 latency in tail-heavy scenarios.

## 4. Conclusion
GraphTok effectively addresses the tokenization bottleneck in Agentic LLM serving by offloading the task to GPU via CUDA graphs. It significantly lowers TTFT and dramatically increases the capacity of single frontends to support large GPU clusters, providing a scalable infrastructure solution for high-throughput LLM agent applications.
