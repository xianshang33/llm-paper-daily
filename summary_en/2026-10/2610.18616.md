## 1. What the Paper Does
- **Background**: Searching text-rich Knowledge Graphs (KGs) requires following relations while examining textual evidence. Existing methods typically access graphs through predefined interfaces (e.g., database queries, subgraph retrievers, or fixed API tools).
- **Limitations of Prior Work**: Predefined graph interfaces constrain the evidence agents can access. Even when agents write code to combine tool calls, their operational freedom is limited by the interface design, making it difficult to flexibly process large node sets in bulk or directly inspect underlying files, thus hindering the capture of complex cross-record evidence.

## Core Contributions
- **Proposed Direct Knowledge Graph Interaction (DKGI)**: An agent harness that treats KGs as files, allowing LLM agents to create and use graph access tools directly over complete node and edge files.
- **Challenge 1: Limited evidence access and flexibility due to predefined interfaces**. The difficulty lies in fixed APIs failing to adapt to all query needs and inefficiently handling large-scale data. **Solution**: DKGI allows agents to write Python code to access underlying data via Shell search and file inspection, bypassing API limits to enable bulk processing and custom evidence selection.
- **Challenge 2: Static separation between tool use and evidence collection**. The difficulty is that traditional tools are static and cannot dynamically adjust search strategies based on execution feedback. **Solution**: DKGI enables the co-evolution of "tool creation" and "tool use." Execution feedback guides the agent to revise and extend code (tools), while evolving tools determine subsequent evidence gathering, forming a dynamic loop.

## Implementation and Evaluation
- **Implementation**: DKGI is a training-free framework. Agents interleave Python code execution, Shell searches, and file inspections. It does not rely on specific graph database backends but treats KGs as accessible files.
- **Evaluation Results**: On benchmark datasets across three domains, DKGI exceeds the strongest published baselines by at least 6.7 Hit@1 points on every graph.
- **Comparison & Ablations**:
    - Outperforms methods using direct predefined tools (e.g., ToG, Graph-CoT, ARK, GRASP).
    - Surpasses code-based methods limited by subgraph retrievers (e.g., Code-on-Graph) due to full file access rights.
    - Ablation studies show that multi-turn programming outperforms shell-only access or predefined graph tools, highlighting the benefit of code revision and tool evolution.

## 4. Conclusion
This paper proposes DKGI, which breaks the constraints of predefined interfaces by treating knowledge graphs as files. Its core innovation lies in allowing agents to dynamically create and modify code for graph access during task execution, achieving co-evolution of tool creation and use. Experiments demonstrate that this training-free approach significantly outperforms state-of-the-art methods on multiple benchmarks, showcasing the value of granting agents higher data access freedom and code evolution capabilities in complex graph search tasks.
