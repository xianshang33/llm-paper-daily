## 1. What the Paper Did
- **Background**: LLM agents are increasingly automating post-training workflows. Research shows that when given control over the full training stack, agents converge on Supervised Fine-Tuning (SFT) and focus primarily on revising training data, highlighting the critical role of data curation.
- **Limitations of Existing Work**: Current automated systems grant agents only a single type of control, such as selecting rows from a fixed pool or calling a generator. In contrast, human data engineers perform a wide range of operations including adjusting proportions, pruning, repairing, replacing, and synthesizing data. Existing systems fail to cover this comprehensive action space, and single-agent approaches suffer from context loss and limited search strategies.

## Core Contributions
- **Proposed AutoSFT**, a multi-agent system designed to automate SFT data research by covering a diverse space of data actions.
- **Challenge 1: Single agents struggle with context window limits and monotonous search strategies in long-loop data optimization.**
  - **Difficulty**: A single agent's context gets filled with execution outputs, leading to information loss mid-search, and it typically converges to simple actions like adjusting category proportions, failing to perform deeper optimizations.
  - **Solution**: Introduced a Meta Agent to separate execution from analysis and deployed independent analysis sub-agents to gather proposals from multiple angles, halving context loss and enhancing search diversity.
- **Challenge 2: Fixed data pools cannot cover capability gaps missing from the existing distribution.**
  - **Difficulty**: Merely selecting or modifying existing data cannot address completely missing capabilities, limiting performance ceilings.
  - **Solution**: Integrated a Synthesis Sub-agent specifically to generate data for capability gaps that the pool cannot cover, supplementing critical high-quality training samples.

## Implementation and Evaluation
- **Implementation**: AutoSFT comprises a Meta Agent, Executor, Analysis Sub-agents, and a Synthesis Sub-agent. The model, trainer, and budget are fixed for fair comparison, with retraining from the base model in each round to ensure accurate attribution of improvements.
- **Evaluation Results**:
  - **Ablation Studies**: The Executor halved context loss; Analysis Sub-agents improved the best IFEval score by +6.5; the Synthesis Sub-agent added further gains of +3.4 on IFEval and +2.9 on IFBench.
  - **Cross-Domain Transfer**: The framework effectively transfers to code generation, where analysis components improved MBPP+ scores by +3.7 over a single-agent baseline that showed no improvement.
- **Comparison**: Results demonstrate that automating SFT data research relies more on covering diverse data actions than on strengthening a single action. AutoSFT significantly outperforms existing systems limited to single-control mechanisms.

## 4. Conclusion
AutoSFT demonstrates that simulating the diverse operations of human data engineers (such as proportion adjustment, pruning, and synthesis) is more effective than single-strategy optimization in automated SFT data research. By employing a multi-agent architecture to separate execution from analysis and introducing data synthesis, AutoSFT overcomes the context bottlenecks and coverage limitations of single-agent systems, achieving significant performance gains in both instruction following and code generation tasks.
