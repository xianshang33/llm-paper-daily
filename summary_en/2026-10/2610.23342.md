## 1. What the Paper Did
- **Background**: Tool-augmented LLM agents rely entirely on text interfaces (tool descriptions, parameter schemas, candidate tool lists) for inference. In production, these interfaces often change due to updates in parameter names, descriptions, or candidate sets, even when the underlying tool semantics remain fixed.
- **Why Existing Work Falls Short**: Prior research largely focuses on training or static evaluation, lacking effective solutions for "interface drift" post-deployment. Retraining base models for every interface change is impractical, and simple retry mechanisms do not adequately address the root causes of failure.

## Core Contributions
- **Proposed SchemaShield-Lite**: A lightweight, training-free inference-time repair layer designed to recover robustness against interface drift.
- **Challenge 1: Candidate set drift and distractor tools cause incorrect tool selection**. The difficulty lies in models failing to identify the correct tool when the candidate list contains distractors or missing names. The method addresses this via "candidate-set retry," dynamically adjusting the candidate pool when tool names are missing or incorrect.
- **Challenge 2: Schema and description inconsistencies lead to invalid argument generation**. The challenge is that field renaming or outdated descriptions cause malformed outputs. The method combines "schema validation" with "one-shot constrained repair" to detect and correct non-compliant outputs at inference time without retraining.

## Implementation and Evaluation
- **Implementation**: SchemaShield-Lite operates as an inference-time module combining schema validation, candidate-set retry for missing tools, and one-shot constrained repair. It is evaluated in a realistic non-oracle setting.
- **Evaluation Results**:
    - On Qwen3.5-9B, accuracy improved from 0.717 to 0.813 on DICE-300 and from 0.580 to 0.805 on BFCL-200.
    - It recovered 19/22 drift-induced failures on DICE and 33/45 on BFCL, with no observed repair harms on originally correct samples.
    - Similar improvements were replicated on Qwen3.5-35B-A3B (BFCL: 0.635 → 0.845).
- **Comparison with Related Work**:
    - **vs. Naive Retry**: Simple retry achieved only 0.727 (DICE) and 0.610 (BFCL), significantly lower than SchemaShield-Lite, proving gains are not due to mere repetition.
    - **Ablation Studies**: Revealed that candidate-set drift (especially distractors) is the primary source of error, while description/schema edits alone are less harmful. The method effectively targets the main bottleneck.

## 4. Conclusion
This paper addresses the "interface drift" problem in deployed LLM agents by proposing SchemaShield-Lite, a training-free inference-time repair method. By integrating schema validation, candidate-set retry, and constrained repair, it significantly enhances function calling robustness across benchmarks, demonstrating the practical value of validation-and-repair layers for production LLM agent tool use.
