## 1. What the Paper Does
- **Background**: In software agents, many decisions involve choosing from a known short list (e.g., routing tickets, approving/refunding). The existing "LLM-as-Jev" approach handles such structured decisions well by returning probabilities for each option. However, deployed agents also need to reply in natural language when no suitable option exists, the user asks a question, or the model is uncertain.
- **Limitations of Existing Work**: Traditional cascaded approaches first call a decision model and then separately call an LLM to generate text if needed. This requires prefilling the same prompt twice, leading to wasted computational resources and increased latency, without fully leveraging the context from the decision phase.

## Core Contributions
- **Proposed System X**: An architecture that integrates text reply capabilities into an LLM decision model, achieving efficient decision-making and response generation by reusing the Key-Value (KV) Cache.
- **Challenge 1: How to generate natural language replies without re-prefilling the prompt?**
  - **Difficulty**: Traditional methods require re-reading the entire context to generate a reply after making a decision, causing high latency.
  - **Solution**: System X introduces a "REPLY_WITH_TEXT" option within the decision logits. When this option wins or confidence is low, the model continues decoding directly from the decision phase's KV cache, avoiding redundant prompt prefilling. This yields token-identical results to a second call but with significantly lower latency.
- **Challenge 2: How to train the model to maintain decision accuracy while generating high-quality replies?**
  - **Difficulty**: Jointly training decision probabilities and generative replies can cause task conflict, potentially degrading decision calibration or reply quality.
  - **Solution**: Uses a hybrid loss function (combining LLM-as-Jev objective, reply LM loss, KL divergence, and Brier score) with LoRA fine-tuning on Qwen3 models. By balancing data (Reason-9k and Bitext reply rows) and using teacher-rewritten reply targets (System X v4), it improves decision accuracy while maintaining good calibration and reply quality.

## Implementation and Evaluation
- **Implementation**: Based on Qwen3-0.6B and Qwen3-1.7B models, fine-tuned with LoRA. Tested on Apple M4 Pro.
- **Evaluation Results**:
  - **Accuracy & Calibration**: Qwen3-0.6B showed no significant change in JevBench accuracy (55.4% vs 54.5%) but reduced Expected Calibration Error (ECE) from 0.292 to 0.169. System X v4 (1.7B) improved JevBench accuracy from 55.0% to 61.0% (p=0.04) compared to the base LLM.
  - **Latency Optimization**: Cache reuse saved 15-37% latency (0.6B model) and 17-39% latency (1.7B model) on Apple M4 Pro.
  - **Reply Quality**: Replies generated via cache reuse were token-identical to those from full-sequence scoring in FP32 cases. An LLM judge preferred System X v4 replies over unadapted second calls (31 to 11 pairs, p=0.003).
  - **Comparison**: Compared to traditional "decision + independent generation" cascades, System X eliminates redundant prefilling. While adding domain-specific data (System X+) improved support tasks but lowered IFEval scores, v4 resolved this via data rebalancing, showing no significant drop in IFEval.

#### Summary
System X innovatively addresses the inefficiency of separating decision-making and generation in LLM agents. By embedding a reply mechanism within decision options and reusing the KV cache, it significantly reduces inference latency while maintaining or improving decision accuracy and calibration. This method demonstrates that a single model can efficiently handle both structured decisions and unstructured text generation, offering a new paradigm for deploying lightweight, low-latency intelligent agents. Despite some failure modes like state conflicts, its potential is validated by the experiments.
