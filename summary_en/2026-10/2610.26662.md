## 1. What the Paper Did
- **Background**: LLM trading agents are predominantly evaluated in backtests and autonomous benchmarks. However, live deployment involves irreversible actions and self-revising capabilities, raising critical questions about who verifies agent actions and which failures can be structurally caught by different verifiers.
- **Limitations of Existing Work**: Current research largely treats agents as unconstrained decision functions in simulated environments. This approach ignores production constraints such as latency, stability, and the irreversible nature of trading errors (e.g., filled orders), failing to capture the compounded risks of self-revised strategies.

## Core Contributions
- **Proposed AllPath**: A layered verification architecture for a personal LLM trading agent deployed on a live paper-brokerage account, utilizing three layers: code, agent self-review, and human oversight.
- **Challenge 1: Ensuring consistency in deterministic rules and risk controls.**
  - **Difficulty**: Hard constraints like risk limits cannot rely on subjective judgment and must be absolutely reliable.
  - **Solution**: Implemented deterministic code gates to enforce risk limits and block any strategy revision that fails integrity checks, ensuring structural consistency.
- **Challenge 2: Handling subjective market judgments and agent self-revisions.**
  - **Difficulty**: Decisions like stop-loss settings involve subjective market views, and self-revisions can compound errors. No single verifier can catch all failure modes.
  - **Solution**: Adopted a layered approach. The agent self-reviews within fixed bounds (no execution tools, iteration caps). Humans verify subjective judgments via approval screens. The system compared "human-gated" vs. "auto-applied" revision policies, showing humans correct market-view errors missed by code, while code prevents structural failures.

## Implementation and Evaluation
- **Implementation & Deployment**: AllPath has run continuously since August 2026 on a live paper-brokerage account, featuring a deterministic rules engine, governed memory, and nightly self-review.
- **Evaluation Results**:
  - **Layered Failure Capture**: Code gates rejected no proposals but maintained consistency. Humans rejected two proposals that passed code checks due to market disagreements and removed 11 of 19 agent-added rules (median lag of 8 days).
  - **Production Incident Taxonomy**: Critical incidents, such as unmonitored strategies, passed all automated gates and were found manually by the operator. Fixes involved interface improvements to enhance visibility.
- **Comparison with Related Work**: Unlike traditional backtest-only evaluations, this study provides empirical data from live deployment, comparing two verification regimes (2.5 weeks human-gated vs. 5 weeks auto-applied) and offering a taxonomy of production incidents unobservable in simulations.

## 4. Conclusion
This paper demonstrates that LLM trading agents in production require a layered verification architecture, as no single verifier is sufficient. Code handles deterministic constraints, humans handle subjective judgment, and agents perform restricted self-reflection. The work provides crucial empirical insights into human-AI collaboration, verification strategies, and failure classification for deploying LLMs in financial contexts.
