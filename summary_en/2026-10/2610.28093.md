## 1. What the Paper Does
- **Background**: Modern AI agents (e.g., Claude Code, Codex) maintain long-term memory derived from web pages and tool outputs. The agent harness, which manages this memory, currently lacks mechanisms to track the origin or authority of stored data.
- **Why Existing Work Fails**: Current memory systems (like MemGPT or ClawVM) optimize storage but do not track data provenance. Defenses relying on model-based detection or content scanning are insufficient because they cannot guarantee security against adversarial inputs and fail to detect poisoned data that has been transformed or summarized over time, making it appear as trusted internal notes.

## Core Contributions
- **Proposed ClawMMU**: A protection-coherent virtual memory system for stateful LLM agents. It labels every piece of memory with owner, scope, origin, and authority tags, enforcing checks whenever data enters context, is stored/retrieved, or triggers tool calls.
- **Challenge 1: Indirect Prompt Injection and Sleeper Memory Poisoning**
    - **Description & Difficulty**: Attackers hide instructions in untrusted external data (web pages/tool results). Since current systems treat all text equally, these instructions gain undue authority. The difficulty lies in detecting malicious intent after the data has been transformed or summarized, evading content-based detectors.
    - **Solution**: ClawMMU attaches "protection descriptors" to data, enforcing the rule: "Information may rise in authority, but authority never lifts itself." By checking source-based labels rather than content, the system blocks unauthorized high-privilege actions at the harness level, even if the model is fooled.
- **Challenge 2: Lack of Source-Based Access Control**
    - **Description & Difficulty**: Unlike OS hardware MMUs, agent harnesses lack permission checks on memory access. User confirmation steps often lack context about data origin, failing to prevent manipulated tool calls.
    - **Solution**: ClawMMU mimics OS MMU behavior by tagging memory pages and their derivatives. It enforces access control based on these tags during every memory operation, converting semantic attacks into classical protection faults that the system intercepts deterministically.

## Implementation and Evaluation
- **Implementation**: ClawMMU is implemented as a protection layer within the agent harness, integrating with the virtual memory manager to assign and check protection descriptors at critical execution points.
- **Evaluation Results**: The system effectively prevents indirect prompt injection and sleeper memory poisoning. Unlike probabilistic content filters, ClawMMU provides deterministic security guarantees by blocking attacks based on provenance labels.
- **Comparison with Related Work**:
    - **vs. MemGPT/ClawVM**: While these works address memory tiering and paging, they lack security protections. ClawMMU adds the missing MMU-like enforcement layer.
    - **vs. Content Detection/Training Defenses**: Existing methods rely on the model's ability to distinguish malicious content, which is error-prone and bypassable. ClawMMU relies on structural metadata (source labels), offering robustness independent of semantic analysis.

#### Summary
ClawMMU introduces OS-style memory protection to LLM agents by tracking data provenance through immutable permission labels. By enforcing access control at the system level rather than relying on model interpretation, it transforms complex semantic attacks into interceptable protection faults, providing a robust security foundation for stateful agents with long-term memory.
