## 1. What the Paper Does
- **Background**: LLM agents increasingly rely on external tools exposed via the Model Context Protocol (MCP). However, current benchmarks assume tools respond correctly and on time, leaving agent resilience to realistic tool failures untested.
- **Limitations of Existing Work**: Infrastructure-level chaos engineering operates below the semantic layer and cannot simulate MCP-specific semantic faults (e.g., well-formed but incorrect values, schema violations, silent hangs). Furthermore, traditional benchmarks lack control over fault persistence or calibrated fault profiles, failing to address which agent designs degrade gracefully or whether model scale improves fault tolerance.

## Core Contributions
- **Proposed MCP-Injector**: A drop-in, protocol-aware fault-injection middleware that interposes on the MCP tool-call path. It injects faults with controlled persistence (permanent, transient, intermittent) based on a fault model calibrated to the observed incident distribution from 57,240 issue/PR threads across 1,774 open-source MCP repositories.
- **Challenge 1: How to simulate realistic, production-aligned tool fault distributions?**
  - **Difficulty**: Manually crafted fault scenarios often deviate from real-world failure modes, making it hard to reflect actual ecosystem vulnerabilities.
  - **Solution**: The authors mined large-scale open-source MCP repository data to extract the joint distribution of failure modes and persistence, using this to calibrate MCP-Injector's injection strategy for realistic experimental conditions.
- **Challenge 2: Does increasing model scale naturally improve fault tolerance against tool failures?**
  - **Difficulty**: It is widely believed that larger models possess stronger reasoning and error-correction capabilities, but there is a lack of empirical study under systematic tool failures.
  - **Solution**: Through a full-factorial experiment crossing two backbone sizes (20B, 120B), three agent stacks, and various fault conditions, the study quantitatively evaluates performance, revealing that scale does not significantly enhance fault tolerance.

## Implementation and Evaluation
- **Experimental Setup**: A 1,350-cell full-factorial study crossing two backbone sizes (20B, 120B), three agent stacks (custom multi-round plan-and-execute, OpenAI Agents SDK, LangChain), and three fault injection conditions.
- **Key Results**:
  - **Severe Performance Degradation**: Under a permanent-heavy stress fault profile, task completion scores dropped by 60% (from 8.08 to 3.23 out of 10).
  - **Scale Does Not Purchase Fault Tolerance**: For the tested gpt-oss backbones, the 120B model showed no significant improvement in resilience ratio compared to the 20B model (p = 0.96), and its completion rate under faults was slightly lower (91.1% vs. 95.6%).
  - **Significant Framework Differences**: Agent stacks varied in their ability to absorb faults, suggesting that framework-level error handling is more critical for resilience than model scale.
- **Comparison Conclusion**: The results demonstrate that capability benchmarks alone mask operational brittleness, motivating protocol-aware fault injection as a complementary evaluation dimension.

#### Summary
This paper reveals the vulnerability of current LLM agents to realistic MCP tool failures and debunks the myth that "larger models are more fault-tolerant." By introducing MCP-Injector calibrated with real-world data, the authors demonstrate that framework-level error handling design is more decisive for agent robustness than model scale. The study calls for the community to incorporate protocol-aware fault injection into agent evaluations, alongside capability benchmarks, to comprehensively assess reliability in production environments.
