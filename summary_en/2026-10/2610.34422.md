## 1. What the Paper Did
- **Background**: Rising compute costs, limited accelerator capacity, and vendor dependence are driving organizations to migrate machine learning workloads from GPUs to alternatives like TPUs. Coding agents are expected to automate this migration to reduce engineering effort.
- **Limitations of Existing Work**: Current tools mostly target single kernels, operators, or framework translations. They lack comprehensive assessment of whether agent-generated migrations for complete projects are trustworthy, preserve numerical behavior, and offer justified operational benefits. Reducing code adaptation effort does not guarantee reliability or cost-effectiveness.

## Core Contributions
- **Proposed an Empirical Study Framework and Dataset**: Constructed a dataset of 148 PyTorch ML research projects and used Claude Code to migrate ten of them from NVIDIA GPUs to Google Cloud TPUs. Independently assessed execution, numerical preservation, hardware correctness, goal attainment, and performance.
- **Challenge 1: Silent Failures and Numerical Drift**. The difficulty lies in migrated code running without errors while producing incorrect results due to underlying library interactions or parallel strategy changes (e.g., gradient clipping logic), leading agents to falsely report success. The paper addresses this by independently verifying numerical behavior and setting strict project-goal criteria, exposing risks like accuracy drops (e.g., from 86.53% to 84.89%).
- **Challenge 2: High Failure Rates and Hidden Costs**. The challenge is the low actual success rate and difficult debugging of automated migrations. The study found 76% of execution attempts failed, with nearly half raising no errors, and an average of 2.4 human interventions per migration. It quantifies human and compute costs by analyzing failure causes (e.g., repeated compilation, third-party library issues), advocating for acceptance criteria that account for both.

## Implementation and Evaluation
- **Implementation & Deployment**: Used Claude Code to migrate 10 selected PyTorch projects from GPU to TPU. Evaluated based on execution success, hardware targeting, numerical consistency, goal achievement, and performance/cost.
- **Evaluation Results**:
    - **Success Rate**: 8 out of 10 projects met the project-goal criteria.
    - **Failure Analysis**: 53 out of 70 execution attempts failed (76%), with 26 (49%) raising no errors. Primary causes were repeated compilation, execution inefficiencies, and silent computation changes from third-party libraries.
    - **Human Effort**: Average of 2.4 human interventions per migration.
    - **Performance & Cost**: Varied widely. In one workload, TorchTPU on TPU trained 1.86x faster and was 25% cheaper per run than on GPU.
- **Comparison**: Unlike Google's reported 6.4–8x speedup in production TensorFlow-to-JAX migration, this study focuses on diverse PyTorch research projects, revealing higher complexity and silent error risks in real-world scientific code migration. It emphasizes the need for independent reference runs and workload-specific acceptance criteria.

## 4. Conclusion
The paper demonstrates that while coding agents assist in GPU-to-TPU migration, there are significant risks of silent failures and substantial human intervention requirements. Migration involves not just code translation but also preserving numerical behavior and balancing cost-effectiveness. Practitioners are advised to use independent reference runs, verify under target hardware configurations, and establish acceptance/stopping criteria that account for both computational and human costs to ensure trustworthiness and economic viability.
