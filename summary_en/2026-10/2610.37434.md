## 1. What the Paper Does
- **Background**: Software features evolve over time as developers extend existing code to meet new requirements. Current coding agent benchmarks (e.g., SWE-bench) primarily evaluate the ability to resolve single requests on fixed codebases, lacking assessment of multi-stage, continuous feature evolution.
- **Why Existing Work Falls Short**: Existing benchmarks treat tasks as independent single-point problems, ignoring inter-stage dependencies and error accumulation. They fail to evaluate whether agents can correctly extend features based on their own previously generated code (which may contain undetected errors) without human intervention, i.e., they lack evaluation of L4 autonomous evolution capabilities.

## Core Contributions
- **Proposed FeatureArc Benchmark and Pipeline**: A benchmark for evaluating coding agents on evolving features, featuring a pipeline that constructs tasks from repository histories. It supports four programming languages and includes explicit requirements, interface contracts, and executable checks.
- **Challenge 1: How to accurately simulate real-world feature evolution dependencies?**
  - **Difficulty**: Simply splitting a single request into stages results in weak dependencies, failing to truly test an agent's ability to inherit and handle prior code.
  - **Solution**: The paper proposes a pipeline that constructs tasks from real repository histories, validating "Fail-to-Pass" (F2P) tests for new behavior and "Pass-to-Pass" (P2P) tests for existing behavior at each stage, ensuring strong inter-stage dependencies and regression testing needs.
- **Challenge 2: How to quantify error accumulation and self-correction capabilities in long-horizon evolution?**
  - **Difficulty**: Errors introduced in early stages are often undetected and inherited in later stages, causing a significant drop in final success rates. Traditional metrics struggle to capture this "inherited defect" mechanism.
  - **Solution**: The study designs an L4 evaluation scenario (no external test feedback or rollback) and uses trajectory analysis to identify "inherited defects" as the primary failure mechanism. It quantifies the rate at which agents ignore early errors in subsequent stages, revealing limitations in their self-verification.

## Implementation and Evaluation
- **Implementation and Deployment**: FeatureArc comprises 73 manually reviewed tasks, each with 2 to 10 stages. Ten coding agents were evaluated in persistent sessions and workspaces without external test feedback or rollback. The pipeline is deployed at Tencent to guide the development of the Hunyuan LLM family.
- **Evaluation Results**:
  - **Significant Success Rate Drop**: Agent success rate falls from 62.7% at the first stage to 28.5% when the entire feature is tested on the final code.
  - **Failure Mechanism Analysis**: Trajectory analysis shows that 72.9% of failures in later stages are caused by "inherited defects." In stages following a failure, agents fail to notice earlier errors about 95% of the time, and their self-tests rarely revisit earlier stages.
- **Comparison**: Compared to existing works that evaluate single stages or provide human feedback (L1-L3), FeatureArc reveals a substantial capability gap in current agents for fully autonomous (L4) multi-stage development, demonstrating that high pass rates on traditional benchmarks (like SWE-bench) do not reflect robustness in real-world evolutionary scenarios.

## 4. Conclusion
FeatureArc fills the gap in evaluating coding agents for evolving feature development. By constructing multi-stage tasks with strong dependencies and an L4 autonomous evaluation environment, the paper reveals severe deficiencies in current agents' handling of long-term dependencies and self-correction, particularly the cliff-like drop in success rates due to "inherited defects." This research provides critical benchmarks and insights for improving agent reliability in complex, continuous software development tasks.
