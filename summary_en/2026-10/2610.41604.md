## 1. What the Paper Did
- **Background**: Agent systems built on local Large Language Models (LLMs) are increasingly marketed using cognitive architecture vocabulary (e.g., global workspace, theory of mind). The presence of a module name is often mistakenly taken as evidence of the mechanism's actual implementation.
- **Limitations of Existing Work**: Current evaluations focus on end-task performance or rely on LLM self-correction, lacking rigorous verification of the gap between "claimed mechanisms" and "actual code implementation." Names may be attached to uncalled code or constants, creating a disconnect between claims and computation that has rarely been audited.

## Core Contributions
- **Proposed a transferable software verification method**: A four-question static audit protocol with line-number evidence and call-chain tracing to address the claim-implementation gap, along with a five-class failure taxonomy.
- **Challenge 1: How to verify if named modules actually perform computations that influence output?**
  - Difficulty: Modules may be defined but never called, or called but their results do not propagate to production outputs; black-box testing cannot easily detect these internal structural defects.
  - Solution: The paper uses static analysis to trace call chains and value flows, pre-registers falsifiable predictions, and executes interventions to directly check if computed values reach the output.
- **Challenge 2: How to quantify and classify these implementation defects?**
  - Difficulty: There is a lack of standardized terminology for "existing but ineffective" code patterns, making systematic repair difficult.
  - Solution: The study identifies three new "idle-wiring" shapes (connected-but-never-called, called-but-inert, called-but-content-blind) and audits module names and computations as independent claims.

## Implementation and Evaluation
- **Implementation & Evaluation**: The authors audited a system claiming 25 cognitive mechanisms, pre-registering falsifiable predictions for 11 modules. The protocol was replicated on a second independent system (IIT-phi core). Two repair experiments served as positive controls.
- **Results**: In 18 of the 25 modules, the computed value never reached any production output. Of 61 frozen criteria across 12 interventions, 53 were confirmed and 5 were falsified. Repairs increased planner task success from 0.028 to 1.000 and reduced state-controller error by 52%.
- **Comparison**: Unlike traditional dead-code analysis, this work reveals new defect patterns specific to cognitive architecture integration (e.g., "called-but-inert"). It demonstrates that module naming does not guarantee functionality and highlights significant engineering gaps in current LLM agent systems.

## 4. Conclusion
The paper exposes the prevalent "claim-implementation" gap in LLM agent systems, arguing that module names and actual computations must be audited as independent claims. The proposed static audit protocol and failure taxonomy provide new perspectives and tools for rigorous code-level verification in AI development, extending beyond cognitive architectures to general software engineering practices like dead-code analysis and integration testing.
