## 1. What the Paper Did
- **Background**: LLM agents operate Web infrastructure via command-line interfaces, relying on a "Return Assumption" that tool calls return within a bounded time with the requested action completed. However, many commands require interactive input (e.g., confirmations, passwords) before executing.
- **Why Existing Work Fails**: Current agent harnesses handle interactive commands poorly. Closing the input stream can cause programs to exit with status 0 without performing the action (silent failure). Keeping the input open (e.g., as a terminal) causes the program to wait until timeout, leading to excessive token consumption and potential misjudgment of task failure due to timeouts. Prior work has neither measured the extent of this assumption's failure nor provided a robust repair mechanism.

## Core Contributions
- **Proposed RECEIPT**, a system to measure and repair the Return Assumption in LLM agents for Web service operations.
- **Challenge 1: Silent Failures and False Successes**. When input is closed, interactive commands may exit successfully without doing any work, misleading the agent. **Solution**: RECEIPT keeps the input open and monitors process states via system calls to detect if a process is waiting for input, preventing the misclassification of unexecuted commands as successful.
- **Challenge 2: Resource Waste and Timeout Misjudgments**. With open input but no automated response, commands wait until timeout, wasting tokens and time. **Solution**: RECEIPT reads what the process is waiting for (e.g., prompts) and returns this state to the unmodified agent via a model-checked protocol, enabling the agent to provide timely input, significantly reducing wait times and token usage.

## Implementation and Evaluation
- **Datasets & Benchmarks**: Collected 91,469 production tool calls and 89,047 public agent trajectories. Built Litmus (a catalog of 158 verified command-line invocations) and Tripwire (a benchmark of 25 task pairs differing only by the presence of an input guard).
- **Measurement Results**: On Litmus, closed input caused 11.5% of invocations to return status 0 without performing the action; 7 out of 8 major harnesses close input when no terminal is attached. On Tripwire, unanswered questions increased token usage by 2.9x, and the input connection method improved Llama-3.3-70B's ranking from 7th to 3rd among 8 LLMs.
- **RECEIPT Performance**: Compared to closed input, RECEIPT reduced false success claims by 73.5%. Compared to plain terminal mode, it reduced token usage by 24.4%. It reported waiting states with 85.0% accuracy and no false positives. In a commercial agent runtime, checks took a median of at most 0.54ms per shell call.
- **Comparison**: Unlike existing frameworks that suffer from either silent failures or high timeout costs, RECEIPT resolves this trade-off by providing precise state feedback, enhancing both reliability and efficiency.

## 4. Conclusion
This paper is the first to quantify and repair the "Return Assumption" in LLM agents for command-line operations. It demonstrates that agent reliability depends not only on the LLM but also on the observability provided by the harness. The authors recommend that agent builders report actual tool execution outcomes rather than just exit codes, and benchmark maintainers should fix and disclose input handling methods before ranking LLMs. RECEIPT effectively eliminates false successes and reduces resource overhead by monitoring system call states and providing structured feedback.
