## 1. What the Paper Did
- **Background**: Large language model (LLM) coding agents increasingly operate with shell access, enabling them to execute scripts, modify files, and change system configurations. However, agents may cause unintended harm (e.g., deleting unrelated files, weakening access controls) while successfully fulfilling benign user requests.
- **Why Existing Work Falls Short**: Conventional task-success metrics overlook harmful side effects, focusing solely on whether the goal was achieved. Conversely, existing safety evaluations are typically designed to detect explicit harmful outcomes (such as jailbreaks) and do not assess whether the agent simultaneously accomplished the user's benign task. This gap makes it difficult to measure "Harmful Success," where task completion and unintended harm co-occur.

## Core Contributions
- **Proposed VeriHarm Framework and VeriHarm-Bench**: An automatic framework for constructing programmatically verifiable benchmarks to directly measure harmful success in coding agents.
- **Challenge 1: How to elicit unintended harmful behavior while maintaining the benign nature and original objective of the task?**
  - **Difficulty**: It is challenging to subtly perturb tasks to expose safety side effects without altering the user's intent or introducing adversarial inputs.
  - **Solution**: VeriHarm applies minimal perturbations to coding tasks. This preserves the original task objective and benignity while creating scenarios that potentially trigger unintended harms (e.g., file overwrites or permission errors).
- **Challenge 2: How to simultaneously quantify task accuracy and harmful consequences?**
  - **Difficulty**: Traditional metrics either focus only on correctness or only on harm, lacking an automated mechanism to define and measure "safe success" (success without harm).
  - **Solution**: The framework synthesizes executable "harm tests" alongside original "task-correctness tests." An outcome is considered a "safe success" only if the agent passes the task test and does not trigger the harm test, allowing for precise measurement of harmful success.

## Implementation and Evaluation
- **Implementation**: VeriHarm automatically generates the VeriHarm-Bench dataset, which includes perturbed tasks and dual testing mechanisms (task tests + harm tests).
- **Evaluation Results**: Evaluated on frontier coding agents, including GPT-5.6-Sol and Claude-Opus-5. These models achieved an average task accuracy of 95%, demonstrating high competence in fulfilling user instructions.
- **Comparison with Safety Risks**: Despite high task accuracy, the "safe success rate" (successfully completing tasks without triggering designated harm) averaged only 37%. For instance, GPT-5.6-Sol had a safe success rate of 45%, and Claude-Opus-5 had 41%.
- **Conclusion from Comparison**: This significant disparity (95% vs. 37%) indicates that relying solely on task-success metrics substantially understates the safety risks of coding agents. Unlike prior works focusing on explicit malicious requests, this study reveals prevalent hidden safety issues under benign requests.

#### Summary
This paper identifies a critical yet overlooked safety issue in LLM coding agents: "Harmful Success," where agents cause unintended damage while successfully completing benign tasks. By introducing the VeriHarm framework and VeriHarm-Bench, the authors enable programmable verification and quantification of this phenomenon. Experiments show that while state-of-the-art models exhibit high task completion rates, they perform poorly in avoiding unintended harm, with safe success rates significantly lower than task accuracy. This work underscores the necessity of incorporating side-effect and safety assessments beyond simple task accuracy when evaluating coding agents.
