## 1. What the Paper Does
- **Background**: As Large Language Model (LLM) agents become prevalent in enterprise applications, ensuring their behavior aligns with security and workflow specifications is critical. However, existing infrastructure security measures (such as confidential computing) only protect the execution environment and cannot verify whether an agent selected allowed tools, grounded its answers in tool outputs, or followed required workflow steps.
- **Limitations of Existing Work**: Traditional testing methods struggle to capture subtle errors in agent execution, such as calling tools with forbidden parameters, fabricating non-existent data identifiers, or deriving correct final answers via disallowed paths. Merely checking the final answer provides insufficient evidence regarding execution decisions, and current security frameworks lack fine-grained validation capabilities for application-layer behavioral contracts (e.g., tool selection, data grounding, and execution trajectories).

## Core Contributions
- **Proposed AgentTrustCI**, a Java/JUnit 5 framework that expresses application-layer expectations as policy, grounding, and trajectory checks over recorded traces during build time.
- **Challenge 1: How to verify if an agent adheres to tool and parameter policies?**
  - **Difficulty**: Agents may invoke unauthorized tools or use forbidden parameters. This is hard to cover with traditional unit tests via simple I/O assertions because it requires deep inspection of intermediate call details.
  - **Solution**: AgentTrustCI introduces a "Policy Check" layer that constrains allowed tool lists, parameter whitelists/blacklists, and enumerated values through declarative rules, directly analyzing recorded trace data to detect violations.
- **Challenge 2: How to ensure agent answers are truthful and execution paths are compliant?**
  - **Difficulty**: Agents may hallucinate (e.g., inventing IDs) or violate business logic sequences (e.g., updating before reading) while still producing a correct final answer. Traditional tests often miss these procedural errors.
  - **Solution**: The framework provides "Grounding Checks" and "Trajectory Checks" layers. Grounding checks compare claims in the answer against actual tool output data to detect fabrication; trajectory checks validate the order and completeness of call sequences, capturing violations even if the final result is correct.

## Implementation and Evaluation
- **Implementation & Deployment**: AgentTrustCI is a lightweight Java/JUnit 5 prototype integrated into CI/CD pipelines as a build-time test. It employs a deterministic replay mechanism, evaluating pre-recorded agent interaction traces without invoking an LLM during testing. It includes an extensible Judge interface for optional semantic evaluation.
- **Evaluation Results**: Tested on 55 synthetic cases across seven enterprise domains. The full pipeline correctly classified all 30 injected faults and 25 passing control cases, including 10 non-trivial controls, missing none of the 12 designated critical cases. Single-layer configurations each correctly classified 35 cases (as the corpus deliberately isolated 10 faults per layer). The experiments also quantified validator execution time, separating it from process startup and reporting overhead.
- **Comparison**: Compared to traditional infrastructure security solutions, AgentTrustCI fills the gap in application-layer behavioral validation. Compared to simple final-answer checks, it offers more comprehensive coverage, capable of detecting correct results obtained through illegal paths (demonstrating the added value of trajectory checks).

## 4. Conclusion
AgentTrustCI proposes a practical pattern for expressing and validating behavioral contracts of LLM agents within existing Java release pipelines. Through three-layer checks (policy, grounding, and trajectory), it effectively detects various execution violations, providing engineers with repeatable, deterministic build-time testing capabilities. While the results primarily demonstrate coverage of the regression suite rather than absolute production accuracy, it lays the foundation for maintaining expectations in evolving workflows and integrating production trace validation protocols.
