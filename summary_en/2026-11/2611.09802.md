## 1. What the Paper Did
- **Background**: LLM-based coding agents (e.g., Claude Code) rely on repository instruction files (like AGENTS.md or CLAUDE.md) for guidance. These files are read in every session but can become stale as code evolves, creating "documentation debt."
- **Why Existing Work Falls Short**: Current evaluations primarily focus on task success rates, ignoring the hidden costs (e.g., extra tool calls, wasted effort) incurred when agents follow outdated instructions. This blind spot allows stale documentation to persist without quantifying its negative impact on efficiency.

## Core Contributions
- **Proposed a** fine-grained empirical study framework to quantify the hidden costs of "documentation debt" in coding agents, analyzing agent behavior trajectories to reveal efficiency losses masked by final task success.
- **Challenge 1: Quantifying the specific impact of stale instructions on agent behavior and recovery.**
  - **Difficulty**: Agents may mask inefficiencies during successful task completion, and the impact varies across different types of stale instructions (commands, paths, procedures), making unified measurement difficult.
  - **Solution**: The paper selected three real-world cases from open-source repositories. It controlled variables (fixed code and tasks) and compared 732 agent trajectories across three conditions (stale, corrected, removed instructions), analyzing tool call patterns at a granular level.
- **Challenge 2: Explaining why agents prioritize stale instructions over correct information in the codebase.**
  - **Difficulty**: Theoretically, agents should perceive the current state of the code, but they often blindly trust configuration files even when correct information is available elsewhere.
  - **Solution**: Case studies revealed that agents follow stale guidance when it is highly relevant to the task, leading to errors. The study showed that correcting or removing instructions reduces invalid operations, but agents do not proactively repair the underlying stale instruction files.

## Implementation and Evaluation
- **Experimental Setup**: Investigated three types of stale instructions (test command, code location, component addition procedure). Two models (including Claude Sonnet 5.5) performed 22 maintenance tasks under three instruction versions (stale, corrected, removed), resulting in 732 analyzed trajectories.
- **Evaluation Results**:
  - **Hidden Costs**: For the stale test command, Claude Sonnet 5.5 required approximately two extra tool calls per run, a one-third increase compared to using the corrected instruction.
  - **Behavioral Differences**: No significant performance difference was detected in the other two cases, though agents still attempted to access obsolete paths.
  - **Recovery Capability**: Agents generally recovered from immediate failures caused by stale instructions and completed tasks, but none actively repaired the underlying stale instruction file.
  - **Intervention Effect**: Correcting instructions eliminated operations on obsolete paths, while removing them prevented most such attempts.
- **Comparison**: Unlike traditional evaluations focusing solely on "task success," this study reveals the efficiency traps behind success rates, demonstrating the inadequacy of current evaluation standards.

## 4. Conclusion
The paper highlights that "documentation debt" is a significant yet overlooked issue for LLM coding agents. While agents possess strong fault tolerance and can overcome obstacles from stale instructions to complete tasks, this comes with significant hidden costs (e.g., additional tool calls and resource consumption). The study emphasizes that task success alone is insufficient for evaluating agent effectiveness; future evaluation systems must incorporate agent behavior trajectories and efficiency costs. Additionally, developers should maintain instruction files promptly to prevent the accumulation of technical debt.
