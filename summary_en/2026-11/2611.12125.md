## 1. What the Paper Does
- **Background**: In ReAct-style LLM agents, external tool calls are a major source of running costs. Since observations from each call remain in the context and are re-processed in subsequent turns, low-yield or redundant calls significantly increase latency and computational expense.
- **Why Existing Work Fails**: Current training objectives focus almost exclusively on task completion, ignoring call costs. While some methods introduce efficiency rewards, they suffer from three key issues: 1) The efficiency anchor (e.g., the shortest correct rollout in a group) moves with the policy, causing instability; 2) Training often drifts toward "policy collapse," where the agent stops making any tool calls; 3) A single training run yields only one operating point, preventing users from trading off efficiency against capability.

## Core Contributions
- **Proposed CARE-PO (Controllable Anchored Relative Efficiency Policy Optimization)**: A method designed to balance tool-call efficiency with task success rates by stabilizing the optimization process and enabling controllable trade-offs.
- **Challenge 1: Instability and Policy Collapse due to Dynamic Anchors**. The difficulty lies in the tendency of models to minimize penalties by avoiding tool calls entirely when the reference standard is dynamic. CARE-PO mitigates this by anchoring the efficiency reward to a reference budget based on task difficulty (fixed before training) and injecting successful trajectories from training data into online GRPO rollout groups, while penalizing the lack of evidence gathering.
- **Challenge 2: Lack of Flexibility with Single Operating Points**. Traditional methods produce a single behavior mode per training run, limiting adaptability. CARE-PO shapes the cost curve using an "effort tag" in the prompt, allowing multiple operating points (e.g., high-efficiency vs. high-capability) to be derived from a single training run, enabling dynamic trade-offs during inference.

## Implementation and Evaluation
- **Experimental Setup**: Evaluated on the GAIA benchmark and four held-out multi-hop benchmarks using Qwen3.5 models (4B, 9B, 27B).
- **Results**:
    - **GAIA Benchmark**: Five out of six operating points across three model sizes improved upon the base model in both success rate and call count. For instance, the 9B model achieved significantly lower average tool calls while maintaining or improving success rates.
    - **Held-out Multi-hop Benchmarks**: Results were size-dependent. For 27B and 4B models, CARE-PO maintained or increased success rates with fewer calls. For the 9B model, both operating points traded a slight decrease in success rate for significantly fewer calls.
    - **Stability**: Unlike baselines (e.g., OTC-PO) which showed signs of degeneration, CARE-PO maintained tool call counts well above zero throughout training for all model sizes, avoiding policy collapse.

## 4. Conclusion
CARE-PO effectively addresses policy collapse and the rigidity of single operating points in existing RL methods for tool-call efficiency by introducing a fixed difficulty-based reference budget and effort tags in prompts. It achieves simultaneous improvements in success rate and efficiency across multiple model sizes and offers flexible controllability, allowing developers to adjust agent behavior post-training to significantly reduce LLM agent running costs.
