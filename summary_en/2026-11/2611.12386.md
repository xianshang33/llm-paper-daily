## 1. What the Paper Does
- **Background**: With LLM-driven agents increasingly used in cyberattacks, attribution must extend beyond the human attacker to identify the software configuration (specific LLM version and Agent Harness). Traditional attribution relies on accessing internal logs or configs, but defenders often operate in a "blind and passive" mode, observing only the effects of agent actions on target systems without direct access to the agent's internal state.
- **Why Existing Work Fails**: Current model fingerprinting techniques (e.g., LLMmap) require active querying of the LLM application to examine responses. This assumes a direct interaction interface, which defenders do not have when facing an attacking agent. They can only observe request sequences and tool execution outcomes, rendering active probing methods inapplicable.

## Core Contributions
- **Proposed "Shibboleth Traps"**: A modular honeypot service designed to elicit discriminative behaviors from agentic attackers by making informative interactions a prerequisite for resource acquisition.
- **Challenge 1: How to identify the LLM model without successful prompt injection?**
  - **Difficulty**: Traditional identification relies on direct Q&A, but attacking agents may not answer identity questions directly, and defenders cannot control the conversation context.
  - **Solution**: The paper introduces "Declarative Gates," which condition access to critical resources (e.g., deploy keys) on the agent declaring its model name or generating text with specific stylistic traits. This forces the agent to reveal distinguishing information to achieve its goal, eliciting model declarations and characteristic writing without needing prompt injection.
- **Challenge 2: How to indirectly identify the Harness (execution environment) wrapping the LLM?**
  - **Difficulty**: The Harness manages tool calls, secret masking, timeouts, and concurrency. These internal mechanisms are invisible to defenders, and behavioral differences between harnesses are subtle.
  - **Solution**: The paper introduces "Behavioral Probes" that infer harness characteristics by observing side effects. For example, by holding a tool call open to test timeout handling or observing how secrets are masked in outputs. These probes reveal unique execution logics (e.g., command time limits, scheduling) using only effects visible in subsequent requests.

## Implementation and Evaluation
- **Implementation**: The authors implemented Shibboleth Traps on an MCP (Model Context Protocol) server, featuring both declarative and behavioral gates. Experiments simulated attacker agents attempting to steal resources from the honeypot.
- **Evaluation Results**:
  - **LLM Identification**: Combined declarative and behavioral inference achieved an average 90% Top-1 accuracy across 15 candidate models. Behavioral classifiers remained effective even on held-out harnesses or task families.
  - **Harness Identification**: In separate experiments across four harnesses, fixed probe rules identified the correct harness with 92% accuracy.
  - **Robustness to Concealment**: When agents were instructed to conceal their identity, their declarations became uninformative, but they still left useful behavioral evidence, demonstrating robustness against adversarial hiding.
- **Comparison**: Unlike methods like LLMmap that require direct query interfaces, this approach achieves high-precision identification of attacker configurations in a fully passive setting, relying solely on target system telemetry, thus filling a gap in passive defense scenarios.

#### Summary
This paper addresses LLM-driven cyberattacks by proposing a passive fingerprinting framework called "Shibboleth Traps." By strategically designing honeypot interaction logic, the method forces attacking agents to expose declarative features of their underlying LLM and behavioral features of their Harness while pursuing objectives. Experiments show that the technique can accurately identify the specific model version and execution framework used by attackers without relying on internal logs or direct query interfaces, remaining effective even against agents attempting to hide their identity, thereby providing a new technical avenue for attack attribution in cybersecurity defense.
