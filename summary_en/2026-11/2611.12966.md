## 1. What the Paper Does
- **Background**: Large Language Models (LLMs) can generate SQL and SQL-Python workflows for investment research, but ensuring Point-in-Time (PIT) validity remains a significant challenge. Agents must enforce disclosure cutoffs and select appropriate historical states and record versions during data retrieval and analysis.
- **Why Existing Work Falls Short**: Existing benchmarks focus on financial SQL generation or general analytical workflows, often ignoring strict temporal constraints. Even recent works checking for future data dependence fail to fully capture PIT validity. Studies show that many workflows passing result checks actually violate PIT principles (e.g., using financial reports disclosed after the research date), leading to distorted historical backtesting results.

## Core Contributions
- **Proposed BuySideFlow Benchmark**: A dataset of 408 Chinese-language tasks derived from buy-side practitioner practices, covering equities, funds, fixed income, and macroeconomics, built on a fixed snapshot of a licensed production financial database.
- **Challenge 1: Difficulty in End-to-End Workflow Evaluation**. Investment research combines data retrieval, calculations, and specific outputs, making isolated evaluation difficult. **Solution**: BuySideFlow provides executable reference workflows and expert audits, evaluating not just the final result but the entire SQL/Python execution path for logical correctness.
- **Challenge 2: Difficulty in Verifying Point-in-Time (PIT) Validity**. Agents inadvertently introduce future information (e.g., using current listing status instead of historical). **Solution**: The paper establishes a taxonomy of temporal errors and conducts expert human audits on 900 runs, specifically detecting violations of disclosure cutoffs and historical state selection, revealing that output matching alone does not guarantee temporal validity.

## Implementation and Evaluation
- **Implementation**: Built on a fixed snapshot of a licensed production financial database. Tasks underwent multiple rounds of expert review and execution checks. Nine LLM agent configurations were evaluated.
- **Evaluation Results**:
    - Result accuracy across all tasks ranged from only 16.2% to 36.8%, indicating limited capability of current agents in handling complex financial workflows.
    - In an audit of 900 runs on 100 shared tasks, 380 passed result checks, but 193 of those (50.8%) contained PIT violations.
- **Comparison**: Unlike existing benchmarks that focus only on code generation or final answer matching, BuySideFlow demonstrates that "correct results" do not equal "compliant processes." It highlights that existing methods severely underestimate the risk of future data leakage in time-sensitive financial scenarios.

#### Summary
BuySideFlow fills the gap in validating point-in-time effectiveness for financial LLM agents. By introducing complex tasks based on real buy-side practices and strict temporal audit mechanisms, the paper reveals widespread time-travel issues in current LLM agents simulating historical investment research. The benchmark emphasizes that reliable financial automation requires not only accurate calculation results but also strict historical data isolation mechanisms, providing a crucial evaluation standard for developing time-aware financial agents in the future.
