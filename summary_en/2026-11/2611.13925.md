## 1. What the Paper Does
- **Background**: LLM-based multi-agent frameworks for Requirements Engineering (RE) are becoming common, utilizing role-specialized agents for eliciting, modeling, negotiating, and verifying requirements.
- **Why Existing Work Falls Short**: Current frameworks (e.g., MARE, iReDev, QUARE) employ different agent roles, negotiation policies, and output formats. They are typically evaluated on their own runtimes, metrics, and small, curated sets of system descriptions. This makes fair, reproducible comparison difficult and limits external validity as inputs lack provenance from real software repositories.

## Core Contributions
- **Proposed OpenRE-Bench**: An open-source benchmarking infrastructure for LLM-based multi-agent RE frameworks.
- **Challenge 1: Difficulty in Fair Comparison of Heterogeneous Frameworks**. Different frameworks have incompatible inputs, outputs, and metrics. OpenRE-Bench addresses this by providing a shared run harness and contract that standardizes input, phase artifacts, and metric contracts, allowing heterogeneous frameworks to be executed and scored under identical conditions.
- **Challenge 2: Lack of Realism and Scalability in Evaluation Data**. Traditional evaluations rely on small, hand-crafted cases. OpenRE-Bench introduces a reproducible GitHub issue-mining pipeline to construct benchmark cases from real feature requests. It also features an adapter mechanism, enabling new frameworks to join the benchmark by implementing a single adapter without altering existing cases or metrics.

## Implementation and Evaluation
- **Implementation & Deployment**: OpenRE-Bench consists of four reusable components: a shared run harness, an adapter mechanism, a GitHub issue-mining pipeline, and a versioned case suite. It is released with a pinned environment, Docker image, frozen API snapshots, and a 651-test suite.
- **Evaluation Results**: As a demonstration, the authors mined 3,000 issues from five projects (three languages, five domains) to create five mined cases, packaged with five hand-built cases into the v1.0 suite. Three heterogeneous frameworks (MARE and iReDev as faithful reimplementations, plus QUARE) were run under this unified protocol.
- **Comparison**: By running these frameworks under a single protocol, OpenRE-Bench enables direct horizontal comparison, addressing the fragmentation of previous evaluation methods. The benchmark has already been reused in two additional studies, demonstrating its utility and generalizability.

## 4. Conclusion
OpenRE-Bench addresses the critical lack of fairness and reproducibility in evaluating multi-agent RE frameworks by standardizing the runtime environment, introducing an adapter mechanism, and constructing a scalable dataset based on real GitHub issues. It provides not only a compact versioned case suite but also a sustainable ecosystem for benchmarking, facilitating standardized comparison and advancing research in the field.
