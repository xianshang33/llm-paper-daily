## 1. What the Paper Did
- **Background**: Software agents built on Large Language Models (LLMs) generate network traffic distinct from human web traffic in duration, rate, and direction. With AI inference traffic projected to account for a quarter of network traffic by 2035, existing router Quality-of-Service (QoS) mechanisms lack a dedicated class for this "agentic traffic," causing latency-sensitive agent calls to share queues with standard web or bulk transfers.
- **Why Existing Work Fails**: Traditional Differentiated Services (DiffServ) are vulnerable to abuse if they blindly trust markings, allowing malicious users to spoof agent status for priority. Conversely, per-flow fair queuing schedulers (like fq_codel) ensure fairness but fail to provide the low-latency guarantees required for interactive agent workflows. Existing solutions either lack verification (security risk) or lack prioritization (performance deficit).

## Core Contributions
- **Proposed Verifiable Agentic Traffic Class (VATC)**: A policed QoS mechanism combining a reserved DSCP value declaration, a router-side classifier for verification, and a rate-limited priority queue.
- **Challenge 1: How to prevent non-agent traffic from spoofing identity to steal priority?**
  - **Difficulty**: Simple DSCP markings are easily spoofed by any sender claiming to be an agent.
  - **Solution**: Introduces a router-side verification engine that compares declared markings with observed flow behavior. Flows contradicting the declaration (e.g., bulk transfers masquerading as agents) are demoted to a class below best-effort, removing the incentive to spoof.
- **Challenge 2: How to ensure low latency for agents while preventing agent traffic floods from degrading human user experience?**
  - **Difficulty**: Granting high priority without limits could allow agent traffic to monopolize bandwidth, increasing latency for human users.
  - **Solution**: Employs a dedicated priority queue with a fixed rate limit. Even verified agent traffic is capped, ensuring that under burst loads or attacks, human user latency remains controlled (experimentally shown to be 11x lower than DiffServ).

## Implementation and Evaluation
- **Implementation**: VATC was evaluated in two simulators and on a real Linux kernel. Key components include an Agentic QoS Identifier (AQI) mapped to a reserved DSCP, a four-feature classifier, and a rate-limited priority queue.
- **Results vs. Related Work**:
  - **Steady Load**: VATC performance matched static DiffServ.
  - **Burst Traffic**: In simulations, VATC reduced mean agent queuing delay by 98% compared to DiffServ, with only a 12% increase in human delay.
  - **Adversarial Testing (Kernel)**: Under spoofed flood attacks, VATC's rate limiting kept human latency 11 times lower than DiffServ. The live classifier successfully demoted all 20 bulk-shaped spoofers, achieving 0.30 ms latency for legitimate agents, though it missed six spoofers that mimicked agent patterns.
  - **Limitations**: Timing-based classification features failed to distinguish agent from human flows when emulated network delay was introduced. On congested links, router queuing accounted for 13% to 63% of total agent task time.

## 4. Conclusion
This paper proposes VATC to address the lack of dedicated QoS classes for LLM agent traffic and the associated risks of abuse. By combining declarative marking, behavioral verification, and rate limiting, VATC significantly reduces agent latency while effectively defending against priority spoofing and protecting human user experience. Although classification accuracy faces challenges under complex network delays, the mechanism offers a viable solution for managing agent traffic in enterprise and campus networks.
