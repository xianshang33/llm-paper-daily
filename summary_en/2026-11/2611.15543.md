## 1. What the Paper Does
- **Background**: LLM applications increasingly rely on translators and compatibility layers to move conversations across different provider APIs. However, API compatibility does not guarantee that the original conversation's information is preserved.
- **Limitations of Existing Work**: Schema validation only checks structural validity, missing semantic loss. Reference-based differential testing is costly and requires additional model calls or reference translations, making it hard to distinguish translation errors from target API limitations. Thus, silent information loss (e.g., in instruction roles, tool interactions, error states) remains undetected by conventional methods.

## Core Contributions
- **Proposed isloss**, a deterministic test oracle for detecting conversation-information preservation across LLM API translations.
- **Challenge 1: How to accurately distinguish legitimate representational changes from harmful information loss without relying on reference translations or extra model calls?**
  - **Difficulty**: Structural differences between APIs make simple field mapping insufficient for semantic equivalence, and traditional differential testing is expensive.
  - **Solution**: isloss maps source and target requests/replies to a shared intermediate representation (ConvIR) and applies explicit rules to identify information loss, requiring no reference implementation.
- **Challenge 2: How to differentiate avoidable translation errors from degradation caused by inherent target API limitations?**
  - **Difficulty**: Some loss stems from the target API's lack of support rather than translator bugs, leading to false positives if not distinguished.
  - **Solution**: The method uses rules to explicitly categorize losses as either avoidable translation faults or unavoidable target API constraints, precisely pinpointing translator defects.

## Implementation and Evaluation
- **Implementation & Evaluation**: Evaluated via specification-based fault injection, human review, and experiments on existing translators, gateways, and client libraries.
- **Key Results**:
  - On held-out tests, isloss detected 95 out of 125 planted faults (76.0%) with a low false positive rate of 2.0%.
  - Across five translator codebases, 18.5% of completed translations passed static checks but silently altered prompt, role, or tool information.
  - In reply streams, 36.4% caused exceptions or silent corruption in official OpenAI SDKs.
- **Comparison & Impact**: Unlike traditional validation, isloss uncovers "structurally valid but semantically damaged" errors. Behavioral experiments confirm that these translation-induced changes significantly alter model performance in dependent tasks, establishing conversation preservation as a distinct correctness requirement.

## 4. Conclusion
The paper exposes the prevalent issue of silent information loss in LLM API translations and introduces isloss, a lightweight, deterministic detection tool. It demonstrates that successful API translation does not equate to conversation preservation. isloss provides a practical foundation for improving the reliability of LLM interoperability, agent execution, and model evaluation.
