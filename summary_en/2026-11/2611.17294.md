## 1. What the Paper Does
- **Background**: With the rise of Apple Silicon (M-series chips) for on-device inference, efficiently generating and evaluating kernels using local accelerators is critical. Language model Agents are employed to generate and optimize Apple Metal kernels, a process involving model requests, code editing, compilation, and GPU execution.
- **Why Existing Work Falls Short**: Current evaluation frameworks (e.g., KernelBench, KernelGYM) focus on CUDA or distributed GPU environments, lacking support for macOS native toolchains and Apple Silicon specifics. Crucially, GPU actual execution time constitutes a tiny fraction (~2.32%) of an Agent's runtime, leaving GPUs idle most of the time. Traditional single-node serial execution fails to utilize these idle cycles effectively and suffers from load imbalance and long tool waiting times in concurrent multi-session scenarios.

## Core Contributions
- **Proposed Metal Sandbox**: An infrastructure designed for GPU coding Agents on Apple Silicon, combining restricted file access isolation, native command execution, and command-level scheduling across interconnected Mac clusters, integrated with Harbor for automated verification and data collection.
- **Challenge 1: Low GPU Utilization due to Task Interleaving**. Since Agent sessions alternate between model inference, CPU preprocessing, and GPU execution, GPUs remain idle for significant periods. Metal Sandbox classifies commands into parallel (e.g., file operations) and serial (e.g., GPU execution), allowing parallel commands to execute without blocking while coordinating serial commands to overlap execution windows and fill idle gaps.
- **Challenge 2: Load Imbalance and Long Tail Latency Across Nodes**. Serializing commands only within a single node leads to uneven queue lengths across Macs, causing long tool waiting times for Agents on busy nodes. Metal Sandbox introduces dynamic cross-node scheduling, allowing eligible waiting commands to migrate to available Mac nodes for execution and return results to the original Agent, thereby balancing load and reducing overall wait times.

## Implementation and Evaluation
- **Implementation & Deployment**: Deployed on 4 Mac mini M4 nodes, where each Agent retains its own workspace and private development environment. The system distinguishes between parallel and serial command slots and implements cross-node command migration logic. Both Metal Sandbox and its Harbor integration are open-source.
- **Evaluation Results**:
    - **Throughput Gain**: Controlled experiments under concentrated demand achieved a 1.68x–2.05x increase in command throughput.
    - **Sustained Throughput Estimate**: Analysis of 16 static Agent traces estimates a 2.14x sustained throughput gain for 4 sessions per node versus 1, assuming continuously replenished sessions.
    - **Latency Reduction**: Replaying measured traces under dynamic scheduling reduced mean tool waiting time by 18.8% and batch elapsed time by 22.3%.
- **Comparison**: Compared to traditional single-node serial execution or unscheduled concurrent execution, Metal Sandbox significantly addresses resource idleness and load imbalance, demonstrating superior performance especially in high-concurrency scenarios.

## 4. Conclusion
Metal Sandbox effectively addresses low resource utilization and high waiting latency for GPU coding Agents on Apple Silicon through fine-grained command-level scheduling and cross-node load balancing. It not only improves hardware efficiency but also accelerates model training data collection, providing an efficient infrastructure for the automated generation and optimization of on-device AI kernels.
