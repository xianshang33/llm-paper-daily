## 1. What the Paper Did
- **Background**: As Large Language Models (LLMs) improve in tool usage, autonomous penetration testing and vulnerability validation have become critical. Evaluating these security agents requires reproducible environments with variable workflow difficulty and diagnosable failures.
- **Limitations of Existing Work**: Current cybersecurity benchmarks often repurpose CTF competitions or web apps, suffering from four design risks: 1) **Training Data Exposure**: Public writeups allow literal replay rather than reasoning; 2) **Execution-Fidelity Overclaiming**: Successful execution does not prove the claimed upstream mechanism was used; 3) **Skin-Swapping Inflation**: Cosmetic rewrites inflate diversity without changing underlying mechanisms; 4) **Coarse Pass@1 Scoring**: Binary metrics fail to diagnose where an agent stalled.

## Core Contributions
- **Proposed VAST (Verifiable Adversarial Scenario Training & Evaluation)**: A declarative range compiler that separates vulnerability scenarios from a compiler-introduced workflow-hardening layer to create verifiable, multi-step environments.
- **Challenge 1: How to ensure authenticity and fidelity of mechanism execution in evaluation environments?**
  - **Difficulty**: Traditional benchmarks struggle to distinguish between memorized paths and genuine understanding, and static checks cannot guarantee runtime behavior.
  - **Solution**: VAST employs post-hoc code and AST audits to retain only seed edges with strict upstream CVE annotations. It compiles scenarios into instances with a workflow-hardening layer, ensuring each step adheres to the expected mechanism rather than just achieving surface-level success.
- **Challenge 2: How to provide fine-grained failure diagnosis and quantify the impact of workflow protocols?**
  - **Difficulty**: Binary scoring lacks diagnostic power, and it is hard to measure how much prompt information contributes to workflow completion.
  - **Solution**: VAST provides structured server error labels for diagnosis and uses contrastive experiments (e.g., contract_only vs. full_guide) to quantify the significant boost in completion rates (from ~13% to ~84%) when shared workflow protocols are provided.

## Implementation and Evaluation
- **Implementation & Dataset**: After auditing, VAST retains 109 seed edges, 72 family identifiers, 81 topic configurations, and 1,387 instances. Evaluations are conducted on the TopicServer compiler stratum and the ranges_v2 ledger.
- **Evaluation Results**:
  - **Prompt Contrast**: On TopicServer, models like glm-5.3, grok-4.7, and deepseek-v4-pro solved only 12/90 instances with `contract_only`, but performance jumped to 76/90 with `full_guide`, showing statistical significance.
  - **Multi-Container Evaluation**: On ranges_v2, agents solved 88/126 (69.8%) instances across 6 non-TopicServer workflows.
  - **Intervention Experiment**: For asynchronous Redis worker chaining (v2_02), disclosing installed worker modules increased the solve rate from 0/18 to 18/18 (100%).
  - **Fine-tuning Comparison**: LoRA fine-tuning on Qwen2.5-Coder-7B-Instruct showed Base model at 0/33, Golden SFT at 1.67/33, and Header-Recovery SFT at 4.67/33 on held-out instances, highlighting the efficacy of specific recovery strategies.
- **Comparison**: Unlike traditional CTF benchmarks, VAST avoids "skin-swapping" inflation through mechanism family clustering and strict audits, offering finer diagnostic capabilities and demonstrating the critical role of workflow protocols in LLM red-teaming performance.

## 4. Conclusion
VAST addresses issues of data leakage, low execution fidelity, and weak diagnostics in existing LLM security benchmarks by introducing a declarative compiler and rigorous post-hoc auditing. Experiments demonstrate that providing explicit workflow protocols significantly enhances LLM agent performance in complex multi-step exploitation tasks, and VAST's fine-grained evaluation framework offers a more accurate means to measure and optimize agent security reasoning.
