## 1. What the Paper Does
- **Background**: Building agentic applications requires integrating Large Language Model (LLM) operations, workflow structures with application state, and model-guided routing. Developers currently rely on SDKs or agent frameworks, using substantial glue code to connect these components, including preparing inputs, propagating state, and dispatching steps selected by the model.
- **Limitations of Existing Work**: Current SDKs and frameworks split execution logic between application code and framework internals. This separation limits compiler visibility into control flow and state dependencies, hindering automatic optimization. Furthermore, changes to workflows require coordinated updates to extensive support code, increasing development and testing efforts.

## Core Contributions
- **Proposed Agent-Native Programming and the Jac Language**: The paper introduces a new programming paradigm called "Agent-Native Programming" and realizes it in Jac, a Python-superset language that unifies LLM operations, workflow structure, and routing under shared execution semantics.
- **Challenge 1: High Development Complexity and Code Redundancy**. Traditional methods scatter LLM calls, state management, and routing logic, leading to significant boilerplate. **Solution**: Jac introduces the `by llm()` construct for typed model operations and tool use, along with "Object-Spatial Programming" for workflow and state management. This approach reduces AI-integration code by 1.8–8.7× compared to the OpenAI SDK.
- **Challenge 2: Lack of Compiler Visibility for Automatic Optimization**. The separation of logic in existing frameworks prevents compilers from analyzing dependencies between model decisions and program execution. **Solution**: Jac introduces the `visit ... by llm()` construct for model-guided routing, which derives model choices from executable workflow steps. This explicit connection provides a common basis for dependency analysis, enabling automatic optimizations like speculative execution and service partitioning.

## Implementation and Evaluation
- **Implementation**: Jac is implemented as a superset of Python with specific syntax extensions for agentic features.
- **Evaluation Results**: Across five benchmarks and five baselines, Jac achieved a 1.8–8.7× reduction in AI-integration code relative to the OpenAI SDK. It maintained competitive task quality while lowering the development effort for coding agents.
- **Case Studies**: Two case studies demonstrated that speculative execution and service partitioning could be achieved through configuration alone, leveraging program analysis and runtime checks to preserve workflow behavior.

## 4. Conclusion
This paper addresses the issues of code redundancy and optimization difficulties in agentic application development by proposing the Agent-Native Programming paradigm and the Jac language. By unifying the execution semantics of LLM operations, workflows, and routing, Jac significantly reduces the glue code required for development and enhances compiler visibility for automatic optimization. Experiments show that this method improves development efficiency and system performance potential while maintaining task quality.
