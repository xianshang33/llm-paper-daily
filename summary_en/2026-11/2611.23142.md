## 1. What the Paper Did
- **Background**: The "AI revolution" has accelerated software code delivery, but customer-facing documentation often fails to keep pace. As users increasingly rely on LLM agents that use documentation as their primary knowledge source, the propagation of stale information becomes a critical issue.
- **Why Existing Work Falls Short**: Current documentation maintenance is reactive, isolated, and lacks standardized practices. Although abundant signals exist (explicit ones like resolved support tickets and implicit ones like code-documentation discrepancies), there is no automated system to continuously extract these signals and repair documentation drift, allowing gaps to widen over time.

## Core Contributions
- **Proposed a multi-agent system called "TriAgent"**: Built around a triage agent, this system continuously extracts signals from support workflows and codebases to identify and repair documentation drift.
- **Challenge 1: How to accurately identify documentation gaps from massive unstructured data?**
  - **Difficulty**: Support tickets and code repositories contain significant noise, with scattered explicit and implicit signals that are costly to filter manually.
  - **Solution**: TriAgent uses multi-agent collaboration to monitor resolved tickets and code changes, automatically extracting potential documentation missing signals. It converts insights generated by human engineers during ticket resolution into explicit documentation gaps.
- **Challenge 2: How to ensure automatically generated documentation repairs are accurate and superior to human or existing docs?**
  - **Difficulty**: LLMs are prone to hallucinations, and it is difficult to guarantee that generated content surpasses trained human engineers or existing authoritative documentation in accuracy and utility.
  - **Solution**: The system employs a panel of LLM judges from independent model families for blind evaluation. Results showed an 81.1% correctness rate for TriAgent's verifiable assertions. In length-comparable pairs, judges preferred TriAgent's responses (70.5%) over human engineers' (23.2%). Furthermore, repairing gaps measurably improved the quality of subsequent agent answers.

## Implementation and Evaluation
- **Deployment**: The system was deployed in "shadow-mode" at Amazon for 43 days.
- **Quantitative Results**:
  - Triage of 499 tickets, surfacing 92 documentation gaps.
  - 81.1% correctness rate on verifiable assertions (245 out of 302 addressed by human resolutions).
  - In blind comparisons, LLM judges preferred TriAgent's responses in 70.5% of cases, compared to 23.2% for human engineers.
  - Post-repair, judges preferred the agent's re-answered responses in 71.4% of cases (n=35), demonstrating effective self-improvement.
- **Comparison**: Unlike traditional manual maintenance, this system is more efficient and captures insights humans might miss or that are buried in existing docs. Human and agent responses are complementary; the system formalizes human insights into documentation fixes, creating a closed-loop optimization.

## 4. Conclusion
This paper presents and deploys TriAgent, a multi-agent system for documentation maintenance that bridges the gap between rapidly iterating code and lagging documentation. By automating the extraction of explicit and implicit signals, the system continuously identifies and repairs documentation drift. Experimental results demonstrate that the system not only identifies gaps with high precision but also generates repairs that often surpass human engineer responses in quality, significantly enhancing downstream LLM agent performance and achieving automated, self-evolving documentation maintenance.
