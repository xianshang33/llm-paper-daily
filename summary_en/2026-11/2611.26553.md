## 1. What the Paper Did
- **Background**: LLM-based agents can now perform high-risk actions like deleting files and making payments. Media reports frequently describe agent failures (e.g., Replit's coding agent deleting a production database), but these reports rarely validate the incident or identify the root cause.
- **Why Existing Work Falls Short**: Current incident catalogs only collect and label reports without testing them. Benchmarks rely on human-designed tasks that do not reflect real-world scenarios. Partial replication tools (e.g., Chronicle, Squidbrake) either use simulated outputs or replay commands without accounting for model decision randomness, and none use controlled experiments to isolate the specific causes cited in reports.

## Core Contributions
- **Proposed ROGUE-AI Framework**: A multi-agent framework that offline rebuilds reported security incidents and creates a matched control group lacking only the "blamed cause," allowing for causal audit and investigation.
- **Challenge 1: How to accurately replicate stochastic agent incidents and verify root causes?**
  - **Difficulty**: Agent behavior depends on probabilistic model decisions, making single runs insufficient to prove causality, and real-world logs are often inaccessible.
  - **Solution**: ROGUE-AI constructs two environments: one with the alleged flaw (e.g., shared database) and a control with the flaw fixed. By running various vendor agents in both environments and comparing harm rates, it causally verifies the root cause.
- **Challenge 2: How to distinguish harm caused by malicious attacks vs. ordinary operational errors?**
  - **Difficulty**: Current defenses focus on prompt injection, but many incidents stem from agents missing ordinary hazards while performing normal tasks, rendering traditional defenses ineffective.
  - **Solution**: The framework reveals that most (62/72) real-world harm incidents involved no underlying attacker. It demonstrates that non-adversarial negligence causes more harm than prompt injections across all tested models, proving that specific hazard warnings are more effective than generic defenses.

## Implementation and Evaluation
- **Implementation**: ROGUE-AI uses agents from different vendors (Claude, Gemini, GPT) to collect reports and build replications, with cross-vendor review and automated code-based harm detection. It forms a reusable audit framework for pre-release testing.
- **Evaluation Results**:
  - **Replication Success**: Successfully reproduced reported harm in 89% of 108 attempts.
  - **Error Rates**: Five major models (GPT, Claude, Gemini, DeepSeek) made mistakes in 18-33% of runs with the blamed cause, compared to ≤1% in control runs without the cause.
  - **Attack Analysis**: Of 72 harmful incidents, 62 had no attacker. Non-adversarial replications caused more harm than prompt injection replications for all models.
  - **Defense Efficacy**: Warnings naming specific hazards and consequences significantly reduced harm across all models, whereas generic notes of equal length did not.
- **Comparison**: Unlike passive catalogs or artificial benchmarks, ROGUE-AI provides causal verification. Compared to partial replication tools, it introduces rigorous control groups to isolate variables accurately.

## 4. Conclusion
ROGUE-AI bridges the gap in LLM agent security analysis by providing automated replication and controlled experimentation. The study confirms that most agent incidents stem from non-adversarial design oversights rather than malicious attacks, highlighting the inadequacy of current prompt injection defenses. It proposes effective mitigation via specific hazard warnings and offers a standardized audit framework for enhancing agent safety before deployment.
