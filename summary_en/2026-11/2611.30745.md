## 1. What the Paper Did
- **Background**: LLM agents convert user requests and retrieved content into tool calls. If argument values point to the wrong recipient, endpoint, or file, harm can occur even if the tool itself is correct. Existing provenance-based defenses block values from untrusted sources but accept values from trusted sources that the user did not authorize.
- **Limitations of Existing Work**: Current defenses focus on whether a parameter's source is trusted, failing to address "Trusted-but-Unauthorized" (T-b-U) issues. For example, an email address from a corporate directory is trusted by source checks but may not be the one intended by the user, leading to potential security risks or errors.

## Core Contributions
- **Proposed IntentFlow**: A mediation layer situated between an unmodified planner and its tools, which checks each authority-bearing argument against an intent contract and a provenance policy.
- **Challenge 1: How to detect and block "Trusted-but-Unauthorized" parameters?**
  - **Difficulty**: These parameters originate from trusted sources (e.g., internal databases, historical emails), making them indistinguishable from legitimate ones via traditional source trust checks.
  - **Solution**: IntentFlow introduces an "intent contract" that compares each authoritative argument against the user's original intent, allowing only those that are both source-trusted and intent-compliant.
- **Challenge 2: How to ensure security without impacting normal task execution (low false positive rate)?**
  - **Difficulty**: Strict checks may incorrectly block numerous benign tasks, affecting user experience and agent availability.
  - **Solution**: Uses layered evaluation and hardened configurations that "fail closed" for tools and endpoints when checks are unresolved, achieving zero false blocks on 200 paired benign tasks and very low false blocks on hard tasks.

## Implementation and Evaluation
- **Implementation**: IntentFlow is deployed as middleware without modifying the underlying LLM planner. It combines intent contracts and provenance policies for runtime mediation.
- **Evaluation Results**:
  - **Synthetic Benchmark**: Attack success rate dropped from 50.5% (provenance-only) to 12.0% with IntentFlow across 200 attacks. All remaining successes involved alterations to content or payload fields.
  - **Benign Task Performance**: IntentFlow wrongly blocked none of the 200 paired benign tasks and only 4 out of 50 hard tasks.
  - **T-b-U Specific Test**: In 50 "Trusted-but-Unauthorized" attacks, provenance-only mediation executed all 50 (failed to block), while IntentFlow blocked all 50. In contrast, a CaMeL-style check blocked all 50 but falsely rejected 16/50 benign tasks.
  - **AgentDojo Replay**: IntentFlow blocked all 20 attacks with a 75% benign success rate. A Progent-style allowlist blocked 19 attacks and maintained 100% benign success.
  - **Live Planner Test**: The mediator blocked all 17 corrupted calls proposed in 110 attacks.

#### Summary
This paper addresses the security risk of "Trusted-but-Unauthorized" parameters in LLM agents by proposing IntentFlow. By introducing intent contracts, IntentFlow effectively identifies and blocks parameters that are source-trusted but inconsistent with user intent, significantly reducing the success rate of attacks like indirect prompt injection. It outperforms existing mechanisms like CaMeL in maintaining low false positive rates, offering a new runtime defense strategy for LLM agent tool-calling security.
