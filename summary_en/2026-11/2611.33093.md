## 1. What the Paper Did
- **Background**: Language model decoders carry state between decoding steps. In hardware, an incorrect state update may leave the current token correct but corrupt outputs several tokens later. Thus, a design can pass output-only tests while still being fundamentally flawed.
- **Limitations of Existing Work**: Current benchmarks typically focus only on final output correctness, lacking fine-grained verification of internal stored states. This "black-box" testing fails to capture latent errors caused by state corruption, leading to overly optimistic evaluations and providing insufficient guidance for Agents to debug complex hardware state logic.

## Core Contributions
- **Proposed AIChipBench**: A benchmarking framework for evaluating LLM coding Agents in automated AI accelerator design (specifically RTL code generation). Agents are tasked with implementing quantized Qwen3.5, Gemma 3/4, and Llama 3.2 decoders against an executable integer reference that specifies both outputs and stored states at every step.
- **Challenge 1: Hidden state errors are difficult to detect with traditional tests**. Due to the lagged effect of state errors, checking only outputs leads to false positives. **Solution**: AIChipBench introduces debugging feedback that exposes stored state mismatches. The study shows that providing the location of the first state mismatch increases acceptance rates by 25.0 to 46.9 percentage points across all Agent-task cells compared to output-only feedback, and halves the agent-hours per accepted design.
- **Challenge 2: Existing test cases do not generalize to real-world scenarios**. Many designs passing development tests fail on unseen data. **Solution**: The benchmark employs a rigorous isolated evaluation process, including tests on held-out token sequences, resets, memory stalls, and synthesis. Results showed that 45 out of 69 designs accepted in public tests failed within 32 steps under new evaluation conditions, demonstrating the necessity of final tests beyond development cases.

## Implementation and Evaluation
- **Implementation & Deployment**: The study involved four major coding Agents (Sol 5.6, Fable 5.1, Astra 6, Opus 5.5) with 9,136 total attempts. Tasks were divided into two tracks: Correctness (implementing RTL from scratch or scaffolds) and PPA (accelerating a correct design with nearly fixed area). The toolchain included linting, compilation, simulation, formal checks, and synthesis.
- **Evaluation Results**:
    - **Overall Ranking**: Sol 5.6 and Fable 5.1 outperformed Astra 6 and Opus 5.5. This ranking remained consistent across all 200 random splits.
    - **Success Rates**: In the Correctness track, Sol 5.6 had an acceptance rate of 24.5% and Fable 5.1 had 25.0%, while Astra 6 and Opus 5.5 achieved only 16.8% and 16.5%, respectively.
    - **PPA Optimization Difficulty**: More than one-third of attempts to speed up correct designs failed. In the PPA track, Sol 5.6 achieved an improvement rate of 62.4%, significantly higher than other models.
- **Comparison Conclusion**: Compared to traditional methods relying solely on output feedback, introducing state-aware feedback mechanisms significantly improved Agent performance and efficiency, highlighting the critical need for debugging support that exposes internal states for hardware design Agents.

#### Summary
AIChipBench reveals that the primary difficulty for LLM Agents in designing state-dependent hardware (like LLM decoders) lies in maintaining correct internal states. The paper demonstrates that traditional output-based testing is insufficient; it is essential to introduce debugging feedback that pinpoints specific state mismatches and to use strict held-out test sets far exceeding development scales for final evaluation. Sol 5.6 and Fable 5.1 performed best in these complex hardware design tasks, but overall success rates indicate room for improvement, emphasizing that future benchmarks must prioritize state integrity and generalization capabilities.
